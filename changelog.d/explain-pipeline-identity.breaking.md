- Consumers of saved explain documents must accept `explain_version` 5 and its new pipeline shape: `pipelines` entries now carry identity, a pipeline `id` and `depends_on` naming the build pipelines drained before it starts, with `source`, `operators` and `sink` as objects whose `id` joins the `physical_plan` node ids. The push executor builds from the same decomposition the document serializes, so the printed pipelines are the executed ones. The additive `logical_plan_initial` field holds the logical plan as resolved, before rewrite passes ran, and `explain` output prints it as the `logical_initial` tree.
