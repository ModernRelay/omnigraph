- `AppState::local` also serves a cluster's storage root to the same account on loopback, applying the cluster's own policies and stored queries for one actor and granting only `read` on a graph the cluster binds no policy to. It serves read-only: it takes no admission and forbids every write action in each policy, and its `/readyz` names the revision it booted from. Read-write is refused, as for a standalone graph, until a write whose outcome is unknown no longer stops the server. See [public embedding APIs][local-cluster-server].
