- A traversal whose destination type has no index on its identity column, read by identity lookup when the destination is too large for a hash join, now gathers its frontier into reads sized from the query's memory pool instead of one read per 256 ids. Each such read scans the destination table, so a large frontier no longer multiplies those scans: over 65,536 destination rows in 16 fragments under a 64 MiB pool, 4,096 frontier ids took 403 object-store requests to the destination table instead of 2,202, and 1,024 took 391 instead of 648. A read batch that shares its decoded pages is copied down to its rows before the read holds it. Results and the memory each read needs are unchanged.
