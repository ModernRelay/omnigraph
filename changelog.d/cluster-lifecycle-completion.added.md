- Cluster apply supports policy grants/revocations and rebinding, embedding-provider changes, and external-Blob rules on existing graphs without restarting the server. Plan previews configuration and schema changes without taking writer admission; served apply rechecks execution eligibility after affected work drains. Unrelated unavailable graphs do not block independent changes. Removing a graph declaration uses the same deployment and physically deletes its managed root and retained history after affected work drains. Deletion recovery accepts older manifests from the same graph lifetime while refusing replacements. A fresh creation can reuse verified empty local directories left by abandoned creation cleanup. Adoption, missing-root recreation and repair overrides are unsupported. See [cluster operations][cluster-lifecycle-completion].
