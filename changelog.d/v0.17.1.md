**Omnigraph 0.17.1 restores names-only graph discovery.** With an identity
admitted to the cluster, use `omnigraph graphs list --discovery` to see every
registered graph’s name. The applied policy still controls who can read or
change its data.

**Upgrade the CLI and server together.** If you used `graphs list --catalog`
in 0.17.0, switch to plain `graphs list` for the full catalog. It still
requires `graph_list`. If you use an `s3://` root, check the
[S3 upgrade instructions][patch-s3-roots] before upgrading.

[patch-s3-roots]: ../docs/user/operations/upgrade.md#s3-roots-that-name-two-keys

## Highlights

### Discover graphs before requesting access

In 0.17.0, an empty list could mean the cluster was empty or your identity
had no graph permissions. In 0.17.1, discovery lists graph IDs and display
names even when your identity has no graph permissions.

## Why these changes

The default command now requests the full catalog. Scripts that used the
0.17.0 default for discovery must select `--discovery` to get names only.
Earlier releases could store parts of the same graph under two different S3
prefixes. Omnigraph now checks the root before it sends a storage request.
