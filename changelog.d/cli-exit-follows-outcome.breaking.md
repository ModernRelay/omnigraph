- **CLI exits follow the outcome.** A failed command whose effects are unknown exits 2 instead of 1; one that did not start still exits 1, a busy refusal 75 and a failed condition 4, and a server refusal stating `not_started` with `retry` now also exits 75. An embedded write's own refusal now carries the engine's outcome, as a server's does, so embedded load conflicts and failed conditions exit as served ones (1 and 4) instead of claiming unknown effects. A refused command line exits 64 instead of 2. Read commands report the same failure envelope as data writes, with `outcome` (always `not_started` and `effects: none`) on stdout in JSON mode and on stderr in human mode. Managed commands keep their own exits for now. Update scripts that read exit 2 as a usage error or exit 1 as every failure. See [failed commands][cli-exit-outcomes].
