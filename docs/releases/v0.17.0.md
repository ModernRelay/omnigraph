Omnigraph 0.17 tells every credential which graphs it can use. A graph that gives the caller no permission answers "graph not found". MCP refuses a read that is too large for an agent to take in. New graphs use storage format 18, which records each branch in the catalog of `main`. Cleanup sends fewer storage requests, and concurrent traversals use less memory. Existing format-17 graphs need no rebuild. Upgrade every reader and writer before you create a format-18 graph. Upgrade the CLI and the server together. Rust hosts of `omnigraph-mcp` must change some calls.

## Highlights

### Every credential can ask which graphs it can use

`graphs list` needed the server's `graph_list` permit, which a cluster with no policy grants to nobody, so a static token or an OAuth client got 403. The discovery route listed every graph to an identity, including graphs it could not open. Now listing and routing use one rule: a caller sees a graph when it holds any permission on it, and every other graph answers `graph not found`, exactly as an absent one does. The listing states its rule (`visibility: granted`) and names the caller's actor. An MCP client gets a `setup` link when the list is empty, and a read over 96 KiB is refused with `result_too_large` instead of being cut off by the client: Claude Code moves a result over 50,000 characters to a file. #1544, #1526

### Branches are entries of the catalog: format 18

A branch existed as Lance ref files, and deleting one took three writes with three recovery rules, ordered only by a lock inside one process. On a format-18 graph a branch is one entry of `main`'s catalog, published by compare-and-swap with the rest of the graph. A crash between steps leaves a branch that refuses as `branch_not_ready` or `branch_deleted` until the next `branch delete` ends it. In the seeded storage-cost run (simulated store), a branch delete sends 17 storage requests instead of 25, and a write on a branch 17 instead of 22. This is the first step toward branch create and delete from several writer processes; one writer process per graph is still the supported setup. #1504, #1542

### Cleanup: 20 delete requests instead of 36

`cleanup` sent one request per freed file and opened each removed version twice. It now sends a table's freed files as one bulk delete (S3 `DeleteObjects`, up to 1,000 keys) and opens each version once. After 16 one-row inserts, `cleanup --keep 1` on RustFS sent 20 delete requests instead of 36, 38 HEADs instead of 60 and 35 GETs instead of 57. Through a proxy that adds 20 ms per request it took 3.8 s instead of 5.1 s (a 2-core VM, not a cloud store). #1502

### Eight concurrent traversals: 886 MiB instead of 3,550 MiB

After an edge write, every traversal that missed the cache built its own in-memory adjacency, outside the query memory budget, so a burst of traversals multiplied memory. Now traversals that miss together build it once and share it, and a read at a past commit uses the same cache. On a local graph of 2 million nodes and 3.5 million edges, eight cold one-hop queries peaked at 886 MiB instead of 3,550 MiB in the same time (dev build, one run). #1540

### Google Cloud Storage roots, in preview

A graph could reach Google Cloud Storage only through its S3 interoperability endpoint, with long-lived keys and no documented support for conditional writes. The embedded Rust API now opens `gs://bucket/prefix` roots with the workload's own credentials, and every commit is conditioned on the object generation, so exactly one writer wins each version. The CLI, the server and cluster roots refuse `gs://` for now. CI tests `gs://` graphs against a simulated bucket, not Google's service. #1462

## Upgrade actions

The old graph listing did not use the rules that control access to a graph. Some callers saw graphs that they cannot use. Other callers saw no graphs. Agents lost MCP results that were larger than the client accepts. A branch was a set of files with its own recovery rules. Now one catalog commit records it.

- `omnigraph graphs list` lists only the graphs your credential holds any permission on, and every other graph answers `graph not found` (404) on every route instead of 403; `og_catalog` keeps its own authorization. `--catalog` lists every graph with `graph_list`. Upgrade the CLI with the server: an older CLI cannot read the new listing; this one reports an older server's listing as `unfiltered`. See [policy][graphs-list-readable-policy]. ([#1544](https://github.com/ModernRelay/omnigraph/pull/1544))
- 0.17 reads and writes existing format-17 graphs without a rebuild. New graphs use format 18, which 0.16 cannot open. Upgrade all readers and writers before creating a graph or [upgrading a standalone graph][format-18-upgrade] to 18; the upgrade records every branch in the graph's catalog and unlinks the branch ref files. ([#1504](https://github.com/ModernRelay/omnigraph/pull/1504))
- Rust hosts of `omnigraph-mcp`: `Host::start_tool` returns `Encoded` (`Encoded::new(&dto)` replaces `bounded_result`), `HostError::from_output` no longer fails, `router` takes a docs revision and `McpSettings::resolve` a setup URL (pass `None` for either), and `ProtocolError` adds `ReadOverBudget`, which an exhaustive match must handle. See [embedding APIs][mcp-embedding]. ([#1526](https://github.com/ModernRelay/omnigraph/pull/1526))

## Features

- Preview: the embedded Rust API opens graphs at `gs://bucket/prefix` Google Cloud Storage roots, with generation-checked writes; CLI and servers come later. See [storage][gcs-storage]. ([#1462](https://github.com/ModernRelay/omnigraph/pull/1462))
- The direct reads, `init`, `schema apply` and `load` accept an inline `s3://` graph, so a graph one loader writes is read anywhere with the bucket's credentials. See [inline S3 graphs][s3-graph]. ([#1557](https://github.com/ModernRelay/omnigraph/pull/1557))

- `omnigraph-server --version` prints the report `omnigraph version` prints, so a server's version, storage formats and HTTP contract can be checked against a CLI. See [verify][server-version-verify]. ([#1549](https://github.com/ModernRelay/omnigraph/pull/1549))
- `omnigraph-bench` measures a `.gqt` `--- concurrent measured` block: every worker loops for the `--- bench` duration, once per swept value, never claim-grade. See [measured blocks][bench-measured-blocks]. ([#1486](https://github.com/ModernRelay/omnigraph/pull/1486))
- `omnigraph-bench report` names the harness commit that drove each row, beside the commit it measured, and lists a group's distinct harness commits (`harness=mixed(n)` in the text form). ([#1488](https://github.com/ModernRelay/omnigraph/pull/1488))
- `omnigraph-bench projection export` emits a store's records and catalogs as graph JSONL for `omnigraph load`, under the schema `projection schema` prints, with stored queries. See [the results graph][bench-results-graph]. ([#1557](https://github.com/ModernRelay/omnigraph/pull/1557))
- `omnigraph-bench run --store s3://… --backend <json> --server-product` runs the server route over a bucket, each repetition's cluster root a prefix under `servers/`. See [server runs][bench-server-s3]. ([#1520](https://github.com/ModernRelay/omnigraph/pull/1520))
- `omnigraph-bench run --store <dir> --server-product` measures against the build's `omnigraph-server`, started per repetition, writes and measured blocks included. See [server runs][bench-server]. ([#1500](https://github.com/ModernRelay/omnigraph/pull/1500))
- `scripts/install.sh` accepts `ARCHIVE_SHA256`, which also requires the downloaded archive to have that digest, so a pinned install refuses an asset replaced under its tag. See [install][install-archive-sha256]. ([#1507](https://github.com/ModernRelay/omnigraph/pull/1507))
- The README and [install guide][python-client] list the Python client, `omnigraph` on PyPI, which speaks HTTP contract `0.14`. ([#1519](https://github.com/ModernRelay/omnigraph/pull/1519))

## Behavior changes

- `GET /graphs/discovery` and MCP `graphs` answer every credential with `visibility: granted`, its `actor_id` and the graphs it holds any permission on, so a token needs no `graph_list`. See [policy][graphs-discovery-policy]. ([#1544](https://github.com/ModernRelay/omnigraph/pull/1544))
- MCP refuses a successful read over a fixed 96 KiB budget with `result_too_large`, naming it, instead of sending more than clients take. Writes and refusals keep 1 MiB. See [limits][mcp-limits]. ([#1526](https://github.com/ModernRelay/omnigraph/pull/1526))
- A branch is a catalog entry, not a ref file; new 409 answers `branch_exists`, `branch_deleted` and `branch_not_ready`. See [Branches][branch-existence]. ([#1504](https://github.com/ModernRelay/omnigraph/pull/1504))
- A load or mutation refused for an edge whose endpoint does not exist names the edge type, and says when the edge is a committed one an `overwrite` would strand. See [edge endpoints][orphan-edge-endpoints]. ([#1497](https://github.com/ModernRelay/omnigraph/pull/1497))
- The MCP `query` and `mutate` descriptions name GQ, the Omnigraph query language, and link its guide at the server's own revision: a stable release's tag or an edge build's commit. ([#1526](https://github.com/ModernRelay/omnigraph/pull/1526))
- `omnigraph-bench --version` prints the source commit and tree state the binary was built from, on two lines after the version; `-V` stays one line. ([#1498](https://github.com/ModernRelay/omnigraph/pull/1498))

## Fixes

- Writes of one entity in one mutation keep only its latest pending version, so a later statement matches it once: no false `@unique` violation, lost update or inflated affected count. See [mutations][mutation-multi-update-limits]. ([#1454](https://github.com/ModernRelay/omnigraph/pull/1454))
- Traversals that start together after an edge write build the in-memory adjacency once and share it; each used to build its own copy. `run_query_at` now reuses it too. ([#1540](https://github.com/ModernRelay/omnigraph/pull/1540))
- A direct write or read of a path that holds no graph is refused as `not_found` with `effects: none` and exit 1, not as an unknown outcome to reconcile. See [failed writes][missing-graph-dispositions]. ([#1495](https://github.com/ModernRelay/omnigraph/pull/1495))
- A load refused before its first effect, such as a malformed row or a refused `load csv` source, reports `effects: none` and `action: fix`, not `unknown` and `reconcile`. See [failed writes][load-refusal-effects]. ([#1505](https://github.com/ModernRelay/omnigraph/pull/1505))
- A direct `load csv` on a cluster graph refuses a `file://` source anywhere in the cluster's storage root, not only in its graph's root. See [CSV loading][load-csv-source-root]. ([#1505](https://github.com/ModernRelay/omnigraph/pull/1505))
- Insert and update statements accept an empty list for a typed list property such as `[I64]`. ([#1377](https://github.com/ModernRelay/omnigraph/pull/1377))
- Update `url` to 2.5.9 for [RUSTSEC-2026-0592](https://rustsec.org/advisories/RUSTSEC-2026-0592): `Url::origin()` overflowed the stack on a deeply nested `blob:` URL. Omnigraph calls it only on its own configured URLs, never on request input. ([#1514](https://github.com/ModernRelay/omnigraph/pull/1514))
- `omnigraph-bench` derives the CPU model on arm64 Linux when `/proc/cpuinfo` names none, from the first `CPU implementer`, `CPU variant`, `CPU part` and `CPU revision` lines, instead of refusing the run. ([#1485](https://github.com/ModernRelay/omnigraph/pull/1485))
- `omnigraph-bench run --at <sha>=<path>` takes a full lowercase 40-character commit sha as written, so it runs on a host with no `git` and no repository. ([#1521](https://github.com/ModernRelay/omnigraph/pull/1521))
- `omnigraph-bench --store s3://…` passes `AWS_ENDPOINT` on to the `omnigraph` and `omnigraph-server` it starts, so they reach the same service as the harness's own store client. ([#1520](https://github.com/ModernRelay/omnigraph/pull/1520))
- On a format-18 graph, `branch create` probes its new branch through the graph's own storage client, so a served graph's request policy and storage target apply to it as to every other request. ([#1542](https://github.com/ModernRelay/omnigraph/pull/1542))
- `branch create` refuses a name that ends in `/`. It used to create a branch that `branch list` shows as `a/.<ULID>` and that `a/` does not name; delete such a branch by its listed name. ([#1532](https://github.com/ModernRelay/omnigraph/pull/1532))
- `branch create` refuses a name with a space, a character such as `^` or `~`, a `..`, or a final `.` by the name as written, not by an internal ref; the branching guide states the rule. ([#1532](https://github.com/ModernRelay/omnigraph/pull/1532))
- `cleanup --help` says a run without `--confirm` lists no candidates, `cluster members --help` that it lists active organization members, and `init --help` that the URI is local. ([#1549](https://github.com/ModernRelay/omnigraph/pull/1549))
- `cluster validate`, `plan` and `apply` refuse a graph ID the server refuses at startup, such as one with an underscore, instead of applying a cluster that cannot be served. See [graph IDs][cluster-graph-id-rule]. ([#1491](https://github.com/ModernRelay/omnigraph/pull/1491))
- `cluster token --ttl` help and docs now say it requests a lifetime: the managed service may issue a shorter credential, and the result's `expires_at` reports the one issued. See [managed data][cluster-token-ttl-guide]. ([#1546](https://github.com/ModernRelay/omnigraph/pull/1546))
- A query the compiler refuses on a direct target reports `action: fix`, as the same refusal from a server does, instead of `refresh`. ([#1549](https://github.com/ModernRelay/omnigraph/pull/1549))
- `omnigraph-gqt` and `omnigraph-bench` read a case whose `# notes:` or `# red_on:` line spells `${`; the parser refused it as a misplaced substitution. ([#1524](https://github.com/ModernRelay/omnigraph/pull/1524))
- An `s3://` clone root whose key overlaps its base's is refused when the two bucket names address one bucket, or the root's bucket holds a copy of the base at that key. ([#1522](https://github.com/ModernRelay/omnigraph/pull/1522))
- An `s3://` clone root with `^`, `~` or a bracket now reads through its base. A root or base that does not name one key (a percent escape, a space, a query, an empty segment) is refused at open. ([#1522](https://github.com/ModernRelay/omnigraph/pull/1522))
- Error messages, command help, MCP instructions and the OpenAPI document spell the product `Omnigraph`. ([#1505](https://github.com/ModernRelay/omnigraph/pull/1505))
- When no graph opens at startup, or `--require-all-graphs` refuses one, the server's error names the first graph that failed and why, without debug logging. ([#1549](https://github.com/ModernRelay/omnigraph/pull/1549))
