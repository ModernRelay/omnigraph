# OmniGraph v0.11.0 (unreleased)

Notes accumulate here until the release is cut.

## Highlights

- **Adaptive traversals with a persisted adjacency index.** The traversal
  cost decision now reruns at every hop with the observed frontier, and a
  traversal that outgrows the indexed path switches to the in-memory CSR
  mid-flight, carrying its state. `optimize` additionally persists the built
  adjacency as a new object under the graph root
  (`__graph_index/csr-current.bin` — derived and regenerable; every load is
  verified and falls back to the in-memory build), so cold traversal builds
  load one object instead of scanning every edge dataset; the artifact is
  refreshed by edge-committing `optimize` runs. An unordered, aggregate-free
  `limit n` on a trailing traversal now stops at the cap: it returns any
  valid `n` rows (a subset, not a slice), so which rows you get for such
  queries can change from v0.10.
- **Search-ordered results are ranked by score, deterministically.**
  `order { nearest(...) }` / `bm25(...)` results are now explicitly sorted on
  the search score (ascending distance / descending relevance) with the
  documented entity-id tie-break, including through multi-hop traversals, and
  keys after the search function apply as secondary sorts. Observable result
  order can change on upgrade where scores tie (previously the storage
  engine's internal order leaked through), and `order … limit n` now runs a
  bounded top-k sort. `_distance` and `_score` become reserved property names
  for NEW schema declarations (existing graphs that already declared them
  keep opening).
- **Bounded ranked full-text scans.** A `bm25()` ordering with a `limit` now
  reads only the top-scoring matches (a small multiple of the limit) instead
  of hydrating every matching entity. This fixes ranked reads with traversals
  failing at corpus scale with an Arrow offset overflow (#563) and makes
  join-free ranked reads proportionally faster. When traversals or filters
  leave the limit unfilled, the query automatically rescans without the
  bound, so result sets are never truncated; aggregate returns are never
  bounded. Full-text rankings inside `rrf()` are not bounded: bounding an
  arm could silently shift fused results when a traversal drops its top
  matches, so each full-text arm still scans every matching entity. `rrf()`
  behavior is unchanged from v0.10, including its cost: an `rrf()` ranked
  read still hydrates its full matched corpus per full-text arm, so at
  corpus scale it keeps v0.10's cost and, with traversals, v0.10's Arrow
  offset-overflow exposure (#563 is fixed for `bm25()` orderings). A
  `nearest()` ranking inside `rrf()` remains top-k, as vector search always
  is: an entity outside its window contributes no vector rank to the
  fusion.
