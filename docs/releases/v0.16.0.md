Omnigraph 0.16 checks access on direct cluster writes. A graph without a policy denies reads by default. A request cannot raise its budget above the server's limit. A cluster server can compact datasets while it serves. Completed compaction survives a later index failure. Small keyed writes and repeat reads send fewer storage requests. Existing format-16 graphs need no rebuild. Upgrade every reader and writer before creating a format-17 graph. See the upgrade actions for changes to login, token files, maintenance APIs and `repair`.

## Highlights

### Servers refuse what the operator did not grant

Any static bearer token could read every graph that had no applied policy, and any request could raise its own memory and work budgets without limit. Any credential could also crash the server, and every graph with it, with one MCP tool call or a deeply nested query. Now a graph with no policy refuses every action (default deny), a budget above the server's default gets a 400, each MCP tool call runs in its own heap allocation, and query nesting is bounded before parsing. The server also refuses a token file that other accounts can write, and a static actor named like a signed identity. #1323, #1324, #1327

### Compaction keeps completed work when an index fails

On a 657-table production graph, an optimize run that changed nothing held up writes for 577 seconds, measured from outside the server's region. With `--max-gate-hold`, the first dataset runs and the deadline stops further datasets from starting. Writers still wait for work already started, publication and configuration cleanup. Use `--datasets` to select datasets. If an index step or its final coverage check fails after compaction, the completed work publishes once. The report marks the dataset `optimized` with reason `index_failed` and includes the error. On a server, submitting the same request with its retained operation ID returns the existing record. A new operation rechecks coverage and retries any remaining index work. Operators upgrading from an early edge build can find the operation-record recovery procedure in the upgrade actions. #1275, #1282, #1415, #1418, #1478, #1479

### Direct optimize runs up to eight compaction tasks at once

At the default concurrency of eight, direct `optimize` can run eight compaction tasks or build up to four independent B-tree indexes at once. Each Blob table still runs one compaction task at a time. A full-text or vector build uses all available slots. Served `optimize` runs one task at a time. If a dataset exceeds a server limit, another run defers it again. Raise the limit or optimize it directly. #1396, #1395, #1441

### Keyed writes: 34 storage requests instead of 212

A one-row keyed write scanned the key column of every fragment, so its cost grew with the table. It now probes the identity index while the unindexed tail is small: at 262,144 rows in 64 fragments, an update sends 34 requests instead of 212 and an insert 18 instead of 83 (simulated store, not S3). A traversal after a write or branch change rebuilds topology only for the edge tables that changed: 26 requests instead of 59 at 131,072 edges. A `limit` with no filter reaches the Lance scanner and reads 1 of 25 data files instead of 16 on local disk. On a server, repeat commit lookups open only the branch that holds them; a hosted graph with nine branches took 13 s per lookup before, and the hosted gain is not yet measured. #1318, #1363, #1342, #1184

### Spilling queries finish within their memory budget

A correlated block that reads the outer row, such as `max($b.x) { … } > 0`, collected every inner match before folding them, so a large fan-out ran out of `query_memory_bytes`: 16,384 one-KiB inner rows were refused at 12 MiB, and now complete there (local disk). A query whose sort spilled could fail at one budget yet pass at smaller and larger ones; its merge now reserves 9.4 MiB instead of 40 at the default 150 MiB and stays within half the budget. Spill files are zstd-compressed: the whole-query spill test wrote 5.9 MB instead of 52.6 MB. #1341, #1362, #1389, #1348

## Upgrade actions

A static token could read graphs without a policy. Direct cluster writes and embedded maintenance skipped policy checks. Login could silently select an organization. Callers could raise their own budgets. Another local account could add tokens through a writable token file. `repair` held write locks to list unused commits. Format 17 lets a branch reject a writer after its replacement claims ownership.

- Any static bearer token could read every graph on the server that had no applied policy. Such a graph now refuses reads as it refuses every other action. Apply a policy granting `read` to each graph a token should read, or set `OMNIGRAPH_ALLOW_READS_WITHOUT_POLICY=1` on the server to keep the old behaviour. See [authentication][no-policy-reads].
- Direct CLI writes and maintenance on a cluster graph now obey the graph's applied policy, as `omnigraph access` already reported; they used to apply none. Pass an `--as` actor the policy admits (`optimize` and `cleanup` now accept `--as`), or the command is refused as `forbidden` with no effects. See [direct writes][direct-cluster-writes]. ([#1423](https://github.com/ModernRelay/omnigraph/pull/1423))
- Scripts creating profiles for people in several organizations must pass `--organization ID`; `--json` returns the choices on stdout. See [login][cli-login-organization-choice]. ([#1344](https://github.com/ModernRelay/omnigraph/pull/1344))
- A served request could raise its own `traversal_work_limit`, `query_memory_bytes`, `write_max_bytes` or `load_source_max_bytes` without limit. A value above the server's default is now refused with a 400; operators raise the ceiling with the setting's environment variable. Lowering a budget still works. See [settings][budget-ceiling]. ([#1327](https://github.com/ModernRelay/omnigraph/pull/1327))
- Another local account that could write `OMNIGRAPH_SERVER_BEARER_TOKENS_FILE` could add a token for any actor. On Unix the server now refuses to start when that file is writable by other accounts or is not a regular file, and warns when they can read it. Run `chmod 600` on it. See [token sources][token-file-mode]. ([#1324](https://github.com/ModernRelay/omnigraph/pull/1324))
- Static bearer-token actors may no longer start with `principal:`, the prefix of signed and OIDC identities, so a server whose token configuration names one refuses to start: rename that actor and its policy rules. The AWS Secrets Manager source now also refuses duplicate token values. See [tokens][reserved-actor-prefix]. ([#1323](https://github.com/ModernRelay/omnigraph/pull/1323))
- 0.16 reads and writes existing format-16 graphs without a rebuild. New graphs use format 17, which 0.15 cannot open. Upgrade all readers and writers before creating a graph or [upgrading a standalone graph][format-17-upgrade] to 17. ([#1402](https://github.com/ModernRelay/omnigraph/pull/1402))
- Embedded hosts with a policy checker: `optimize` and `cleanup` ran unchecked. Now `optimize_as`, `ensure_indices_as`, `ensure_indices_on_as` and `rebuild_full_text_indices_on_as` need `maintain`, `cleanup_as` needs `reclaim`, and `change` admits no maintenance. The methods without an actor are removed. Grant the new actions. See [policy actions][maintenance-actions-upgrade]. ([#1275](https://github.com/ModernRelay/omnigraph/pull/1275))
- Embedded hosts: `optimize_as` takes an `OptimizeRequest` (`OptimizeRequest::default()` is a full run) and returns an `OptimizeReport` whose `datasets` holds the per-table stats; `committed` is a method. `optimize --json` reports the `__manifest` row as `configuration_clear` and drops the always-null `skipped`, `published_dataset_version` and `lance_head_version`. See [bounding a run][optimize-request-upgrade]. ([#1275](https://github.com/ModernRelay/omnigraph/pull/1275))
- If an early edge build saved `tables` or `more_tables` in a recorded `optimize`, follow the [offline recovery steps][edge-optimize-record] before using operations again. Moving that record aside loses its results and resume position and lets an old operation ID start work again. ([#1402](https://github.com/ModernRelay/omnigraph/pull/1402))
- `omnigraph repair` and the embedded `Omnigraph::repair` report (`RepairOptions`, `RepairStats`) are removed; they only listed foreign Lance commits, which no read or write uses. A confirmed `cleanup --keep N --confirm` run, which also reclaims unretained history, lists them per table (`foreign_versions` under `--json`); embedded hosts can call the read-only `cleanup_plan`. See [foreign versions][repair-removed-foreign-versions]. ([#1372](https://github.com/ModernRelay/omnigraph/pull/1372))
- Custom benchmark catalogs: the `groups:` key is `suites:`. A `benchmarks.yaml` or custom config with `groups:` is refused by the loader with a message naming `suites`; move the key, the scenario lists keep their shape. `list scenarios` prints suites, the suite diagnostics are `invalid_suite_*`, and a run or report selects a suite by its name as before. See [the catalog][benchmark-catalog]. ([#1439](https://github.com/ModernRelay/omnigraph/pull/1439))

## Features

- After the first dataset, `--max-gate-hold` stops new work at the deadline. Use `--datasets` to select datasets or the printed `--start-at` to [resume a direct run][optimize-bounded-runs]. ([#1275](https://github.com/ModernRelay/omnigraph/pull/1275))
- A cluster server can run `optimize` while it serves, as a recorded operation tracked by id; `omnigraph optimize` against it submits and waits. Enable with `OMNIGRAPH_OPERATION_ROUTES=true`. See [operations][recorded-optimize]. ([#1282](https://github.com/ModernRelay/omnigraph/pull/1282))
- Embedded hosts can bound, cancel and observe an optimize run through `OptimizeRequest`: table and run ceilings, an adjacency artifact limit, cancellation and a before-publish callback. ([#1275](https://github.com/ModernRelay/omnigraph/pull/1275))
- An embedded program can claim a format-17 branch (`claim_branch_writer`) so no stale process lands a write on it; other writers, server and CLI too, get 409 `writer_fenced`. See [writer epoch][writer-epoch-guide]. ([#1350](https://github.com/ModernRelay/omnigraph/pull/1350))
- Embedded hosts can open a clone (`Omnigraph::open_clone`) that reads an unchanging base graph in place and writes only to its own root, on local disk or `s3://`; `omnigraph-gqt --base` opens one. ([#1367](https://github.com/ModernRelay/omnigraph/pull/1367))
- An embedded host's query profile shows which operators spilled to scratch files and how much (`node` `spill`), and spill files are zstd-compressed to a third or a tenth of their size. See [profile][spill-profile]. ([#1348](https://github.com/ModernRelay/omnigraph/pull/1348))
- The [onboarding guide][skill-onboarding] starts with the user's use case or a cookbook and walks an agent through querying a local graph. ([#1333](https://github.com/ModernRelay/omnigraph/pull/1333))
- `omnigraph-bench run --local-route direct|object-store|read-through` compares how an engine-target repetition reaches its fixture; `read-through` opens an empty clone root over the frozen fixture. ([#1365](https://github.com/ModernRelay/omnigraph/pull/1365))
- `omnigraph-bench --catalog <DIR|FILE>`, repeatable on `run`, `report`, `show`, `list` and `cache status`, reads several catalogs: a name resolves in the first that declares it. ([#1439](https://github.com/ModernRelay/omnigraph/pull/1439))
- `omnigraph --base <root>` opens a graph shallow clone of a direct target over its frozen base; `--stats <path>` writes one document per invocation with its store calls, exit code and peak RSS. ([#1416](https://github.com/ModernRelay/omnigraph/pull/1416))
- `omnigraph organization list --profile NAME` lists the organizations you are an active member of, with names and IDs, and marks the profile's. See [your organizations][cli-organization-list]. ([#1344](https://github.com/ModernRelay/omnigraph/pull/1344))
- A `.gqt` case may declare branches: `--- branches generate: v1 count: <n> prefix: <name>` after `--- seed` forks and loads each one before step 1, as no step; see the [fixture contract][gqt-branches-fixture]. ([#1443](https://github.com/ModernRelay/omnigraph/pull/1443))
- `omnigraph-gqt --check` names every case rule by a stable code with the line to write; `--explain <code>`, `--grammar` and `--version` describe the case format. See the [GQT runner guide][gqt-check-rules-guide]. ([#1410](https://github.com/ModernRelay/omnigraph/pull/1410))
- `omnigraph-gqt --check <case.gqt|dir>...` prints every format error of a `.gqt` case at once, each with its code, the quoted line and the fix, and runs nothing. See the [GQT runner guide][gqt-check-guide]. ([#1398](https://github.com/ModernRelay/omnigraph/pull/1398))
- A `.gqt` `--- concurrent` block is free-running on every host, with worker counts and dealt `load generate:` rows; the scripted block is spelled `--- concurrent scripted`; see the [block contract][gqt-concurrent]. ([#1477](https://github.com/ModernRelay/omnigraph/pull/1477))
- `schema apply` widens an edge type's `@card` range in place, such as `@card(1..1)` to `@card(0..1)`, without rewriting data; tightening one is still refused ([guide][edge-cardinality], [#1403][1403]). ([#1406](https://github.com/ModernRelay/omnigraph/pull/1406))

## Behavior changes

- An update, delete or overwrite load overtaken by another commit reruns once on the new head, selecting its rows again, instead of returning `read_set_conflict`; `--if-commit` refuses. See [mutations][overtaken-writes-mutations]. ([#1349](https://github.com/ModernRelay/omnigraph/pull/1349))
- Check the [outcome of each dataset][optimize-run-outcomes] even when `optimize` exits successfully. One dataset can fail while others publish their work. ([#1275](https://github.com/ModernRelay/omnigraph/pull/1275))
- If an index step or coverage check fails after compaction, [`optimize`][optimize-index-failed] keeps the rewrite and reports `optimized` with reason `index_failed` and the error. Direct reports keep known pending indexes. ([#1418](https://github.com/ModernRelay/omnigraph/pull/1418))
- A Blob write whose branch was recreated, or whose schema changed meanwhile, returns `read_set_conflict` as other writes do, not a generic `conflict`. See [Blob writes][blob-identity-refusal]. ([#1349](https://github.com/ModernRelay/omnigraph/pull/1349))
- The installers stop on a failed download instead of switching to an edge build, which can write a format stable binaries refuse, and verify build provenance when `gh` is signed in. See [install][installer-provenance]. ([#1325](https://github.com/ModernRelay/omnigraph/pull/1325))
- The storage and embedding guides cover encryption at rest, catalog growth, the conditional writes an S3-compatible store needs (GCS is untested), and running with no outbound requests. See [storage][operator-notes]. ([#1326](https://github.com/ModernRelay/omnigraph/pull/1326))
- `benchmarks.yaml` scenarios name no environment: `omnigraph-bench run` supplies it (`--server`, else the host's local default); the 18 `-served` twins are gone and the two `-xfs` ids drop the suffix. ([#1416](https://github.com/ModernRelay/omnigraph/pull/1416))
- `omnigraph-bench run --store … --at <a> --at <b>` measures each scenario once per ref before the next scenario, so the refs share machine state; records and outputs keep their shape. ([#1439](https://github.com/ModernRelay/omnigraph/pull/1439))
- The `omnigraph-bench` README names the S3 credential sources its client renews (instance metadata, container endpoint, web identity) and the one it never does (static keys). ([#1439](https://github.com/ModernRelay/omnigraph/pull/1439))
- A refused sign-in names the check that failed. Provider tokens that do not fit the API's sign-in configuration refuse with `provider_response_invalid`, not `credential_invalid`. See [login][cli-login-refusals]. ([#1344](https://github.com/ModernRelay/omnigraph/pull/1344))
- CSV query output writes a null as an empty field instead of `null`, so `load csv` reads it back as null and a stored string `null` stays distinct. See the [CLI reference][csv-null-reference]. ([#1440](https://github.com/ModernRelay/omnigraph/pull/1440))
- A converged local or S3 [cluster apply][direct-apply-lock] releases its lock after writes settle. An unconfirmed release identifies the deployment and lock to check. Azure retains its lock. ([#1360](https://github.com/ModernRelay/omnigraph/pull/1360))
- A merge refused by its validation limit now names `branch-merge retained validation key bytes`, counting only the delta's keys; such a branch merges in stages. See the [validation limit][merge-validation-key-limit]. ([#1433](https://github.com/ModernRelay/omnigraph/pull/1433))

## Fixes

- In 0.15.0 any MCP tool call, even `health`, crashed `omnigraph-server` with a stack overflow, taking every graph down, for any credential. Each tool call now runs in its own heap allocation.
- A deeply nested query, or an `and`/`or` chain past about 256 terms, crashed the server for any signed-in caller. It is now refused with `Q006` before parsing; use `in [...]` for long lists. See [parse codes][codes].
- Writes no longer stall or fail while `optimize` publishes in the same process: a write that meets an optimize commit is carried over it without preparing again. See [maintenance][carried-writes-maintenance]. ([#1349](https://github.com/ModernRelay/omnigraph/pull/1349))
- A served `optimize` defers a dataset over its [per-dataset limit][optimize-ceiling-every-run] on every run. Raise the limit or optimize it directly. ([#1441](https://github.com/ModernRelay/omnigraph/pull/1441))
- A storage failure while `optimize` or `index build` rebuilds a vector index is an error again; it was reported as a column that cannot train an index. See [build indexes][vector-rebuild-errors]. ([#1418](https://github.com/ModernRelay/omnigraph/pull/1418))
- `index build` and `optimize` no longer fail on every run after an `update` of an indexed vector property empties its index; they rebuild it. ([#1446](https://github.com/ModernRelay/omnigraph/pull/1446))
- A query whose sort spills no longer fails at one memory budget yet passes at smaller and larger ones: the merge reserves less up front (9.4 MiB, not 40, by default) and stays within half the budget. ([#1389](https://github.com/ModernRelay/omnigraph/pull/1389))
- A failed storage read on the served deployment routes (`cluster apply` or `plan` against a server, deployment status) answers 503 to retry, or 500 if it repeats, not 409. See [recorded operations][recorded-operations-guide]. ([#1357](https://github.com/ModernRelay/omnigraph/pull/1357))
- The `policy` commands accept a graph bundle beside a `cluster` bundle and answer each action from the bundle a server uses for it. See [validate and test][policy-commands-by-scope]. ([#1311](https://github.com/ModernRelay/omnigraph/pull/1311))
- The container entrypoint refuses `OMNIGRAPH_TARGET_URI`, `OMNIGRAPH_CONFIG` and `OMNIGRAPH_TARGET` by name and points to `OMNIGRAPH_CLUSTER`. See [container][entrypoint-cluster]. ([#1329](https://github.com/ModernRelay/omnigraph/pull/1329))
- Upgrade `rmcp` from 3.3.0 to 3.9.0 for three RustSec advisories: an SSRF host-string check, an unbounded tool-schema cache and unbounded client response buffering. The MCP endpoint is unchanged. ([#1291](https://github.com/ModernRelay/omnigraph/pull/1291))
- Update `rustix` to 1.1.6 for [RUSTSEC-2026-0486](https://rustsec.org/advisories/RUSTSEC-2026-0486): its extended-attribute functions were unsound for a zero-length buffer. Omnigraph does not call them. ([#1350](https://github.com/ModernRelay/omnigraph/pull/1350))
- `omnigraph-bench --store s3://bucket/prefix`, on `run` and `report`, admits a colon in a prefix segment, the shape of an EC2 instance role's `${aws:userid}` (`<role id>:<instance id>`). ([#1480](https://github.com/ModernRelay/omnigraph/pull/1480))
- Concurrent sign-ins creating the same profile preserve the successful sign-in. If a profile cannot be saved, a previously saved sign-in the CLI reused remains available. ([#1344](https://github.com/ModernRelay/omnigraph/pull/1344))
- A conditional mutation that loses a race reports `precondition_failure`, not an edge `@card` violation caused by the winning commit. See [conditional mutations][conditional-race-guide]. ([#1426](https://github.com/ModernRelay/omnigraph/pull/1426))
- CSV query output quotes empty strings so a single empty field survives a CSV round trip. ([#1375](https://github.com/ModernRelay/omnigraph/pull/1375))
- A `branch merge --dry-run` whose answer is lost, such as to a client deadline, now reports `effects: none` and exits 1, as a read does, instead of `effects: unknown` with `reconcile`. ([#1448](https://github.com/ModernRelay/omnigraph/pull/1448))
- Cleanup and optimize reject duration arguments whose unit conversion would overflow seconds, and cleanup refuses an `--older-than` age that reaches before the earliest representable time. ([#1378](https://github.com/ModernRelay/omnigraph/pull/1378))
- A `branch merge` no longer refuses a delta for the width of its rows: validation streams the delta and counts only its keys toward its 32 MiB limit. See the [validation limit][merge-validation-streams]. ([#1433](https://github.com/ModernRelay/omnigraph/pull/1433))
- An applied state in which two policy bundles bind one scope, or one bundle binds both the cluster and a graph, is now refused by every reader, as the server already refused it. See [binding][policy-binding]. ([#1434](https://github.com/ModernRelay/omnigraph/pull/1434))
- `query --format arrow` writes an Arrow IPC stream from a direct target to a redirected stdout instead of always refusing; a terminal or a served target refuses before any work. See [Arrow output][query-arrow-output]. ([#1429](https://github.com/ModernRelay/omnigraph/pull/1429))
- Deployment recovery that a graph's policy refuses, including one with no `--as`, now refuses `policy_denied` before taking the lock, not `deployment_outcome_unknown`. See [recovery][reconcile-actor]. ([#1438](https://github.com/ModernRelay/omnigraph/pull/1438))
- Removing nodes an edge type references (overwrite load, `load csv`, delete or merge) no longer needs memory that grows with removed ids times edge fragments. ([#1444](https://github.com/ModernRelay/omnigraph/pull/1444))
- The agent skill says a nullable property can be promoted to required once every stored row holds a value, and that index builds and the full-text rebuild need `maintain`, not `change`. See [the skill][skill-promotion-maintain]. ([#1422](https://github.com/ModernRelay/omnigraph/pull/1422))
- A traversal reads each step's edges one batch at a time, so a read from a node with many edges no longer exceeds `query_memory_bytes` once the edge tables are indexed. ([#1460](https://github.com/ModernRelay/omnigraph/pull/1460))

## Performance

- A keyed write of a few rows (`insert`, `update ... where <key> = v`, `load --mode merge`) finds them through the identity index, not a scan: 34 requests instead of 212 at 262,144 rows (simulated store). ([#1318](https://github.com/ModernRelay/omnigraph/pull/1318))
- On a server or other long-running process, looking up one unmerged commit after another (history, review, `commit changes`) opens only the branch that holds it after the first, not every live branch. ([#1184](https://github.com/ModernRelay/omnigraph/pull/1184))
- A traversal after a write or a branch change no longer rebuilds topology for edges the change did not touch: 26 requests instead of 59 at 131,072 edges (simulated store). Results are unchanged. ([#1363](https://github.com/ModernRelay/omnigraph/pull/1363))
- A `limit` with no filter or `order` stops Lance reading ahead: `match { $p: Person } return { $p.name } limit 10` reads only the fragments holding those rows (1 of 25 files, not 16, on local disk). ([#1342](https://github.com/ModernRelay/omnigraph/pull/1342))
- A correlated block that reads the outer row, such as `max($b.x) { … } > 0`, no longer runs out of `query_memory_bytes` on a large fan-out: it folds inner matches batch by batch. Results are unchanged. ([#1341](https://github.com/ModernRelay/omnigraph/pull/1341))
- A read, diff or change page pinned to a graph commit opens that version directly instead of finding the latest first: one GET fewer on local disk, and one LIST fewer on object stores (inferred). ([#1390](https://github.com/ModernRelay/omnigraph/pull/1390))
- A reader or branch still at a table version that a write replaced reopens nothing: the cache keeps that handle until its budget (64 handles or 64 MiB) needs the room. ([#1319](https://github.com/ModernRelay/omnigraph/pull/1319))
- The next read or write after a write in the same process reuses the table versions it committed instead of reopening them, and a mutation holds the write gates for less time. ([#1291](https://github.com/ModernRelay/omnigraph/pull/1291))
- A direct `optimize` compacts a table's fragments in parallel tasks, sharing `OMNIGRAPH_MAINTENANCE_CONCURRENCY` (8) with index work; served runs and Blob tables still run one task at a time. ([#1396](https://github.com/ModernRelay/omnigraph/pull/1396))
- `index build` and `optimize` build up to four BTREE indexes at once per run, within and across tables. A full-text or vector build runs alone: in `optimize`, no compaction or other build runs beside it. ([#1395](https://github.com/ModernRelay/omnigraph/pull/1395))
- Filters evaluated in memory use less CPU when few rows pass: the right side of `and`/`or`, and each later condition, run only on rows not yet decided. Results are unchanged. ([#1346](https://github.com/ModernRelay/omnigraph/pull/1346))
- Export, the change feed, merges and key matching (`not`, `count` and `sum` blocks, bound edges, hash joins) use less CPU: one copy per chunk instead of two, and keys hashed a batch at a time. ([#1347](https://github.com/ModernRelay/omnigraph/pull/1347))
- `--format kv` works out its columns once per response, not once per row; against an older server that omits column names, 1,000 rows print in 0.17 s instead of 0.46 s. ([#1376](https://github.com/ModernRelay/omnigraph/pull/1376))
