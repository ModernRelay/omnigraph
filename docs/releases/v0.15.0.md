In local LDBC SF30 runs, CSV bulk loads take under half the 0.14 time. Reads on an open graph do not wait for its writes. Diffs and merges read only the data that changed. MCP exposes every graph operation except byte streams. Policy alone decides what an agent can run. An S3 cluster server stops writing at its lease deadline. This release changes `@card` and `@unique` checks, MCP flags, organization commands, saved plans and a Rust error type. Read the upgrade actions before you upgrade. Graph storage and the HTTP contract stay the same. Existing graphs open without a rebuild.

## Highlights

### CSV bulk load: SF30 in under half the 0.14 time

Pipelined bulk load: an overwrite `load csv` streams from the source object to the Lance writers. Each parse partition range-reads its own 8 MiB pieces, checks uniqueness in a shared hash table and probes integer-keyed edge endpoints as rows arrive; full fragments are written while the next rows parse. The removal scan runs only when a retained-edge check needs it, and a refused load leaves no fragment. In the pull requests' LDBC SNB SF30 runs (31 overwrite statements into a fresh graph, release builds, an Apple silicon workstation on local disk), the load fell from 261 s at 0.14.0 to 87–110 s. #1141, #1147, #1158, #1178

### Reads no longer wait for a write

Read-copy-update: an open graph's branch state is a copy-on-write value behind an atomic pointer. A read loads it without a lock; a publish, refresh or schema pass works on a copy and installs it with one compare-and-swap. A multi-table write validates and commits its tables concurrently: two serial round trips at commit instead of two per table. The first read after another process commits refreshes `__manifest` in 11 or 12 storage calls instead of 18 to 20 (DST cost ledger, in-memory store). #1228, #1270, #1230

### Merges at 1,024 commits: 4,168 storage requests down to 54

Change discovery from fragment metadata: Lance keeps each row's stable row id and the version that last wrote it in its fragment's metadata. A diff across several commits of one history pairs rows by id and reads only those whose stamps differ, so its data read is flat in table size; ten updated rows in a 100,000-row type cost 277 data reads and 6.9 MB before. A merge reads candidates only from each side's changed fragments, which the exact-id primary key makes safe. After 1,024 one-row commits, a fast-forward merge sends 54 storage requests instead of 4,168 and a three-way merge 135 instead of 3,216 (GQT `--measure`, DST in-memory store). Diverged heads and Blob tables keep the full comparison. #1201, #1220, #1229

### MCP: every graph operation, gated by policy

Tool parity: `/mcp` has a tool for every graph operation that is not a byte stream, including `diff`, `branches_diff`, `commits_publish` and stored mutations. Each tool calls its HTTP route's handler under the same Cedar action, so the server lists every tool and the caller's policy decides what runs. `query` takes GQ source or a stored read's `name`. A ranked read returns a `ranking` object: the search, its score order, whether it was exhaustive, and the score columns. #1139, #1207, #1130

### S3 clusters: no write after the lease deadline

Deadline fencing: the storage scope holds the owner's lease deadline, and admission, each multipart part and each poll of a request check it before sending. After a process pause, whichever task resumes first sends nothing past the deadline, and a restarted server never takes the lock from an owner that still heartbeats. A conditional control-object write on S3 or Azure whose answer was lost is re-issued unchanged and read back; equal bytes mean it landed. #1221, #1176

## Upgrade actions

Each change closes a gap between what Omnigraph declared and did. A `@card` minimum held or failed by how a write reached the graph. A `@unique` on a list or vector could never be satisfied. MCP flags hid tools the same credential could call over HTTP; policy is now the only gate. Organization roles came from provider defaults and local grants; you now name them. A `U64` above `i64::MAX` was refused, and an in-doubt publication named no commit to check.

- **A non-zero `@card` minimum now counts every source node a write inserts or updates**, and schema apply refuses a new such edge type from an existing node type (`OG-MF-107`). Writers that load nodes before their edges must send each node with its edges in one write; an orphan query finds nodes already below the minimum. See [edge cardinality][card-minimum-schema]. ([#1212](https://github.com/ModernRelay/omnigraph/pull/1212))
- Schema admission refuses a body-level `@unique` on a list or vector property, which no write could satisfy. A graph that already has one still opens, but every apply of source that keeps it is refused, including any `cluster apply` of its deployment. Drop the properties it names in one change, or rebuild the graph. See [unique constraints][unique-list-vector-schema]. ([#1306](https://github.com/ModernRelay/omnigraph/pull/1306))
- `/mcp` lists every tool under its HTTP route's policy action, and `query` now takes GQ source or a stored read's `name`, replacing the ad-hoc `read` tool. `--mcp-allow-adhoc` and `--mcp-allow-writes` stop the server from starting; `OMNIGRAPH_MCP_ALLOW_*` variables are ignored. Narrow an agent's policy to keep it read-only. See [MCP][mcp-tools-by-policy-guide]. ([#1207](https://github.com/ModernRelay/omnigraph/pull/1207))
- Organization commands follow provider roles: service permissions come from each member's organization roles, and graph and deployment access from applied cluster policy. Replace `organization members apply` with `members set --role ROLE`, repeating `--role` for every role the member keeps; add `--role` to new invitations; offboard by email or user ID, without `--expected-version`. See [team administration][organization-role-selection-guide]. ([#1200](https://github.com/ModernRelay/omnigraph/pull/1200))
- Saved query plans now use envelope version 11, which carries a `U64` parameter above `i64::MAX` as its decimal text. Regenerate plans saved with earlier binaries; older binaries reject version 11 plans. See [saved plans][u64-param-above-i64-max-plans]. ([#1102](https://github.com/ModernRelay/omnigraph/pull/1102))
- Rust embedders must pass a graph commit ID to `manifest_publish_in_doubt`; `ManifestError.publication_in_doubt` now holds `Option<Box<String>>` instead of `bool`. Follow the [error API update][publication-error-api]. ([#1124](https://github.com/ModernRelay/omnigraph/pull/1124))

- `schema apply` can make a nullable property required and add node `@unique` to a populated type; it checks stored rows first and refuses, changing nothing, on a null or duplicate ([#721][721]). ([#1271](https://github.com/ModernRelay/omnigraph/pull/1271))
- `omnigraph index build --branch <branch>` builds the indexes a branch's tables lack and rebuilds lagging BTREE/vector ones; `optimize` still does this on `main` with compaction. See [Build indexes][index-build-guide]. ([#1150](https://github.com/ModernRelay/omnigraph/pull/1150))
- `branch list --detailed`, `GET /branches?detailed=true` and MCP `branches_list` with `detailed` report each branch's head, where it started, and when it was created and last moved. See [Branches][branch-list-details]. ([#1012](https://github.com/ModernRelay/omnigraph/pull/1012))
- `query` and `alias` accept `--format toon` and `defaults.output: toon`, encoding the same read document as JSON in TOON for LLM prompts. See [query output][toon-output]. ([#1198](https://github.com/ModernRelay/omnigraph/pull/1198))
- Managed profiles can acquire and renew OAuth client credentials for existing cluster, graph and MCP commands. See [workload profiles][workload-client-credentials]. ([#1154](https://github.com/ModernRelay/omnigraph/pull/1154))
- The server keeps the OAuth client of a verified OIDC token beside the person's actor: `GET /graphs/{id}/access` answers it as `client_id`, and the policy decision log records it. See [sign-in][oidc-client]. ([#1196](https://github.com/ModernRelay/omnigraph/pull/1196))
- Optional OTLP tracing and correlated JSON logs omit payloads and credentials. Tracing and warning/error correlation work at every log level. See [logs and traces][server-otel-guide]. ([#1001](https://github.com/ModernRelay/omnigraph/pull/1001))
- Cluster deployment and recovery commands, and direct maintenance with `--graph`, accept an inline `s3://` cluster root, so a stopped S3 cluster can be recovered and maintained. See [inline S3 roots][cli-inline-s3-root]. ([#1189](https://github.com/ModernRelay/omnigraph/pull/1189))
- `omnigraph studio --target NAME` opens Omnigraph Studio on a configured server target through an `omnigraph-studio://open` link, without sending a request or reading a credential. See [Open Studio][cli-studio]. ([#1137](https://github.com/ModernRelay/omnigraph/pull/1137))
- `omnigraph` and `omnigraph help` tell a first-time agent to call the omnigraph skill before a schema or query. See [the matching skill][skill-on-help]. ([#1198](https://github.com/ModernRelay/omnigraph/pull/1198))
- A Nix flake builds `omnigraph`, `omnigraph-server` and `omnigraph-azure-admission` with the release toolchain on Linux x86_64/arm64 and macOS arm64: `nix build github:ModernRelay/omnigraph` ([install guide][nix]). ([#1153](https://github.com/ModernRelay/omnigraph/pull/1153))
- macOS release binaries are Developer ID signed; Apple notarization can finish after publication. A fixed CLI identity lets Keychain recognize updates; older ad hoc builds may need one authorization. ([#1293](https://github.com/ModernRelay/omnigraph/pull/1293))
- `omnigraph-gqt --measure` reports the ticks a concurrent block's session waited at each engine gate (`wait.<gate>` in the TSV, after `waiting` in the table). See the [GQT runner guide][gqt-gate-waits]. ([#1237](https://github.com/ModernRelay/omnigraph/pull/1237))
- `omnigraph-gqt --store` runs an `omnigraph-engine-dst` environment on a prepared graph of any size: reads fall through to the root, writes stay in memory, the root is never written ([guide][gqt-store-read-through]). ([#1287](https://github.com/ModernRelay/omnigraph/pull/1287))
- `omnigraph-bench` admits served writes as unpublished commits: a workload writes `as commit`, reads at the bound snapshot and drops it, so no head moves and no reset is needed. ([#1238](https://github.com/ModernRelay/omnigraph/pull/1238))

## Behavior changes

- Graph diffs and branch reviews over several commits with no merge between them now read only the changed rows, flat in table size; the `change_lineage` setting selects or verifies the pairing (#969). ([#1201](https://github.com/ModernRelay/omnigraph/pull/1201))
- Traversals allocate less per row: one-pass expand sizing, bulk-hashed joins, one visited table per walk, engine-side key sieving, block predicates run once. Results are unchanged. ([#1241](https://github.com/ModernRelay/omnigraph/pull/1241))
- A mutation `where` that compares more than four properties more than once each with `=`, `!=` or `in` is now refused before any effect. See the [mutations guide][mutation-where-bound]. ([#1286](https://github.com/ModernRelay/omnigraph/pull/1286))
- A `load csv` overwrite admits `query_memory_bytes` once, one share per partition; a refusal reports the smallest admitting limit; a keyed overwrite near the limit may need more ([settings][load-memory-shares]). ([#1187](https://github.com/ModernRelay/omnigraph/pull/1187))
- `ensure_indices` and `ensure_indices_on` also rebuild lagging BTREE/vector indexes, report lagging full-text coverage as pending, and under a policy need an actor with `Change`: use `ensure_indices_on_as`. ([#1150](https://github.com/ModernRelay/omnigraph/pull/1150))
- `cleanup --keep N` without `--older-than` no longer stops on an unreadable catalog manifest of a graph commit it drops; `--older-than` still stops. See [cleanup][cleanup-unread-drops]. ([#1188](https://github.com/ModernRelay/omnigraph/pull/1188))
- Server logs name an unknown publication's graph commit in a `publication` field without exposing its error message. See [storage failures][unknown-publication-log]. ([#1124](https://github.com/ModernRelay/omnigraph/pull/1124))
- Human logins can renew for 30 days without extending saved deadlines. Transient refresh and identity checks retry within fixed bounds; graph operations are never replayed. ([#1199](https://github.com/ModernRelay/omnigraph/pull/1199))
- Release pages open with an intro and highlights, explain upgrade actions, and link each change to its pull request. ([#880](https://github.com/ModernRelay/omnigraph/pull/880))

## Fixes

- A filter or mutation `where` that tests a nullable property twice with `=`, `!=` or `in` no longer selects, updates or deletes rows whose value is null. See the [query guide][null-rows-in-tests]. ([#1286](https://github.com/ModernRelay/omnigraph/pull/1286))
- A server paused past its S3 lease deadline no longer sends a storage write after that deadline, whichever of its tasks resumes first. See [lease restarts][lease-deadline]. ([#1221](https://github.com/ModernRelay/omnigraph/pull/1221))
- A restarted server no longer takes the S3 cluster lock from a server that is still heartbeating, and a server whose lock was taken over or unlocked stops at its next heartbeat. See [lease restarts][lease-live-owner]. ([#1221](https://github.com/ModernRelay/omnigraph/pull/1221))
- A conditional write on S3 or Azure whose answer was lost is re-issued and read back instead of failing. See [storage failures][control-object-reissue]. ([#1176](https://github.com/ModernRelay/omnigraph/pull/1176))
- Steady writes to one branch no longer keep up to 64 superseded manifests of a hot table in memory: a write drops the cached handle of each table version it replaced. ([#1276](https://github.com/ModernRelay/omnigraph/pull/1276))
- A `U64` query parameter above `i64::MAX` now binds instead of being refused; send it as a decimal string to keep every digit. See [query parameters][query-parameters]. ([#1102](https://github.com/ModernRelay/omnigraph/pull/1102))
- Diff, `commit changes`, `query --snapshot` and the change feed read a commit of a deleted branch while a live branch retains it, such as a stacked branch's merge base. ([#1240](https://github.com/ModernRelay/omnigraph/pull/1240))
- `nearest()` always ranks by L2 and reports `exhaustive` truthfully: it ranks every row instead of using a vector index Omnigraph does not build. See the [search guide][nearest-foreign-index]. ([#1299](https://github.com/ModernRelay/omnigraph/pull/1299))
- An update's `write_max_bytes` charge now counts only the rows it matches, not the rows stored beside them in the same fragment, which could refuse it. ([#1304](https://github.com/ModernRelay/omnigraph/pull/1304))
- A keyed load of wide vectors is no longer refused at about half of `write_max_bytes`: its input estimates now charge a vector its Arrow size. See [load limits][wide-vector-load-limits]. ([#1308](https://github.com/ModernRelay/omnigraph/pull/1308))
- OIDC clients no longer loop on sign-in: an unadmitted identity returns 403 `not_admitted`, and an expired admission snapshot returns 503. See [MCP][oidc-not-admitted-guide]. ([#1185](https://github.com/ModernRelay/omnigraph/pull/1185))
- Full-text refusals and `optimize`'s pending full-text reason name `omnigraph index build` and `omnigraph index rebuild --kind full-text` with `--target`, not a positional address; every remedy now parses. ([#1150](https://github.com/ModernRelay/omnigraph/pull/1150))
- Managed `cluster plan` and `cluster apply` now wait for their submission until the `--timeout` deadline instead of a fixed 10 seconds. See [managed configuration][managed-plan-apply-timeout]. ([#1208](https://github.com/ModernRelay/omnigraph/pull/1208))
- Managed plans now poll the original preview until ready. Timeouts retain its ID, revision and key; `--no-wait` returns on acceptance without cancelling work. ([#1209](https://github.com/ModernRelay/omnigraph/pull/1209))
- Managed `access`, `queries list` and `mcp` use scoped credentials. MCP renews expired helpers without replay or identity switches, and redacts credentials from upstream errors and challenges. ([#1179](https://github.com/ModernRelay/omnigraph/pull/1179))
- The exported agent skill now covers `load csv`, Blob writes, diffs, ranked-read `ranking`, 0.13 graphs and inline S3 roots, and drops stale 0.12 and MCP flag advice. See [the skill][skill-current]. ([#1215](https://github.com/ModernRelay/omnigraph/pull/1215))
- The guides, agent skill and policy help describe the released 0.14 CLI, HTTP and MCP contracts, and a [release overview][014-docs-overview] collects the final upgrade actions. ([#1142](https://github.com/ModernRelay/omnigraph/pull/1142))
- The [0.13 to 0.14 upgrade guide][upgrade-014-checklist] is an ordered checklist with operator YAML and CLI commands, and says released 0.13 graphs need no export and rebuild. ([#1144](https://github.com/ModernRelay/omnigraph/pull/1144))
- Arrow crates 58.3.0 to 58.4.1 (RUSTSEC-2026-0442, RunEndEncoded array validation); the unmaintained `pin-utils` advisory (RUSTSEC-2026-0441) is ignored with its path, aws-smithy-http through lance-io. ([#1270](https://github.com/ModernRelay/omnigraph/pull/1270))
- Remove `crypto-bigint` 0.5 (RUSTSEC-2026-0387): data tokens are verified with `p256` 0.14 and OIDC tokens through `aws-lc-rs`; the tokens the server accepts are unchanged. ([#1151](https://github.com/ModernRelay/omnigraph/pull/1151))
- `omnigraph-gqt --measure`: a concurrent block's `wait.<gate>` ticks and makespan replay per seed, up to one tick where Lance CPU work overlaps a modeled sleep; they were wall time. See the [runner guide][gqt-block-clock]. ([#1246](https://github.com/ModernRelay/omnigraph/pull/1246))
- Require Tokio 1.53.3 or newer to address [RUSTSEC-2026-0386](https://rustsec.org/advisories/RUSTSEC-2026-0386), an I/O safety issue in its Unix file-descriptor registration API. ([#1145](https://github.com/ModernRelay/omnigraph/pull/1145))

## Performance

- A branch merge reads only the table fragments that changed, so its storage requests stay flat as one-row commits accumulate instead of growing with each table's fragment count. ([#1229](https://github.com/ModernRelay/omnigraph/pull/1229))
- A `load csv` overwrite reads its source by partition in 8 MiB pieces instead of capturing the whole object first, and refuses a first record over 8 MiB. LDBC SF30 loads 1.4× faster. ([#1158](https://github.com/ModernRelay/omnigraph/pull/1158))
- A `load csv` overwrite writes its Lance fragments while the rows drain instead of after validation, and a refused load leaves no fragment behind. LDBC SF30 loads 1.2× faster. ([#1178](https://github.com/ModernRelay/omnigraph/pull/1178))
- A `load csv` overwrite into an empty node table or an edge table no longer scans its committed ids or hashes every input id, the largest cost of a bulk load into a new graph. See [explain load][explain-load-removal]. ([#1141](https://github.com/ModernRelay/omnigraph/pull/1141))
- An edge `load csv` over integer-keyed node types checks its endpoints on the parse partitions as rows arrive, not on one thread after the parse. See [explain load][explain-load-probe]. ([#1147](https://github.com/ModernRelay/omnigraph/pull/1147))
- A read no longer waits for a publish, refresh or schema pass on the same handle: the branch state installs by one pointer swap after the round trips. ([#1228](https://github.com/ModernRelay/omnigraph/pull/1228))
- A multi-table write commits its tables, and reads their index facts for validation, side by side instead of one after another; what is written and the storage format are unchanged. ([#1270](https://github.com/ModernRelay/omnigraph/pull/1270))
- A read after another process commits refreshes `__manifest` with one read of the new version instead of two, about 40% fewer requests for that read. See the [freshness probe][stale-read]. ([#1230](https://github.com/ModernRelay/omnigraph/pull/1230))
- Reading one branch's ref takes one storage request instead of three, so a write, merge or delete on a named branch sends 6 to 10 fewer requests. ([#1229](https://github.com/ModernRelay/omnigraph/pull/1229))
- A delete reads each table it removes rows from once, uses the id index for a delete by `@key`, and validates against cached tables. ([#1232](https://github.com/ModernRelay/omnigraph/pull/1232))
- Endpoint and `@unique` checks of an append, merge or mutation on a node table without a full `@key` BTREE read its id column once, not a filter of every key, so memory stops growing with fragment count. ([#1231](https://github.com/ModernRelay/omnigraph/pull/1231))
- A bound edge traversal (`$a $e:knows $b`) sizes each pair of a list or vector edge property by its own elements, so pairs no longer leave in chunks of a few rows. Results are unchanged. ([#1268](https://github.com/ModernRelay/omnigraph/pull/1268))
- `cleanup` no longer sends a HEAD request before each file it deletes; it takes the file's size from the listing it already made. ([#1266](https://github.com/ModernRelay/omnigraph/pull/1266))
- `cleanup` lists `__manifest` versions instead of reading every one: `--keep N` alone reads only those it retains and the merge bases, and `--older-than` reads the others' times concurrently. See [cleanup][cleanup-keep-listing]. ([#1188](https://github.com/ModernRelay/omnigraph/pull/1188))
- An index that Lance keeps as several segments now covers the rows its segments cover together, so a traversal over such an edge table keeps its index lookups. Results are unchanged. ([#1300](https://github.com/ModernRelay/omnigraph/pull/1300))
- A branch merge that deletes rows now removes them by the row ids its walk already read, so its delete no longer scans the `id` column of fragments the `id` index does not cover. ([#1301](https://github.com/ModernRelay/omnigraph/pull/1301))
- A scalar-only `update` on a type with Blob or vector properties writes just those columns when cheaper or when whole rows exceed `write_max_bytes`, keeping external Blobs unread. See the [Blob guide][update-column-patch]. ([#1272](https://github.com/ModernRelay/omnigraph/pull/1272))
