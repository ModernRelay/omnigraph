**Omnigraph 0.17.1 restores names-only graph discovery.** With an identity admitted to the cluster, use `omnigraph graphs list --discovery` to see every registered graph’s name. The applied policy still controls who can read or change its data.

**Upgrade the CLI and server together.** If you used `graphs list --catalog` in 0.17.0, switch to plain `graphs list` for the full catalog. It still requires `graph_list`. If you use an `s3://` root, check the [S3 upgrade instructions][patch-s3-roots] before upgrading.

[patch-s3-roots]: ../user/operations/upgrade.md#s3-roots-that-name-two-keys

## Highlights

### Discover graphs before requesting access

In 0.17.0, an empty list could mean the cluster was empty or your identity had no graph permissions. In 0.17.1, discovery lists graph IDs and display names even when your identity has no graph permissions.

## Upgrade actions

The default command now requests the full catalog. Scripts that used the 0.17.0 default for discovery must select `--discovery` to get names only. Earlier releases could store parts of the same graph under two different S3 prefixes. Omnigraph now checks the root before it sends a storage request.

- Upgrade the CLI and server together and use [`graphs list --discovery`][restore-identity-discovery] to see every registered graph name with an admitted identity. Replace `graphs list --catalog` with `graphs list` for the catalog, which requires `graph_list` as does MCP listing with a static token. ([#1562](https://github.com/ModernRelay/omnigraph/pull/1562))
- An `s3://` root whose refusal names two keys, Omnigraph's and Lance's (from a space, a non-ASCII letter, a brace or an escape Lance decodes, such as `%41`), is now refused before any request: earlier releases split its objects between those keys. Export each graph there with the earlier release and rebuild it under a plain prefix; see the [upgrade guide][s3-root-one-key-upgrade]. ([#1556](https://github.com/ModernRelay/omnigraph/pull/1556))
- An `s3://` root whose refusal names another spelling (a dot segment, `%2e%2e` included, a port or user information) is now refused, but its objects are whole: finish any outstanding deployment with the earlier release, then use that spelling. A refusal that names no key (a query, a fragment, an empty segment) names no replacement: choose a plain prefix. See the [upgrade guide][s3-root-one-spelling-upgrade]. ([#1556](https://github.com/ModernRelay/omnigraph/pull/1556))

## Behavior changes

- A scoped S3 adapter built from a captured binding now retries a write to a fresh immutable key, as other scoped stores do. Conditional writes and writes to mutable keys still make one attempt. ([#1533](https://github.com/ModernRelay/omnigraph/pull/1533))
- A loading, blocked or transitioning graph answers 503 `graph_unavailable`, not 404, to every admitted identity. See [deployment][unavailable-graph-answers-identities]. ([#1562](https://github.com/ModernRelay/omnigraph/pull/1562))

[unavailable-graph-answers-identities]: ../user/deployment.md

## Fixes

- The CLI now waits up to 300 seconds for a managed branch merge or dry run. The old 30-second timeout could report unknown effects for a merge that had already published. ([#1492](https://github.com/ModernRelay/omnigraph/pull/1492))
- A scoped S3 adapter built from a captured binding, which a managed first bootstrap reads through, and a scoped S3 clone open's clone-root reads retry transient failures within a [retry budget][scoped-s3-read-retry]. ([#1533](https://github.com/ModernRelay/omnigraph/pull/1533))
