# OmniGraph v0.12.0

Unreleased.

## Highlights

- **A stale mutation or load recovery sidecar no longer makes every read-write
  open fail.** When a mutation's or load's sidecar update write was lost (the
  object store acknowledged it but the file still holds the arm-time bytes)
  while the operation's manifest commit landed, every later read-write open
  failed with `OCC recovery sidecar '<id>' found original commit id '<id>' but
  its manifest delta differs`, an internal error, and nothing could reopen the
  graph for writing. The commit is the authority for the operation: recovery
  now checks that the commit carries every table at the sidecar's planned
  version and that the planned transaction is the one recorded at that
  version, records a `RolledForward` audit row against the original commit,
  deletes the sidecar, and the open succeeds. A sidecar whose recorded or
  planned values contradict the committed snapshot still refuses the open,
  and the error now names the sidecar object and says not to delete it by
  hand. The same shape on a branch merge, schema apply, or index build sidecar
  still refuses; that heal is a follow-up. Fixes #602.

## Compatibility and behavior changes

- **Mutations and loads stage detached Lance commits and arm no recovery
  sidecar (RFC 0067).** Each table effect is a detached commit of the pinned
  base, published as a pin `(target, staged version, transaction uuid)` in
  the one manifest CAS, and promoted to its linear twin by the writer right
  after. A mutation or load that fails before publication leaves the graph
  unchanged with nothing to recover; a `RecoveryRequired` from a mutation or
  load, the `__recovery` sidecar it used to write, and the reopen-time
  recovery of that sidecar are gone. A write that dies after publication
  leaves a pending pin that reads serve through the staged version and that
  the next write on the table, or `omnigraph cleanup`, promotes. Branch
  merge, index maintenance, schema apply and optimize promote a pending pin
  before they commit on the table's linear history, and refuse a table whose
  pin a foreign commit blocks; `omnigraph repair` reports such a table as
  `blocked_promotion` while mutations and loads keep writing behind the
  pin. `ensure_indices` and the explicit full-text rebuild follow: each
  index batch is a detached commit published as a pin, a rebuild interrupted
  after publication keeps serving search through the staged batch, and no
  `EnsureIndices` sidecar is written. Branch merge follows: every chunk of a
  merged table commits detached and chained, a pointer adoption carries the
  source's pin, a first-touch fork is created without an intent record, and
  the merge publishes once and promotes each chain; a merge that fails before
  publication leaves the target untouched, and no `BranchMerge` sidecar or
  `RecoveryRequired` outcome remains. Schema apply follows: an
  existing-table rewrite is a detached commit published as a pin, an added
  type is a linear create whose leftover from a crashed attempt the retry
  reclaims, the staged schema contract records the graph commit that
  publishes it so the next read-write open promotes or discards it, and no
  `SchemaApply` sidecar is written; a failure before the manifest commit
  returns the plain error, and only a failure after it reports
  `RecoveryRequired`, naming the published commit. Optimize follows: each
  table's compaction is one detached rewrite of its pin, a scalar or vector
  index whose coverage lags is rebuilt whole as a detached commit chained on
  it, the batch publishes once with an exact check on every pin it planned
  from, and no `Optimize` sidecar is written; a run that loses a table to a
  concurrent write fails with a read-set conflict and the next run re-plans,
  and a run interrupted after publication leaves pins the next write or
  `cleanup` promotes. Optimize no longer strips a stale `lance.auto_cleanup`
  configuration from data tables: every engine commit skips Lance's
  auto-cleanup, so the key is inert. Test seams
  `mutation.post_arm_pre_effect`, `mutation.post_sidecar_pre_fork`,
  `mutation.sidecar_confirm_put`, `mutation.sidecar_post_publish_delete`,
  `ensure_indices.post_sidecar_pre_fork`,
  `ensure_indices.post_effects_pre_confirm`, `branch_merge.post_sidecar_pre_fork`,
  `branch_merge.post_effects_pre_confirm` and `branch_merge.pre_error_recovery`
  are gone;
  `mutation.post_publish_pre_promotion`, `promotion.post_landed`,
  `cleanup.pre_reap`, `ensure_indices.post_fork_pre_commit`,
  `ensure_indices.post_publish_pre_promotion`,
  `branch_merge.post_fork_pre_commit`, `branch_merge.post_table_effect`,
  `branch_merge.post_publish_pre_promotion`,
  `schema_apply.post_publish_pre_promotion`, `optimize.post_table_effect`
  and `optimize.post_publish_pre_promotion` name the new windows
  (`optimize.post_compact_pre_reindex` is gone), and the
  GQT cases that armed the retired seams are retired or repointed with them.

- **Storage format v10; every existing graph needs one explicit upgrade.**
  Normal open now serves internal manifest schema v10 only. A v8 or v9
  graph from the 0.11.x line is refused until `omnigraph upgrade <graph>`
  (run `--check` first) takes it to v10: a metadata-only step that restamps
  main and every live branch, keeps every branch, every table byte and the
  graph's system column spellings, and refuses a graph with a pending
  recovery sidecar until the 0.11.x binary that wrote it has resolved it.
  v10 exists for RFC 0067: a table registration may name a detached Lance
  version whose linear target is published before it exists, and an older
  binary would misread such a pin as reclaimed history, so the stamp refuses
  it before any open. Older binaries refuse v10 graphs. `--to-format 9` is
  no longer a target: the system-column respelling that v9 used to mark is
  `omnigraph schema upgrade-system-columns` on a served graph and no longer
  changes the stamp; a legacy-vintage graph is born at v10 too. That upgrade
  now has schema apply's RFC 0067 shape: each table's rename commits detached
  and is published as a pin, the staged contract names the publishing graph
  commit, and no recovery sidecar is written; a run interrupted before its
  manifest commit leaves the graph unchanged and is simply rerun, and one
  interrupted after it is completed by the next read-write open. Test seam
  `schema_apply.post_sidecar_pre_effect` is now
  `schema_apply.post_lock_pre_effect`, and
  `system_column_upgrade.after_stamp_advance` is gone. The
  `V5 ↔ V9 Format Fence` CI job is now `V5 ↔ V10 Format Fence`.

- **GQ logic tests:** several `--- seam` blocks may precede one mutate step
  when they name distinct seams; each is armed and recorded on its own, and
  the same seam twice before one step is refused. Two new skip seams,
  `mutation.sidecar_confirm_put` and
  `mutation.sidecar_post_publish_delete`, name the two writes of a mutation's
  sidecar that a store can lose; `action: skip` on each is the lost write, and
  the #602 case names both.

- **GQ logic tests:** the `--- fault` block that named a code hook is replaced
  by `--- seam`. Rename the section, keep `at`, `occurrence` and `scope`, and
  write `action: fail` (was `return_error`) or `action: skip`; a seam precedes
  a mutate step and must name a seam in the engine catalog with a matching
  effect. An old `--- fault` block is refused with that instruction. Delivery
  is proved by the runner's own decision (`seam_delivered`, `seam_unobserved`)
  instead of the injected error text. See `crates/omnigraph-gqt/README.md`.
- **Rust consumers of the engine's test seams:** the feature-gated
  `omnigraph::failpoints` module (`registry`, `set_registry`,
  `ScopedFailPoint`, `names`) and the `dst_clock`/`dst_ids`/`dst_gate`
  install and uninstall functions are removed. Seams are statics in
  `omnigraph::seams::catalog` armed through the `omnigraph-seams` crate
  (`SEAM.fire_always()`, `.fire_once_at(n)`, `.panic_at()`, `.hold()`,
  `.observe(f)`; `CLOCK.install(..)` and friends for the thread-local seams),
  each returning a guard that uninstalls on drop. `fail-parallel` is no longer
  a dependency.
