# Omnigraph v0.16.0 — highlights and upgrade actions

Released 2026-11-20.

**Upgrading from 0.15.0 does not require a graph rebuild.** Install 0.16.0
and keep using your format-16 graphs. Reads and writes keep them at format 16.
New graphs use format 17, which 0.15.0 cannot open. Upgrade every reader and
writer before creating a graph they will share or explicitly converting a
standalone graph. [Storage upgrade](../user/operations/upgrade.md#storage-upgrade)

**If you run compaction on a cluster, you can now check what happened after a
lost response.** The server records each run under an operation ID. If an index
step fails after a dataset was compacted, the completed rewrite is kept. The
report tells you which dataset still needs attention.

Before upgrading a server, check which graphs rely on static tokens without an
applied policy. Before upgrading scripts, check how they select a managed
organization and whether they invoke `repair`. The [upgrade actions](#upgrade-actions)
cover these changes and the Rust maintenance API. [Complete 0.16.0 changelog](v0.16.0.md)

## Highlights

### Check access before upgrading a server

In 0.15 a static bearer token could read any served graph that lacked a
policy. In 0.16, give that actor `read` access in the policy of each graph it
needs. Direct cluster writes now check the graph's applied policy too. The
server also checks token file permissions, reserves signed identities for
signed credentials, and refuses requests that exceed the server's memory or
work ceiling. [Graph authorization](../user/operations/policy.md) · [#1323](https://github.com/ModernRelay/omnigraph/pull/1323) · [#1324](https://github.com/ModernRelay/omnigraph/pull/1324) · [#1327](https://github.com/ModernRelay/omnigraph/pull/1327)

### Find out whether compaction finished before retrying

A cluster can compact a graph while it serves requests. Enable
`OMNIGRAPH_OPERATION_ROUTES=true` on the server and grant the actor behind the
bearer token `maintain` on the graph's `main` branch. That grant covers
submitting, looking up and cancelling a run. For a server target named
`production` and a graph named `knowledge`, start a run with the first command.
Set `OPERATION_ID` to the ID it prints and use the second command to check it.

```bash
omnigraph optimize --target production --graph knowledge --no-wait
omnigraph optimize --target production --graph knowledge --operation "$OPERATION_ID"
```

If an HTTP client loses the response, submitting the same request with the
same retained ID returns the existing record. If lookup returns `unknown`,
reconcile what happened before submitting more work. Read the outcome for each dataset. An
`optimized` result with `reason: index_failed` means the completed work was
published and the later index step or coverage check failed. Read `detail` for
the error. Start a **new operation** to check coverage and retry remaining work.
[Recorded operations and early edge upgrade instructions](../user/operations/recorded-operations.md#submit-look-up-cancel) · [#1282](https://github.com/ModernRelay/omnigraph/pull/1282) · [#1415](https://github.com/ModernRelay/omnigraph/pull/1415) · [#1418](https://github.com/ModernRelay/omnigraph/pull/1418) · [#1478](https://github.com/ModernRelay/omnigraph/pull/1478) · [#1479](https://github.com/ModernRelay/omnigraph/pull/1479)

To limit how long writers wait, select the datasets with `--datasets` or set
`--max-gate-hold`. The first dataset always runs. Once the deadline passes,
Omnigraph starts no more datasets, but work in progress, publication, and
configuration cleanup can still keep writers waiting. For a direct run over
the full graph, pass the reported `resume_at` to `--start-at` on the next run.
The server keeps its own position. [Bounding a run](../user/operations/maintenance.md#bounding-a-run) · [#1275](https://github.com/ModernRelay/omnigraph/pull/1275)

### Direct maintenance can compact several fragments at once

Direct `optimize` shares eight work slots by default. It can run up to eight
compaction tasks or build up to four independent B-tree indexes at once. Each
Blob table still compacts serially. A full-text or vector index build uses all
slots. A server runs one heavy maintenance task at a time. If a server defers
a dataset because it exceeds a resource limit, another run will defer it again.
Raise the relevant limit or optimize the dataset directly. [Server limits](../user/operations/recorded-operations.md#table-ceilings-and-the-byte-budget) · [#1396](https://github.com/ModernRelay/omnigraph/pull/1396) · [#1395](https://github.com/ModernRelay/omnigraph/pull/1395) · [#1441](https://github.com/ModernRelay/omnigraph/pull/1441)

### Small writes and short reads do less storage work

Updating one row by key used to scan the key column across every fragment.
In a simulated store with 262,144 rows in 64 fragments, using the identity
index cut one update from 212 storage requests to 34. In a separate local
read, a query asking for ten rows with no filter or ordering read one of 25
data files, down from 16. Traversals reuse the adjacency data for untouched edge tables,
and repeated commit lookups can go straight to the branch that holds the
commit. [#1318](https://github.com/ModernRelay/omnigraph/pull/1318) · [#1363](https://github.com/ModernRelay/omnigraph/pull/1363) · [#1342](https://github.com/ModernRelay/omnigraph/pull/1342) · [#1184](https://github.com/ModernRelay/omnigraph/pull/1184)

### Queries with many matches can finish within a smaller memory budget

A query that aggregates matches for each outer row now consumes its inner
matches in batches. In a local test, 16,384 one-KiB matches completed within
the 12 MiB budget that the same query previously exhausted. Sorts that spill to disk reserve
less memory when merging their runs, and scratch files are compressed. The
whole-query spill test wrote 5.9 MB, down from 52.6 MB. Embedded applications
can inspect a query profile to see which operator spilled and how much it
wrote. [Query profiles](../user/queries/explain.md#profile) · [#1341](https://github.com/ModernRelay/omnigraph/pull/1341) · [#1362](https://github.com/ModernRelay/omnigraph/pull/1362) · [#1389](https://github.com/ModernRelay/omnigraph/pull/1389) · [#1348](https://github.com/ModernRelay/omnigraph/pull/1348)

## Upgrade actions

- **If your server uses static bearer tokens, grant `read` on each graph those
  tokens should reach.** In 0.15, any static token could read every graph on
  that server that had no applied policy. In 0.16 those graphs deny reads by
  default. Apply a graph policy that permits the intended actors. If you need
  the previous behavior during rollout, setting
  `OMNIGRAPH_ALLOW_READS_WITHOUT_POLICY=1` restores it for **all** static
  tokens and **every** graph without a policy on that server.
  [Server authentication](../user/operations/server.md#authentication)

- **If scripts write directly to a cluster graph, pass an actor its policy
  permits.** Direct writes now enforce the same applied policy that
  `omnigraph access` reports. This also applies when opening the graph through
  its own storage path. Add `--as ACTOR` to affected commands, including
  `optimize` and `cleanup`. A missing or unauthorized actor gets `forbidden`
  before the graph changes. HTTP requests continue to take their identity from
  the bearer token. [Actor identity](../user/operations/policy.md#actor-identity)
  · [#1423](https://github.com/ModernRelay/omnigraph/pull/1423)

- **If a script creates a profile for someone in several organizations, name
  the organization.** Use `omnigraph login --create-profile NAME
  --organization ID`. Interactive login prompts for a choice. With `--json`,
  the CLI returns `organization_required` and an `organizations` array on
  stdout so the script can prompt and retry. Someone with one active
  membership gets a profile in that organization automatically.
  [Managed login](../user/cli/login.md#choose-the-organization)
  · [#1344](https://github.com/ModernRelay/omnigraph/pull/1344)

- **If a served request raises a resource budget, check the server ceiling.**
  This applies to `traversal_work_limit`, `query_memory_bytes`,
  `write_max_bytes` and `load_source_max_bytes`. Each ceiling is the larger of
  the built-in default and the configured server default. A request above it
  gets HTTP 400 before execution. Lower the request or have the operator raise
  the corresponding environment setting. [Query settings](../user/queries/settings.md)
  · [#1327](https://github.com/ModernRelay/omnigraph/pull/1327)

- **If you load tokens from a file on Unix, restrict who can write it.**
  Another account with write access could add a token for any actor. The
  server now refuses to start if `OMNIGRAPH_SERVER_BEARER_TOKENS_FILE` names
  anything other than a regular file or the file is group- or world-writable.
  Group or world read access produces a warning. Use `chmod 600` on the token
  file. [Token configuration](../user/operations/server.md#authentication)
  · [#1324](https://github.com/ModernRelay/omnigraph/pull/1324)

- **If a static token names an actor starting with `principal:`, rename it
  and update the matching policy rules.** That prefix identifies signed and
  OIDC identities. The server now refuses a static token configuration that
  could impersonate one. If you use AWS Secrets Manager, also give each actor
  a distinct token value. [Static token sources](../user/operations/server.md#authentication)
  · [#1323](https://github.com/ModernRelay/omnigraph/pull/1323)

- **Keep an existing format-16 graph when upgrading from 0.15.0.** 0.16.0
  reads and writes it in place. It stays at format 16 and needs no rebuild.
  New graphs use format 17, which 0.15.0 cannot open. Upgrade every reader
  and writer that will open a new graph first. To opt an existing standalone
  graph into format 17, stop all readers and writers, verify a whole-graph
  backup, then follow the offline `omnigraph upgrade` procedure. It updates
  branch metadata and preserves rows and commit history. Existing format-16
  cluster graphs stay at 16. [Storage upgrade](../user/operations/upgrade.md#storage-upgrade)
  · [#1402](https://github.com/ModernRelay/omnigraph/pull/1402)

- **If you embed the engine, name the actor that runs maintenance.** Move
  callers to `optimize_as`, `ensure_indices_as`, `ensure_indices_on_as`,
  `rebuild_full_text_indices_on_as` and `cleanup_as`. With a policy checker
  installed, grant `maintain` for compaction and index work and grant
  `reclaim` for cleanup, which can delete history. An actor with only `change`
  can no longer perform maintenance. [Policy actions](../user/operations/policy.md#actions)
  · [#1275](https://github.com/ModernRelay/omnigraph/pull/1275)

- **Update code that calls `optimize_as` or parses `optimize --json`.** Pass
  an `OptimizeRequest` in Rust, using `OptimizeRequest::default()` for a full
  run. Read the entries in `OptimizeReport.datasets` and call
  `committed()` on each entry to see whether that dataset published work. In JSON, read `configuration_clear` for the
  result previously reported as the `__manifest` row. Drop references to the
  old `skipped`, `published_dataset_version` and `lance_head_version` fields,
  which were always null. [Optimize reports](../user/operations/maintenance.md#bounding-a-run)
  · [#1275](https://github.com/ModernRelay/omnigraph/pull/1275)

- **If you ran recorded `optimize` on an early edge build, check its saved
  record.** An old record containing `tables` or `more_tables` causes submit,
  lookup and cancel to return HTTP 409 `operation_record_invalid`. Stop the
  server, move `__cluster/operations.json` outside the cluster root and
  restart. Results and the resume position are lost. An old operation ID can
  now start work again, so reconcile outstanding work before retrying it.
  [Recorded operation recovery](../user/operations/recorded-operations.md#submit-look-up-cancel)
  · [#1402](https://github.com/ModernRelay/omnigraph/pull/1402)

- **If you used `repair` to list foreign Lance versions, change how you
  inspect them.** Omnigraph ignores these versions when reading and writing a
  graph. The CLI `repair` command and the embedded `Omnigraph::repair`,
  `RepairOptions` and `RepairStats` are gone. Embedded hosts can inspect
  `Omnigraph::cleanup_plan` read-only. If you already intend to reclaim
  history, a confirmed `cleanup --keep N --confirm --json` lists
  `foreign_versions` per table and deletes history outside the retention
  policy. The foreign versions themselves stay in place.
  [Foreign versions](../user/operations/maintenance.md#foreign-versions)
  · [#1372](https://github.com/ModernRelay/omnigraph/pull/1372)

- **If you maintain a benchmark catalog, rename `groups:` to `suites:`.**
  Keep the existing scenario lists under that key. The catalog loader refuses
  the old spelling. If you parse the CLI output, `list scenarios` now lists
  suites and the corresponding diagnostics start with `invalid_suite_`. Run
  and report commands still select a suite by name.
  [Benchmark catalog](../../benchmarks/README.md)
  · [#1439](https://github.com/ModernRelay/omnigraph/pull/1439)

## Features

- To fit direct compaction into a maintenance window, pass `--max-gate-hold`
  to `omnigraph optimize`. The first dataset runs, and the deadline stops the
  run from starting further work. Writers can still wait for work already
  started to finish and publish. Use `--datasets` to choose specific datasets,
  or copy the printed `--start-at` argument to continue a bounded run.
  [Bounding a run](../user/operations/maintenance.md#bounding-a-run) · [#1275](https://github.com/ModernRelay/omnigraph/pull/1275)

- A cluster can compact a graph while its server stays online. Enable
  `OMNIGRAPH_OPERATION_ROUTES=true` on the server. `omnigraph optimize`
  against that server prints the operation ID and waits for the result. If
  you lose the response, `--operation <id>` lets you look up the same run.
  [Recorded operations](../user/operations/recorded-operations.md) · [#1282](https://github.com/ModernRelay/omnigraph/pull/1282)

- A Rust host can use `OptimizeRequest` to cap work per table and across
  the run, limit the size of the traversal adjacency artifact, request
  cancellation, or run a callback before graph publication.
  [#1275](https://github.com/ModernRelay/omnigraph/pull/1275)

- A Rust host taking over a format-17 branch can call `claim_branch_writer`.
  Once the claim succeeds, a stale process trying to publish on that branch
  receives `writer_fenced` (HTTP 409). The same check covers writes through
  the CLI and server. [Writer claims](../user/operations/troubleshooting.md#writer-epoch) · [#1350](https://github.com/ModernRelay/omnigraph/pull/1350)

- `Omnigraph::open_clone` lets a Rust program try changes against a frozen
  graph without copying it first. Reads can use the base in place. Writes
  go to the clone's own directory or S3 prefix. GQT can open the same kind
  of clone with `--base`. [#1367](https://github.com/ModernRelay/omnigraph/pull/1367)

- When a query runs short of memory and writes rows to disk, its embedded
  query profile identifies the operator and the number of files, rows and
  bytes it wrote. The scratch files use zstd compression, so the scratch
  quota counts the compressed bytes. [Query profiles](../user/queries/explain.md#profile) · [#1348](https://github.com/ModernRelay/omnigraph/pull/1348)

- The agent onboarding guide starts from a question you want to answer or
  a worked example, then walks through creating and querying a local graph.
  [Onboarding guide](../../skills/omnigraph/references/onboarding.md) · [#1333](https://github.com/ModernRelay/omnigraph/pull/1333)

- Benchmark authors can compare three ways to access the same local fixture
  with `omnigraph-bench run --local-route`. `direct` opens a restored copy
  on disk, `object-store` accesses that copy through the object-store API,
  and `read-through` writes to a fresh clone over the frozen fixture.
  [#1365](https://github.com/ModernRelay/omnigraph/pull/1365)

- To run your own benchmarks alongside the built-in ones, repeat
  `--catalog <directory-or-file>` on `run`, `report`, `show`, `list` or
  `cache status`. If catalogs share a scenario or suite name, the first
  catalog declaring it wins. [#1439](https://github.com/ModernRelay/omnigraph/pull/1439)

- The CLI can open a direct graph target as a writable clone. Supply the
  frozen graph with `--base` every time you open the clone. To measure one
  command, `--stats <path>` writes its exit code, logical storage calls
  and peak memory use where the platform reports it. [CLI reference](../user/cli/reference.md) · [#1416](https://github.com/ModernRelay/omnigraph/pull/1416)

- `omnigraph organization list --profile NAME` shows a signed-in person's
  active organization memberships, with names and IDs, and marks the one
  selected by the profile. You can use an ID from that list when creating
  another profile. [Find your organizations](../user/cli/managed-team.md#find-your-organizations) · [#1344](https://github.com/ModernRelay/omnigraph/pull/1344)

- GQT authors can create a family of branches in the test fixture. For
  example, `--- branches generate: v1 seed: 0 count: 2 prefix: w` after
  `--- seed` forks `w0` and `w1` before the first test step. A recipe can
  populate each branch. [Generated fixtures](../../crates/omnigraph-gqt/README.md#generated-fixtures-and-loads) · [#1443](https://github.com/ModernRelay/omnigraph/pull/1443)

- GQT format errors now have stable codes. `omnigraph-gqt --explain <code>`
  gives the rule and its fix, `--grammar` prints the format, and `--version`
  identifies the supported format version. [GQT runner](../../crates/omnigraph-gqt/README.md#run-and-reproduce) · [#1410](https://github.com/ModernRelay/omnigraph/pull/1410)

- To check test files before running them, pass files or directories to
  `omnigraph-gqt --check`. It reports all format errors together, with the
  source line and suggested correction for each. [#1398](https://github.com/ModernRelay/omnigraph/pull/1398)

- A GQT `--- concurrent` block can run freely on every host, take a worker
  count and distribute generated rows among the workers. Use
  `--- concurrent scripted` for a deterministic simulation that must follow
  a specific order. [Concurrent blocks](../../crates/omnigraph-gqt/README.md#concurrent-block) · [#1477](https://github.com/ModernRelay/omnigraph/pull/1477)

- `schema apply` can relax an edge cardinality rule in place. For example,
  changing `@card(1..1)` to `@card(0..1)` makes the edge optional and
  preserves existing data. Omnigraph still refuses to tighten a range this
  way. [Edge cardinality](../user/schema/index.md#edge-cardinality) · [Issue #1403](https://github.com/ModernRelay/omnigraph/issues/1403) · [#1406](https://github.com/ModernRelay/omnigraph/pull/1406)

## Behavior changes

- If another commit overtakes an update, delete or overwrite load, the
  engine tries once more against the new branch head and selects the rows
  again. If a mutation should apply only to the commit you reviewed, pass
  `--if-commit` so a change of head refuses it. [Conditional mutations](../user/mutations/conditional.md) · [#1349](https://github.com/ModernRelay/omnigraph/pull/1349)

- Check each dataset's `outcome` even when `optimize` exits successfully.
  A run can publish work for several datasets and report `failed` with an
  error for another. A `deferred` dataset has work left for a later run.
  [Maintenance reports](../user/operations/maintenance.md#bounding-a-run) · [#1275](https://github.com/ModernRelay/omnigraph/pull/1275)

- If compaction finishes and index maintenance or its coverage check then
  fails, the graph keeps the completed work. The dataset reports `optimized`
  with reason `index_failed` and the error. A direct run also lists indexes
  it already knows are pending. A new run checks coverage again and plans
  the work still needed. [#1418](https://github.com/ModernRelay/omnigraph/pull/1418)

- If the schema changes or a branch is deleted and recreated during a Blob
  write, the write now returns `read_set_conflict`. Clients can handle the
  same code for this conflict across Blob writes and other mutations.
  [Blob writes](../user/blobs.md) · [#1349](https://github.com/ModernRelay/omnigraph/pull/1349)

- The installers stop if a stable download fails. Moving to an edge build
  now requires an explicit choice, since it can create a graph an older
  stable binary cannot open. With a supported, signed-in GitHub CLI, the
  installers also verify the archive's build provenance. [Release channels](../user/install.md#release-channels) · [#1325](https://github.com/ModernRelay/omnigraph/pull/1325)

- Operators can find the encryption-at-rest options, how the catalog grows,
  which conditional writes an S3-compatible store must honor, and how to
  run without outbound requests. Google Cloud Storage's S3 interoperability
  endpoint is untested. [Storage guide](../user/concepts/storage.md) · [#1326](https://github.com/ModernRelay/omnigraph/pull/1326)

- The same `benchmarks.yaml` scenario can run against a server or locally.
  Pass `--server` to select the server, or use the host's local default.
  Update scripts using the 18 retired `-served` scenario IDs or either of
  the two IDs that dropped `-xfs`. [#1416](https://github.com/ModernRelay/omnigraph/pull/1416)

- When comparing two revisions with `omnigraph-bench run --store … --at A
  --at B`, the harness measures both revisions on one scenario before
  moving to the next. That gives their runs more comparable machine
  conditions. Existing reports and records keep their formats.
  [#1439](https://github.com/ModernRelay/omnigraph/pull/1439)

- For a long benchmark run against S3, instance metadata, container
  credentials or web identity let the client renew expiring credentials.
  Static keys from environment variables cannot renew. A temporary session
  supplied that way can expire partway through a run. [Benchmark harness](../../crates/omnigraph-bench/README.md) · [#1439](https://github.com/ModernRelay/omnigraph/pull/1439)

- A refused sign-in identifies the check that failed. If the identity
  provider returns tokens that disagree with the API's sign-in configuration,
  `provider_response_invalid` includes details to give your service
  administrator. `credential_invalid` identifies a problem with a saved
  session or its verification. [Sign-in errors](../user/cli/login.md#when-a-sign-in-is-refused) · [#1344](https://github.com/ModernRelay/omnigraph/pull/1344)

- CSV query output writes a null as an empty field and keeps the string
  `null` as text. `load csv` can now read that distinction back. It still
  treats a quoted empty string as null and skips empty lines, including a
  one-column row whose only value is null. [CLI reference](../user/cli/reference.md) · [#1440](https://github.com/ModernRelay/omnigraph/pull/1440)

- Once a direct `cluster apply` on local storage or S3 has settled its
  writes and confirmed the deployment is current, it releases its lock so
  the server or next operator can take over. If it cannot confirm release,
  it identifies the deployment and lock to inspect. Azure keeps its lock.
  [Cluster bootstrap](../user/clusters/index.md#bootstrap-a-cluster) · [#1360](https://github.com/ModernRelay/omnigraph/pull/1360)

- A merge that hits its validation memory limit now reports
  `branch-merge retained validation key bytes` and counts only keys from
  the changes being merged. For a large branch, merge an intermediate
  commit first, then the rest. If one commit alone is too large, write the
  change again as smaller commits. [Merge validation limits](../user/branching/merge.md#validation-limit) · [#1433](https://github.com/ModernRelay/omnigraph/pull/1433)

## Fixes

- MCP clients can call tools again. In 0.15.0 even a health check could
  terminate the server process and interrupt every graph it served.

- The server rejects excessively nested queries with `Q006` before parsing
  them. Clients that generate long lists of alternatives on one property can
  express those as `in [...]`. [Query diagnostics](../user/queries/diagnostics.md#parse-codes)

- A write prepared in the same process can proceed across a concurrent
  `optimize` commit. If compaction moved a row that the write changes, the
  engine prepares the write again once. [Maintenance guide](../user/operations/maintenance.md#optimize)
  · [#1349](https://github.com/ModernRelay/omnigraph/pull/1349)

- A served `optimize` reports `deferred` with reason `resource_limit` every
  time a dataset exceeds its ceiling. A new run with the same limits
  defers that dataset again. Raise the applicable server limit or
  run `optimize` directly. [Server limits](../user/operations/recorded-operations.md#table-ceilings-and-the-byte-budget)
  · [#1441](https://github.com/ModernRelay/omnigraph/pull/1441)

- When storage fails during a vector-index rebuild, `index build` and
  `optimize` report the underlying error. Previously an operator could
  mistake a storage failure for a vector column with too little data to
  train the index. [Building indexes](../user/operations/maintenance.md#build-indexes)
  · [#1418](https://github.com/ModernRelay/omnigraph/pull/1418)

- Updating indexed vector values can leave the old index covering zero
  fragments. The next `index build` or `optimize` rebuilds the index.
  Previously every subsequent attempt could fail.
  [#1446](https://github.com/ModernRelay/omnigraph/pull/1446)

- A large sort that spilled to disk could fail at a memory setting between
  two settings where it succeeded. The sort now limits its initial merge
  reservation to half the query budget. At the default 150 MiB it reserves
  9.4 MiB, down from 40 MiB. [#1389](https://github.com/ModernRelay/omnigraph/pull/1389)

- A storage read failure during served `cluster plan`, `cluster apply` or a
  deployment status check used to look like a deployment conflict. HTTP 503
  means the read can be retried. HTTP 500 covers persistent failures such as
  denied storage access that need repair before a retry can help.
  [Recorded operations](../user/operations/recorded-operations.md)
  · [#1357](https://github.com/ModernRelay/omnigraph/pull/1357)

- You can validate and test a cluster that has both a graph policy and a
  cluster policy. Each action is checked against the same bundle the server
  uses for it. [Testing policies](../user/operations/policy.md#validate-and-test)
  · [#1311](https://github.com/ModernRelay/omnigraph/pull/1311)

- If a container still sets `OMNIGRAPH_TARGET_URI`, `OMNIGRAPH_CONFIG` or
  `OMNIGRAPH_TARGET`, startup names the obsolete variable. Point
  `OMNIGRAPH_CLUSTER` at the cluster's storage URI or mounted directory.
  [Container setup](../user/deployment.md#container)
  · [#1329](https://github.com/ModernRelay/omnigraph/pull/1329)

- The bundled MCP library moves from `rmcp` 3.3.0 to 3.9.0. The update
  addresses host validation and limits memory used by the tool-schema cache
  and client response buffering. Existing clients keep their endpoint.
  [#1291](https://github.com/ModernRelay/omnigraph/pull/1291)

- The bundled `rustix` 1.1.6 fixes handling of empty buffers in
  extended-attribute functions. Omnigraph has no callers of those functions.
  [RustSec advisory](https://rustsec.org/advisories/RUSTSEC-2026-0486)
  · [#1350](https://github.com/ModernRelay/omnigraph/pull/1350)

- Benchmark `run` and `report` accept S3 store prefixes containing a colon.
  This lets an EC2 instance role use an IAM-scoped prefix derived from
  `${aws:userid}`, where the role ID and instance ID are separated by a colon.
  [#1480](https://github.com/ModernRelay/omnigraph/pull/1480)

- If two CLI sign-ins create the same profile at once, the successful sign-in
  survives. A profile-save failure also preserves any previously saved sign-in
  the CLI reused. [#1344](https://github.com/ModernRelay/omnigraph/pull/1344)

- A conditional mutation that loses a race reports `precondition_failure`
  even when the winning write also filled an edge's cardinality limit. Read
  the new branch state before deciding whether to submit another mutation.
  [Conditional mutations](../user/mutations/conditional.md)
  · [#1426](https://github.com/ModernRelay/omnigraph/pull/1426)

- CSV query output quotes an empty string as `""`. A CSV reader can now
  distinguish a row containing one empty string from a blank line. Omnigraph's
  `load csv` reads the quoted field as null.
  [#1375](https://github.com/ModernRelay/omnigraph/pull/1375)

- If the client loses the response to `branch merge --dry-run`, the CLI
  exits 1 and reports `effects: none`. You can repeat the preview safely.
  [#1448](https://github.com/ModernRelay/omnigraph/pull/1448)

- `cleanup` and `optimize` reject durations too large to convert to
  seconds. `cleanup --older-than` also rejects an age that would put its
  cutoff before the earliest representable time.
  [#1378](https://github.com/ModernRelay/omnigraph/pull/1378)

- A merge with wide rows could hit the 32 MiB validation limit even when
  the keys it had to check were small. Validation now reads changed rows a
  batch at a time. The limit counts their keys, including IDs, unique values
  and relevant edge endpoints. [Merge validation](../user/branching/merge.md#validation-limit)
  · [#1433](https://github.com/ModernRelay/omnigraph/pull/1433)

- The server, direct writes and policy tools now agree on which applied
  policy configurations they accept. Bind at most one bundle to a given
  scope and use separate bundles for graph and cluster scopes.
  [Policy binding](../user/operations/policy.md#bind-a-policy)
  · [#1434](https://github.com/ModernRelay/omnigraph/pull/1434)

- A direct `query --format arrow` can write an Arrow IPC stream to a file
  or pipe. A terminal or a served target gets a refusal before the query
  runs. [Query output](../user/cli/reference.md#query-inputs-and-output)
  · [#1429](https://github.com/ModernRelay/omnigraph/pull/1429)

- If graph policy denies deployment recovery, including when a required
  `--as` actor is missing, recovery now reports `policy_denied` before
  taking the lock. Previously it could report that the deployment outcome
  was unknown. [Deployment recovery](../user/clusters/index.md#inspect-and-recover-a-deployment)
  · [#1438](https://github.com/ModernRelay/omnigraph/pull/1438)

- Removing many nodes could exhaust memory while checking the edges that
  reference them. Overwrite loads, CSV loads, deletes and merges now check
  indexed edges in batches and can scan uncovered edge fragments once.
  [#1444](https://github.com/ModernRelay/omnigraph/pull/1444)

- The bundled agent skill explains when a nullable property can become
  required. First fill in every missing value. It also identifies
  `maintain` as the permission for index builds and full-text rebuilds.
  [Agent skill](../user/cli/index.md#give-an-agent-the-matching-skill)
  · [#1422](https://github.com/ModernRelay/omnigraph/pull/1422)

- Traversals from high-degree nodes could exhaust query memory even with
  indexed edges. Each traversal step now reads its matching edges one batch
  at a time. [#1460](https://github.com/ModernRelay/omnigraph/pull/1460)

## Performance

- A small keyed insert, update or merge load can look up affected rows by
  their identity index. On a simulated store with 262,144 rows in 64
  fragments, a one-row update went from 212 storage requests to 34, and an
  insert from 83 to 18. [#1318](https://github.com/ModernRelay/omnigraph/pull/1318)

- A long-running server remembers which branch held a group of unmerged
  commits. Later history, review and `commit changes` lookups in that group
  try that branch first, avoiding repeated searches across every live branch.
  [#1184](https://github.com/ModernRelay/omnigraph/pull/1184)

- After a write or branch change, traversals can reuse the cached topology
  for edge tables the change left alone. At 131,072 edges, a traversal in
  the simulated store went from 59 requests to 26.
  [#1363](https://github.com/ModernRelay/omnigraph/pull/1363)

- A scan with a `limit` and no filter or ordering can stop once it has its
  rows. A query for ten names opened one of 25 local data files. Previously
  read-ahead opened 16. [#1342](https://github.com/ModernRelay/omnigraph/pull/1342)

- An aggregate in a correlated block can process each outer row's matches
  one batch at a time. In a local test, 16,384 one-KiB inner rows now fit
  a 12 MiB query budget that previously refused them.
  [#1341](https://github.com/ModernRelay/omnigraph/pull/1341)

- Reads, diffs and change pages pinned to a commit open its known catalog
  version directly. This saves one measured GET on local disk. On object
  storage the expected saving is one LIST.
  [#1390](https://github.com/ModernRelay/omnigraph/pull/1390)

- A reader on an older snapshot, or a branch still using an older table
  version, can keep using its cached table handle after another write
  publishes. The cache evicts old handles as it reaches its budget of
  64 handles or 64 MiB. [#1319](https://github.com/ModernRelay/omnigraph/pull/1319)

- The next read or write in the same process can reuse the table versions
  that a write just committed. Mutations also spend less time holding the
  locks other writers need. [#1291](https://github.com/ModernRelay/omnigraph/pull/1291)

- Direct `optimize` can compact several groups of fragments from one table
  at once. Compaction and index builds share
  `OMNIGRAPH_MAINTENANCE_CONCURRENCY` slots, eight by default. Each Blob
  table still compacts one group at a time, and a served run uses one slot.
  [#1396](https://github.com/ModernRelay/omnigraph/pull/1396)

- `index build` and direct `optimize` can build up to four independent
  B-tree indexes at once, within one table or across tables. A full-text or
  vector build uses the whole run's capacity and runs alone.
  [#1395](https://github.com/ModernRelay/omnigraph/pull/1395)

- In-memory filters do less work when an early condition decides most rows.
  If at most 20% of a batch still needs a later condition, the engine evaluates
  it on just those rows. [#1346](https://github.com/ModernRelay/omnigraph/pull/1346)

- Export, the change feed and merges use less CPU to assemble rows. An export
  chunk takes one copy, down from two. Queries that group or match keys,
  including `not`, `count`, `sum`, bound edges and hash joins, can hash the
  keys in batches. [#1347](https://github.com/ModernRelay/omnigraph/pull/1347)

- The CLI works out the columns for `--format kv` once per response.
  When an older server omitted column names, printing 1,000 rows took
  0.17 seconds in the test, down from 0.46 seconds.
  [#1376](https://github.com/ModernRelay/omnigraph/pull/1376)
