# RFC: Branch existence in the catalog

> A term set in ***bold italics*** is being defined at that exact spot.

> 2026-11-19: the stamp this RFC takes is provisional until its order with the RFC and the PR in `blocked_on` is settled.

## Summary

A graph's ***catalog*** is main's `__manifest`: a Lance dataset whose numbered versions are written only if absent, so each version is one compare-and-swap, and whose rows record the tables, the schema contract, the commit graph and the ***writer epoch***, the generation of the process allowed to move a head. Every branch, main included, has a ***chain***, its own numbered `__manifest` versions under its ***tree***, the directory `__manifest/tree/<branch>/`, and main's chain is the catalog. A branch has no row in it. Its existence is a ***ref file***, the object `__manifest/_refs/branches/{logical}.{ULID}.json` that Lance writes once, if absent; its deletion rewrites that file, archives a copy inside the branch's tree (a create of a fresh key) and unlinks the file: two unconditional writes to one mutable key, each with its own recovery rule. In database words, the catalog records tables and commits in a versioned, atomically committed table and records branches as files in a directory.

This RFC gives a branch a ***branch row***: a ***control fact***, a `__manifest` row that changes no `table` row and no schema contract and records no graph commit, published on main's chain under main's version compare-and-swap through the ***publisher***, the catalog's one commit path, keyed by the branch's ***native name*** `{logical}.{ULID}`, carrying Lance's lifetime identifier, the ***fork point***, the source branch and the version of it the branch starts from, the creation time and the attempt id. The row is the ***registration*** of [Graph access and cross-process writes](2026-10-16-graph-access-serving-and-cross-process-writes.md), that RFC's main-side record that a branch exists, given its shape, and it becomes the only record that the branch exists: `branch create` publishes the row and writes no ref file; `branch delete` publishes a ***tombstone***, that RFC's control fact that ends a chain, on the branch's own chain and then retires the row on main; `branch list`, name resolution and every existence check read main's rows, which every operation already holds, and send no request on a held main whose rows resolve the name. The row's bytes ride main's version file, not the catalog's data file, so a control operation on main is one commit, a transaction file and a version file, and no data file. Trees that no live row names are the collector's (§The collector).

Unchanged: the per-branch `__manifest` chain as the branch's commit point, with its head as the branch's head; the version put-if-absent as the one compare-and-swap; the head precondition every publish carries; the publisher's reload-and-retry loop; the ***stamp***, the storage-format number a graph carries, and the stamp-only upgrade route that raises it; ***history settlement*** at delete, the copy of a deleted branch's commits into `__history/`. Lance is unchanged.

## Motivation

Every operation on a graph opens main's catalog, and the catalog says nothing about branches. A branch's existence is answered by Lance's ref directory: a `branch list` lists `_refs/branches/` and reads each file; a write on a branch resolves its name through the same listing, then reads the ref again under its gate (`crates/omnigraph-core/src/branch_control.rs`, which lists `_refs/branches/` and decodes the native names Lance's way). The storage-cost golden records the shape: a branch create is six GETs, six LISTs and six PUTs, a branch delete sixteen GETs, six LISTs, two PUTs and one DELETE, a branch write thirteen GETs, three LISTs and six PUTs (`crates/omnigraph-dst/cost_table.txt`). Lance itself names the ref file the authority: `Dataset::create_branch` is "a two-phase operation", the tree's clone commit and then the `BranchContents`, "not atomic", with the `BranchContents` as "the source of truth for the branch" and a cleanup procedure for the zombie trees the gap leaves (`rust/lance/src/dataset.rs`). The engine's `list_branch_contents` wraps Lance's `list_branches`, which `branch list` goes through; name resolution (`live_manifest_branches_matching`) lists `_refs/branches/` and reads only the matching refs. The requests are not the catalog's; they re-read a directory for a fact a row would carry.

Deletion is the clearest case. `retire_branch_recoverably` rewrites the ref file with the marker `omnigraph.retired_manifest_branch` inside it through Lance's `Branches::replace_metadata`, an existence check, a read and a put of the same object, `archive_retired_ref` copies the `BranchContents` into the tree as the archive file `RETIRED_BRANCH_ARCHIVE` names, then the ref is unlinked (`crates/omnigraph-core/src/branch_control.rs`; `docs/dev/recovery.md` §Graph branch controls describes the protocol and its retry rule: "bare absence is not proof of completed retirement"). Neither the marker rewrite nor the unlink is conditional: Lance 13's `replace_metadata` reads the ref and puts it back with no version check, the engine's unlink is a plain object delete with no precondition, and object stores offer no conditional delete, as the graph-access RFC records. Each of the three writes therefore has a recovery rule of its own, and `reclaim_ref_absent_tree` carries the sentence that only the single-writer gate stops a create between a cleanup's last ref read and its delete.

The graph-access RFC closes the races by moving every control operation's deciding step onto a `__manifest` chain's version compare-and-swap: a branch's registration on main, its tombstone on its own chain, a proposal's drop record. It keeps the ref file beside the registration, created after it and reclaimed when no registration names it. This RFC starts where that leaves the design: once main registers a branch, the ref file carries nothing the row does not, every reader can take the row, and the ref file's put, its read back, its marker rewrite, its archive and its unlink go with it. The question this RFC answers is what the row is, where its bytes live, what reads it, and what the operations cost once the directory is gone.

## User and operational behavior

Nothing changes for a graph below this RFC's stamp. An operator raises an existing graph to it (Compatibility) through the stamp-only route `omnigraph upgrade` already has, `stamp_live_refs`, which this RFC extends; a graph this binary creates is born at the stamp and carries rows from its first branch. After the upgrade:

- **`branch create <name>`** and **`branch create <name> --from-commit`** publish the branch row on main and then write the branch's tree. Two creates of one logical name in two processes race on main's version; the loser reloads, finds the name live and refuses with `branch_exists` before it has written a tree; its lost attempt's transaction file is an unreferenced fresh key. A create whose process dies between the row and the tree leaves a branch that lists as ***not ready***, the graph-access RFC's state for a registered branch whose ref and tree do not exist yet, after this RFC one whose tree does not exist yet: it refuses reads and writes with `branch_not_ready`, the one new code, "branch '<name>' is not ready: its tree was never written", and `branch list --detailed` reports it with `head`, `from_commit_id` and `updated_at` absent. `branch delete` removes it; a new `branch create` of the name starts a new lifetime. A logical name keeps Lance's branch alphabet (§The row).
- **`branch delete <name>`** publishes a tombstone on the branch's chain, settles the branch's history as today, and writes the retired row on main (§The row, below). It no longer refuses while a native tag pins the tree: a tag pins a tree, not a logical branch, and the collector keeps a pinned tree. A concurrent write on the branch is refused with `branch_deleted` at its publish, as the graph-access RFC specifies; this RFC also refuses a read of a tombstoned branch with `branch_deleted` (§Readers). A delete that finds its branch already tombstoned by another attempt completes the retirement and succeeds. A delete of a not-ready branch retires the row and writes no tombstone, since no chain exists. A delete of a branch another process holds under the writer epoch proceeds: the tombstone publishes at any epoch, the one exception to the fence, so a claimant that exited never pins a branch, and the holder's next publish is refused `branch_deleted`; a delete on a main another process holds is refused `writer_fenced` before the tombstone when main's current rows show the claim, and the operator runs it on the server target (§Writer epoch).
- **`branch list`** and **`branch list --detailed`** read main's rows: `name`, `from` and `created_at` from the row; `head` and `updated_at` from the tree, absent on a not-ready branch; `from_commit_id` from the branch's own tree at `parent_version`, as today, and from the head of the tree while it has written none, absent on a not-ready branch. A not-ready branch is listed by name; the human line of `--detailed` prints `<name> not_ready from=… created_at=…`, and the line of a ready branch is unchanged. `branch list` reads the installed main-bound coordinator's rows, sends no request on a held main and one metadata-only refresh (§Readers, below) otherwise; `--detailed` reads each tree's head as today, and a branch whose tree read meets a tombstone, a delete crashed before its retired row or finished after the rows were read, keeps its name, prints `<name> deleted (retirement pending)` and carries `retirement_pending: true` in the JSON beside its name, so an operator finds the delete to rerun.
- **Name resolution** everywhere (`--target` branch selection, `mutate branch:`, `diff`, `merge`, `merge-base`, the served routes) reads the row. A retired row (§The row, below) is not found: `BranchNotFound`, "branch '<name>' not found", as today.
- **`cleanup --confirm`** (a retention policy is required, as today; the tree reclaim, the entry removal and the unlinks run under any policy) reclaims every tree under `__manifest/tree/` that no live row names, after the keep set the collector holds as `protected_manifest_branches` (a live tag, a retention root, imported merge-base lineage, every tree a kept tree's data files live in); it removes retired rows whose tree is reclaimed or was never written, a tree a tag pins keeps its retired row, and an entry whose removal a concurrent publication deferred stays until a later run removes it; it repeats the upgrade's unlink of the ref files (Compatibility). It reports the four counts, `manifest_trees_removed`, `branch_entries_removed`, `branch_entries_deferred` and `ref_files_unlinked`, on its JSON and one human line, `branches: N trees removed, N entries removed (N deferred), N refs unlinked`. The age rule is §The collector's, below.
- **Policy**, HTTP routes and GQ syntax are unchanged: `branch_create`, `branch_delete` and the existing routes and statements keep their names and shapes.
- **Refusals.** `branch_exists` and `branch_deleted` as the graph-access RFC defines them, new registry codes with whichever RFC lands first, HTTP 409 (the branch-start refusal reason of the same name, `--from-commit` at a deleted branch's commit, is unchanged); `branch_exists` replaces `conflict` as the code of a duplicate create; `branch_not_ready`, new here, HTTP 409; the three take the action `refresh`, as `writer_fenced` does, so the CLI exit is 1; `schema_changed`, the branch-start refusal reason under `branch_start_refusal`, on a create whose fork point no longer carries main's schema contract, on every attempt, as the graph-access RFC keeps it until PR 963 lands; `writer_fenced` reaches two operations it did not reach, `branch create` and `branch delete` (§Writer epoch); the unknown-branch error as today.
- **Operators** see one fewer object class under `__manifest/`: `_refs/branches/` is empty after the upgrade's follow-ups and nothing writes it again. `_refs/tags/` is unchanged.

## Design

Checked against `ModernRelay/omnigraph` at `00b8cca8` and Lance 13.0.0 on 2026-11-20, over the crates `omnigraph-catalog`, `omnigraph-core`, `omnigraph`, `omnigraph-api-types`, `omnigraph-cli`, `omnigraph-policy`, `omnigraph-gqt` and `omnigraph-dst` and Lance's `lance` and `lance-table`; every file the body names is of those versions.

### The row

A control-fact row on main's `__manifest`, one per branch lifetime; main has none:

```text
object_id    = "branch:<native>"
object_type  = "branch"
fields       = { native: "agent-7.01JC…", identifier: "3:9f1c…", parent: "main",
                 parent_version: 3, created_at: 1763500000, attempt_id: "01JD…" }
```

`native` is the native name `{logical}.{ULID}`; the logical name is what precedes the final `.` and the ULID, as [RFC 0042](0042-incarnation-suffixed-branch-refs.md) defines; a native name without the suffix is a legacy lifetime whose logical name is the whole native, as `split_native_branch_name` reads it, and the upgrade writes its row as any other. A logical name keeps Lance's branch alphabet, `check_valid_branch` (`rust/lance/src/dataset/refs.rs`): non-empty, segments of alphanumerics, `.`, `-` and `_` joined by single `/`, no leading or trailing `/`, no `..`, no `\`, no `.lock` suffix, not `main`. The engine calls it on the logical name before the row, as `create_branch_recoverably` does today, beside `ensure_logical_branch_name` and the policy crate's `ensure_canonical_branch_name`; Lance checks the native name again at every open of the tree. RFC 0042's rule that `review` and `review/alice` cannot coexist stays: a live row whose logical name is the requested one, or an ancestor or descendant of it, refuses the create. `identifier` is Lance's `BranchIdentifier`, the `version_mapping` of `(parent version, token)` pairs that `BranchIdentifier::new(parent, parent_version)` mints, written by the engine in the string form `BranchIdentifier::parse` reads, `ver1:token1:ver2:token2`, at least one pair, each token 32 lowercase hex. The row is the identifier's home: every capture of a branch's identifier, today a read of the ref, reads the row of the main the operation holds, and every compare of it stays (§Readers). `parent` and `parent_version` are the fork point: the native name of the source branch, main shown as `main`, and the source's `__manifest` version the branch starts from; the graph commit the branch starts at is that version's head row. For `--from-commit`, `parent` is the branch the commit was published on and `parent_version` the `__manifest` version that published it, the commit row's `graph_manifest_version`. `created_at` is the creation time in Unix seconds; the listing multiplies to microseconds as today. `attempt_id` is the ULID the creating operation minted before its first attempt, the control fact's identity for the graph-access RFC's read-back; a row the upgrade writes carries the upgrade run's attempt. The row carries no head, no manifest size and no metadata: the head is the branch's own chain, and the two fields of Lance's `BranchContents` the row has no use for are dropped: `manifest_size` was compared only between a ref and its archive, which goes, and the marker that lived in `metadata` becomes the retired row, below.

The ***retired row*** is the same key with the value `-`, written in place of the row by `branch delete`; every reader skips it. A branch whose row is retired does not exist; its tree is the collector's.

### Where the bytes live

The catalog's rows live in two places: the version file, a protobuf manifest with a string-to-string `config` map that every open reads, and the data file, a Lance fragment the publisher writes when rows change. The branch row's bytes ride the version file as one config entry:

```text
omnigraph.branch.<native> = 1|<identifier>|<parent>|<parent_version>|<created_at>|<attempt_id>
omnigraph.branch.<native> = -                                        (retired)
omnigraph.tombstone       = 1|<attempt_id>|<deleted_at>              (on the branch's tree, §Delete)
```

The key is the prefix `omnigraph.branch.` and the native name, which may itself contain `.`; a reader strips the prefix and splits nothing. The value `-` alone is the retired row. Any other value's leading field is the entry's encoding version, `1` under this stamp; a value that is neither, has other than six fields, or has a field that does not parse as §The row types it, is malformed and fails the open naming the key; a tombstone value is three fields under `1`, malformed otherwise. `identifier` is Lance's `ver:token` form; `parent` is `-` for main, which the row shows as `main`; no field contains `|`, since the alphabet admits none, so the entry needs no escaping. A branch's tree starts as a shallow clone of its source's version and carries that version's config map (`Manifest::shallow_clone`, `rust/lance-table/src/format/manifest.rs`), so every tree holds a copy of main's branch entries as of its fork; the loader decodes `omnigraph.branch.` entries into `branch` rows of `ManifestRows` on main's chain only, told by the manifest's own `branch` field, `None` on main, and decodes `omnigraph.tombstone` into a `tombstone` row on a tree only; a row's entry on a tree and a tombstone entry on main's chain are ignored, never decoded. Beside the rows the data file holds, every reader of the catalog then sees rows; `ManifestState` and `omnigraph_catalog::Snapshot` carry the live branch set, read through `Snapshot::branch_rows()` on a main-bound snapshot, the surface the tests and the DST assert over; a branch-bound snapshot has none, since its coordinator's main is a copy as of its last refresh (§Readers). An entry is about 130 bytes with its key for a branch off main with a short name, 35 more per level of fork depth plus the source's native name once the source is not main; the open's one tail read of the version file is 64 KiB (`PREFETCH_SIZE`, `rust/lance-table/src/io/manifest.rs`), shared with the manifest's own bytes, so a few hundred live branches fit before the open reads a second range; the evidence pins the count at which the open's requests change.

The choice is the cost of a control operation. A row in the data file costs a data-file put beside the version put on every create and delete, since the publisher writes the fragment that holds the changed rows; an entry in the version file rides the put the operation makes anyway. Iceberg keeps its branches the same way, as the `refs` map of the table's metadata file, swapped with the file.

### The publication

A branch row is published as a control-fact publication, the kind [Writer epoch fence on the branch manifest](2026-11-09-writer-epoch-fence.md) defines for its claim: through the publisher, asserting the process's writer epoch on main, no lineage intent, the loaded head unchanged, no graph commit. The claim's commit stages a data file; the row's does not. The changes to the publisher are five: a `RowIntent { attempt_id, entries, assertion }` beside `ClaimIntent`, prepared as a claim is, loading main as a publish does (`load_publish_state`: the acknowledged image when this publisher holds one, else main's version file and its hot fragment) and asserting the epoch as a publish does for the row and the retired row, with no bump; a third `EpochAssertion` arm beside `Publish` and `Claim`, one that checks nothing and clears nothing, carried by the tombstone's intent alone (§Writer epoch); a placement `Placement::ConfigOnly { entries }` of `overwrite_probed` (`crates/omnigraph-catalog/src/commit.rs`) that names the loaded version's cold fragments and then its hot fragment by reference, since Lance renumbers them in list order, re-stamps the loaded schema, stages nothing and carries the entries as `config_upsert_values`; a read-back arm that settles a lost acknowledgement by the entry under the key in the attempted version (§Create, §Delete), `omnigraph.tombstone` on a chain, where the claim's arm reads the `writer_epoch` row; and the create's name and schema-contract checks inside the retry loop, on every attempt. The commit is Lance's `Operation::Overwrite` with zero Lance retries: the version file's put-if-absent and nothing else; the publisher's own reload-and-retry loop is the only retry. Lance calls this a strict overwrite, "not subject to any sort of automatic conflict resolution", and skips the `_versions/` listing and rebase every other commit kind makes (`rust/lance/src/io/commit.rs`, `commit_transaction`). Every linear publication through the publisher is already an `Operation::Overwrite` with zero retries, as the graph-access RFC records. Every Lance commit, this one included, first puts a transaction file under `_transactions/`, a fresh key, and then the version file; the engine does not disable it, so a commit is two puts, and a control operation on main is two puts and no data file.

A strict overwrite's `config_upsert_values` adds to the map and never removes from it, which is why a retired row is a value and not an absence; the collector removes retired entries (§The collector).

### Create

1. Mint the native name `{logical}.{ULID}` and the attempt id; check the logical name against the alphabet (§The row). The identifier is `BranchIdentifier::new(&parent_identifier, parent_version)`, the source's identifier from its row (or `BranchIdentifier::main()` when the source is main) and the fork point's version (§The row): the source's current `__manifest` version, re-taken with the identifier on every attempt of step 2 from the reloaded main when the source is main, so the row forks from the version it lands beside, or for `--from-commit` the commit row's `graph_manifest_version`, fixed.
2. Load main's rows through a main publisher of the same root, the coordinator's own when it is main-bound and one built over the held main otherwise (§Readers, below). Refuse `branch_exists` if a live row's logical name is the requested one, or an ancestor or descendant of it (RFC 0042's rule); `schema_changed` when main's schema contract is not the fork point's, on every attempt, until PR 963 lands (the graph-access RFC's rule); `branch_deleted` when the source's chain carries a `tombstone` row at the fork point's version (§Delete), which step 3's read of the source's version file shows and no read of its own, and `--from-commit` at a commit of a tombstoned or retired branch by the branch-start reason `branch_deleted`, as today. Publish the row as a control fact at main's next version. A put-if-absent that loses reloads and rechecks; the publisher's retry budget bounds the loop. A lost acknowledgement is settled by the attempted version's entry: the row landed if the entry under the key carries this attempt id.
3. Write the tree: the engine's own shallow-clone commit, built from Lance's public `CommitBuilder` with the engine's commit handler, `Operation::Clone { is_shallow: true, ref_name: source, ref_version: parent_version, ref_path: source tree URI, branch_name: Some(native) }` at `__manifest/tree/<native>/`, under the engine's `CLONE_CONTEXT` scope (`crates/omnigraph-core/src/lance_clone.rs`), which reuses main's manifest location when the source is main; the first phase of Lance's `create_branch` (`rust/lance/src/dataset.rs`) and the only one kept. This RFC adds `create_branch_tree` beside `create_branch` in `lance_clone.rs`; Lance's `Branches::create`, the second phase that writes the ref, is never called. One read of the source's version file (`__manifest` holds no index section, so Lance's clone reads nothing else; a branch source costs one existence probe before the read, which the cost test pins), one commit, a transaction file and a version file. No ref file.
4. Probe main for a version after the row's, two or three existence requests and one GET when it moved: a row retired meanwhile refuses `branch_deleted` and leaves the tree to the collector. Install the main the probe settled on in the process (§Readers), cross `branch_create.post_tree` (§Evidence, DST), return.

A crash after step 2 leaves a row with no tree: the branch lists as not ready, `branch delete` removes it, and `cleanup` keeps the fork point's tree while the row names it. A lost acknowledgement of step 3 is settled by the tree: a first version that exists is step 3 done, and a transaction file alone is no version; the tree's first version carries `parent_version`'s number, as Lance's clone keeps it. The creation is the row's version: the branch exists from the moment step 2's put is durable.

### Delete

1. Resolve the name through main's rows to its native name, before the branch coordinator opens. Unknown or retired: `BranchNotFound`. Read main's `writer_epoch` row through the main publisher's load (§Readers, below; one hot-fragment GET on a cache miss) and refuse `writer_fenced` when another process holds main (§Writer epoch). List `__manifest/tree/<native>/_versions/` unless the process holds the branch, whose held version is the one step 2 opens at: an empty listing is the not-ready verdict, a row with no chain, so skip the branch coordinator's open and step 2 and retire through the main publisher (step 3); otherwise the branch coordinator opens as today and its open's listing is this one; a tree written after that listing is the collector's.
2. Withdraw the held version, as `retire_held_branch` does today before its first request. Open the chain at the version step 1 found, no second listing: this open and the branch publisher's load are one of the two readers a tombstone does not refuse (§Readers), and a head that already carries a tombstone is not tombstoned again; the delete settles the history (below) and goes to step 3. Publish the tombstone on the branch's chain through the branch coordinator's own publisher, under the assertion that checks nothing (§Writer epoch), the graph-access RFC's control fact, as a strict overwrite of the tree's next version: one commit, its bytes one entry in that version file, `omnigraph.tombstone = 1|<attempt_id>|<deleted_at>`, `attempt_id` the ULID the delete minted before its first attempt and `deleted_at` in Unix seconds, which the loader decodes into a `tombstone` row of the chain's `ManifestRows`. A publisher on the branch that loses that version reloads, finds the tombstone and refuses `branch_deleted`; its staging is unreferenced and the collector reclaims it, as a `writer_fenced` write's is. One that wins it moves the head, and the delete reloads into the new head and tombstones that. The tombstone's compare-and-swap is what validates the delete's read of the branch's head: history settlement (`settle_head_of`) reads the rows the tombstone's publish loaded, up to the tombstone, and is complete; it writes one block to `__history/` when the branch published a commit, a fresh key as today.
3. Publish the retired row on main as a control fact through the main publisher (§Readers, below), one commit. A delete that reloads here and finds the row already retired succeeds without a publish. A lost acknowledgement is settled by any `-` under the key in the attempted version, since two deletes converge. Then release the process's in-process claim, as `retire_held_branch` does today once its retire has landed.
4. Nothing else: no marker rewrite, no archive, no unlink.

A crash between 2 and 3 leaves a tombstoned branch whose row is live: it refuses writes and reads with `branch_deleted`, lists, blocks a create of its logical name with `branch_exists`, and the next `branch delete` of the name settles the chain's history again from its tombstoned head, a retry that appends copies as `settle_head_of` does today, and finishes step 3. A crash between 1 and 2 leaves nothing. A delete racing a create of the same logical name races on main's version at step 3 against the create's step 2; both orders leave one live row of the name or none, and the create's row is a new lifetime with a new native name, so neither refers to the other's tree.

### Readers

Main is open in every operation: a main-bound `GraphCoordinator` holds it, and a branch-bound one gains the main it resolved its branch through, `ManifestCoordinator.main: Option<Dataset>` beside the branch's dataset, `None` when main-bound, copied by `capture`, and a ***main publisher*** of the same root for the row, the retired row and the delete's epoch read, the coordinator's own publisher when it is main-bound and one built over `main` otherwise, whose epoch assertion reads the process-wide holder registry (`WriterEpochHolders::of_process`); the branch's own publisher publishes the tombstone. `refresh_inner` re-reads main at its latest version on every branch refresh, as today's open does, resolves the native name through its rows and takes the row's identifier; a native name other than the held one is a recreation, and a tombstone on the branch's own chain is seen when the refresh opens the tree's version file. A branch-bound coordinator's `main` is read for its own row and nothing else: a name its held rows do not resolve is answered after one re-read of main at its latest version, and `branch list` reads the installed main-bound coordinator's rows, whose freshness probe is main's. Every reader of a branch's existence or identifier takes the rows of that main:

A control operation moves main's version. Every holder of main in the publishing process adopts the committed main without a request when its rows are the ones it holds: the installed coordinator, the branch-bound coordinator's main, the publisher's acknowledged image. A holder in another process sees the new version at its next freshness check and takes it as a ***metadata-only refresh***, a change to `refresh_inner` this RFC makes: the new version lists the same data files, whatever their fragment ids, and the same schema, so the refresh swaps the dataset, keeps its rows, table pins and read caches, and decodes the config entries again; the data-file rows are not reloaded. The engine reads the manifest's `config` map in one place today, `optimize`'s configuration clear (`clear_stale_auto_cleanup_config`, `crates/omnigraph/src/db/omnigraph/optimize.rs`), which removes Lance's `lance.auto_cleanup.*` keys through `update_config`; the decode of `omnigraph.` entries is new code in the loader, run at open, at refresh and at the publisher's load. A tombstoned chain refuses `branch_deleted` to a read and to an ordinary publication at each of those points, and a handle already holding the branch refuses at its next refresh; two openers read the `tombstone` row and go on: a delete's own open and load of the chain it is retiring, which takes another attempt's tombstone as its own landed one (§Delete), and the collector's inventory, which judges a tombstoned chain's stagings dead and its tree by the row set (§The collector). At a branch open and in `--detailed`'s tree read, Lance's not-found on the tree's `_versions/` for a native a live row names is the not-ready verdict, mapped to `branch_not_ready` where `branch_ref_error` maps today's ref miss. This is the price a second process pays for another's control operation: the freshness probe's two or three existence requests and one GET for a version it did not make, and at its next publish on main one hot-fragment read, since the publisher's cache keys on the manifest image; the collector's removal of a retired entry (§The collector) costs main's next publisher the same reload.

Lance opens a branch tree by its path: `checkout_branch` resolves the tree's location from the name and lists its versions for the latest, and reads no ref (`rust/lance/src/dataset.rs`, `checkout_by_ref`), so a tree without a ref file opens as any other.

### The collector

The collector is the last reader of the rows. The graph-access RFC's rule, with the ref file removed: the collector lists trees, then reads main's latest version, a listing of `_versions/` and one read and never the held image, and takes its rows, so any tree whose create is in flight is already in the rows it reads; a tree without a row is never a create in flight, so an orphan and a reclaimable tree are one case. A tree no live row names is a candidate with no age threshold; the keep set of `protected_manifest_branches` still holds a tree a live tag pins, a retention root, imported merge-base lineage (`retained_merge_bases`), a not-ready row's fork point, and every tree a kept tree's data files live in, transitively, live rows and tag-pinned trees alike, read from each kept tree's head version file: a Lance manifest records the base path of every data file it references (`base_paths`), and the clone stamps a base only on files that have none, so a grandchild references its grandparent's tree directly and a walk over the rows' `parent`, which a retired row no longer carries, would stop short. The collector's inventory opens every live branch at HEAD, as today, and reads a tombstoned chain's tombstone row rather than refusing (§Readers); `NativeForkInventory`'s `__manifest` arm takes the `base_paths` set in place of the refs' `parent_branch` and `identifier` walk, and the table arm keeps `BranchContents`. The deciding authority is the row set, never an age, as invariant 5 requires. The collector removes a tree with the object store's `remove_dir_all` on `__manifest/tree/<native>/` and nothing above it, the call it already makes for `_indices/`: Lance's `force_delete_branch`, which the `__manifest` arm of `optimize`'s `collect_native_forks` and `branch_control.rs`'s reclaim of a ref-less tree call today, derives the path to remove from the refs that remain, and with none left removes the first segment of a slash-named branch's path, `tree/team/` for `team/agent-7.01JC…`, with every live sibling; after the upgrade it is never called on `__manifest`, and the table datasets' native forks keep Lance's delete. Once a retired row's tree is reclaimed, or the row names a tree that was never written, the collector removes the entry through Lance's `Operation::UpdateConfig` carrying `config_updates` alone, a delete of the key: a Lance commit outside the publisher, unfenced, the class `optimize`'s configuration commit is in and the same `update_config` delete that commit makes; Lance rebases that shape past the publisher's overwrites (`rust/lance/src/io/commit/conflict_resolver.rs`, `check_update_config_txn`) and refuses it when a concurrent publication wrote the same key, which the next `cleanup` retries, the entry staying until a later run removes it, reported as deferred; one that touches schema metadata, as the stamp commit does, is refused as incompatible. The commit moves main's version and changes no row a reader holds, which is acceptable for a maintenance operation that runs rarely and holds nothing. A tree a tag pins keeps its retired row.

### Writer epoch

A branch row is a publication on main, so it asserts the publishing process's epoch on main and is refused `writer_fenced` when main is claimed by another process. Once the writer-epoch RFC's phase 3 has the admitted server claim `main`, that server creates and deletes branches, and a direct `branch create` or `branch delete` beside it is refused `writer_fenced`, so the operator runs either on the server target; the refusal's `writer_fenced` details carry main's epochs and its message names `main`; until a process claims `main`, nothing is asserted. The tombstone is the one publication that asserts no epoch: its intent carries the assertion arm that checks nothing and clears nothing (§The publication), since it ends the chain, so a delete of a branch another process holds, or whose claimant has exited, proceeds, the holder's next publish is refused `branch_deleted`, and the tombstone leaves the chain's `writer_epoch` row as it was, so a tombstoned chain keeps its last epoch. The retired row asserts main's epoch, so the delete reads main's `writer_epoch` row through the main publisher's load before the tombstone (§Delete step 1) and refuses `writer_fenced` up front when that load shows another process's claim, so an already-fenced delete leaves no tombstone; a claim that lands between that read and step 3 refuses step 3 after the tombstone, the state of a crash between 2 and 3, which the next `branch delete` on the holder finishes. This settles the second gate of the writer-epoch RFC's `blocked_on`. Branch create becomes a fenced operation and branch delete a half-fenced one: today their ref writes sit outside the publisher and are not fenced (`docs/dev/invariants.md`, `docs/dev/writes.md`); after this RFC a create's deciding step, the row, and a delete's retired row are publications the epoch covers, and the tombstone, a delete's deciding step, is the exception above.

## Invariants

Against [the architectural invariants](../dev/invariants.md):

- **1, respect the substrate.** Lance owns the tree, its versions and the version put-if-absent; the row rides Lance's own config map through Lance's own strict overwrite. Lance's ref directory is a feature the engine stops using; the one Lance behaviour the engine replaces is the forced branch delete's path cleanup, which removes more than the tree (§The collector).
- **2, one publication door.** The row, the tombstone and the retired row publish through the publisher as control facts, the tombstone under the assertion that checks nothing (§Writer epoch); `forbidden_apis.rs` registers their three paths and the collector's commit below, relabels its `NativeRefControl` rows to the control-fact protocol, and loses the `branch_control.rs` rows for `create_branch`, `replace_metadata`, the archive's `put_opts` and the unlink's `delete`; the `force_delete_branch` rows stay for the table datasets' native forks. One commit on `__manifest` joins the ones that stay outside the publisher today, `optimize`'s configuration commit and the stamp-only route's stamp commits, main's among them, and asserts no epoch as those do: the collector's removal of a retired entry, which changes no row a reader holds. The upgrade's rows ride main's existing stamp commit, which runs with every writer stopped.
- **3, one coherent accepted view.** A branch's existence is read from the main the operation holds, the same version its other catalog reads come from; today it is read from a directory whose state is not versioned with anything. The native ref identity a writer captures (`docs/dev/invariants.md`, invariant 3) is captured from that main's row; the wording changes with phase 1.
- **5, crash convergence.** Every durable step of create and delete is a zero-retry publication (the row, the tombstone, the retired row), a conditional key (the tree's version file) or a fresh key (the transaction files, the history blocks); a crash leaves state the next delete completes; no step has a recovery rule of its own. The collector's entry removal and the upgrade's unlinks are idempotent maintenance writes outside the publisher. The collector decides from the row set, never an age (§The collector).
- **6, identity.** The lifetime's identity is the ULID and Lance's `identifier`, both in the row; the native name carries the ULID as a table's path carries `table_incarnation_id`, and nothing infers a lifetime from the logical name.
- **8, integrity failures are loud.** A malformed entry, a field that does not parse included, fails the open with the decoding error naming the key.
- **11, bounded.** On main's chain the config map holds one entry per live branch and one per retired branch whose tree stands, and every open reads it; the collector removes retired entries, so the map scales with the live branch set and the trees awaiting reclamation, not with history. A tree's map carries the copy its clone took and is not decoded (§Where the bytes live).
- **12, one source of truth.** The row is the only record that a branch exists. Today there are three, the ref file, its marker and its archive, with a rule for each disagreement (`docs/dev/recovery.md`).
- **13, evidence matches the boundary.** Compatibility, refusal, crash, collector and cost evidence on checked-in instruments, below.

Deny list: "maintained parallel truth" names today's ref, marker and archive; this RFC removes them. "Process-local locks presented as distributed writer fencing": the branch gates stay contention optimizations, as the graph-access RFC makes them. "Acknowledgement before durable graph visibility": a create is acknowledged after its row's version exists, a delete after the retired row's. No invariant is weakened.

Support boundary, "Branch creation/deletion and cleanup retain their existing single-writer-process control boundary": this RFC implements the branch part of the graph-access RFC's lifting of it; the sentence changes when that RFC's evidence gates pass, not here. Inside today's boundary the in-process branch gate alone keeps a publish off a deleted branch; the tombstone is the first step of that lifting, paid now, one commit per delete (Alternatives).

## Compatibility and reversibility

- **Storage.** The row is a new config entry and a new row kind under a new stamp, `BRANCH_ROWS_STAMP`: the next after `CONTROL_FACTS_STAMP` 17 (`crates/omnigraph-catalog/src/migrations.rs`), or the graph-access RFC's stamp when phase 1 lands its tombstone first, or whichever the order with [schema apply with live branches](https://github.com/ModernRelay/omnigraph/pull/963) assigns. A graph this binary creates is born at it. An existing graph is raised to it by the stamp-only route `omnigraph upgrade` already has, `stamp_live_refs` (`crates/omnigraph/src/db/upgrade.rs`), writers stopped, which this RFC extends: main first, a row per live ref from the live-ref inventory the route reads (at most `MAX_BRANCHES` live refs, as today), the stamp route reading each ref's `parent_branch` and `create_at` into a row type of its own beside `SourceBranch`, which the fence intent keeps unchanged, every row carrying the upgrade run's attempt id, as `config_updates` of the same `UpdateConfig` commit that writes main's stamp, outside the publisher and asserting no epoch, as that route is today; then each branch's stamp; then the unlinks of the ref files, its follow-ups, which run on every invocation after the route's authorization and are repeated by `cleanup` until none is left. A rerun below main's stamp is the first run; one at or above it takes its branch list from main's rows, writes no row, stamps each branch still behind as today, and, after the route's authorization, unlinks the refs that remain; it reports `UpgradeWork.rows_written` and `UpgradeWork.refs_unlinked`, the human line `rows: N written, refs: N unlinked`, `rows_written` counting rows and never main, so one below `live_refs`, the boundary `unlinked:ref '<native>'` after each unlink, outcome `completed` when it stamped or unlinked anything and `already_current` otherwise; `--check` answers `check_passed` with both counts it would make. From main's stamped version on no omnigraph reader resolves a branch through `_refs/branches/`; the route's rerun and `cleanup` list it only to unlink what remains. A tree created after the upgrade keeps the stamp of the version it clones; the row's stamp is main's. An older binary refuses the graph at open through `guard_stamp`. A graph below the stamp keeps today's ref protocol in full, and the new binary writes no row there.
- **Mixed binaries.** Before the upgrade, as today. After it, an old binary's open fails the stamp guard with today's message for every stamp.
- **Wire.** No new command, route or statement. `head` and `head_is_own` become `Option` in `GraphBranchDetail`, and `head` and `updated_at` become `Option` in `BranchDetail` and `BranchDetailOutput`, omitted from the JSON as the other optional fields are, absent on a not-ready branch, and `retirement_pending` is added to the three, `true` on a branch whose tree read met a tombstone (§User and operational behavior), a wire change this RFC makes. `branch_not_ready` is new here; `branch_exists` and `branch_deleted` are new with whichever RFC lands first; all three HTTP 409 beside `conflict` and `writer_fenced`, action `refresh`, the CLI exit of a refusal; `branch_exists` replaces `conflict` as the code of a duplicate create, which answers `conflict` today; a create refused `branch_deleted` at step 4 reports `effects: none`, since the name is not live. The routes' documented responses change accordingly: `DELETE /branches/{branch_name}` gains 409 `writer_fenced`, `POST /branches` gains `branch_exists`, `branch_deleted` and `writer_fenced` under its 409, every route that takes a branch gains 409 `branch_not_ready`, and `GET /branches?detailed=true` gains the not-ready and retirement-pending shapes. The rows have no operator surface beyond `branch list`, `upgrade`'s and `cleanup`'s counts and the DST's `Snapshot::branch_rows()`, stated as a gap. The refusal `cannot retire graph branch … while native manifest tag … pins it` is removed.
- **Native tags.** `branch delete` no longer refuses under a native tag that pins the tree; the tree stays while the tag does, a read at the tag still opens it, and the collector keeps it in `protected_manifest_branches`.
- **Retention.** A branch's name, fork point and timestamps enter main's history: every older version of main keeps the map it had, readable until version retention reclaims that version of main, and the retired row stays in the current map until the collector removes it. Today the unlinked ref leaves only its archive inside the tree. Deleting a branch bounds its name by version retention, not by the delete.
- **Lance.** Lance's own `list_branches` and `delete_branch` see no branches after the upgrade; the engine's `list_branch_contents`, which wraps the first, stays as the one raw `list_branches` call for the table datasets' native forks, and its `__manifest` callers take the live row set from the held main (§Readers); `delete_branch` stays on the `forbidden_apis.rs` list, as today, and the `__manifest` arm of `collect_native_forks` stops calling `force_delete_branch`, whose rows stay for the table arm (§The collector).
- **Downgrade.** Export and load.
- **Revert.** A release whose stamp-only route rewrites a ref file per live row, drops the entries and lowers the stamp, writers stopped; the reverted binary starts after the route.

| The row's commit as a raw Lance commit outside the publisher | Asserts no writer epoch, so a process fenced off main could still create a branch on it |
| Tree then row | A tree with no row would be either a create in flight or an orphan, and the collector would need an age to tell them apart |
| Delete as the retired row alone, no tombstone on the branch's chain | A publisher on the branch reads its own chain, not main; its publish lands on a tree nothing resolves, an acknowledged write no branch shows. Inside today's single-writer boundary the in-process gate prevents it and the retired row would suffice; the tombstone is the branch part of the graph-access RFC's lifting of that boundary, paid now, one commit per delete |
| Today's refusal of a delete under a native tag | It guarded the ref's unlink, which the delete no longer performs; the tag pins the tree, which the collector keeps |
| The branch's head inside the row, one compare-and-swap for every branch | Every publish on every branch contends on main's version; at most one commit per round trip store-wide, a regression from the per-branch isolation the chains give today |
| Keep the marker, archive and unlink as follow-ups of the retired row | Three mutable-key writes for a tree the collector reclaims from the row set anyway; the archive existed so a retry could prove retirement, and the retired row proves it |
| A marker key that says "this main carries branch rows", so a store can adopt rows without a stamp | A reader of a main without the marker falls back to the ref directory, two protocols in one binary for the life of the store; a per-main marker is a second gate beside the stamp the loader already applies, and the stamp is the existing mechanism for exactly this decision |

A head object per branch moved by conditional put, and the catalog in a transactional store beside the bucket, are the writer-epoch and graph-access RFCs' alternatives for the chain itself; this row changes neither answer.

Precedent audit. In-repo: `table_incarnation_id`, identity in the path and no side record, which the native name `{logical}.{ULID}` already follows and the row keeps as its key; the `schema_contract` row, a non-table row of the catalog; the `writer_epoch` row, the first control fact and the publication kind this row uses; the legacy `table_tombstone` row kind (`crates/omnigraph-catalog/src/legacy.rs`), a tombstone as a catalog row, which the retired row follows. Divergence from the nearest: the writer epoch's bytes ride the data file as a `metadata` payload, the branch row's ride the version file's config, because a branch row is written per branch lifetime and a claim per takeover, and a control operation on main would otherwise write a data file for under two hundred bytes for a branch off main. The price is two encodings of control facts, one loader each. External: Iceberg records branches and tags as the `refs` map of the table metadata file, swapped with that file's compare-and-swap; Dolt exposes branches as the `dolt_branches` system table under one root; Git replaced one file per ref with `packed-refs` and then reftable; Postgres drops a table by changing its `pg_class` row and unlinks the files afterwards.

## Rollout

1. **The row.** The row kind and its loader, the control-fact publication on main with its publisher placement, the stamp and the upgrade route's row write with its ref unlinks, `branch create` and `branch delete` on the row and the tombstone, the not-ready state and `branch_not_ready`, the tombstone itself if this RFC lands before the graph-access RFC, every reader of §Readers on the rows, the metadata-only refresh, the collector on the row set with its own tree removal, the optional `head` and `updated_at`, the amended sentences of the graph-access RFC, and the developer guides: `docs/dev/recovery.md` §Graph branch controls rewritten to the row protocol, the ref-write clauses of `docs/dev/invariants.md` and `docs/dev/writes.md` removed, invariant 3's "native ref identity" reworded, `docs/dev/writes.md`'s native-branch control-exception paragraph ("`BranchContents` is the logical authority"), its create-admission paragraph, the epoch holder's branch-delete sentences and its branch-deletion and detailed-listing paragraphs rewritten to the row, `docs/dev/lance.md`'s ref sentence with them; `docs/user/branching/index.md` and `docs/user/cli/reference.md` gain the not-ready state, the retirement-pending line and the three codes, and the `branches` doc comment reads "every branch with a live row". Nothing changes for a graph below the stamp.
2. **Nothing cloned at create**, a later amendment: the row names the fork point, a branch with no tree would be a readable snapshot of its source at that version, and the first publish on the branch would write the tree; a create is then one commit and a delete of an unwritten branch one. Its one open race, a delete of an unwritten branch against a first write that writes the tree and publishes without reading main, is decided by the authors in that amendment, with the two-process evidence above as its gate.

`implementation` moves to `in-progress` at phase 1 and to `complete` when phase 1 ships.

## Decision log

- 2026-11-19: Created. The decisions, each with what it rejects:
  - **What a branch is.** A row of main's catalog, published under main's version compare-and-swap, and nothing else: no ref file, no marker, no archive. Rejected: the ref name as the registry, whose cost is a directory listing and a file read per existence check and two unconditional writes with an archive per delete; the registration beside a kept ref file, two records of one fact.
  - **Where the bytes live.** The version file's config map, one entry per lifetime, under two hundred bytes, decoded into a row by the loader. Rejected: the packed record's data file, a data-file put per control operation for under two hundred bytes.
  - **How it is published.** A control-fact publication through the publisher, a strict `Operation::Overwrite` with zero retries carrying the entry as `config_upsert_values`, a placement of the publisher's overwrite that stages no data file. Rejected: `UpdateConfig`, which rebases past the uniqueness check; a raw commit outside the publisher, which asserts no writer epoch.
  - **What a delete is.** The graph-access RFC's tombstone on the branch's chain, then the retired row on main. Rejected: the retired row alone, which lets a concurrent publish land on a tree nothing resolves once the single-writer boundary is lifted; the marker, archive and unlink as follow-ups, three mutable writes for what the row already proves.
  - **The retired row.** A value, `-`, for the reason §The publication gives. Rejected: an empty value, which a reader must then special-case beside the absent key; `-` reads as a value.
  - **Order at create.** Row, then tree, so a tree no row names is never a create in flight and the collector needs no age. Rejected: tree then row, which the collector cannot tell from an orphan.
  - **Adoption without a stamp.** Rejected: a marker key that lets a store carry rows below the stamp, two protocols in one binary.
  - **Phase 2.** Named, not shipped with phase 1.
- 2026-11-20: Changed, each with what it rejects:
  - **The identifier.** The row is its home: every capture reads the held main's row and every compare stays, the writer-epoch claim's `ExactBranchIdentity` included. Rejected: dropping the compare, which touches every compare site and empties the claim's precondition; writing it into the tree's config, a second commit at every create.
  - **A tree's map.** The loader decodes branch entries on main's chain only and the tombstone on a tree only, since a shallow clone copies the source's map. Rejected: stripping the copy at create, a second commit on the tree.
  - **The retired entry's removal.** The collector, through a `config_updates`-only `UpdateConfig` outside the publisher, once the tree is reclaimed or was never written. Rejected: through the publisher, which has no delete; never, which grows the map with every abandoned create.
  - **A crashed delete.** Only the next `branch delete` of the name finishes it; `branch list --detailed` shows it as retirement pending. Rejected: `cleanup`, which would publish on main under its epoch from inside a maintenance run; a listing that drops the name, which hides the delete to rerun.
  - **Not ready.** Listed by name, `head`, `from_commit_id` and `updated_at` optional on the wire, `branch_not_ready` at HTTP 409, no `repair` command (the graph-access RFC's). Rejected: a `ready` field in the row; listing a not-ready branch under `--detailed` alone.
  - **The upgrade's door.** The rows as `config_updates` of the route's own stamp commit, outside the publisher. Rejected: through the publisher, which cannot raise a stamp.
  - **Native tags.** A tag pins a tree; a delete proceeds and the collector keeps the tree while the tag stands. Rejected: today's refusal, which guarded the ref's unlink the delete no longer performs.
  - **Two encodings.** The branch row and the tombstone in the version file's map, the writer epoch in the data file, stated as a cost. Rejected: moving the epoch, a second stamp; the tombstone in the data file, a put the delete avoids.
  - **The tombstone and the epoch.** The tombstone publishes at any epoch through an assertion arm of its own that checks nothing, the one exception, since it ends the chain; the retired row asserts main's, and the delete reads main's epoch through the main publisher before the tombstone. Rejected: a fenced tombstone, which lets a claimant that exited pin a branch until a claim and gives `branch delete` a `--claim` flag; the epoch read from the coordinator's held main, which holds no data-file row.
  - **The main publisher.** A branch-bound coordinator publishes the row and the retired row through a main publisher of the same root built over its held main; the tombstone goes through its own. Rejected: one publisher for both, which the precondition check refuses.
  - **The keep set.** Every tree a kept tree's data files live in, read from the trees' `base_paths`, live rows and tag-pinned trees alike. Rejected: a walk over the rows' `parent`, which the retired row does not carry and which stops at the first deleted ancestor; a retired row that keeps its fields, a bigger map for a fact the trees already record.
  - **A create overtaken by a delete.** Step 4 probes main and refuses `branch_deleted`. Rejected: leaving it to the support boundary.
  - **The fork point.** Re-taken on every attempt from the reloaded main when the source is main, so a row forks from the version it lands beside; fixed for `--from-commit`. Rejected: minted once, a row that names a fork point behind the version it lands on.
  - **The assertion surface.** `Snapshot::branch_rows()` on a main-bound snapshot only. Rejected: a branch snapshot's copy of main, older than main's latest by up to one refresh.
  - **An operator surface for the rows.** None beyond `branch list`, the counts `upgrade` and `cleanup` report, and the DST, stated as a gap. Rejected: `snapshot --json` growing a `branches` field, a wire change for a surface the listing already gives.
  - **Phase 2.** Its race is decided in the amendment that opens it, gated on the two-process evidence.
