# RFC: GQ 3: the language, its search contracts, one break and the programme

> A term set in ***bold italics*** is defined at that spot; it is plain text
> afterwards. Code references are at `main` `03e0b623`, Lance 13.0.0; the
> bump base is `GQ_LANGUAGE_VERSION` `(2, 3)` and `EXPLAIN_VERSION` `8`. A
> rule this RFC chooses, rather than one an axiom forces or today's behaviour
> supplies, is marked *[choice]*; a rule carried over unchanged, *[as today]*.
>
> This is the one GQ 3 document. It replaces the grammar RFC (PR #1202), the
> programme RFC (PR #1213), the analyzed lexical search RFC (PR #792) and
> RFC 0048 (PR #793), closed without merge on 2026-11-07, and it answers
> PR #1244. Its evidence is the
> [evaluation](assets/2026-10-28-gq-3-grammar-evaluation.md), the
> [grammar comparison](assets/2026-11-07-gq-3-grammar-comparison.md) and the
> [before-and-after corpus](assets/2026-11-07-gq-3-before-and-after.md).

## Summary

GQ is restated from the bottom up in four layers, each fixed before the next
is designed, and the whole lands in one breaking release followed by
additive stages.

- **Axioms.** Eight: every read is total with a cost readable from its plan,
  observes one snapshot, is described completely by its plan, composes
  (every operator's output is a relation any input position accepts),
  carries its semantics as typed terms, has one spelling per term, keeps
  reads free of effects, and declares rather than chooses its quality.
- **Core.** Thirteen operators over typed relations with the graph pattern as
  the only leaf, three terminal write sinks, and a term former that inlines
  declared reads. Every surface form desugars into exactly one core term,
  and a reference interpreter of the core (`spike/gq3-core`) runs the
  RFC's examples and 50,000 random terms against the rules below.
- **Surface.** Two clauses in `match`, `let` (a named value) and `from` (rows
  drawn from a relation); arithmetic; retrieval as relation functions,
  `distance`, `nearest` and `bm25`, with `rrf` and `union` over relations; one
  declaration keyword, `query`, whose body's shape says whether it reads or
  writes; a write body that takes a read's clauses before its statements.
- **Search contracts.** Text analysis, scoring, vector distance and
  embedding recipes are schema-owned and resolved before acceptance:
  `@index(p, fulltext, analyzer = …)` with three immutable profiles and the
  `bm25_v1` scorer over the field corpus; `terms(…)` as the one lexical
  query, consumed by the predicate `match_terms` and by `bm25`;
  `Vector(n, distance = …)`; an exact scan as the correctness oracle under
  every index state, and native indexes as acceleration that must prove
  parity.
- **The break.** Edition 3, selected by `gq 3;`. Seven spellings of edition 2
  stop compiling, each rewritten by `omnigraph queries migrate` with a
  typed-IR proof (six of them) or a rows-equality proof (the `rrf` rewrite);
  edition 2 compiles for one more release and is rewritten at boot.
- **The programme.** After the break, every later capability is a registry
  row, a catalogue type, an envelope field, a plan node, or a production
  that starts at a token edition 3 refuses, in the stage order section 11
  fixes; every open language, search and access RFC receives a verdict
  there.

What does not change: static closed typing, three-valued logic with no null
literal in reads, pattern conjunction, stratified blocks and the safety rule,
reachability semantics for bounded traversal, one total order, index
requirements at compile time, keyed insert as upsert, one commit per write,
the constructive-or-destructive rule, branch and commit statements, the `@`
namespace, the four-field diagnostic, the storage format, the `__manifest`
publication door, the HTTP contract version and the plan-acceptance
contract.

## Motivation

GQ grew one capability at a time, each answering the request in front of it:
a logic word reserved when a filter needed it, a ranking placed in `order`
because that is where a score was first wanted, a search function added as a
keyword, an explain version per feature, a deprecation shim per rename. The
language carries decisions whose only justification is the order they
arrived in. The [evaluation](assets/2026-10-28-gq-3-grammar-evaluation.md)
against SQL, GQL, Cypher, GraphQL, Datalog and the query languages of
Elasticsearch, LanceDB and Vespa found the semantics sound and the accretion
the problem, and the
[construct-by-construct comparison](assets/2026-11-07-gq-3-grammar-comparison.md)
found the expression language the smallest of the five it compares.

The first drafts answered the accretion with a freeze: one break and a list
of reserved clauses for the forms the next RFCs would need. Their review, and
the independent alternative in PR #1244, showed the freeze repeating the
pattern at a larger grain: `retrieve { }` for the ranking shape, `having { }`
for the filtered-group shape, `view` for the reuse shape, each one spelling
for one job because the language had no general way to use a result. The
evaluation had called that general way, compositional closure, the root of
every expressiveness gap, and had refused it on the ground that non-closure
is what makes plan truth and bounded execution possible. That claim was too
strong. Compile-time closure, every nested read inlined into one bound plan
against one snapshot, keeps plan truth and replay; what it costs is
cardinality estimation across a correlation, a budget on expansion, a report
that nests, and cuts that stay explicit. Those are four obligations, not a
reason for a clause per shape.

Search has the same history in one domain. Text answers change with physical
index state: without an index `search` runs a bare case-sensitive scan
(#747), with one `fuzzy` spends its edit budget on letter case (#748), and
rows appended after an index build are analyzed differently from indexed
ones (#749), each a violation of invariant 7. A downstream `limit` sizes an
upstream window, so a page size changes a vector arm's recall; `rrf()` takes
exactly two positional arms; `Vector(n)` declares no distance and every index
is built with L2; a caller who needs the exact nearest targets cannot ask
for them. Two RFCs (PRs #792 and #793) fixed these on the edition 2 surface
and were reviewed; one review found their default window inconsistent with
their own law. The core of this RFC resolves that by construction, so their
contracts are restated here on the new surface and the two drafts close.

So this RFC designs in layers that do not move. The axioms are the contract.
The core is a small algebra whose operators are each necessary and together
closed. The surface is sugar with one desugaring per form, chosen by
precedent among the languages agents have read most. The search contracts
are schema-owned meaning that no index state can change. The break is the
one release that moves stored text from the old surface to the new one,
mechanically and with proof. A later capability is checked against the core
instead of argued on its own.

Three facts make one early break cheaper than the several that were
scheduled. Stored text is small and mechanical to rewrite, and the compiler
already emits byte-range machine-applicable edits. The agent is the author,
and its cost is round trips: on this grammar a general agent answered 45 of
45 tasks with 8 first attempts refused for a missing `()` (RFC 0047,
Evidence), and published comparisons find a 10 to 45 point zero-shot gap on
novel syntax that five retrieved examples erase, so one spelling per
construct and one example per operation are what reliability costs. And
every construct that would otherwise be built twice, once additively and
once at the later break, is built once.

## 1. Axioms

These are the contract. A later layer never changes one; an RFC that does
names the axiom it changes.

**A1. Totality with declared cost.** Every accepted read terminates, and its
cost is a function of its bound plan and the snapshot it runs against, known
before execution. A recursion is a least fixpoint over a finite domain, and
a value it invents is bounded; nothing else recurses.

**A2. One snapshot.** A read observes one accepted snapshot for its whole
lifetime. Composition never opens a second snapshot, session or request.

**A3. The plan is the truth.** The bound plan describes everything that
runs. The report has one row per operator, nested as the plan nests, and
replay from the plan and the snapshot reproduces the rows. A declared helper
is captured with the plan; a changed helper refuses the replay.

**A4. Closure.** Every operator consumes relations and produces a relation.
Every input position that accepts a base relation accepts a derived one. The
exceptions are a finite named list, each with its reason
([the closure table](#closure)).

**A5. Semantics are typed terms.** Meaning lives in the core term and the
plan. No semantics pass through strings, settings, transport flags or side
tables. Every refusal is a typed code with the fix that makes the text legal.

**A6. One canonical spelling per term.** Two surface forms that desugar to
the same core term are a violation unless the formatter's list
([`queries fmt`](#queries-fmt)) names one of them as the non-canonical form
it rewrites; that list is complete, and a literal and a reference to the
same value (a declared read and its inlined body among them) are the one
standing exception.

**A7. A read has no effects; a write is fed by reads.** A declaration whose
body has no sink never writes, which is what lets it be planned, replayed,
cached and run under read policy without a transaction. A declaration whose
body ends in sinks names the rows it writes through the same clauses a read
uses, evaluates them and its effects on one snapshot (A2), and publishes
once (A4). The kind is the body's shape, known from the parse tree, never a
declared word the parser must check it against: a body opening with
`match { }` is a read when `return` follows and a write when a statement
does. No sink appears inside a read body.

**A8. Quality is declared, never chosen.** An operator that may omit a
correct row declares its bound and reports what it achieved. Exact and
approximate are different operators. The planner never substitutes one for
the other.

## 2. Core

### Values

| Kind | Form | Notes |
|---|---|---|
| Scalar | `I32 I64 F32 F64 Bool String Date DateTime Vector(n) Blob`, enums, `List<scalar>`, each with a nullable variant | *[as today]*; the exact integer carrier stays internal |
| Node reference | `N<T>`, `T` a node type | identity, typed properties, meta-fields; equality is identity |
| Edge reference | `E<e>` | identity, endpoints, properties *[as today]* |
| Relation | `R[c1: t1, …, cn: tn]`, an ordered list of named typed columns over a bag of rows | column types are scalar, node or edge references; a relation-valued column is refused *[choice]*, which keeps the algebra first-order ([Alternatives](#9-alternatives)) |

A row has no identity. Node and edge references do, and that is what
ordering ties, fusion and `distinct` resolve on. Two values are ***not
distinct*** when both are null or both are equal; `Group`, `distinct`,
`Fix` and the derived difference use that relation, so a null is one key
value, while a filter's `=` stays three-valued. Values have one fixed total
order, nulls first then ascending *[as today]*, which ties fall back on.

An ***environment*** Γ maps names to types. A term is typed under Γ; a
***correlated*** term is typed under the enclosing row's columns added to Γ.
Free variables resolve lexically outward. A forward reference or a cycle is
an error.

### Operators

Thirteen operators are the core, over three leaves: `Unit`, the one empty
row; `Env`, one row of the correlated bindings, exposing exactly the free
variables of the term it feeds; and `RecRef`, the recursive relation inside
a `Fix`. Everything else in the language is a derived form with one
desugaring ([Derived forms](#derived-forms)). Each record states signature,
semantics, cardinality bound and cost shape; the cardinality bounds are what
make A1 provable.

| Operator | Signature | Semantics | Cardinality | Cost shape |
|---|---|---|---|---|
| **Scan**(T) | → `R[$x: N<T>]`, or `R[$k: E<e>]` for an edge type | every node of type T, or every edge of type e, in the snapshot | `\|T\|` | linear in `\|T\|`, or index-bounded by a pushed Filter |
| **Expand**(R, $x, sel, m..n, [$k]) | `R` → `R + [$y: N<T′>] (+ [$k: E<e>])` | bounded reachability over an ***edge selector***, a set of (edge type, direction) pairs: for each row, every `$y` reachable from `$x` over any member in `m..n` hops, set semantics over endpoint pairs, shortest distance across all members *[as today]*; the single hop is the case `m = n = 1`, the only one where `$k` binds, then one row per edge | `≤ \|R\| · Σ_{h=m..n} fanout^h` and `≤ \|R\| · \|T′\|`, `fanout` counting distinct neighbours (edges when `$k` binds) | frontier-bounded, index or scan per hop |
| **Filter**(R, φ) | `R` → `R` | rows where φ is true under three-valued logic; null is not true | `≤ \|R\|` | linear; pushdown is a plan choice |
| **Project**(R, [(name, expr)]) | `R` → `R′` | one output row per input row; bag, duplicates kept | `\|R\|` | linear |
| **Group**(R, keys, aggs) | `R` → `R[keys…, aggs…]` | one row per distinct key tuple; null is a key value *[as today]*; with no keys, exactly one row, `count` 0 and the other aggregates null over empty input | `≤ \|R\|`, exactly 1 with no keys | hash, linear plus groups |
| **Correlate**(R, f) | `R`, `f: Env → R′` → `R + R′` | for each outer row, the inner term evaluated with `Env`, the leaf that is that one row, in scope; the output is the outer columns then the inner term's new columns; an inner column that bears an outer column's name is a type error (`T68`); a binding inside an inline read that reuses an outer variable's name is `T68` too, while a block re-mentions an outer variable to correlate on it *[as today]* | `Σ_r \|f(r)\|` | nested or decorrelated, the planner's choice under A3 |
| **Union**(R1, R2) | `R`, `R` → `R` | bag union; column base types must agree by position, a column is nullable when either arm's is, names from the left | `\|R1\| + \|R2\|` | linear |
| **Order**(R, [(expr, dir)]) | `R` → ordered `R` | a total order: the keys, then the identity (type, id) of every reference column in column order, node and edge alike, then every remaining column's value in column order under the fixed value order; rows that still tie are equal in every column and a bag cannot tell them apart. Only `Order`, and `Filter`, `Project` and `Cut` over an ordered input, produce an ordered relation; every other operator's output is unordered | `\|R\|` | `\|R\| log \|R\|`, or `\|R\| log k` under a Cut |
| **Cut**(R, k) | `R` → `R` | the first `k` rows of an ordered `R`; over an unordered `R` it orders by the tie rule alone first *[as today]* | `min(k, \|R\|)` | `k` |
| **Score**(R, $x.f, kind, q) | `R` → `R + [s]` | an exact score per row of the named column's field: `distance` is the field's declared distance (`l2`, `cosine` or `dot`) to `q`, typed `F32` *[as today]*; `bm25` is `bm25_v1` of the field against the field corpus, typed `F64`, keeping only the rows whose field matches `q`; a null field value drops the row *[as today]*; a non-finite input is a typed error; the other columns of `R` ride through unchanged | `≤ \|R\|` | reads every row's field |
| **ApproxTopK**(R, $x.f, q, k, recall) | `R` → `R + [s: F32]` | the `k` nearest distinct targets of the named column under the field's distance, approximate with declared `recall`, reported exhaustive when the engine searched everything (A8); every row of a selected target survives; the overfetch ladder and probe policy are its plan policy *[as today]* | `≤ k` targets, every row of each | index probes, widened by the ladder |
| **Fuse**(R1…Rn, method, params) | scored relations over one node column, the same name and type in every arm → `R[$x, s: F64]` | each arm ranks its distinct targets by its own score in its kind's direction (distance ascending, score descending), then by target id, from 1; `rrf`: `Σ weight_i / (k + rank_i)` over the arms in which `$x` appears; a missing arm contributes nothing, not zero; one row per target, unordered, carrying no other column | `≤ Σ \|Ri\|` targets | linear in the arms |
| **Fix**(f) | `f: R → R` monotone → `R` | the least fixpoint of a declared read over itself, over sets: inclusion on its key columns, `≤` and `≥` on its `min` and `max` columns, rows replaced by better values and added until a round changes nothing; its `return` is `distinct` or `min`/`max`; monotone means, on the term: no `not` over its own rows; a `Group` over them only when it has no aggregate (`distinct`) or is the read's own `return` with `min` and `max` alone; a count block over them only in its `exists` reading; no `Order`, `Cut`, `nearest` or `rrf` over them; and no `Filter`, `Group` key or `Order` key inside the cycle reading a `min` or `max` column; a column it computes rather than reads is admitted only under `min` or `max` with a declared round budget; its type is the fixpoint from its base arms, and a recursion with no base arm is `T70` | rows `≤ \|domain\|` of its key columns; rounds `≤` the budget | semi-naive: each round joins only the rows the last round added |

`limit` without `order` therefore stays legal and deterministic, and a
`Correlate` keeps no outer order: a `Cut` above it orders first. The
reference interpreter found 138 of 12,799 random ordered terms
nondeterministic under the earlier rule (keys, then node identities only)
and none under this one.

Three ***sinks*** close the core on the write side. Each takes a relation
and a target type and produces effects, not a relation, so a sink is
terminal and the read algebra stays thirteen operators.

| Sink | Signature | Semantics | Cardinality | Cost shape |
|---|---|---|---|---|
| **Insert**(R, T, [(prop, expr)]) | `R`, `T` → effects | one keyed insert into `T` per row of `R`, the assignments evaluated under that row; an endpoint assignment is a key literal or a bound reference of the endpoint's type; keyed insert is upsert *[as today]* | `\|R\|` writes | linear in `\|R\|` plus the keyed write |
| **Update**(R, $x, [(prop, expr)]) | `R` with a reference column `$x` → effects | for each row of `R`, the entity `$x` names takes the assignments evaluated under that row | `\|R\|` writes | linear in `\|R\|` plus the keyed write |
| **Delete**(R, $x) | `R` with a reference column `$x` → effects | for each row of `R`, the entity `$x` names is removed | `\|R\|` writes | linear in `\|R\|` plus the keyed write |

A write is a sequence of ***groups***, each a relation term followed by one
or more sinks over it; a group after the first opens with a clause. A group's
clauses are evaluated once (A2), against the state the groups before it left;
its statements run in order, each keyed effect, an upsert or an endpoint
resolution, seeing the statements before it *[as today]*, which is how
edition 2 runs `insert Person {…}  insert WorksAt { from: $h, … }` and a body
of several statements (52 stored bodies reproduce under this rule, none
differ); the whole write publishes once (A4), and whole-write validation,
cardinality minimums, uniqueness and byte limits, runs once at that
publication. The three sinks share one shape: a sink names its rows by a
reference column, and the selection is the group's `Filter`, never a second
predicate on the sink. `insert` with no clauses runs once over `Unit`, which
is today's statement; edition 2's `delete T where φ` is
`Delete(Filter(Scan(T), φ), $x)`, which the rewriter spells as
`$x: T  φ  delete $x`, `Scan` over an edge type included. Two different
values for one entity and property reached through the rows of one statement
are a refusal at run time (`E` namespace), since physical row order would
otherwise decide; across statements the later effect wins *[as today]*. The
target type is the reference's declared type, static, so policy gates it as
it does now; the constructive-or-destructive split stays per write *[as
today]*, so a body mixes no `delete` with an `insert` or `update`; a write
whose groups select nothing publishes no commit *[as today]*; a sink inside a
read term is refused (A7).

**Call**(name, args) is a term former, not an operator: the body of a
declared read, closed, with its scalar arguments evaluated in the caller's
scope and bound to its parameters, inlined at compile time; it is binding,
never textual substitution, so an argument that names a variable the body
also binds cannot be captured. The expanded tree, not the shared graph, must
fit the ***plan budget***, declared as `@budget(plan = n)` on the declaration
and otherwise a compile-time constant, or the compile refuses with the chain
named. A cycle in the call graph is a recursion: it compiles to `Fix` when
every read on the cycle is monotone in the recursive relation and every
recursive call passes the parameters through unchanged, and is refused with
the cycle and the offending construct named otherwise (`T70`); a computed
recursive argument is value invention with no fixpoint. Scalar arguments
only *[choice]*; a relation-valued parameter is a named closure exception
([Alternatives](#9-alternatives)).

***Scalar expressions*** are the operand language of Filter, Project, Group
and Order: literals, parameters, column references, property and meta-field
access on a reference, arithmetic, comparison, `and or not`, `is null`, `in`
over a list, and registry functions, each declared pure and either total or
`can_fail`. A function that can fail keeps its failure where it was written;
the planner may not move it past a guard (A3). The exact distance is `Score`,
not a registry scalar *[choice]*, so it has one spelling (A6). `if(null, a,
b)` is `b`; an `F32` beside an `F64` is `F64`.

Arithmetic is `+ - * / %` and unary `-` over the numeric scalars, each a
pure term that `can_fail`: integer overflow and a zero divisor are typed
errors that keep their place (A3), never a wrapped value, a null or an
infinity *[choice]*, which is what every comparator with fixed-width
integers does; integer division truncates toward zero, as in all of them; a
narrower integer widens to the wider operand and an integer with a float is
`F64`; an integer literal takes the other operand's type when it fits *[as
today]*, so `$p.age + 1` over an `I32` is `I32`; a float literal is `F64`;
`U32` with `I32` is `I64` and `U64` with a signed integer is refused; `%`
over floats is admitted; `Date` arithmetic is refused; an assignment never
narrows; the result is nullable when an operand is; comparison casts stay
explicit `Cast` nodes *[as today]*. Edition 2 has no arithmetic at all, so
this is new text in the break, not a rewrite.

### Derived forms

Each surface form desugars to exactly one core term. This table is the
one-spelling check made concrete; it is also a test
([Evidence](#10-evidence-and-tests)).

| Surface | Core |
|---|---|
| `match { … }` | `Scan`, `Expand`, `Filter`, `Correlate` composed in clause order: binders in written order; a filter placed after the last variable it names, or after the first binder when it names none (over `Unit` with no binder); a block, `let` and `from` seeing only earlier text, so a block correlates on names bound before it *[as today]*; a triple with neither end bound starting from a `Scan` of the edge's declared source type (the smaller-named end for `<e>`), which edition 2 refused (`T5`) |
| a triple whose two ends are both bound | `Expand` to a fresh column, then `Filter` equal to the bound end |
| `return { … }`, `order`, `limit` | `Project(Cut(Order(Extend(R, items), keys), k), items)`: the return items are computed beside every match column, the order keys may read either, the cut takes the first `k`, and the projection comes last; without an aggregate `Extend` is a `Project` that keeps the match columns, with one it is a `Group` followed by a `Project` for any expression over the aggregates |
| `return distinct { … }` | `Group` with no aggregates |
| `count { p }`, `sum`, `avg`, `min`, `max` as a value | `Correlate(R, Group(p, [], [agg]))`, the aggregate column |
| `exists { p }` | `count { p } > 0`; the planner's semi-join is a mechanism |
| `not { p }` | `Filter(¬ exists { p })` |
| `optional { p }` | `Union(Correlate(R, p), Project(Filter(R, ¬ exists p), nulls))` |
| two patterns sharing no variable | `Correlate` with an inner term that has no free variables |
| `$a (e1 \| e2) $b` | one `Expand` whose selector holds every member in its own orientation |
| `$a <e> $b` | one `Expand` whose selector holds both orientations of `e` |
| `$k: E` | `Scan` over the edge type |
| `union(rel, rel, …)` | `Union`, folded from the left |
| `let $v = expr` | `Project` adding one named column, in scope downstream |
| `let $r = rel` | the relation's term, named; no operator |
| `from rel` | `Correlate` |
| `distance(rel, $x.f, $q)`, `bm25(rel, $x.f, q)` | `Score` |
| `nearest(rel, $x.f, $q, k: n)` | `ApproxTopK` |
| `rrf(rel, …, k: n)` | `Fuse` |
| a named read, `name(args)` | `Call` |
| a declared read that calls itself | `Fix` over its body, when monotone |
| a write body, `(clauses  statements)+` | one group per run of clauses and statements: the clauses' term, then one sink per statement over it |
| `delete T where φ`, `update T set { … } where φ` (edition 2, rewritten) | `Delete(Filter(Scan(T), φ), $x)`, `Update(Filter(Scan(T), φ), $x, …)` |

Nothing in the table needs an operator outside the thirteen and the three
sinks.

### Orthogonality

The reference interpreter desugars 5,000 random surface reads to exactly
the term built directly, and found five pairs that share a term; each is on
the formatter's list.

Each operator is necessary: without `Scan` nothing is a leaf, without
`Expand` there is no graph, without `Correlate` no closure and no aggregate
as a value, without `Union` no alternation and no `optional`, without
`Order` and `Cut` no deterministic prefix, without `Score` no exact
qualifying top-k, without `ApproxTopK` no window with a declared quality (A8
forbids substituting it for the exact one), and without `Fuse` no fusion,
since ranks are not scalar expressions. Difference is derived (`not` on
full-row not-distinct equality), so Codd's six are covered. The
[evaluation](assets/2026-10-28-gq-3-grammar-evaluation.md) carries the
argument per operator.

### Closure

A4's table. Every input position, and whether a derived relation is accepted
there.

| Input position | Derived relation accepted | Exception and reason |
|---|---|---|
| `Correlate` inner term | yes | |
| `Union` arms | yes, types must agree | |
| `Group`, `Project`, `Filter`, `Order`, `Cut` input | yes | |
| `Expand` source | yes, when the column is a node reference | a relation with no node column has nothing to traverse from |
| `Score`, `ApproxTopK` population | yes, with the ranked column named in the call | the field is resolved on that column's type; the other columns ride as payload |
| `Fuse` arms | yes, scored, over one node column of the same name and type | |
| `Call` argument | scalars only | relation parameters need higher-order typing; deferred to its own RFC |
| `Fix` body | yes, monotone in the recursive relation | negation or a non-lattice aggregate over it would leave the fixpoint undefined |
| a column of a relation | scalar or reference | nested relations refused; keeps the algebra first-order |
| a sink's input | yes | the target type is static; the rows may come from any relation |
| a sink inside a read | never | A7 |

### Inexpressible by decision

- Non-monotone recursion: a read that negates or counts its own rows; the
  fixpoint would be undefined (A1).
- Unbounded value invention: an arithmetic column inside a recursion without
  `min` or `max` and a round budget; Cozo accepts it and warns that it can
  be expensive, GQ refuses it (A1).
- Paths as values: `Expand` yields endpoints and single-hop edges only
  *[as today]*.
- Relation-valued columns and parameters (first-order; the closure table).
- A write inside a read (A7); a statement reading an earlier statement's
  effect inside one group (A2).
- A scalar exact-distance function beside `Score` (A6).
- A recursive call with a computed argument, which is value invention
  without a fixpoint (A1).
- A list enumerated as rows (GQL `FOR`, Cypher `UNWIND`): `from` binds no
  name and a list element has none; a list is matched with `in`
  ([Alternatives](#9-alternatives)).

### The envelope

Every core term is a finite tree whose `Fix` nodes run to a least fixpoint
over a finite domain: `Call` expansion is budgeted, each operator maps a
finite relation to a finite relation, and every cardinality bound is a
polynomial in the snapshot's sizes whose degree is the nesting depth of
`Correlate`, `Expand` and `Fix`. The language is therefore stratified
Datalog with monotone aggregation, plus ordering, plus two operators with a
declared quality bound, and every read is total with a cost readable from
its plan. Combined complexity is NP-hard in the query's size, as for every
conjunctive query language, which is why the plan budget and the planner
exist. This places GQ at Datalog's reach for recursion over references,
below it where a recursion invents values (bounded, where Datalog engines
warn), and above the relational algebra (ordering, cuts, declared-quality
retrieval); it is where a language whose every query must have a cost before
it runs belongs.

## 3. Surface

Three rules. Every surface form names exactly one core term. A
row-multiplying form and a value-binding form are different words. Where
precedent among SQL, Cypher, GQL, Kusto, XQuery and TypeQL is split, the
most common spelling wins, because it is the one an agent has read most.

### Kept

From edition 2, unchanged: `query name($p: T) { match { } return { } order { }
limit n }`; pattern bindings `$x: Type { prop: val }`; triples `$a e $b` in
either written order, `<e>`, `(a | b)`, `*{m,n}`, `$k:e`; filters; the blocks
`count { }`, `sum`, `avg`, `min`, `max`, `exists { }`, `not { }`; `return
distinct`; aliases `as name`; the statements `show`, `branch`, `commit`,
`load`, `explain`, the settings. From the 2026-11-01 revision of the break:
every function a registry call with named options,
`@name(args)` on any declaration, the six reserved words, `limit $k`,
parameter defaults, `gq 3;`, the catalogue types and their `@`-prefixed
edges, `a::b::C`, and `optional { }` as the one outer-join primitive, now
served. One binding form is added: `$k: E` binds every edge of type `E`, the
`Scan` of an edge type, which is what a write over an edge type selects by.

### Added: two clauses inside `match`

```
let $v = <scalar expression>     // Project: a named value, in scope downstream
let $r = <relation expression>   // a name for a relation; binds and multiplies nothing
from <relation expression>       // Correlate: one outer row per inner row
```

`let` names a value. It computes an expression once per current row and
makes the result available under a name for the rest of the read, in
filters, `return` and `order`. It never adds or removes rows. With a
relation on the right it names the relation so it can be passed to a
ranking function or drawn from twice; that form adds nothing to the current
rows either.

`from` is the one clause that multiplies rows by a relation, as two
patterns that share no variable multiply them by a product. It takes a
relation expression, evaluates it once per current row, and joins its rows
in. The relation's columns enter the enclosing scope under their own names:
a column written `$c` arrives as `$c`, a column written `count($p) as
headcount` arrives as `$headcount`. Every column of a relation drawn from
must therefore be variable-shaped, a bare variable or an alias; a name
already in scope is a type error (`T68`) whose fix is an alias on the inner
`return`, and so is a binding inside an inline read that reuses a name the
enclosing scope holds, since the inner read would otherwise silently become
a filter on the outer row. A block is different: `not { $p: Person { name:
"bob" } }` re-mentions the outer `$p` to correlate on it, as edition 2 reads
it and five stored cases rely on, so a block is never `T68`. A called read's
columns enter the inner scope, so a helper called twice is wrapped once:
`from { match { from colleagues($of) } return { $q.handle as h } }  from
colleagues($h)`. This is the scoping rule of Cypher's and GQL's
`CALL { … RETURN x }` and of SQL's `FROM`. No destructuring, positional or
named, exists *[choice]*: no language agents read binds query columns by
position, and named destructuring would be a second way to rename.

Two words because they do different things to the row count, and every
language that has both keeps them apart: XQuery `let` and `for`, GQL `LET`
and `FOR`, LINQ `let` and `from`, Kusto's scalar and tabular `let`. One word
for both would be the overload `order { nearest(…) }` was. `let` is what every
one of those languages uses for a value. `from` is SQL's and LINQ's word for
"rows come from here" and reads as a sentence; Cypher's `CALL { }` carries
the same scoping rule but reads as a procedure call, which it is not.

### Added: arithmetic

Edition 2's expression language has comparison, `and or not`, `is null`,
`in` and calls, and no arithmetic; a weight, a ratio or a threshold computed
from two columns cannot be written. Edition 3 adds `+ - * / %` and unary
`-` at the precedence every comparator uses (unary minus, then `* / %`,
then `+ -`, then comparison, then `not`, `and`, `or`), with the contract the
core states. A negative number is unary minus over a literal, never a
token. Because clauses and `return` items have no separator, a `-` with
whitespace before it and none after it (`$n -1`, `$x  -$y`) is refused: read
as a subtraction it would silently merge two items or two clauses, and read
as a sign it would depend on the clause before it. The fix follows the gap:
one space prints `$n - 1`, a newline or two spaces print two items.
Numeric literals end at a word boundary, and an exponent needs a fraction
(`1.5e3`, never `1e3`). `CASE`, `COALESCE` and
`||` are not grammar: `if(c, a, b)`, `coalesce(a, …)` and `concat(a, …)`
are scalar registry rows, additive like every row, and the keyword forms
are parse errors whose fix prints the call.

### Relation expressions

The operand of `let $r =` and of `from`:

| Form | Core | Example |
|---|---|---|
| `{ match … return … order? limit? }` | the inline read's term | `from { match { $p worksAt $c } return { $c, count($p) as n } }` |
| `name(args)` | `Call`, inlined | `from colleagues($x.handle)` |
| `$r` | the named relation's term | `from $docs` |
| `distance(rel, $x.f, $q)` | `Score`, vector | every row scored with the field's declared distance, exact |
| `bm25(rel, $x.f, q)` | `Score`, lexical | every matching row scored, exact; `q` a String or a `terms(…)` value ([Search](#4-search)) |
| `nearest(rel, $x.f, $q, k: n, recall: r)` | `ApproxTopK` | at most `n` targets with every row of each; `recall` the declared bound, the engine's policy when omitted *[as today]* |
| `rrf(rel, rel, …, k: n, weights: [w, …])` | `Fuse` | arms are scored relations over one node column; the result has that column and `score` only |
| `union(rel, rel, …)` | `Union` | a bag; arms agree by column base type in order, nullable when any arm is, names from the first |

A ranking function names the column it ranks as a property access on the
population, `$d.embedding`, resolved at compile time, never a string; the
population may carry other node, edge and scalar columns, which ride through
as that target's payload (law 4), so a population that returns a whole
pattern needs no narrowing. It adds `distance` (vector) or `score` (lexical,
fused). `rrf` yields the target column and `score` alone; a read that needs
the population's other columns after fusion draws them again with a `from`
over the population correlated on the target. Two arms drawn into one scope
collide on both names; the fix is the one renaming mechanism, a wrapper read
whose `return` aliases.

Three names where edition 2 had one: `distance` is the exact score of every
row under the field's declared distance, `nearest` is the approximate window
under the same distance, `bm25` is the exact lexical score. Each is one core
term, which A6 requires, and each is named by what it selects; `distance`
rather than `l2` because a cosine field's exact form is cosine. The window
form and the exact form answer different questions, and the text shows which
was asked ([The syntax by example](#8-the-syntax-by-example)).

### Scope and correlation

A relation expression may read any variable in scope at the point it is
written; that is what makes `from` correlated. It may not read a variable
bound after it, and an inline read may not rebind one (`T68`); a `let`
relation is a
named term under the `Call` rule, within the plan budget and never
recursive, since only a declared read may call itself (`T70`). A `from`
whose relation reads no outer variable is a plain join; the planner decides
between nested and decorrelated evaluation and the report says which ran
(A3). An inner `order` and `limit` belong to the inner read: an outer
predicate never widens an inner cut, and an outer `limit` never becomes the
inner's ([core, Cut](#operators)). Clause order inside `match` is part of
the meaning for `let`, `from` and the blocks, and for nothing else: binders
run in written order, a filter waits for every variable it names, and a
block, `let` and `from` see only the text before them *[as today for
blocks]*, so `$d: Doc  from { … $d … }` correlates and the swapped order
does not; the formatter keeps the relative order of those clauses among the
others and moves a filter to just after the binder of the last variable it
names.

### Recursion

A declared read may call itself, directly or through other declared reads,
passing its parameters through unchanged, and the cycle compiles to `Fix`.
The rules are Datalog's with monotone aggregation, as the core states them
on the term: the read's `return` is `distinct` or carries `min` or `max`;
nothing on the cycle negates, orders, cuts or ranks the recursive rows, a
count block over them is admitted only in its `exists` reading, and nothing
on it filters, groups or orders by a `min` or `max` column; the read's type
is the fixpoint from its base arms, and a recursion with no base arm is
`T70`. Its columns are node or edge references or
values read from stored properties, and a column it computes is admitted
only under `min` or `max` with `@budget(rounds = n)` declared, whose overrun
is a typed error; `min` with a non-negative step converges on its own, `max`
on a cycle does not, and the budget is what makes the second safe. No new
syntax: the recursion is `from name(args)` inside the body of `name`, and a
`union` joins the base case to the step.

```gq
query reachable($from: String) {
  match {
    from union(
      { match { $p: Person { handle: $from }  $p knows $q } return { $q } },
      { match { from reachable($from)  $q knows $r } return { $r as q } })
  }
  return distinct { $q }
}

query distance($from: String) @budget(rounds = 50) {
  match {
    from union(
      { match { $p: Person { handle: $from }  $p knows $q } return { $q, 1 as d } },
      { match { from distance($from)  $q knows $r } return { $r as q, $d + 1 as d } })
  }
  return { $q, min($d) as d }
}
```

`Expand{m,n}` stays the shortest-distance form for a bounded depth;
`reachable` is the unbounded case, and `distance` the one that invents a
value. They differ at the start node: `reachable` returns it when a cycle
leads back, and `Expand` never does. The report shows the rounds and the
frontier per round as it shows an `Expand`'s frontier. In release B the type
checker accepts a monotone cycle and types it to `Fix`, so every `T70` rule
is tested at B, and the planner refuses the node naming stage Rec
([Programme](#11-programme-and-rollout)). The reference interpreter agrees with
itself under naive and semi-naive evaluation on every one of 2,801 random
recursions these rules admit, and disagreed on 74 of 817 that the earlier
rule (`min` and `max` only) admitted.

### Writes fed by reads

A write is a `query` whose body is one or more groups, each zero or more
clauses written bare, not inside `match { }`, followed by one or more
statements; the parser knows the kind from the body's shape, so no second
keyword declares it. `as commit` and `as unattached branch` are admitted on
a write body and refused on a read body. The clauses are exactly a read's:
bindings, triples, filters, the blocks, `optional`, `let`, `from`, and the
edge binding `$k: E`. The statements name what they write by reference:
`delete $x` and `update $x set { … }` take a bound node or edge variable, and
`insert T { … }` takes a type and assignments, an endpoint assignment being a
key literal or a bound reference, and `null` the one way to clear a
property. There is no `where` on a statement: the clauses are the selection,
and a second predicate on the sink would be a second spelling of a filter
(A6). Each statement runs once per row of its group's relation; its
assignment expressions read the bound variables as `$x.prop`. A statement
binds nothing. A group's clauses are evaluated once; its statements run in
order, each keyed effect seeing the ones before it *[as today]*, so `hire`'s
edge insert finds the person inserted beside it and a body that inserts a
document and then updates it by key still works; a later group sees the
groups before it; the write publishes once (A4). A body mixes no `delete`
with an `insert` or `update` *[as today]*. An `insert` with no clauses is edition 2's text and
means what it meant; edition 2's `delete T where φ` and `update T set { … }
where φ` are rewritten to `$x: T  φ′  delete $x` and `$x: T  φ′  update $x
set { … }`, the same `Filter` over the same `Scan`, one group per edition-2
statement.

```gq
query close_company($slug: String) {
  $c: Company { slug: $slug }
  $p $k:worksAt $c
  delete $k
}

query relocate_staff($slug: String) {
  $c: Company { slug: $slug }
  $p worksAt $c
  update $p set { city: null }
}
```

Edition 2 writes `close_company` as `delete WorksAt where @dst = $slug`,
since the company is the edge's own endpoint; the read-fed form is new where
the selection needs a neighbour's property or a second hop, and there it
replaces the two-step an agent writes today, a read for the ids and a write
with `in [ids]`, whose two snapshots can disagree. The written set
is known only by running the clauses, which is what `returning` and the
dry run are for; both are the writes RFC's, and until it lands the
write's `explain` shows the clauses' plan and its estimates.

Each is a typed error with the fix printed.

| Written | Code | Fix |

### Precedent

XQuery, GQL, Cypher, TypeQL 3, Kusto, LINQ and SQL each keep a value binder
and a row enumerator apart, and none binds query columns by position; the
surface follows both. Construct by construct, the read skeleton and the two
clauses are GQL's (`LET`, `CALL (x) { }`, `OPTIONAL`, `EXISTS`,
`RETURN DISTINCT`, `LIMIT $k`, `$p`) with SQL's word `from`; the traversal is
Datalog's, positional and schema-resolved with no arrow; the expression
language was the smallest of the five compared, which is why this RFC adds
arithmetic and names the conditional rows. The
[comparison](assets/2026-11-07-gq-3-grammar-comparison.md) holds every row.

## 4. Search

Retrieval is three relation functions and a fusion, and this section fixes
what they mean independently of any index. The rule is one sentence: meaning
comes from the accepted schema and the plan, never from index presence,
coverage or segment layout (invariant 7). An exact evaluation path is the
oracle at every coverage state; a native index accelerates only where it
proves the same answer.

### Schema

**Text.** A String property becomes searchable by declaring its full-text
index with an analyzer:

```pg
node Doc {
  slug: String @key                                            // exact only
  title: String @index(fulltext, analyzer = "english_v1")      // matching and ranking
  body: String @index(fulltext, analyzer = "standard_v1", scorer = "bm25_v1")
}
```

`analyzer` names one of three immutable profiles; `scorer` is `bm25_v1`
(the default) or `none`, which allows matching and makes a ranking call on
the field a type error. Every setting of a profile is explicit; unspecified
Lance defaults are never part of the contract.

| Setting | `standard_v1` | `standard_folded_v1` | `english_v1` |
|---|---|---|---|
| Tokenizer | `simple` | `simple` | `simple` |
| Lowercase | yes | yes | yes |
| Stemming and stop words | neither | neither | English stemmer, then English stop words |
| ASCII folding | no | yes | yes, after stemming |
| Token-length filter | disabled | disabled | disabled |
| Unicode normalization | NFC before tokenization | same | same |

A profile never changes once accepted; a different pipeline is a new
profile, and a new profile or scorer version needs an RFC. There are no
query-time analyzer overrides. A String `@index(fulltext)` written without
`analyzer` keeps edition 2's index analysis, Lance's default (English
stemming, stop words, ASCII folding, a 40-byte token filter), so no existing
graph changes rows at the break; lint `L` names the profile to declare,
`english_v1` being the closest, and the contract below applies to declared
analyzers. Declaring one is a schema change applied in place: the field's
index is rebuilt once with the profile, and RFC 0043's certificate records
the field's analyzer fingerprint, so a certificate for the old analysis does
not establish the new one. Accepted SchemaIR owns the fingerprint (profile,
normalizer and Unicode data identity, tokenizer and filter order, scorer
version) as a feature name under RFC 0040; a rename keeps it, drop and
re-add makes a new one.

**Vectors.** `Vector(n, distance = "l2" | "cosine" | "dot")`; an omitted
distance is `l2`, today's meaning, so no accepted schema changes meaning.
`distance(…)` and `nearest(…)` both read the field's declared distance.
The resolved distance is persisted; the index is built with it, and an index
built for another distance is never used, so a changed distance serves from
the exact scan until the index is rebuilt.

| Distance | Value, ascending |
|---|---|
| `l2` | sum of squared component differences, no square root |
| `cosine` | `1 - dot(x, q) / (norm(x) · norm(q))` |
| `dot` | `1 - dot(x, q)`; can be negative |

**Recipes.** `@embed("source", model = "…")` binds a vector to the String it
embeds. An embedding space is the immutable model revision plus the query
and record encoding choices (roles or prompts, pooling, normalization,
dimensions); a model label, a provider name or a matching dimension is not
proof of a shared space. A schema may declare one default recipe;
`@embed("source")` without a model inherits it when the field first gains a
binding, changing the default never rebinds an existing field, and canonical
export spells out every field's resolved recipe. A String query argument
uses the field's query encoder; a raw vector argument is the caller's
assertion that it is in the field's space, refused when the dimension is
wrong. Three identities stay separate, each a typed versioned descriptor
whose hash is a derived view: the encoding recipe (the space), the field
representation (owner, property, source, resolved analyzer or recipe,
distance) and the query encoding (the recipe and the exact input, belonging
to one execution). A field whose distance changes needs its index rebuilt;
one whose recipe changes needs its vectors regenerated; no export and
reload.

### The lexical query

`terms(text, mode: all | any, max_edits: 0..=2)` describes matching
independently of its consumer: `text` is a non-null String literal or
parameter; `mode` is `all` (every analyzed query term has a matching document
term, the default) or `any`; `max_edits` is a literal or parameter in
`0..=2`, default `0`. Two consumers:

- **`match_terms(field, terms(…))`**, a predicate registry row: a top-level
  conjunct of a `match` (`T38` *[as today]*), legal inside `not`, `exists`
  and the count blocks. It introduces no score.
- **`bm25(rel, $x.f, q)`**, the lexical `Score`: `q` is a `terms(…)` value
  or a String, which means `terms(q, mode: any)`, today's any-term zero-edit
  matching (Lance's `Operator::Or`); the String is the canonical spelling
  of that case, and the formatter writes it. The ranking and the predicate
  agree on membership for the same `terms` value before any cut.

| Aspect | Rule |
|---|---|
| Analysis | the field's analyzer on document and query text, at every edit budget including zero |
| Distance | insertions, deletions and substitutions over analyzed Unicode scalar values, one each; a transposition costs two; no prefix restriction, no length-based tolerance |
| Term identity | repeated query terms need no repeated occurrences; reordering cannot change membership; neither phrase matching nor distance over the whole value |
| Empty text | a query with no searchable terms is a type error; a null or token-empty document does not match |
| Completeness | every result satisfies the predicate exactly; an edit-tolerant predicate advertises no approximate recall |

```text
matches(edits = 0) ⊆ matches(edits = 1) ⊆ matches(edits = 2)
matches(indexed) = matches(unindexed) = matches(partially indexed)
```

**`bm25_v1`** is one versioned scorer for exact and tolerant queries.
Membership is the `terms` relation, evaluated before any cut; a score is
never a second membership test. The statistics population is the
snapshot-visible field corpus: distinct policy-visible entities owning the
property with non-empty analyzed values, before any graph or property
filter, so narrowing a population leaves a surviving entity's score
unchanged and scoring composes with graph filters (the guard
`fts_statistics_scope_can_reverse_ranking` shows the alternative reverses an
order). With `N` the corpus size, `df_q` the documents holding an
alternative of query term `q`, `len_d` and `avg_len` the document and mean
token counts, and `tf(t, d)` a term's occurrences:

```text
idf(q)      = log1p((N - df_q + 0.5) / (df_q + 0.5))
norm(d)     = 1.2 · (0.25 + 0.75 · len_d / avg_len)
weight(t,d) = 2.2 · tf(t,d) / (tf(t,d) + norm(d))
part(q,d)   = idf(q) · max over stored terms t within the budget of 2^(-edit(q,t)) · weight(t,d)
score(d)    = Σ over distinct query terms q of part(q,d)
```

Alternatives share their group's IDF, so a rare misspelling cannot gain
weight, and the maximum inside a document stops several spellings summing as
independent evidence; the edit weights `1`, `1/2` and `1/4` are versioned
choices. The numeric profile is `F64` with `libm`'s `log1p`, checked `u64`
counting, no reassociation, summation in ascending UTF-8 query-term order; a
match yields a finite positive score or a typed numeric failure. Native
Lance BM25 is this formula in `f32` at zero edits, membership included, and
something else with edits: each expansion gets its own IDF, alternatives
add, and there is no edit penalty, so seven of the ten edit-tolerant oracle
fixtures rank differently natively, by up to 24.5 times
([Evidence](#10-evidence-and-tests)). Only the zero-edit shape can therefore
ever be certified on a native path.

**Exact execution and qualified acceleration.** The analyzer is
instantiated from accepted SchemaIR whether or not an index exists; an index
is never its carrier. Engine v2's scan evaluates the typed predicate over
streamed document tokens with that analyzer and the edit relation, bounding
query bytes, distinct terms, value sizes and work before allocation (NFC can
expand UTF-8). This path is the oracle at every coverage state, and it is
what lets a declared but unbuilt index answer instead of refusing (RFC
0047's `FullTextIndexRequired`). A native path is eligible only when its
artifact passes RFC 0043's proof for the accepted profile and its whole
pipeline is qualified for the mode and edit budget. Lance 13's fuzzy
expansion keeps the fifty lexicographically smallest expansions per term and
does not protect the exact term, so a one-edit query can miss the document
that holds the term exactly: the native path breaks `matches(0) ⊆
matches(1)`, not only completeness, and edit-tolerant shapes use the exact
scan even with an index until an expansion budget covering the automaton's
limit is qualified. A native index also carries no NFC step and, with the
experimental 256-document posting blocks, quantizes document lengths, so
the RFC 0043 fingerprint that qualifies one records the posting block size
and format version, a 256-block index never qualifies, and how a declared
profile's NFC reaches the index, a derived normalized column or
normalization at write, is for stage L to decide
([Unresolved](#unresolved-questions)). RFC 0047's validator checks the plans
as invariants, search identity, retained predicate, scoring corpus, score
origin, required ordering, cut placement, prerequisites and the declared
contract, and each shape joins its exact subset only through a versioned
rule addition with its own regression.

A `Cut` over an `Order` over a zero-edit `bm25` may use Lance's limited
full-text path, block-max WAND, as a ***certified candidate generator***
when nothing above the scan drops rows, every filter is a prefilter under
full coverage, no fragment of the table carries a deletion file, no
row-level read policy narrows the property's entities, and the property's
entities live in one table, since native statistics are the index's and not
the field corpus otherwise. The fetch asks for `k + m` candidates, rescored
in `F64` by `bm25_v1`, and is accepted when the k-th rescored score exceeds
the last fetched native score times `1 + ε`, `ε` a stated bound on Lance's
`f32` error for the query's term count; a tie fails the margin, and the
exact scan is the fallback. Lance's limited and unlimited paths return
bit-identical scores and the exact top-k score set, but its `f32` order can
tie or invert two documents whose `F64` scores differ by less than an ulp,
which is why bit-identity with Lance is not exactness and the margin is
needed. The fetch prunes scoring work by an amount that depends on `k`
against the matched set and is not reproducible run to run, so the plan
states its cost as the unlimited scan's and the report keeps Lance's
comparison counter out of anything replay compares.

**Migration.** `search`, `match_text` and `fuzzy` stay registry rows for
good; `queries fmt` canonicalises them to
`match_terms(f, terms(q, mode: any[, max_edits: n]))`, the mapping that keeps
today's any-term membership (`fuzzy(f, q)` with no budget is two edits, as
today), and lint names the rewrite. An edit budget outside `0..=2` becomes a
type error. On a field whose index declares no analyzer the three keep
today's behaviour.

### Vector retrieval

| Call | Core | Result | Cost | `recall` descriptor |
|---|---|---|---|---|
| `distance(rel, $x.f, $q)` | `Score` | every row of the population with its exact distance under the field's declared distance | a scan of the population's field | `exact` |
| `nearest(rel, $x.f, $q, k: n, recall: r)` | `ApproxTopK` | at most `n` targets with every row of each; the index may miss some, a boundary tie included | index probes widened by the ladder, plus the uncovered tail | `approximate`, with the declared `r` |

A returned distance is always the exact distance under the field's
distance; approximation affects only which targets are found. Today's index
family, IVF_FLAT, keeps raw vectors and meets this; a quantized family must
refine its candidates. Missing coverage never drops the uncovered rows; it
changes cost. `recall` is the one place a read declares the bound it
accepts; physical effort (`ann_nprobes`, the overfetch ladder) stays a
session setting the plan records, because the query states meaning and not
effort. The exact top `n` is `distance` with `order { $distance }` and
`limit n`, the tie rule taking the boundary to the smaller id, so its
membership is the same on every run. `nearest` is the canonical answer to an
unqualified request for the `k` most similar; `distance` is for an exact
answer or a radius, and it scans the population, which the skill says in
those words, since an agent given both chose the scan three times of three.

### Fusion

`rrf(arm, arm, …, k: 60, weights: [w, …])` takes 2 to 16 arms, each a
scored relation over one node column of the same name and type in every
arm. An arm produced by a ranking function is ranked by its own column in
its kind's direction, distance ascending and score descending; any other arm
must be an inline read with an `order`. Each arm ranks the distinct targets
it selected, then by target id, from 1, so two targets tied in every arm
still get distinct fused scores *[choice]*:

```text
rrf(target) = Σ over arms that selected target of weight[arm] / (k + rank[arm, target])
```

The sum runs in written order in `F64`; `k` is in `1..=1000000` and each
weight in `(0, 1000000]`, default `1.0`, so the sum cannot overflow; a
target no arm selected is absent, and a missing arm contributes nothing
rather than zero. Two arms with the same population, field and query are a
type error, since `weights` expresses emphasis; arms over different node
columns are a type error, since the fused target would be a pair. Fan-out
rows of one target carry its score and add no vote; the result is one row
per target with the target column and `score`. An arm's own score is a
column of that arm's relation: a wrapper read renames it, and
`optional { from … }` keeps the targets the other arm missed, so an arm
metric is null exactly where the arm did not select the target.

### Populations and laws

Four populations stay distinct, and every implementation keeps passing
their counterexamples: three eligible incidents and a window of two count
three before the window and two after; after fan-out three rows can hold two
incidents and `count($i)` counts rows; a global window can leave a group
empty and nothing refills it; changing eligibility leaves `bm25`'s corpus
statistics unchanged.

| Population | Meaning |
|---|---|
| Eligible | the distinct targets of the relation a ranking function takes, with their rows |
| Scoring corpus | the data behind a scorer's statistics, the field corpus for `bm25` |
| Selected | the targets that survive a window or cut |
| Aggregate input | the rows an aggregate reduces |

The laws, each one sentence because the core already holds most of them:

1. Eligibility before selection: the population relation decides who is
   eligible; a ranking selects and orders within it; projection changes
   neither.
2. Cuts are semantic: no predicate, traversal or aggregate crosses a `Cut`
   without a proof the answer is the same; policy is never a filter after
   a cut.
3. Windows are separate: `k`, physical effort and the final `limit` are
   three values, and an outer `limit` never sizes an inner window; `k` is
   required, so no default can couple them.
4. Target identity: a ranking ranks the distinct targets of one node column;
   fan-out carries the score and adds no vote.
5. Index state never changes an exact answer: `distance`, `bm25` and `match_terms`
   return the same rows under every index state in which they answer; an
   approximate `nearest` may miss targets but never drops the uncovered
   rows as a whole.
6. Every cut is total, over one total order.
7. Partitions never redefine the population: fragments, segments and shards
   are physical; a per-partition cut needs an exact merge or a declared
   approximate contract.
8. Meaning is resolved and versioned: analyzer, scorer, distance, recipe and
   fusion formula come from the accepted schema and the plan.
9. One snapshot for every arm, traversal, statistic and read (A2).
10. Separate facts: completion, representation coverage, approximation and
    relevance are reported apart; none is a probability the answer is
    right.
11. One resource protocol: rankings, fusion and exact scans charge the
    query's memory; exhaustion is a typed failure.

### Errors

Type errors: an unknown option, listing the admitted names; an option out of
range; `weights` whose length differs from the arm count; duplicate arms;
arms over different node columns; fewer than two or more than sixteen arms;
a ranking call on a `scorer = "none"` field; a token-empty query; an edit
budget outside `0..=2`; a raw vector of the wrong dimension; a ranked column
that is not a node column of the population, or whose property is not
declared for its type (`T27` *[as today]*);
`nearest` without `k` (`T17` *[as today]*). Execution errors: exhausted
memory or an exceeded work bound, typed, never an empty or truncated result.
A target missing from one arm is not an error.

## 5. Types and diagnostics

Every refusal keeps the four-field diagnostic. Codes are allocated at
implementation under the catalogue rule in
`crates/omnigraph-compiler/src/query/codes.rs`; the names below are the ones
this RFC uses for them.

- A `let` scalar has the expression's type and nullability. A `let`
  relation has the relation's column list. A relation in scalar position is
  `T69`; a scalar in relation position (`from $v` where `$v` is a scalar) is
  the same code with the other fix.
- `from` adds the relation's columns to Γ by name; a collision is `T68`, and
  so is a binding inside an inline read that reuses a name in Γ; a block's
  re-mention of an outer name is correlation, never `T68`. A column that is
  neither a variable nor aliased cannot be drawn from (`T74`), and the type
  checker names the column and the alias to add.
- `Call` resolves against the declarations of the same source unit *[choice]*,
  case-sensitively, exactly one; the registry is not searched for a declared
  read's name, and a declared read may not shadow a registry name. A budget
  overrun, a cycle that is not monotone, or a cycle with no base arm, is
  `T70` with the chain and the offending construct; a monotone cycle types to
  `Fix`, its type the fixpoint from the base arms; `let $r = rel` names a
  term under the same budget, at local scope, and may not recurse.
- `distance`, `bm25`, `nearest`, `rrf` and `union` are registry rows of
  kind `relation`; a ranking's second argument is a property access on a
  node column of its population, `Vector(n)` for `distance` and `nearest`
  and indexed full-text for `bm25` (`T27` *[as today]*), the error naming
  the column when it is not one; `nearest` requires `k` (`T17` *[as
  today]*) and takes `recall` in `(0, 1]`, the one place a read declares it:
  a per-query annotation would be a second spelling, and two windows in one
  read can want two bounds. A registry row is never named a clause keyword
  (`let`, `from`, `optional`, `exists`, `not`), for the reason a declared
  read never shadows a registry name.
- A block aggregate in operand position has the aggregate's type; `T40` no
  longer restricts its comparison partner.
- Arithmetic types as the core states: operands of one numeric width keep
  it, a narrower integer widens to the wider, an integer with a float is
  `F64`, a non-numeric operand is a type error naming it, and the result is
  nullable when either operand is. Overflow, a zero divisor and a non-finite
  float result are typed execution errors on the row, never a null or a
  wrapped value; the term carries `can_fail` so the planner keeps it behind
  its guards.
- `if(c, a, b)`, `coalesce(a, …)` and `concat(a, …)` are scalar registry
  rows added with the registry; `union` is a relation row whose arms must
  agree by column type in order, the mismatch naming the arm and column.
- In a write body, `delete` and `update` take a bound node or edge variable
  and `insert` a type; an endpoint assignment is a key literal of the
  endpoint's key type or a bound reference of the endpoint's type, the
  mismatch naming both; a `where` on a statement is a parse error whose fix
  prints the binding and filter, the bare names of the predicate and of the
  assignments qualified and the binding's name chosen outside the scope; a
  body opening with `match {` is a parse error whose fix removes the

  error, since the kind is in the parse tree; the registry, the `@View` row,
  MCP write gating and policy scope read the kind there; a body mixing
  `delete` with `insert` or `update` is `T76`; two different values for one
  entity and property from the rows of one statement are a run-time refusal
  (`E` namespace), and across statements the later wins.
- The search refusals of [section 4](#4-search): an unknown option listing
  the admitted names, an option out of range, duplicate arms, arms over
  different node columns, an arm count outside 2 to 16, a `weights` length
  that differs from it, a ranking on a `scorer = "none"` field, a
  token-empty query, an edit budget outside `0..=2`, a raw vector of the
  wrong dimension.
- `T65` for a ranking written as a call in `order` or `return`, with the
  `from` fix; `T5`, `T22`, `T33`'s projection-under-`rrf` rule and the rest
  of today's codes keep their texts, re-anchored to registry rows. Infix
  `contains` is refused at type check, not parse, because the left operand's
  type decides between the `contains(…)` and the `in` fix; the same holds
  for the bare `in` edge, whose quoted fix `T7` prints.
- Every fix is a `suggestion` of byte-range edits, the human text derived
  from it, so that an agent or the tool applies it mechanically; a test
  applies the suggestion of every refusal code and compares the reparsed
  tree with a pinned one. A refusal of a form a later stage adds names the
  stage. A parse error names the construct, never a grammar rule, and a
  short table recognizes the habits agents bring from other languages
  (single-quoted strings, `<>`, `==`, `&&`, `!`, uppercase keywords,
  `count(*)`, `-[:e]->`, `(a:T)`, `return x` without braces, `offset`,
  `group by`, `having`, `where`, `with`, `call`, `detach`) and prints the
  GQ form; the table is a lexical pass whose edits compose with the grammar
  recognizers into one suggestion; a bare identifier is not a value in a
  `match` or `return`, so a foreign word is a parse error at the word rather
  than a filter the type checker refuses later; the one bare-name position
  besides an `order` alias is the predicate of the `where` recognizer, so
  that edition 2's `delete Person where handle = $h` still prints its fix. A
  malformed edition line is refused with `gq 3;` as the fix. A parse error
  prints a suggestion wherever one exists; the refusals with none are
  listed in section 3 and name the construct. On the red-team corpus of 395
  agent-written texts (`spike/gq3-grammar2`), 151 of 178 refusals carry a
  suggestion that reparses to the intended text and 6 texts still parse
  differently from the RFC's reading.
- The codes this RFC allocates beside `T65`, `T68`, `T69` and `T70`: `T71`
  an option unknown, out of range or positional; `T72` a non-numeric or
  unsupported arithmetic operand; `T73` `union` arms that disagree; `T74` a
  name refused as a relation; `T75` an `rrf` arm fault; `T76` a write
  mixing kinds; `T77` a statement over a variable that is not a reference;
  `T78` an endpoint assignment of the wrong type; `T79` a ranked column that
  is not a node column; `T80` an annotation that is not read; `P006` a core
  node the planner does not lower; and the `E` namespace for run-time
  refusals: integer overflow, a zero divisor, a non-finite float, a round
  budget overrun, a write conflict found through rows. `T27` stays the
  full-text code and `T15` the vector one. A String key literal for an
  integer key in an edge endpoint is accepted *[as today]*.
- The lint prefix `L` is added for the formatter's rewrites (`count { } > 0`
  to `exists`, a directed triple written against schema order to schema
  order, an equality between a bound variable's property and a value written
  as a filter into that binding's braces, a `search` or `match_text` or
  `fuzzy` call to `match_terms` once that lands) and for two rows-equal
  rewrites the formatter does not apply because they change the typed IR,
  `count { } >= 1` to `exists` and `count { } = 0` to `not`, and for a
  `limit` no larger than a preceding `nearest(…, k:)`.
- An unknown annotation is refused, with the exception of an allow-list of
  pure metadata the compiler never reads (`@description`, `@instruction`,
  `@example`, `@rename_from`), which is retained as `.pg` retains it today.
  Retaining every unknown name would make a later typed annotation
  non-additive: a `@budget` accepted and ignored in this release would start
  refusing reads when its stage types it. The rule for a later form is
  therefore: it starts at a token edition 3 refuses, or at a name the type
  checker refuses today with a pinned test (`@type_id` under `T6`, an open
  traversal bound under `T15`, a schema catalogue name, an unknown
  annotation); a form edition 3 accepts and ignores is not additive and is
  not admitted.

The catalogue exposes the same contracts: `@Function` rows carry kind,
parameters, options, result columns for relation functions, `can_fail` and
`volatile`; a declared read is a `@View`-shaped row with its parameters and
result columns, which is the one place the word survives.

## 6. The break

### The edition line

A file may open with `gq 3;` before its settings lines. A file without the
line is read in the compiler's current edition, which this release makes 3.
`gq 2;` selects the edition-2 grammar for one release; any other edition is
refused at parse. The stored-query registry records the edition each source
was validated under, and `queries validate`, `cluster plan` and `lint` report
an edition-2 source with the rewrite that moves it.

### What a reader sees changed

```gq
// edition 2
query passages($matter: String, $q: String) {
  match {
    $r: SourceRevision { matter_number: $matter }
    $r hasPassage $p
    $p.text contains "tariff"
  }
  return { $r.path, $p.locator, bm25($p.text, $q) as score }
  order { bm25($p.text, $q) desc }
  limit 5
}
```

```gq
gq 3;
query passages($matter: String, $q: String, $k: I64 = 5) {
  match {
    from bm25(
      { match { $r: SourceRevision { matter_number: $matter }  $r hasPassage $p  contains($p.text, "tariff") }
        return { $r, $p } },
      $p.text, $q)
  }
  return { $r.path, $p.locator, $score }
  order { $score desc }
  limit $k
}
```

The ranked read is longer: the population is written out as a relation and
the score arrives as a column. That is the cost of one shape for every
retrieval, and the rewriter pays it, not the author of stored text.

### The rewriter

`omnigraph queries migrate` takes `.gq` and `.pg` files or a `--target`,

New text written by hand ranks the population, which is the canonical form |

The population the rewriter writes returns every variable the pattern binds,
and the ranking names its column, so every downstream reference still
resolves; after `rrf` the tool draws the population's other columns again
with a correlated `from`. A result column an edition-2 query produced keeps
its name and type through the alias the tool adds, with the one rename the
fixed map lists. The tool takes the schema as a required input, since a
`contains` over a list and over a String are different rows, and it has a
fragment mode for a fenced block that is not a whole declaration. A human
may simplify afterwards; the rewriter never has to. On the repository's
3,231 stored declarations (the spike of 2026-11-08) 600 are rewritten,
2,581 need no edit, and 50 carry a refusal: 17 fusions with duplicate arms
or arms over two bindings, which edition 3 refuses by type and which are
edited by hand, 2 `asc` rank keys, 3 rankings illegal in both editions, and
28 multi-statement bodies that the group rule rewrites.

The proof compares typed IR. It holds for the four expression rows and for
the two write-statement rows, which lower to the `Filter` over the `Scan`
the edition-2 `where` lowered to, with the sink above it; the spike proved
the selection equal on the engine for 114 corpus statements and the group
rule equal on 52 multi-statement bodies. For the ranking rows it holds after
a stated ***normalisation*** of seven rules: N1, the read's only `match`
clause is the `from` of a ranking; N2, the population is the whole `match`,
returning exactly the variables the pattern binds, with no `distinct`,
`order` or `limit`; N3, a `nearest` window has `k = limit`, and an arm under
`rrf` has `k = limit` or `k = 100` with no `limit`; N4, the score column is
the leading order key, or absent under an aggregate; N5, a bare rank key
sorts descending; N6, a `let` population is inlined; N7, `k: 60` on `rrf` is
the default. Under them the window over a population lowers to the ranked
scan the edition-2 `order` lowered to, the pattern's filters as the scan's
prefilter *[as today]*, so `search_node` finds what it finds today: 107 of
111 `nearest`, 35 of 39 `bm25` and 27 of 28 `rrf` rewrites are IR-equal,
every remaining one a refusal both editions make or the one rename the
fixed map carries. Rows are checked on the engine too: 79 of 79 `nearest`
and 29 of 29 `bm25` steps equal, and `rrf` 21 of 21 in the type-population
form above (18 of 21 in the population form, which is why the tool emits
the former). The 2026-11-01 numbers (1,818 declarations IR-equal, 2,968
generated reads) were measured on the `retrieve` rows and are superseded.

### The edition window at boot

The edition-3 release boots an edition-2 stored source by rewriting it in
memory and logging the edits, once per source per boot, until an operator
runs `queries migrate` on the bundle; a source the proof refuses quarantines
its graph with the construct named. `cluster plan` prints the same edits.
The release after compiles edition 3 only. The bundled skill, the user guide
and the GQT corpus are edition 3 in the release that ships it.

### `queries fmt`

The formatter canonicalises what the grammar cannot forbid and never
changes the typed IR. Its list is the complete set of non-canonical forms
A6 admits: `count { P } > 0` to `exists { P }`; the filter `not exists { P }`
to `not { P }`; a directed triple to schema order where an end is typed;
`$p: Person  $p.handle = $h` to `$p: Person { handle: $h }`, since the braces
and the filter are one `Filter` and the braces are its canonical instance; a
filter to just after the binder of the last variable it names; a nested
`union` to the flat one; the ends of `<e>` and the members of an alternation
to a stable order; `asc` dropped; an alias equal to its column's name
dropped; a call's options in the registry's order with those equal to their
default dropped; a top-level `and` split into clauses; `bm25` over
`terms(q, mode: any)` to the String; commas between `return` items; an
edition-2 order key beginning with `nearest(` parenthesised, since the
edition-2 grammar shadows it; and, once the lexical RFC lands `match_terms`,
the three older lexical calls to it. Thirteen of these are exact collisions
in the typed IR and the type checker spike pins them as the only ones. Two
rewrites that are rows-equal but change the IR, `count { P } >= 1` to
`exists` and `count { P } = 0` to `not`, are lint's and not the formatter's.
A `from` over a wrapper read whose only purpose is a rename is left alone;
the formatter does not invent a shorter form the grammar does not have.

## 7. The grammar

One grammar for schema and queries, today's `query_file` extended, as
revised on 2026-11-01. The read body and clauses:

The edition-3 rules live in the one grammar file beside edition 2's, each
suffixed `3` where a name would collide, and the rule-set pin of section 11
names that set. In full:

```pest
query_decl3    = { kw_query ~ ident ~ param_list3 ~ annotation3* ~ (as_commit_clause | as_unattached_clause)? ~ "{" ~ (read_body3 | mutation_body3) ~ "}" }
param_list3    = { "(" ~ (param3 ~ ("," ~ param3)*)? ~ ")" }
param3         = { variable ~ ":" ~ type_ref_or_kind ~ ("=" ~ "-"? ~ literal)? }
annotation3    = { "@" ~ ident ~ ("(" ~ annotation_arg3 ~ ("," ~ annotation_arg3)* ~ ")")? }
annotation_arg3 = { ident ~ "=" ~ annotation_value | annotation_value }
read_body3     = { match_clause3 ~ return_clause3 ~ order_clause3? ~ limit_clause3? }
match_clause3  = { kw_match ~ "{" ~ clause3+ ~ "}" }
clause3        = { let_clause | from_clause | negation3 | optional_block | binding3 | traversal3 | filter3 }
let_clause     = { kw_let ~ variable ~ "=" ~ (inline_read | expr3) }
from_clause    = { kw_from ~ relation_expr }
relation_expr  = { inline_read | call | variable }
inline_read    = { "{" ~ read_body3 ~ "}" }
optional_block = { kw_optional ~ "{" ~ clause3+ ~ "}" }
negation3      = { kw_not ~ "{" ~ clause3+ ~ "}" }
binding3       = { variable ~ ":" ~ type_name ~ ("{" ~ prop_match_list ~ "}")? }       // a node or an edge type
traversal3     = { !(variable ~ "*" ~ variable ~ continuation) ~ variable ~ edge_binding? ~ (undirected_edge3 | edge_sel3) ~ traversal_bounds? ~ variable }
edge_ident3    = @{ !(kw_let | kw_from | kw_true | kw_false | stmt_keyword | kw_is | kw_null) ~ ident }   // these are written quoted
filter3        = { expr3 }
block_value    = { (agg_name ~ ("(" ~ expr3 ~ ")")? | kw_exists) ~ "{" ~ clause3+ ~ "}" }
operand3       = { "(" ~ expr3 ~ ")" | block_value | agg_distinct | literal | call | prop_access | meta_field | variable }
call           = { call_head ~ call_args? ~ ")" }
call_head      = ${ call_name ~ "(" }                                                      // the name touches its parenthesis
call_args      = { positional ~ ("," ~ positional)* ~ ("," ~ option)* | option ~ ("," ~ option)* }
positional     = { !(ident ~ ":") ~ (inline_read | expr3) }
option         = { ident ~ ":" ~ (expr3 | expr_ident) }                                    // a bare word for an enumerated option, `mode: any`
agg_distinct   = { agg_name ~ "(" ~ kw_distinct ~ expr3 ~ ")" }
expr3          = { or_expr3 }                                                              // or, and, not as today
comparison3    = { sum3 ~ ((comp_op ~ sum3) | (kw_in ~ sum3) | null_test)? }
sum3           = { product3 ~ (("+" | "-") ~ product3)* }                                  // a "-" with whitespace before and none after is refused
product3       = { unary3 ~ (("*" | "/" | "%") ~ unary3)* }
unary3         = { "-" ~ unary3 | operand3 }
continuation   = { "." | "+" | "-" | "*" | "/" | "%" | comp_op | kw_and | kw_or | kw_in | kw_is }
integer3       = @{ ASCII_DIGIT+ ~ !(ASCII_ALPHANUMERIC | "_" | ".") }
float_lit3     = @{ ASCII_DIGIT+ ~ "." ~ ASCII_DIGIT+ ~ (("e" | "E") ~ ("+" | "-")? ~ ASCII_DIGIT+)? ~ !(ASCII_ALPHANUMERIC | "_") }
return_clause3 = { kw_return ~ kw_distinct? ~ "{" ~ projection3+ ~ "}" }
projection3    = { expr3 ~ (kw_as ~ expr_ident)? ~ ","? }
order_clause3  = { kw_order ~ "{" ~ ordering3 ~ ("," ~ ordering3)* ~ "}" }
ordering3      = { (expr3 | expr_ident) ~ order_dir? }                                    // a bare name here is a return alias
limit_clause3  = { kw_limit ~ (integer3 | variable) }
mutation_body3 = { write_group+ }
write_group    = { (!stmt_keyword ~ clause3)* ~ mutation_stmt3+ }
stmt_keyword   = @{ ("insert" | "update" | "delete") ~ !(ASCII_ALPHANUMERIC | "_") }
mutation_stmt3 = { where_stmt | insert_stmt3 | update_stmt3 | delete_stmt3 }
insert_stmt3   = { "insert" ~ type_name ~ "{" ~ assignment3+ ~ "}" }
update_stmt3   = { "update" ~ variable ~ "set" ~ "{" ~ assignment3+ ~ "}" }
delete_stmt3   = { "delete" ~ variable }
assignment3    = { ident ~ ":" ~ (null_value | expr3) ~ ","? }
null_value     = { kw_null ~ &("," | "}" | ident ~ ":") }
where_stmt     = { ("update" ~ (variable | type_name) ~ "set" ~ "{" ~ assignment3+ ~ "}" | "delete" ~ (variable | type_name)) ~ "where" ~ where_expr }   // edition 2's form, recognised first to print the fix; where_expr admits bare names
```

The rules that exist only to print a fix are `arrow_traversal`,
`where_stmt`, the `mutation` and `match {` recognizers at a write body, the
infix `contains` and `starts_with` recognizer (word-bounded, not touching
`(`), the `name (` recognizer, the chained-comparison recognizer, the
`let … in`, `for`, `unwind`, `CASE` and `||` recognizers, and the table of
foreign words. Each prints a byte-range suggestion.

Decisions the prototype forced, each pinned by a parser test:

- A positional argument admits an inline read, or no ranking example would
  parse; an inline read is not an operand, so a clause still cannot begin
  with `{`.
- A block in clause position is a filter. The edition-2 `subquery_predicate`
  and `exists_block` rules are gone, since with a block as an operand they
  gave `count { p } > 2` two trees and read `count { p } > 1 or $x` with
  the wrong precedence.
- `$a * $b` is the wildcard triple only when no operator follows; followed
  by one it is a product.
- `let`, `from`, `true`, `false`, `insert`, `update`, `delete`, `is` and
  `null` are never bare edge names (quoted, like `"in"`), since `$ok  from
  $r` and, in a write body, `$ok  delete $p` otherwise parse silently as
  triples; a bare `from` or `let` clause after a lone variable is a parse
  error with the quoted edge as the fix. `not`, `and`, `or` and `in` as bare
  edges are legal expressions and are refused by type.
- A call's name touches its `(`, since `n  (2026 - $p.age)` otherwise
  reads as a call to `n`; `now ()` with a space is refused.
- A bare identifier is an operand nowhere in a `match` or `return`; it is a
  return alias in `order` and nothing else, so a word from another language
  fails at the word.
- `date("…")` is the literal, not a call, and like a call its name touches
  its `(`.
- A declaration's kind is decided at the token after an opening `match { }`
  block: `return` makes a read, a statement makes a write, since a write
  body wrapped in `match { }` is recognised to print its fix.
- A write group after the first opens with a clause; consecutive statements
  are one group.
- A negative parameter default admits one sign; `signed_integer` stays
  schema-only.

`let` and `from` are contextual, word-bounded keywords, legal as property
names, binding keys, aliases, assignment names and parameter names. At
clause start, `from` is the clause when the next token is `{`, `$` or an
identifier touching `(`, and `let` when the next token is `$`; otherwise
each is a parse error there, since a bare filter of that name is never
well typed. The parser spike's corpus walk is the regression owner: of
2,753 stored texts, every one keeps its edition-2 result without the edition
line, 2,398 parse unchanged under edition 3, and every refusal is one of the
rewriter rows with its fix printed; four `expect error` cases move from a
type code to the parse code of the bare-identifier rule. Every byte-range
suggestion trims the trailing whitespace pest leaves inside a span.

## 8. The syntax by example

The [before-and-after corpus](assets/2026-11-07-gq-3-before-and-after.md)
writes forty-three kinds of query in edition 2 and in edition 3 over one
schema, marking what edition 2 cannot express. The schema and three of its
examples are enough to read the rest of this document.

```pg
interface Named { name: String }

node Person implements Named { handle: String @key  name: String  age: I32?  city: String? }
node Company implements Named { slug: String @key  name: String }
node Doc { id: String @key  title: String  body: String @index(fulltext, analyzer = "english_v1")  year: I32  tags: [String]  embedding: Vector(3, distance = "cosine")? @embed("body") }
node Collection { slug: String @key  min_docs: I32 }

edge WorksAt: Person -> Company @card(0..1)
edge Knows: Person -> Person
edge Authored: Person -> Doc
edge Cites: Doc -> Doc
edge In: Doc -> Collection        // traversed as "in": the bare name is reserved
```

**A grouped result, filtered.** The inner read groups; the outer filters its
rows like any others. This is what `having` was for. For "each company and
its headcount" the block form, `$c: Company  let $n = count { $p worksAt
$c }`, keeps a company with no employees at zero, which the grouped form
drops; agents reach for the block form unprompted, and the two are different
terms, not two spellings.

```gq
query big_employers() {
  match {
    from { match { $p worksAt $c } return { $c, count($p) as headcount } }
    $headcount >= 100
  }
  return { $c.name, $headcount }
  order { $headcount desc }
}
```

**A ranked window scoped by the graph, then a traversal from the hit.** The
population is a relation; `k: 20` is the window; the traversal and the count
run on those twenty rows.

```gq
query cited_near($coll: String, $q: Vector(3)) {
  match {
    from nearest(
      { match { $d "in" $x  $x: Collection { slug: $coll } } return { $d } },
      $d.embedding, $q, k: 20
    )
    $d cites $other
  }
  return { $d.title, $distance, count($other) as cites }
  order { $distance }
}
```

**A write fed by a read.** The clauses choose the rows; each statement
names the bound entity it writes; one snapshot per group, one commit. A
write mixes no `delete` with an `update`, so retiring a person is two
declarations, or two requests.

```gq
query retire($h: String) as commit {
  $p: Person { handle: $h }
  $p $k:worksAt $c
  delete $k
}

query relocate($h: String) {
  $p: Person { handle: $h }
  update $p set { city: null }
}
```

**Recursion.** A declared read calling itself; the `union` joins the base
case to the step, and the fixpoint is the reachable set.

```gq
query reachable($from: String) {
  match {
    from union(
      { match { $p: Person { handle: $from }  $p knows $q } return { $q } },
      { match { from reachable($from)  $q knows $r } return { $r as q } })
  }
  return distinct { $q }
}
```

## 9. Alternatives

| Alternative | Why not |
|---|---|
| Keep non-closure and add one clause per shape (`retrieve`, `having`, `view`; this RFC's drafts to 2026-11-01) | Each clause was one spelling for one job because the language had no general way to use a result; the evaluation's claim that non-closure is what makes plan truth possible was too strong for compile-time closure, whose four costs are stated and bounded in the core |
| PR #1244's forms: `let ($a, $b) in rel`, positional tuples, `squared_l2` beside `nearest`, no reserved forms, no break | The model converges with the core (three value kinds, one binder, relation expressions); the differences are the four guardrails it leaves to acceptance gates, one ranking operator per contract instead of a scalar exact distance beside an approximate ranking, `from` instead of a Haskell-style `let … in` for a row-multiplying form, column names instead of positions, and the one-spelling rule, which it declines; without the break, `order { nearest(…) }` and `from nearest(…)` would both be legal for a release per construct |
| Relation-valued columns (nested results, GraphQL-shaped output) | Nested relational algebra: every operator needs a rule for a nested cell, row size stops being bounded, equality becomes bag equality; `List<scalar>` aggregates and node references as cells give the common shapes, and nesting flat rows by a parent column is the transport's job |
| Relation-valued parameters to a declared read | Higher-order typing: a declared relation type, a subtyping rule for extra columns, and the correlation rule at the call boundary; `from` over the helper's rows then more matching covers the reuse; deferred to its own RFC |
| A registry scalar `distance($d.embedding, $q)` usable in any expression (pgvector's shape) | A second spelling of `Score` (A6); invisible to the ranking machinery as a predicate, so the `distance_range` pushdown and the exhaustive report would need the planner to pattern-match an expression (A5); `bm25` cannot be pointwise at all. If the corpus shows the operator form costs repair turns, the Layer 3 answer is to make a scalar `distance` the surface and `Score` its desugaring, which keeps one core term |
| Stage pipelines as the closure mechanism (TypeQL 3) | Closed by construction, but the text order is the plan order, each stage's output is its input crossed with its matches, and reads and writes mix in one transaction; `from` gives the same composition under one planner-owned shape and one commit |
| `CALL { … }` as the row-multiplying form (Cypher, GQL) | The same scoping rule; it reads as a procedure call, which it is not, and GQL also has `FOR` for the plain case |
| `for $x in rel` as the row-multiplying form | XQuery's and GQL's word; rejected narrowly because it suggests an iteration variable and GQ binds columns by name, so there is nothing for the variable to be |
| Positional or named destructuring on `from` | No query language agents read binds by position; named destructuring is a second way to rename beside `as` |
| A population shorthand: a node binding in relation position meaning its rows so far | Would shorten every ranked read; needs a correlation rule (uncorrelated with respect to that binding, correlated with every other) that the corpus should show agents get right before it is added; unresolved |
| A keyword `union { } { }` or an infix `rel union rel` | A form that takes relations and yields one is a relation function, as `rrf` is; a keyword would be a second shape for that |
| A list as rows: `from $list`, `unnest($list)`, GQL `FOR`, Cypher `UNWIND` | `from` binds no name and a list element has none, so the form needs the binder `from` was chosen not to have; a list parameter is matched with `in` against stored values, and constants become rows through `load`; if the corpus shows a read that needs it, it enters as a relation function with a declared column name, not as a binder |
| `CASE … END`, `COALESCE` and `\|\|` as grammar | Each is a pure scalar function; the registry rule makes them rows (`if`, `coalesce`, `concat`), and a keyword form would be a second spelling |
| Wrapping or null-producing integer arithmetic | SQL, Cypher, GQL and Soufflé's signed integers all raise on overflow and on a zero divisor; a null would be a silent partial result (invariant 8) and a wrapped value a wrong one |
| A `WHERE` inside a binding, `(n WHERE n.age > 30)` (GQL) | A second spelling for a filter clause; a binding's braces hold property equalities and a comparison is a clause |
| Writes that read nothing but their own `where` (the earlier A7) | Nothing in A1 to A6 needs it; it cost one round trip and two snapshots per read-driven write and made a traversal-shaped target set unwritable; the half that matters, a read has no effects, is kept |
| Reads and writes interleaved in one body (Cypher, GQL, TypeQL pipelines) | Within a group every sink sees one snapshot; between groups a later one sees the earlier effects, as edition 2's sequential statements do, because 28 stored bodies depend on it and refusing them would be an eighth break; one publication either way |
| Explicit correlation imports, `from (q) { … }` (Cypher 25, GQL) | Implicit correlation by name is SQL's and every inner read's; the silent case, an inner binding reusing an outer name and becoming a filter, is a type error instead, which removes the hazard without a second scoping syntax |
| `l2` as the exact vector function | On a cosine field the exact form of `nearest` is cosine, so `l2` would lie or refuse; `distance` reads the field's declared distance, one spelling for one meaning on every field |
| A bare field name as a ranking's second argument | A population that returns a whole pattern has several node columns, and 68 of the 178 edition-2 ranked reads the rewriter met do; naming the column, `$d.embedding`, says which, and the other columns ride as payload |
| Lifting the constructive-or-destructive split so one write may delete and update | Invariant 4 keeps the split explicit; the RFC's first write examples mixed the two and the engine refuses that today, so the examples were split instead |
| `Fuse` carrying the population's other columns | Arms may disagree on them; the fused row has the target and its score, and a correlated `from` draws the rest, which the rewriter emits |
| Retaining every unknown annotation as metadata | A later typed `@budget` would change the meaning of text edition 3 accepts, against the additivity rule; an allow-list of pure metadata keeps `.pg`'s convenience without the trap |
| `$n -1` as a subtraction | With no separator between items a `-` after whitespace silently merges two `return` items or a `let` and a filter; the asymmetric spacing is refused with the fix |
| Bare identifiers as operands in a read | Edition 2 admitted them and typed them away; in edition 3 they let every foreign keyword parse as a filter and fail later with a message that names the wrong construct, so they are parse errors at the word |
| Removing the property braces, a second spelling of an equality filter | Every pattern language has them and agents write them first; the braces are the canonical instance and `fmt` moves the filter form into them, as it moves `count { } > 0` to `exists` |
| A `where` on `update` and `delete` beside the clauses (edition 2's form) | A second predicate position for one `Filter`; the clauses select and the sink names its rows by reference |
| `@approximate(recall)` as an annotation beside `nearest(…, recall:)` | Two spellings of one bound; quality is the operator's property, and one read may hold two windows |
| `@satisfice` beside `@budget` | The same parameters with a different overrun behaviour; one bound with `on_exceed` |
| `@analyzed` beside `@index(p, fulltext)` | Two annotations configuring one index; the analyzer is the index's option |
| A `mutation` keyword beside `query` (GraphQL, Kusto's `.` commands; the 2026-11-01 revision) | The body's shape is the kind at parse time, so the keyword is a second source the parser must check against the first; every consumer that wants the kind at the head (the registry, MCP's write gating, policy scope, `queries list`) reads it from the parse tree, the derived view the engineering rules ask for; the languages that declare it do so because their transport needs it before parsing, which a server that compiles stored declarations at boot does not |
| A staged search syntax (`rank … yield`, named sources, `metric()`, `limit … of … per`, a `filter` stage; the 2026-09-13 draft of RFC 0048) | A second surface for the same plan nodes; `from` over relation functions is the one composition shape |
| A window equal to `limit`, or a default of `max(limit, 100)` (RFC 0048's draft) | Violates law 3, and the 2026-10-05 review's example changes the winner between `limit 100` and `limit 101`; `k` is required and no default exists |
| `candidates:` and `exact: true` as options on `nearest` | `k` is the window and `distance` the exact operator: two contracts, two operators (A8) |
| An explicit distance required on every vector | Every accepted schema would break; an omitted distance is `l2`, what they mean today |
| An `oversample` or effort option in the query | Effort is a session setting the plan records; the query states meaning, and `recall` is a bound, not an effort |
| Default `terms` to `any` and keep `search` as a synonym; or map `search` to the `all` default | Three spellings of one operation; `all` is the precise default for a predicate, and mapping to it would silently narrow every multi-word search, so the canonicalisation writes `mode: any` |
| A separate `filter` clause for predicates | A correlated block already scopes a predicate to its pattern |
| Native fuzzy defaults or truncated expansion as the contract; rescoping statistics by every graph filter; a warning on unindexed search | Results would change with analyzer, index and segment state; rescoping can reverse the order of the same entities; a warning does not repair a matched set |
| Removing `search`, `match_text` and `fuzzy` after a deprecation release, and tightening `T27` to require the analyzer (PR 792) | A registry row is never removed and `bm25` over `@index` is text every graph writes; `fmt` canonicalises and lint names it |
| Cross-type fusion now | A node variable binds one type; an interface population answers the common case, and fusion across different node columns waits for the polymorphism stage |
| Separate RFCs for the grammar, the programme, lexical search and the search contracts (PRs 1202, 1213, 792, 793) | Four documents specifying one surface drifted from each other within a week each; one document with one decision log, and assets for the evidence |
| No programme; each stage RFC accepted on its own | The state before: ten open language, search and access RFCs, three of them permissions, three scheduling their own break, two specifying one grammar position |
| A `batch` declaration holding several reads under one snapshot (the 2026-10-31 programme) | One snapshot and one round trip are properties of a request, which already pins a snapshot and already compiles a file of declarations, so `batch { q1 q2 }` is a second spelling of a file with two declarations; `@brief` and `@phase` describe the agent's session and change no plan, so they are request fields; a stored, named group of reads is a request listing names |
| Cozo's recursion with unbounded value invention | Termination is not guaranteed and Cozo says so; GQ admits recursion over references, where the domain bounds it, and an invented value only under `min` or `max` with a round budget (A1) |
| An open upper bound on `Expand` as the only recursion (this RFC's text until 2026-11-07) | A special case of `Fix` (`reachable`); one operator covers it and the shortest path, and `Expand{m,n}` keeps the bounded-depth form |
| `min` and `max` alone as the monotonicity rule (this RFC's text until 2026-11-08) | A filter on a `max` column, an inner cut and a nested aggregate all pass it and diverge between naive and semi-naive evaluation (74 of 817 random recursions); the stated rules admit exactly the recursions on which the two agree |
| Bit-identity with Lance's unlimited scan as the WAND qualification | Lance scores in `f32`; two documents whose `F64` scores differ by less than an ulp can tie or invert, and did on a real index, so a certified margin with an `F64` rescore is needed, not a tie check |
| Cozo's fixed-rule algorithms as syntax; triggers; an imperative sublanguage | Algorithms are relation functions with declared bounds (stage R); a trigger hides what a write does from its plan (A3) and a write body with several statements says it in the open; an imperative layer has no place under A1 and A3 |
| Additive first, break last | Every construct built twice, agents reading two spellings per construct for a release; three open RFCs already schedule four majors this way |
| An arrow spelling for traversals; refusing the incoming triple; freezing the score column as `F64?`; removing the three lexical rows; `@distance` and `@score` meta-fields; a `file` rule; `query` for writes; a `where { }` clause; `graph@ns::Type`; a permanent two-edition compiler; one RFC for grammar and semantics; silent triple correction; role-named ends; do nothing | As recorded in the 2026-11-01 revision; none is changed by closure |

## 10. Evidence and tests

## 11. Programme and rollout

The language lands in one break and a sequence of additive stages. The
order is a set of edges: a stage ships after every entry in its cell and
nothing else constrains it. After the break, a change that needs a new
grammar rule is an amendment to this RFC, enforced by a test that pins the
grammar's rule set.

### One IR

The compiler has one typed IR, the core of section 2, and both editions
lower into it. Edition 2 reaches it through the same surface tree and type
checker as edition 3, the seven freeze-list rows being the only places the
edition changes what the checker accepts; the planner reads only the core.
Scalar expressions in the core are today's typed expression nodes (the
`Cast` nodes of invariant 9 included), extended for arithmetic, because
plans, the bound-plan mirror and the engine already carry them. The proof
that edition 2 did not move is the GQT corpus: every edition-2 case keeps
its rows, shapes, plan lines and codes, and a code that moves is one the
fixed map of section 6 names.

Today's pipeline IR is deleted when the planner reads the core, and the
frozen v1 reference engine with it: v1 reads that IR, and each of its
fifteen `expect same as v1` comparisons sits beside pinned rows. No module
carries an edition number in its name. Edition-2 parsing is the one
edition-specific part, and it goes when the edition window closes.

### Rules every later change answers

1. **No new grammar rule without an amendment.** A test pins the rule names
   of `query.pest`; a red pin is an amendment here, accepted only when the
   production starts at a token edition 3 refuses and the collision it
   designs around is named.
2. **One spelling per meaning** (A6), answered in the change's Alternatives;
   a form that falls out of a general construct is canonicalised by
   `queries fmt` and named by lint.
3. **Enabler before consumer.** An order the sequence table does not state
   does not exist; a new edge is a row change here.
4. **Measure at every stage.** The M0 instrument is re-run on the same
   corpus; the four numbers go in the release note; a stage that lowers
   first-try validity shows repair turns compensate.
5. **Cases first.** Every refusal this RFC names has an `expect error` GQT
   case written at B; a stage that lifts one flips it.
6. **Storage on its own clock.** The distributed sequence, I and Poly follow
   the storage-upgrade matrix.

## Invariants

- **7, physical acceleration is derived.** Index presence never chooses the
  analyzer, the matched set, the score or the distance; a lagging or missing
  index changes cost; an index built for another distance is never used.
- **8, integrity failures are loud.** Every refusal and resource failure is
  typed; no plausible subset, no silent default window, no truncated result.
- **9, query semantics are typed structures.** Options are typed call
  arguments carried into typed plan nodes; the lexical query is one
  `LexicalQuery`; nothing travels in strings or transport flags; a
  declaration's kind is its body's shape in the parse tree.
- **3, one coherent view.** A read holds one snapshot; a write evaluates its
  clauses and effects on one; every arm, statistic and nested read of one
  query shares it.
- **4 and 5, one publication, crash convergence.** A write with clauses
  publishes once; the sinks change no staging protocol.
- **6, stable identity.** Analyzer fingerprints and representation
  identities bind to property identity; a rename keeps them, drop and re-add
  does not.
- **10, trust at the boundary.** Policy gates a write by its static target
  type whether or not the body reads.
- **11, bounded resource use.** Every `Expand` is bounded, every `Call`
  chain acyclic and budgeted, every relation function declares finite
  cardinality, and rankings, fusion and exact scans charge the query's
  memory.
- **12, one source of truth.** SchemaIR owns analyzer, scorer, distance and
  recipe; the plan owns windows and weights; descriptors and catalogue rows
  derive from them.
- **13, evidence matches the boundary.** Compiler tests own the grammar,
  GQT owns rows and errors, the oracles own scores, the instrument owns
  agent competence.

Deny-list: no synchronous index build on a content write, no logical
precondition on index coverage, no string-built predicates, no side channel
for discarded rank, no silent partial results.

## Compatibility and reversibility

- **Language.** Seven spellings of edition 2 stop compiling under `gq 3;`
  (the rewriter table), and two shapes edition 2 accepted become type errors
  with no rewrite: an `rrf` whose arms are identical (15 stored cases, used
  to test fusion mechanics) and an `rrf` whose arms rank two bindings (2
  cases); those seventeen are edited by hand and listed in the rewriter's
  report. Three texts edition 2 accepts are refused by the RFC's own rules:
  an order key over grouped rows that is a meta-field neither returned nor a
  key (3 stored cases), since an order over groups reads keys and aggregates
  only. Nine texts edition 2 refuses are accepted, intentionally: a block
  compared with a column (`T40`), a triple with neither end bound (`T5`, 4
  cases), an order key that is not a return item (`T42`), and a Boolean or
  property item beside aggregates (`T9`, `T58`). Everything else is
  additive, the schema's `@index(fulltext, …)` option included. Edition 2 text
  compiles for one release and is rewritten at boot with a warning;
  `queries migrate` rewrites stored text with proof. The widening of `<e>`
  over an asymmetric alternation turns a refusal into a meaning and changes
  no accepted text.
- **Schema.** Every declaration of section 4 is additive and applied in
  place: an omitted distance is `l2`; an index without `analyzer` keeps
  edition 2's analysis; a field that declares an analyzer or changes a
  distance rebuilds its index once; one that changes a recipe regenerates
  its vectors. No export and reload.
- **Results.** Rows change only where edition 2's answer depended on index
  state or letter case, and on a field that adopts a profile, where today's
  English index analysis differs from the declared one (`english_v1` is
  closest, differing by the token filter and NFC). Fusion rows change where
  an arm's window differs from today's `limit`-sized one. Scores change on
  adopting fields.
- **Wire.** The retrieval descriptor fields are additive; the HTTP
  contract version does not change; `openapi.json` regenerates; the explain
  and bound-plan versions advance once.
- **Reverting.** Before the break, delete this document. After it, reverting
  restores the seven spellings behind another edition line; reverting a
  distance or recipe needs the rebuild or regeneration that adopting it
  needed.
