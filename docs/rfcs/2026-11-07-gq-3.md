# RFC: GQ 3: the language, its search contracts, one break and the programme

> A term set in ***bold italics*** is defined at that spot; it is plain text
> afterwards. Code references are at `main` `03e0b623`, Lance 13.0.0; the
> bump base is `GQ_LANGUAGE_VERSION` `(2, 3)` and `EXPLAIN_VERSION` `8`. A
> rule this RFC chooses, rather than one an axiom forces or today's behaviour
> supplies, is marked *[choice]*; a rule carried over unchanged, *[as today]*.
>
> This is the one GQ 3 document. It replaces the grammar RFC (PR #1202), the
> programme RFC (PR #1213), the analyzed lexical search RFC (PR #792) and
> RFC 0048 (PR #793), closed without merge on 2026-11-07, and it answers
> PR #1244. Its evidence is the
> [evaluation](assets/2026-10-28-gq-3-grammar-evaluation.md), the
> [grammar comparison](assets/2026-11-07-gq-3-grammar-comparison.md) and the
> [before-and-after corpus](assets/2026-11-07-gq-3-before-and-after.md).

## Summary

GQ is restated from the bottom up in four layers, each fixed before the next
is designed, and the whole lands in one breaking release followed by
additive stages.

- **Axioms.** Eight: every read is total with a cost readable from its plan,
  observes one snapshot, is described completely by its plan, composes
  (every operator's output is a relation any input position accepts),
  carries its semantics as typed terms, has one spelling per term, keeps
  reads free of effects, and declares rather than chooses its quality.
- **Core.** Thirteen operators over typed relations with the graph pattern as
  the only leaf, three terminal write sinks, and a term former that inlines
  declared reads. Every surface form desugars into exactly one core term,
  and a reference interpreter of the core (`spike/gq3-core`) runs the
  RFC's examples and 50,000 random terms against the rules below.
- **Surface.** `match { }` holds the comma-separated elements that produce
  rows and one `where` the predicate that removes them; two elements, `let`
  (a named value) and `from` (rows drawn from a relation); arithmetic;
  retrieval as relation functions, `distance`, `nearest` and `bm25`, with
  `rrf` and `union` over relations; one declaration keyword, `query`, whose
  body's shape says whether it reads or writes; a write body that selects
  with a read's `match` and `where` before its statements.
- **Search contracts.** Text analysis, scoring, vector distance and
  embedding recipes are schema-owned and resolved before acceptance:
  `@index(p, fulltext, analyzer = …)` with three immutable profiles and the
  `bm25_v1` scorer over the field corpus; `terms(…)` as the one lexical
  query, consumed by the predicate `match_terms` and by `bm25`;
  `Vector(n, distance = …)`; an exact scan as the correctness oracle under
  every index state, and native indexes as acceleration that must prove
  parity.
- **The break.** Edition 3 replaces edition 2 in one change, with no edition
  line and no compatibility path. Edition 2's clause list inside `match`,
  its property braces and seven other spellings stop compiling; the
  repository's text is rewritten in the same change by a one-shot rewriter
  with a typed-IR proof for every row but the `rrf` rewrite, which has a
  rows-equality proof.
- **The programme.** After the break, every later capability is a registry
  row, a catalogue type, an envelope field, a plan node, or a production
  that starts at a token edition 3 refuses, in the stage order section 11
  fixes; every open language, search and access RFC receives a verdict
  there.

What does not change: static closed typing, three-valued logic with no null
literal in reads, pattern conjunction, stratified blocks and the safety rule,
reachability semantics for bounded traversal, one total order, index
requirements at compile time, keyed insert as upsert, one commit per write,
the constructive-or-destructive rule, branch and commit statements, the `@`
namespace, the four-field diagnostic, the storage format, the `__manifest`
publication door, the HTTP contract version and the plan-acceptance
contract.

## Motivation

GQ grew one capability at a time, each answering the request in front of it:
a logic word reserved when a filter needed it, a ranking placed in `order`
because that is where a score was first wanted, a search function added as a
keyword, an explain version per feature, a deprecation shim per rename. The
language carries decisions whose only justification is the order they
arrived in. The [evaluation](assets/2026-10-28-gq-3-grammar-evaluation.md)
against SQL, GQL, Cypher, GraphQL, Datalog and the query languages of
Elasticsearch, LanceDB and Vespa found the semantics sound and the accretion
the problem, and the
[construct-by-construct comparison](assets/2026-11-07-gq-3-grammar-comparison.md)
found the expression language the smallest of the five it compares.

The first drafts answered the accretion with a freeze: one break and a list
of reserved clauses for the forms the next RFCs would need. Their review, and
the independent alternative in PR #1244, showed the freeze repeating the
pattern at a larger grain: `retrieve { }` for the ranking shape, `having { }`
for the filtered-group shape, `view` for the reuse shape, each one spelling
for one job because the language had no general way to use a result. The
evaluation had called that general way, compositional closure, the root of
every expressiveness gap, and had refused it on the ground that non-closure
is what makes plan truth and bounded execution possible. That claim was too
strong. Compile-time closure, every nested read inlined into one bound plan
against one snapshot, keeps plan truth and replay; what it costs is
cardinality estimation across a correlation, a budget on expansion, a report
that nests, and cuts that stay explicit. Those are four obligations, not a
reason for a clause per shape.

Search has the same history in one domain. Text answers change with physical
index state: without an index `search` runs a bare case-sensitive scan
(#747), with one `fuzzy` spends its edit budget on letter case (#748), and
rows appended after an index build are analyzed differently from indexed
ones (#749), each a violation of invariant 7. A downstream `limit` sizes an
upstream window, so a page size changes a vector arm's recall; `rrf()` takes
exactly two positional arms; `Vector(n)` declares no distance and every index
is built with L2; a caller who needs the exact nearest targets cannot ask
for them. Two RFCs (PRs #792 and #793) fixed these on the edition 2 surface
and were reviewed; one review found their default window inconsistent with
their own law. The core of this RFC resolves that by construction, so their
contracts are restated here on the new surface and the two drafts close.

So this RFC designs in layers that do not move. The axioms are the contract.
The core is a small algebra whose operators are each necessary and together
closed. The surface is sugar with one desugaring per form, chosen by
precedent among the languages agents have read most. The search contracts
are schema-owned meaning that no index state can change. The break is the
one release that moves stored text from the old surface to the new one,
mechanically and with proof. A later capability is checked against the core
instead of argued on its own.

Three facts make one early break cheaper than the several that were
scheduled. Stored text is small and mechanical to rewrite, and the compiler
already emits byte-range machine-applicable edits. The agent is the author,
and its cost is round trips: on this grammar a general agent answered 45 of
45 tasks with 8 first attempts refused for a missing `()` (RFC 0047,
Evidence), and published comparisons find a 10 to 45 point zero-shot gap on
novel syntax that five retrieved examples erase, so one spelling per
construct and one example per operation are what reliability costs. And
every construct that would otherwise be built twice, once additively and
once at the later break, is built once.

## 1. Axioms

These are the contract. A later layer never changes one; an RFC that does
names the axiom it changes.

**A1. Totality with declared cost.** Every accepted read terminates, and its
cost is a function of its bound plan and the snapshot it runs against, known
before execution. A recursion is a least fixpoint over a finite domain, and
a value it invents is bounded; nothing else recurses.

**A2. One snapshot.** A read observes one accepted snapshot for its whole
lifetime. Composition never opens a second snapshot, session or request.

**A3. The plan is the truth.** The bound plan describes everything that
runs. The report has one row per operator, nested as the plan nests, and
replay from the plan and the snapshot reproduces the rows. A declared helper
is captured with the plan; a changed helper refuses the replay.

**A4. Closure.** Every operator consumes relations and produces a relation.
Every input position that accepts a base relation accepts a derived one. The
exceptions are a finite named list, each with its reason
([the closure table](#closure)).

**A5. Semantics are typed terms.** Meaning lives in the core term and the
plan. No semantics pass through strings, settings, transport flags or side
tables. Every refusal is a typed code with the fix that makes the text legal.

**A6. One canonical spelling per term.** Two surface forms that desugar to
the same core term are a violation unless the formatter's list
([`queries fmt`](#queries-fmt)) names one of them as the non-canonical form
it rewrites; that list is complete, and a literal and a reference to the
same value (a declared read and its inlined body among them) are the one
standing exception.

**A7. A read has no effects; a write is fed by reads.** A declaration whose
body has no sink never writes, which is what lets it be planned, replayed,
cached and run under read policy without a transaction. A declaration whose
body ends in sinks names the rows it writes through the same `match` and
`where` a read uses, evaluates them and its effects on one snapshot (A2),
and publishes once (A4). The kind is the body's shape, known from the parse
tree, never a declared word the parser must check it against: a body is a
read when `return` follows its `match` and `where`, and a write when a
statement does. No sink appears inside a read body.

**A8. Quality is declared, never chosen.** An operator that may omit a
correct row declares its bound and reports what it achieved. Exact and
approximate are different operators. The planner never substitutes one for
the other.

## 2. Core

### Values

| Kind | Form | Notes |
|---|---|---|
| Scalar | `I32 I64 F32 F64 Bool String Date DateTime Vector(n) Blob`, enums, `List<scalar>`, each with a nullable variant | *[as today]*; the exact integer carrier stays internal |
| Node reference | `N<T>`, `T` a node type | identity, typed properties, meta-fields; equality is identity |
| Edge reference | `E<e>` | identity, endpoints, properties *[as today]* |
| Relation | `R[c1: t1, …, cn: tn]`, an ordered list of named typed columns over a bag of rows | column types are scalar, node or edge references; a relation-valued column is refused *[choice]*, which keeps the algebra first-order ([Alternatives](#9-alternatives)) |

A row has no identity. Node and edge references do, and that is what
ordering ties, fusion and `distinct` resolve on. Two values are ***not
distinct*** when both are null or both are equal; `Group`, `distinct`,
`Fix` and the derived difference use that relation, so a null is one key
value, while a filter's `=` stays three-valued. Values have one fixed total
order, nulls first then ascending *[as today]*, which ties fall back on.

An ***environment*** Γ maps names to types. A term is typed under Γ; a
***correlated*** term is typed under the enclosing row's columns added to Γ.
Free variables resolve lexically outward. A forward reference or a cycle is
an error.

### Operators

Thirteen operators are the core, over three leaves: `Unit`, the one empty
row; `Env`, one row of the correlated bindings, exposing exactly the free
variables of the term it feeds; and `RecRef`, the recursive relation inside
a `Fix`. Everything else in the language is a derived form with one
desugaring ([Derived forms](#derived-forms)). Each record states signature,
semantics, cardinality bound and cost shape; the cardinality bounds are what
make A1 provable.

| Operator | Signature | Semantics | Cardinality | Cost shape |
|---|---|---|---|---|
| **Scan**(T) | → `R[$x: N<T>]`, or `R[$k: E<e>]` for an edge type | every node of type T, or every edge of type e, in the snapshot | `\|T\|` | linear in `\|T\|`, or index-bounded by a pushed Filter |
| **Expand**(R, $x, sel, m..n, [$k]) | `R` → `R + [$y: N<T′>] (+ [$k: E<e>])` | bounded reachability over an ***edge selector***, a set of (edge type, direction) pairs: for each row, every `$y` reachable from `$x` over any member in `m..n` hops, set semantics over endpoint pairs, shortest distance across all members *[as today]*; the start node is at distance 0, so a range other than the single hop never returns it, through a cycle *[as today]* or a self-loop *[choice]*; the single hop is the case `m = n = 1`, the edge relation itself, so a self-loop returns its start, and the only case where `$k` binds, then one row per edge *[as today]* | `≤ \|R\| · Σ_{h=m..n} fanout^h`, `fanout` counting distinct neighbours (edges when `$k` binds); with no `$k`, also `≤ \|R\| · \|T′\|`, one row per endpoint pair; with `$k`, `≤ \|R\| · deg`, `deg` the most selector edges at one node, since parallel edges give a row each | frontier-bounded, index or scan per hop |
| **Filter**(R, φ) | `R` → `R` | rows where φ is true under three-valued logic; null is not true | `≤ \|R\|` | linear; pushdown is a plan choice |
| **Project**(R, [(name, expr)]) | `R` → `R′` | one output row per input row; bag, duplicates kept | `\|R\|` | linear |
| **Group**(R, keys, aggs) | `R` → `R[keys…, aggs…]` | one row per distinct key tuple; null is a key value *[as today]*; with no keys, exactly one row, `count` 0 and the other aggregates null over empty input | `≤ \|R\|`, exactly 1 with no keys | hash, linear plus groups |
| **Correlate**(R, f) | `R`, `f: Env → R′` → `R + R′` | for each outer row, the inner term evaluated with `Env`, the leaf that is that one row, in scope; the output is the outer columns then the inner term's new columns; an inner column that bears an outer column's name is a type error (`T68`); a binding of an outer variable's name inside any inner scope, a block, an `optional { }` or an inline read, is `T68` too: an inner scope correlates on an outer variable by reading it, never by binding it again | `Σ_r \|f(r)\|` | nested or decorrelated, the planner's choice under A3 |
| **Union**(R1, R2) | `R`, `R` → `R` | bag union; column base types must agree by position, a column is nullable when either arm's is, names from the left | `\|R1\| + \|R2\|` | linear |
| **Order**(R, [(expr, dir)]) | `R` → ordered `R` | a total order: the keys, then the identity (type, id) of every reference column in column order, node and edge alike, then every remaining column's value in column order under the fixed value order; rows that still tie are equal in every column and a bag cannot tell them apart. Only `Order`, and `Filter`, `Project` and `Cut` over an ordered input, produce an ordered relation; every other operator's output is unordered | `\|R\|` | `\|R\| log \|R\|`, or `\|R\| log k` under a Cut |
| **Cut**(R, k) | `R` → `R` | the first `k` rows of an ordered `R`; over an unordered `R` it orders by the tie rule alone first *[choice]*; today's engine takes the first rows its scan yields (Compatibility) | `min(k, \|R\|)` | `k` |
| **Score**(R, $x.f, kind, q) | `R` → `R + [s]` | an exact score per row of the named column's field: `distance` is the field's declared distance (`l2`, `cosine` or `dot`) to `q`, typed `F32` *[as today]*; `bm25` is `bm25_v1` of the field against the field corpus, typed `F64`, keeping only the rows whose field matches `q`; a null field value drops the row *[as today]*; a non-finite input is a typed error; the other columns of `R` ride through unchanged | `≤ \|R\|` | reads every row's field |
| **ApproxTopK**(R, $x.f, q, k, recall) | `R` → `R + [s: F32]` | the `k` nearest distinct targets of the named column under the field's distance, approximate with declared `recall`, reported exhaustive when the engine searched everything (A8); every row of a selected target survives; the overfetch ladder and probe policy are its plan policy *[as today]* | `≤ k` targets, every row of each | index probes, widened by the ladder |
| **Fuse**(R1…Rn, method, params) | scored relations over one node column, the same name and type in every arm → `R[$x, s: F64]` | each arm ranks its distinct targets by its own score in its kind's direction (distance ascending, score descending), an ordered inline arm by each target's first row in its order, then by target id, from 1; `rrf`: `Σ weight_i / (k + rank_i)` over the arms in which `$x` appears; a missing arm contributes nothing, not zero; one row per target, unordered, carrying no other column | `≤ Σ \|Ri\|` targets | linear in the arms |
| **Fix**(f) | `f: R → R` monotone → `R` | the least fixpoint of a declared read over itself, over sets: inclusion on its key columns, `≤` and `≥` on its `min` and `max` columns, rows replaced by better values and added until a round changes nothing; its `return` is `distinct` or `min`/`max`; monotone means, on the term: no `not` over its own rows; a `Group` over them only when it has no aggregate (`distinct`) or is the read's own `return` with `min` and `max` alone; a count block over them only in its `exists` reading; no `Order`, `Cut`, `nearest` or `rrf` over them; no `Filter`, `Group` key or `Order` key inside the cycle reading a `min` or `max` column; and every expression on the cycle that reads one preserves its order, so the step is monotone in the lattice: `$d + t`, `$d - t` or `t + $d` with `t` reading no lattice column, `$d * c` with a constant `c ≥ 0`, and `min` or `max` of such expressions, while anything else, `-$d` and `1 / $d` among them, is `T70`; a column it computes rather than reads is admitted only under `min` or `max` with a declared round budget; its type is the fixpoint from its base arms, and a recursion with no base arm is `T70` | rows `≤ \|domain\|` of its key columns; rounds `≤` the budget | semi-naive: each round joins only the rows the last round added |

`limit` without `order` therefore stays legal and deterministic, and a
`Correlate` keeps no outer order: a `Cut` above it orders first. The
reference interpreter found 138 of 12,799 random ordered terms
nondeterministic under the earlier rule (keys, then node identities only)
and none under this one.

Three ***sinks*** close the core on the write side. Each takes a relation
and a target type and produces effects, not a relation, so a sink is
terminal and the read algebra stays thirteen operators.

| Sink | Signature | Semantics | Cardinality | Cost shape |
|---|---|---|---|---|
| **Insert**(R, T, [(prop, expr)]) | `R`, `T` → effects | one keyed insert into `T` per row of `R`, the assignments evaluated under that row; an endpoint assignment is a key literal or a bound reference of the endpoint's type; keyed insert is upsert *[as today]* | `\|R\|` writes | linear in `\|R\|` plus the keyed write |
| **Update**(R, $x, [(prop, expr)]) | `R` with a reference column `$x` → effects | for each row of `R`, the entity `$x` names takes the assignments evaluated under that row | `\|R\|` writes | linear in `\|R\|` plus the keyed write |
| **Delete**(R, $x) | `R` with a reference column `$x` → effects | for each row of `R`, the entity `$x` names is removed | `\|R\|` writes | linear in `\|R\|` plus the keyed write |

A write is a sequence of ***groups***, each a relation term followed by one
or more sinks over it; a group after the first opens with its `match`. A
group's selection is evaluated once (A2), against the state the groups
before it left; its statements run in order, each keyed effect, an upsert or
an endpoint resolution, seeing the statements before it *[as today]*, which
is how edition 2 runs `insert Person {…}  insert WorksAt { from: $h, … }`
and a body of several statements (52 stored bodies reproduce under this
rule, none differ); the whole write publishes once (A4), and whole-write
validation, cardinality minimums, uniqueness and byte limits, runs once at
that publication. The three sinks share one shape: a sink names its rows by
a reference column, and the selection is the group's `Filter`, never a
second predicate on the sink. `insert` with no `match` runs once over
`Unit`, which is today's statement; edition 2's `delete T where φ` is
`Delete(Filter(Scan(T), φ), $x)`, which the rewriter spells as `match { $x:
T } where φ  delete $x`, `Scan` over an edge type included. Two different
values for one entity and property reached through the rows of one statement
are a refusal at run time (`E` namespace), since physical row order would
otherwise decide; across statements the later effect wins *[as today]*. The
target type is the reference's declared type, static, so policy gates it as
it does now; the constructive-or-destructive split stays per write *[as
today]*, so a body mixes no `delete` with an `insert` or `update`; a write
whose groups select nothing publishes no commit *[as today]*; a sink inside
a read term is refused (A7).

**Call**(name, args) is a term former, not an operator: the body of a
declared read, closed, with its scalar arguments evaluated in the caller's
scope and bound to its parameters, inlined at compile time; it is binding,
never textual substitution, so an argument that names a variable the body
also binds cannot be captured. The expanded tree, not the shared graph, must
fit the ***plan budget***, declared as `@budget(plan = n)` on the declaration
and otherwise a compile-time constant, or the compile refuses with the chain
named. A cycle in the call graph is a recursion: it compiles to `Fix` when
every read on the cycle is monotone in the recursive relation and every
recursive call passes the parameters through unchanged, and is refused with
the cycle and the offending construct named otherwise (`T70`); a computed
recursive argument is value invention with no fixpoint. Scalar arguments
only *[choice]*; a relation-valued parameter is a named closure exception
([Alternatives](#9-alternatives)).

***Scalar expressions*** are the operand language of Filter, Project, Group
and Order: literals, parameters, column references, property and meta-field
access on a reference, arithmetic, comparison, `and or not`, `is null`, `in`
over a list, and registry functions, each declared pure and either total or
`can_fail`. A function that can fail keeps its failure where it was written;
the planner may not move it past a guard (A3). The exact distance is
`Score`, not a registry scalar *[choice]*, so it has one spelling (A6).
`if(c, a, b)` evaluates `c` and then only the branch it selects, so
`if(null, a, b)` is `b`, and `coalesce(a, …)` evaluates its arguments left
to right and stops at the first non-null; a branch not taken never fails, so
`if($a = 0, 0, 1 / $a)` returns `0` where `$a` is `0`, and the selecting
argument is a guard under A3. These two are the registry's lazy rows, marked
so in the registry; every other function evaluates all its arguments. An
`F32` beside an `F64` is `F64`.

Arithmetic is `+ - * / %` and unary `-` over the numeric scalars, each a
pure term that `can_fail`: integer overflow and a zero divisor are typed
errors that keep their place (A3), never a wrapped value, a null or an
infinity *[choice]*, which is what every comparator with fixed-width
integers does; integer division truncates toward zero, as in all of them; a
narrower integer widens to the wider operand and an integer with a float is
`F64`; an integer literal takes the other operand's type when it fits *[as
today]*, so `$p.age + 1` over an `I32` is `I32`; a float literal is `F64`;
`U32` with `I32` is `I64` and `U64` with a signed integer is refused; `%`
over floats is admitted; `Date` arithmetic is refused; an assignment never
narrows; the result is nullable when an operand is; comparison casts stay
explicit `Cast` nodes *[as today]*. Edition 2 has no arithmetic at all, so
this is new text in the break, not a rewrite.

### Derived forms

Each surface form desugars to exactly one core term. This table is the
one-spelling check made concrete; it is also a test
([Evidence](#10-evidence-and-tests)).

| Surface | Core |
|---|---|
| `match { e, … } where φ` | `Scan`, `Expand`, `Correlate` and `Project` composed in written order, then `Filter(φ)` over them: binders in written order; `let` and `from` seeing only the elements before them; `φ` seeing every element, its pushdown below them the planner's choice wherever it crosses no `can_fail` term (A3); a block correlating on the variables in scope where it is written; a triple with neither end bound starting from a `Scan` of the edge's declared source type (the smaller-named end for `<e>`), which edition 2 refused (`T5`) |
| a triple whose two ends are both bound | `Expand` to a fresh column, then `Filter` equal to the bound end |
| `return { … }`, `order`, `limit` | `Project(Cut(Order(Extend(R, items), keys), k), items)`: the return items are computed beside every match column, the order keys may read either, the cut takes the first `k`, and the projection comes last; without an aggregate `Extend` is a `Project` that keeps the match columns, with one it is a `Group` followed by a `Project` for any expression over the aggregates |
| `return distinct { … }` | `Group` with no aggregates |
| `count { p }`, `sum`, `avg`, `min`, `max` as a value | `Correlate(R, Group(p, [], [agg]))`, the aggregate column; a block's elements and its own `where` are `p` as a `match` and `where` |
| `exists { p }` | `count { p } > 0`; the planner's semi-join is a mechanism |
| `not exists { p }` | `¬ exists { p }`, a Boolean operand of `where` |
| `optional { p }` | `Union(Correlate(R, p), Project(Filter(R, ¬ exists p), nulls))` |
| two patterns sharing no variable | `Correlate` with an inner term that has no free variables, admitted only when every component but one is ***key-pinned***: a single node binding whose every `@key` property, or whose `@id`, `where` equates, in a top-level conjunct, with a literal or a parameter; a component of two or more elements is never pinned, components are the bindings and triples joined by shared variables, a predicate in `where` connects none of them, and an uncorrelated `from` is the written product rather than a component; otherwise `T81`, whose fix either joins the components through a triple or writes the intended product as a named relation, `let $r = { match { … } return { … } }, from $r` |
| `$a (e1 \| e2) $b` | one `Expand` whose selector holds every member in its own orientation |
| `$a <e> $b` | one `Expand` whose selector holds both orientations of `e` |
| `$k: E` | `Scan` over the edge type |
| `union(rel, rel, …)` | `Union`, folded from the left |
| `let $v = expr` | `Project` adding one named column, in scope downstream |
| `let $r = rel` | the relation's term, named; no operator |
| `from rel` | `Correlate` |
| `distance(rel, $x.f, $q)`, `bm25(rel, $x.f, q)` | `Score` |
| `nearest(rel, $x.f, $q, k: n)` | `ApproxTopK` |
| `rrf(rel, …, k: n)` | `Fuse` |
| a named read, `name(args)` | `Call` |
| a declared read that calls itself | `Fix` over its body, when monotone |
| a write body, `((match { … } where φ)?  statements)+` | one group per `match` and its statements: the selection's term, then one sink per statement over it |
| `delete T where φ`, `update T set { … } where φ` (edition 2, rewritten) | `Delete(Filter(Scan(T), φ), $x)`, `Update(Filter(Scan(T), φ), $x, …)` |

Nothing in the table needs an operator outside the thirteen and the three
sinks.

### Orthogonality

The reference interpreter desugars 5,000 random surface reads to exactly
the term built directly, and found five pairs that share a term on the
clause-list surface; each pair is now either a refused spelling or on the
formatter's list.

Each operator is necessary: without `Scan` nothing is a leaf, without
`Expand` no traversal costs what its frontier costs (one hop is an edge
`Scan` correlated on its endpoints and a bounded depth unrolls, so `Expand`
is necessary for cost rather than expressiveness), without `Correlate` no
closure and no aggregate as a value, without `Union` no alternation and no
`optional`, without `Order` and `Cut` no deterministic prefix, without
`Score` no exact qualifying top-k, without `ApproxTopK` no window with a
declared quality (A8 forbids substituting it for the exact one), and without
`Fuse` no fusion, since ranks are not scalar expressions. Difference is
derived (`not` on full-row not-distinct equality), so Codd's six are
covered. The [evaluation](assets/2026-10-28-gq-3-grammar-evaluation.md)
carries the argument per operator.

### Inexpressible by decision

- Non-monotone recursion: a read that negates or counts its own rows; the
  fixpoint would be undefined (A1).
- Unbounded value invention: an arithmetic column inside a recursion without
  `min` or `max` and a round budget; Cozo accepts it and warns that it can
  be expensive, GQ refuses it (A1).
- Paths as values: `Expand` yields endpoints and single-hop edges only
  *[as today]*. Stage Path lifts this for bounded and shortest paths
  ([Designs for later stages](#designs-for-later-stages)).
- Relation-valued columns (first-order; the closure table). Relation-valued
  parameters wait for stage RP, which inlines them before planning
  ([Designs for later stages](#designs-for-later-stages)).
- A write inside a read (A7); a statement reading an earlier statement's
  effect inside one group (A2).
- A scalar exact-distance function beside `Score` (A6).
- A recursive call with a computed argument, which is value invention
  without a fixpoint (A1).
- A list enumerated as rows (GQL `FOR`, Cypher `UNWIND`): `from` binds no
  name and a list element has none; a list is matched with `in`
  ([Alternatives](#9-alternatives)).

### The envelope

Every core term is a finite tree whose `Fix` nodes run to a least fixpoint
over a finite domain: `Call` expansion is budgeted, each operator maps a
finite relation to a finite relation, and every cardinality bound is a
polynomial in the snapshot's sizes, composed from the operator table's
bounds: `Correlate` multiplies its inputs' bounds, `Union` adds them,
`Expand` multiplies by its fanout term, `Fix` is bounded by the domain of
its key columns, and the other operators do not grow; the degree is the
number of factors multiplied along the term, not its nesting depth, so
`Correlate(Correlate(A, B), Correlate(C, D))` has degree four. The language
is therefore stratified Datalog with monotone aggregation, plus ordering,
plus two operators with a declared quality bound, and every read is total
with a cost readable from its plan. Combined complexity is NP-hard in the
query's size, as for every conjunctive query language, which is why the plan
budget and the planner exist. This places GQ at Datalog's reach for
recursion over references, below it where a recursion invents values
(bounded, where Datalog engines warn), and above the relational algebra
(ordering, cuts, declared-quality retrieval); it is where a language whose
every query must have a cost before it runs belongs.

## 3. Surface

Three rules. Every surface form names exactly one core term. A
row-multiplying form and a value-binding form are different words. Where
precedent among SQL, Cypher, GQL, Kusto, XQuery and TypeQL is split, the
most common spelling wins, because it is the one an agent has read most.

### Kept

From edition 2, unchanged: the read's skeleton `query name($p: T) { match {
} return { } order { } limit n }`; the binding `$x: Type`; triples `$a e $b`
in the edge's declared order, source first (the reversed triple is `T82`,
whose fix swaps the ends, so the written order is the direction whatever the
end types; a selection, `(a | b)` or `*`, matches each member in the
direction its end types fix, in written order where both ends have one type,
and is `T82` only when no member points along the written order, since its
members may point both ways and no one order fits them all), `<e>` for either direction, `(a | b)`, `*{m,n}`, `$k:e`; the
blocks `count { }`, `sum`, `avg`, `min`, `max` and `exists { }`; `return
distinct`; aliases `as name`; the statements `show`, `branch`, `commit`,
`load`, `explain`, the settings. From the 2026-11-01 revision of the break:
every function a registry call with named options, `@name(args)` on any
declaration, the six reserved words, `limit $k`, parameter defaults, the
catalogue types and their `@`-prefixed edges, `a::b::C`, and `optional { }`
as the one outer-join primitive, now served. One binding form is added: `$k:
E` binds every edge of type `E`, the `Scan` of an edge type, which is what a
write over an edge type selects by. Node and edge types are separate
namespaces, and a schema may give one name to both: there `$x: Name` binds
the node, as `insert Name` targets the node today, and the edges are bound
by position, `$a $k:name $b`, which with neither end otherwise bound scans
the edge type; the typed term records the namespace the compiler selected,
and execution never chooses again (invariant 9).

### Changed: `match` holds the pattern, `where` the predicate

```gq
query colleagues($h: String) {
  match { $p: Person, $p worksAt $c, $q worksAt $c }
  where $p.handle = $h and $q != $p and not exists { $q blocked $p }
  return { $q.name }
}
```

Edition 2 writes a pattern and its predicates as one list of clauses inside
`match`, separated by whitespace. Edition 3 splits them by what they do to
the rows *[choice]*. `match { }` holds the ***elements***, the forms that
produce rows: bindings, triples, `optional { }`, `let` and `from`, separated
by commas, a trailing comma allowed. `where`, after the braces, holds one
Boolean expression, the predicate that removes rows: comparisons, `exists {
}` and `not exists { }`, the other blocks as values, and the lexical
predicates. A block holds elements and its own `where` inside its braces,
`count { $q: Person, $p knows $q where $q.age > 30 }`, and so does `optional
{ }`.

Three things follow. Each part is one kind of core term: the elements are
`Scan`, `Expand`, `Correlate` and `Project`, and the `where` is the `Filter`
over them, so a reader sees where the pattern ends. A property map,
`$p: Person { handle: $h }`, was a second spelling of the equality
`$p.handle = $h`, and it goes, so a predicate has one place (A6). And no list
in the language is separated by whitespace alone: elements, `return` items,
`order` keys, arguments and assignments take commas, so a typo that merged
or split two items is a parse error instead of a different query, and the
rules that kept whitespace-separated clauses apart, a `-` refused by the
space around it, a call's name touching its `(` and the quoted and reserved
edge names, are not needed.

`where` sees every variable the elements bind and is evaluated after all of
them, `let` included, so a `let` runs on every row its earlier elements
produce, the rows `where` then removes among them, and a term in it that can
fail fails there (A3). `can_fail` places a term and never refuses one: the
type checker accepts it in a `let`, and the planner pushes no conjunct of
`where` below it. An author who wants such a row not to fail guards the term
with `if` on the condition, `let $r = if($n > 0, $t / $n, null)`, which
fails on no row since the branch not taken is never evaluated, or writes the
expression in `return`, which runs after `where`. `where` is the word of SQL, Cypher, GQL, Kusto, XQuery and LINQ, so the
most-common-spelling rule picks it. A filter, a `where` or a comparison
inside the braces, a property map and a missing comma are parse errors with
the fix printed. A write selects with the same `match` and `where`
([Writes fed by reads](#writes-fed-by-reads)), so a selection has one form
in reads and writes. The competence instrument measured this surface
against the clause list on 2026-11-11 and found no difference in
correctness ([Alternatives](#9-alternatives)); with none, the cleaner
surface is taken.

### Added: two elements of `match`

```
let $v = <scalar expression>     // Project: a named value, in scope downstream
let $r = <relation expression>   // a name for a relation; binds and multiplies nothing
from <relation expression>       // Correlate: one outer row per inner row
```

`let` names a value. It computes an expression once per current row and
makes the result available under a name for the rest of the read, in
`where`, `return` and `order`. It never adds or removes rows. With a
relation on the right it names the relation so it can be passed to a
ranking function or drawn from twice; that form adds nothing to the current
rows either.

`from` is the one element that multiplies rows by a relation; two components
of a `match` that share no variable multiply them only when each but one is
a single node binding pinned to one row by its key (section 2's derived
forms), and are otherwise `T81`, whose fix writes the product as a `from`. It takes a relation
expression, evaluates it once per current row, and joins its rows in. The
relation's columns enter the enclosing scope under their own names: a column
written `$c` arrives as `$c`, a column written `count($p) as headcount`
arrives as `$headcount`. Every column of a relation drawn from must
therefore be variable-shaped, a bare variable or an alias; a name already in
scope is a type error (`T68`) whose fix is an alias on the inner `return`,
and so is a binding inside an inline read that reuses a name the enclosing
scope holds, since the inner read would otherwise silently become a filter
on the outer row. A block and `optional { }` follow the same rule: each
correlates on an outer name by reading it, `not exists { $m: Person, $m
manages $p }`, and a binding of an outer name inside it is `T68`; edition
2's re-mention, `not { $p: Person { name: "bob" } }`, is rewritten to the
conjunct `not coalesce($p.name = "bob", false)`, which keeps the rows with
a null name as the block did (section 6). A called read's columns enter the inner scope, so a
helper called twice is wrapped once: `from { match { from colleagues($of) }
return { $q.handle as h } }, from colleagues($h)`. This is the scoping rule
of Cypher's and GQL's `CALL { … RETURN x }` and of SQL's `FROM`. No
destructuring, positional or named, exists *[choice]*: SQL's column alias
list, `AS t(a, b)`, binds by position, as `UNION` arms do in every
comparator and in GQ's own `union`, but a name taken from a position breaks
silently when a helper reorders its `return`, and named destructuring would
be a second way to rename.

Two words because they do different things to the row count, and every
language that has both keeps them apart: XQuery `let` and `for`, GQL `LET`
and `FOR`, LINQ `let` and `from`, Kusto's scalar and tabular `let`. One word
for both would be the overload `order { nearest(…) }` was. `let` is what every
one of those languages uses for a value. `from` is SQL's and LINQ's word for
"rows come from here" and reads as a sentence; Cypher's `CALL { }` carries
the same scoping rule but reads as a procedure call, which it is not.

### Added: arithmetic

Edition 2's expression language has comparison, `and or not`, `is null`,
`in` and calls, and no arithmetic; a weight, a ratio or a threshold computed
from two columns cannot be written. Edition 3 adds `+ - * / %` and unary
`-` at the precedence every comparator uses (unary minus, then `* / %`,
then `+ -`, then comparison, then `not`, `and`, `or`), with the contract the
core states. A negative number is unary minus over a literal, never a
token, so `$n -1` and `$n - 1` are one subtraction. Numeric literals end at
a word boundary, and an exponent needs a fraction (`1.5e3`, never `1e3`).
`CASE`, `COALESCE` and `||` are not grammar: `if(c, a, b)`, `coalesce(a, …)`
and `concat(a, …)` are scalar registry rows, additive like every row, and
the keyword forms are parse errors whose fix prints the call.

### Relation expressions

The operand of `let $r =` and of `from`:

| Form | Core | Example |
|---|---|---|
| `{ match … where? return … order? limit? }` | the inline read's term | `from { match { $p worksAt $c } return { $c, count($p) as n } }` |
| `name(args)` | `Call`, inlined | `from colleagues($x.handle)` |
| `$r` | the named relation's term | `from $docs` |
| `distance(rel, $x.f, $q)` | `Score`, vector | every row scored with the field's declared distance, exact |
| `bm25(rel, $x.f, q)` | `Score`, lexical | every matching row scored, exact; `q` a String or a `terms(…)` value ([Search](#4-search)) |
| `nearest(rel, $x.f, $q, k: n, recall: r)` | `ApproxTopK` | at most `n` targets with every row of each; `recall` the declared bound, the engine's policy when omitted *[as today]* |
| `rrf(rel, rel, …, k: n, weights: [w, …])` | `Fuse` | arms are scored relations over one node column; the result has that column and the fused score, named by the `as` of the `from` that draws it, and nothing else |
| `union(rel, rel, …)` | `Union` | a bag; arms agree by column base type in order, nullable when any arm is, names from the first |

A ranking function names the column it ranks as a property access on the
population, `$d.embedding`, resolved at compile time, never a string; the
population may carry other node, edge and scalar columns, which ride through
as that target's payload (law 4), so a population that returns a whole
pattern needs no narrowing. Its score column is named where the ranking is
drawn, `from nearest($pop, $d.embedding, $q, k: 20) as $dist`: `as` is
required on a `from` whose relation carries an unnamed score and refused on
any other (`T85`), so a score never enters scope unwritten. The rule reads
the relation's type, not its spelling: a ranking function's result carries
an unnamed score, and so does a `let` name bound to one, so `let $r =
nearest(…)` then `from $r` needs `as`, while an inline read that returns a
named score carries none. Inside a relation function's argument an arm's
score stays unnamed: no expression reads it, no result carries it, and the
enclosing function consumes it by position, `rrf` as the arm's ranking; a
read that needs an arm's score names it in a wrapper read, `{ match { from
nearest(…) as $d } return { $x, $d } }`. The canonical ranked read,
which the cards, the skill and this RFC's examples use, names its population
with `let` before the ranking, so the text runs in data-flow order: `let
$pop = { match { … } where … return { $d } }, from nearest($pop,
$d.embedding, $q, k: 20) as $dist`. `rrf` yields the target column and its
score alone; a read that needs the population's other columns after fusion
draws them again with a `from` over the population correlated on the target.
Two arms drawn into one scope collide on the target column, since each names
its own score; the fix is the one renaming mechanism, a `let` over the
population whose `return` aliases the target.

Three names where edition 2 had one: `distance` is the exact score of every
row under the field's declared distance, `nearest` is the approximate window
under the same distance, `bm25` is the exact lexical score. Each is one core
term, which A6 requires, and each is named by what it selects; `distance`
rather than `l2` because a cosine field's exact form is cosine. The window
form and the exact form answer different questions, and the text shows which
was asked ([The syntax by example](#8-the-syntax-by-example)).

### Scope and correlation

A relation expression may read any variable in scope at the point it is
written; that is what makes `from` correlated. It may not read a variable
bound after it, and an inline read may not rebind one (`T68`); a `let`
relation is a named term under the `Call` rule, within the plan budget and
never recursive, since only a declared read may call itself (`T70`). A
`from` whose relation reads no outer variable is a plain join; the planner
decides between nested and decorrelated evaluation and the report says which
ran (A3). An inner `order` and `limit` belong to the inner read: an outer
`where` never widens an inner cut, and an outer `limit` never becomes the
inner's ([core, Cut](#operators)). Element order inside `match` is part of
the meaning for `let` and `from`, and for nothing else: binders run in
written order, and `let` and `from` see only the elements before them, so
`$d: Doc, from { … $d … }` correlates and the swapped order does not; the
formatter keeps their order. Every inner scope, a block, an `optional { }`
or an inline read, follows one rule: a name it reads from the scope where it is written
correlates; a name new to it is introduced by a binding element, `$m:
Person`, inside it; and a binding of a name already in scope is `T68`. A
triple in an inner scope naming a variable that is neither in scope nor
bound there is `T84`, whose fix inserts the binding with the type the edge
declares for that end. The names a block or an inline read introduces stay
inside it; those an `optional { }` introduces enter the enclosing scope,
nullable, since it is a join and not a value. A block written in `where`
sees every element; in a `let`, the earlier elements.

### Recursion

A declared read may call itself, directly or through other declared reads,
passing its parameters through unchanged, and the cycle compiles to `Fix`.
The rules are Datalog's with monotone aggregation, as the core states them
on the term: the read's `return` is `distinct` or carries `min` or `max`;
nothing on the cycle negates, orders, cuts or ranks the recursive rows, a
count block over them is admitted only in its `exists` reading, and nothing
on it filters, groups or orders by a `min` or `max` column; the read's type
is the fixpoint from its base arms, and a recursion with no base arm is
`T70`. Its columns are node or edge references or values read from stored
properties, and a column it computes is admitted only under `min` or `max`
with `@budget(rounds = n)` declared, whose overrun is a typed error, and
every expression on the cycle that reads a `min` or `max` column preserves
its order, as the core lists (`$d + 1` does; `-$d` and `1 / $d` are `T70`);
`min` with a non-negative step converges on its own, `max` on a cycle does
not, and the budget is what makes the second safe. No new syntax: the
recursion is `from name(args)` inside the body of `name`, and a `union`
joins the base case to the step.

```gq
query reachable($from: String) {
  match {
    from union(
      { match { $p: Person, $q: Person, $p knows $q } where $p.handle = $from return { $q } },
      { match { from reachable($from), $r: Person, $q knows $r } return { $r as q } })
  }
  return distinct { $q }
}

query hops($from: String) @budget(rounds = 50) {
  match {
    from union(
      { match { $p: Person, $q: Person, $p knows $q } where $p.handle = $from return { $q, 1 as d } },
      { match { from hops($from), $r: Person, $q knows $r } return { $r as q, $d + 1 as d } })
  }
  return { $q, min($d) as d }
}
```

`Expand{m,n}` stays the shortest-distance form for a bounded depth;
`reachable` is the unbounded case, and `hops` the one that invents a value.
They differ at the start node: `reachable` returns it when a cycle leads
back, and `Expand` over a range does not, though a single hop returns it
through a self-loop. The report shows the rounds and the frontier per round
as it shows an `Expand`'s frontier. In release B the type checker accepts a
monotone cycle and types it to `Fix`, so every `T70` rule is tested at B,
and refuses the node at type check (`T86`), naming stage Rec, so that no accepted
read reaches the planner unlowered
([Programme](#11-programme-and-rollout)). The reference interpreter agrees
with itself under naive and semi-naive evaluation on every one of 2,801
random recursions these rules admit, and disagreed on 74 of 817 that the
earlier rule (`min` and `max` only) admitted.

### Writes fed by reads

A write is a `query` whose body is one or more groups, each a `match { }`
and its optional `where`, written as a read writes them, followed by one or
more statements; the parser knows the kind from the body's shape, so no
second keyword declares it. `as commit` and `as unattached branch` are
admitted on a write body and refused on a read body. The elements are
exactly a read's: bindings, triples, `optional`, `let`, `from`, and the edge
binding `$k: E`; the `where` is a read's. The statements name what they
write by reference: `delete $x` and `update $x set { … }` take a bound node
or edge variable, and `insert T { … }` takes a type and assignments, an
endpoint assignment being a key literal or a bound reference, and `null` the
one way to clear a property. There is no `where` on a statement: the group's
`match` and `where` are the selection, and a second predicate on the sink
would be a second spelling of a filter (A6). Each statement runs once per
row of its group's relation; its assignment expressions read the bound
variables as `$x.prop`. A statement binds nothing. A group's selection is
evaluated once; its statements run in order, each keyed effect seeing the
ones before it *[as today]*, so `hire`'s edge insert finds the person
inserted beside it and a body that inserts a document and then updates it
by key still works; a later group, opening with its own `match`, sees the
groups before it; the write publishes once (A4). A body mixes no `delete`
with an `insert` or `update` *[as today]*. An `insert` with no `match` is
edition 2's text and means what it meant; edition 2's `delete T where φ` and
`update T set { … } where φ` are rewritten to `match { $x: T } where φ′
delete $x` and `match { $x: T } where φ′  update $x set { … }`, the same
`Filter` over the same `Scan`, one group per edition-2 statement.

```gq
query close_company($slug: String) {
  match { $c: Company, $p $k:worksAt $c } where $c.slug = $slug
  delete $k
}

query relocate_staff($slug: String) {
  match { $c: Company, $p worksAt $c } where $c.slug = $slug
  update $p set { city: null }
}
```

Edition 2 writes `close_company` as `delete WorksAt where @dst = $slug`,
since the company is the edge's own endpoint; the read-fed form is new where
the selection needs a neighbour's property or a second hop, and there it
replaces the two-step an agent writes today, a read for the ids and a write
with `in [ids]`, whose two snapshots can disagree. The written set is known
only by running the selection, which is what `returning` and the dry run
are for; both are the writes RFC's, and until it lands the write's
`explain` shows the selection's plan and its estimates.

### Precedent

XQuery, GQL, Cypher, TypeQL 3, Kusto, LINQ and SQL each keep a value binder
and a row enumerator apart, and none but SQL's column alias list binds query
columns by position; the surface follows both. Construct by construct, the
read skeleton, `where` and the two elements are GQL's (`LET`, `CALL (x) {
}`, `OPTIONAL`, `EXISTS`, `WHERE`, `RETURN DISTINCT`, `LIMIT $k`, `$p`) with
SQL's word `from`; the traversal is Datalog's, positional and
schema-resolved with no arrow; the expression language was the smallest of
the five compared, which is why this RFC adds arithmetic and names the

## 4. Search

Retrieval is three relation functions and a fusion, and this section fixes
what they mean independently of any index. The rule is one sentence: meaning
comes from the accepted schema and the plan, never from index presence,
coverage or segment layout (invariant 7). An exact evaluation path is the
oracle at every coverage state; a native index accelerates only where it
proves the same answer.

### Schema

**Text.** A String property becomes searchable by declaring its full-text
index with an analyzer:

```pg
node Doc {
  slug: String @key                                            // exact only
  title: String @index(fulltext, analyzer = "english_v1")      // matching and ranking
  body: String @index(fulltext, analyzer = "standard_v1", scorer = "bm25_v1")
}
```

`analyzer` names one of three immutable profiles; `scorer` is `bm25_v1`
(the default) or `none`, which allows matching and makes a ranking call on
the field a type error. Every setting of a profile is explicit; unspecified
Lance defaults are never part of the contract.

| Setting | `standard_v1` | `standard_folded_v1` | `english_v1` |
|---|---|---|---|
| Tokenizer | `simple` | `simple` | `simple` |
| Lowercase | yes | yes | yes |
| Stemming and stop words | neither | neither | English stemmer, then English stop words |
| ASCII folding | no | yes | yes, after stemming |
| Token-length filter | disabled | disabled | disabled |
| Unicode normalization | NFC before tokenization | same | same |

A profile never changes once accepted; a different pipeline is a new
profile, and a new profile or scorer version needs an RFC. There are no
query-time analyzer overrides. A String `@index(fulltext)` written without
`analyzer` keeps edition 2's index analysis, Lance's default (English
stemming, stop words, ASCII folding, a 40-byte token filter), so no existing
graph changes rows at the break; lint `L` names the profile to declare,
`english_v1` being the closest, and the contract below applies to declared
analyzers. Declaring one is a schema change applied in place: the field's
index is rebuilt once with the profile, and RFC 0043's certificate records
the field's analyzer fingerprint, so a certificate for the old analysis does
not establish the new one. Accepted SchemaIR owns the fingerprint (profile,
normalizer and Unicode data identity, tokenizer and filter order, scorer
version) as a feature name under RFC 0040; a rename keeps it, drop and
re-add makes a new one.

**Vectors.** `Vector(n, distance = "l2" | "cosine" | "dot")`; an omitted
distance is `l2`, today's meaning, so no accepted schema changes meaning.
`distance(…)` and `nearest(…)` both read the field's declared distance.
The resolved distance is persisted; the index is built with it, and an index
built for another distance is never used, so a changed distance serves from
the exact scan until the index is rebuilt.

| Distance | Value, ascending |
|---|---|
| `l2` | sum of squared component differences, no square root |
| `cosine` | `1 - dot(x, q) / (norm(x) · norm(q))` |
| `dot` | `1 - dot(x, q)`; can be negative |

Cosine is undefined at a zero vector, so a `cosine` field refuses one: a
write that stores a zero vector there fails validation, a zero query vector
is refused before the read runs, and a zero vector stored by an earlier
writer drops its row from `distance` and `nearest` alike, as a null does, so
the scan and the index agree.


**Recipes.** `@embed("source", model = "…")` binds a vector to the String it
embeds. An embedding space is the immutable model revision plus the query
and record encoding choices (roles or prompts, pooling, normalization,
dimensions); a model label, a provider name or a matching dimension is not
proof of a shared space. A schema may declare one default recipe;
`@embed("source")` without a model inherits it when the field first gains a
binding, changing the default never rebinds an existing field, and canonical
export spells out every field's resolved recipe. A String query argument
uses the field's query encoder; a raw vector argument is the caller's
assertion that it is in the field's space, refused when the dimension is
wrong. Three identities stay separate, each a typed versioned descriptor
whose hash is a derived view: the encoding recipe (the space), the field
representation (owner, property, source, resolved analyzer or recipe,
distance) and the query encoding (the recipe and the exact input, belonging
to one execution). A field whose distance changes needs its index rebuilt;
one whose recipe changes needs its vectors regenerated; no export and
reload.

### The lexical query

`terms(text, mode: all | any, max_edits: 0..=2)` describes matching
independently of its consumer: `text` is a non-null String literal or
parameter; `mode` is `all` (every analyzed query term has a matching document
term, the default) or `any`; `max_edits` is a literal or parameter in
`0..=2`, default `0`. Two consumers:

- **`match_terms(field, terms(…))`**, a predicate registry row: a top-level
  conjunct of a `match` (`T38` *[as today]*), legal inside `not`, `exists`
  and the count blocks. It introduces no score.
- **`bm25(rel, $x.f, q)`**, the lexical `Score`: `q` is a `terms(…)` value
  or a String, which means `terms(q, mode: any)`, today's any-term zero-edit
  matching (Lance's `Operator::Or`); the String is the canonical spelling
  of that case, and the formatter writes it. The ranking and the predicate
  agree on membership for the same `terms` value before any cut.

| Aspect | Rule |
|---|---|
| Analysis | the field's analyzer on document and query text, at every edit budget including zero |
| Distance | insertions, deletions and substitutions over analyzed Unicode scalar values, one each; a transposition costs two; no prefix restriction, no length-based tolerance |
| Term identity | repeated query terms need no repeated occurrences; reordering cannot change membership; neither phrase matching nor distance over the whole value |
| Empty text | a query with no searchable terms is a type error; a null or token-empty document does not match |
| Completeness | every result satisfies the predicate exactly; an edit-tolerant predicate advertises no approximate recall |

```text
matches(edits = 0) ⊆ matches(edits = 1) ⊆ matches(edits = 2)
matches(indexed) = matches(unindexed) = matches(partially indexed)
```

**`bm25_v1`** is one versioned scorer for exact and tolerant queries.
Membership is the `terms` relation, evaluated before any cut; a score is
never a second membership test. The statistics population is the
snapshot-visible field corpus: distinct policy-visible entities owning the
property with non-empty analyzed values, before any graph or property
filter, so narrowing a population leaves a surviving entity's score
unchanged and scoring composes with graph filters (the guard
`fts_statistics_scope_can_reverse_ranking` shows the alternative reverses an
order). With `N` the corpus size, `df_q` the documents holding an
alternative of query term `q`, `len_d` and `avg_len` the document and mean
token counts, and `tf(t, d)` a term's occurrences:

```text
idf(q)      = log1p((N - df_q + 0.5) / (df_q + 0.5))
norm(d)     = 1.2 · (0.25 + 0.75 · len_d / avg_len)
weight(t,d) = 2.2 · tf(t,d) / (tf(t,d) + norm(d))
part(q,d)   = idf(q) · max over stored terms t within the budget of 2^(-edit(q,t)) · weight(t,d)
score(d)    = Σ over distinct query terms q of part(q,d)
```

`part(q, d)` is zero when `d` holds no stored term within `q`'s budget, which
`mode: any` admits, so the max is never over an empty set. Alternatives
share their group's IDF, so a rare misspelling cannot gain
weight, and the maximum inside a document stops several spellings summing as
independent evidence; the edit weights `1`, `1/2` and `1/4` are versioned
choices. The numeric profile is `F64` with `libm`'s `log1p`, checked `u64`
counting, no reassociation, summation in ascending UTF-8 query-term order; a
match yields a finite positive score or a typed numeric failure. Native
Lance BM25 is this formula in `f32` at zero edits, membership included, and
something else with edits: each expansion gets its own IDF, alternatives
add, and there is no edit penalty, so seven of the ten edit-tolerant oracle
fixtures rank differently natively, by up to 24.5 times
([Evidence](#10-evidence-and-tests)). Only the zero-edit shape can therefore
ever be certified on a native path.

**Exact execution and qualified acceleration.** The analyzer is
instantiated from accepted SchemaIR whether or not an index exists; an index
is never its carrier. Engine v2's scan evaluates the typed predicate over
streamed document tokens with that analyzer and the edit relation, bounding
query bytes, distinct terms, value sizes and work before allocation (NFC can
expand UTF-8). This path is the oracle at every coverage state, and it is
what lets a declared but unbuilt index answer instead of refusing (RFC
0047's `FullTextIndexRequired`). A native path is eligible only when its
artifact passes RFC 0043's proof for the accepted profile and its whole
pipeline is qualified for the mode and edit budget. Lance 13's fuzzy
expansion keeps the fifty lexicographically smallest expansions per term and
does not protect the exact term, so a one-edit query can miss the document
that holds the term exactly: the native path breaks `matches(0) ⊆
matches(1)`, not only completeness, and edit-tolerant shapes use the exact
scan even with an index until an expansion budget covering the automaton's
limit is qualified. A native index also carries no NFC step and, with the
experimental 256-document posting blocks, quantizes document lengths, so
the RFC 0043 fingerprint that qualifies one records the posting block size
and format version, a 256-block index never qualifies, and how a declared
profile's NFC reaches the index, a derived normalized column or
normalization at write, is for stage L to decide
([Unresolved](#unresolved-questions)). RFC 0047's validator checks the plans
as invariants, search identity, retained predicate, scoring corpus, score
origin, required ordering, cut placement, prerequisites and the declared
contract, and each shape joins its exact subset only through a versioned
rule addition with its own regression.

A `Cut` over an `Order` over a zero-edit `bm25` may use Lance's limited
full-text path, block-max WAND, as a ***certified candidate generator***
when nothing above the scan drops rows, every filter is a prefilter under
full coverage, no fragment of the table carries a deletion file, no
row-level read policy narrows the property's entities, and the property's
entities live in one table, since native statistics are the index's and not
the field corpus otherwise. The fetch asks for `k + m` candidates, rescored
in `F64` by `bm25_v1`, and is accepted when the k-th rescored score exceeds
the last fetched native score times `1 + ε` plus `δ`: `ε` a stated bound on
Lance's relative `f32` error for the query's term count, and `δ` an absolute
bound, the largest error of a term's native IDF times the largest weight,
`2.2`, summed over the query's terms, since Lance rounds a common term's
IDF to zero at `N = 2^24` ([Evidence](#10-evidence-and-tests)) and no
relative bound covers an error from zero; a tie fails the margin, and the
exact scan is the fallback. Lance's limited and unlimited paths return
bit-identical scores and the exact top-k score set, but its `f32` order can
tie or invert two documents whose `F64` scores differ by less than an ulp,
which is why bit-identity with Lance is not exactness and the margin is
needed. The fetch prunes scoring work by an amount that depends on `k`
against the matched set and is not reproducible run to run, so the plan
states its cost as the unlimited scan's and the report keeps Lance's
comparison counter out of anything replay compares.

**Migration.** `search`, `match_text` and `fuzzy` stay registry rows for
good; `queries fmt` canonicalises them to
`match_terms(f, terms(q, mode: any[, max_edits: n]))`, the mapping that keeps
today's any-term membership (`fuzzy(f, q)` with no budget is two edits, as
today), and lint names the rewrite. An edit budget outside `0..=2` becomes a
type error. On a field whose index declares no analyzer the three keep
today's behaviour.

### Vector retrieval

| Call | Core | Result | Cost | `recall` descriptor |
|---|---|---|---|---|
| `distance(rel, $x.f, $q)` | `Score` | every row of the population with its exact distance under the field's declared distance | a scan of the population's field | `exact` |
| `nearest(rel, $x.f, $q, k: n, recall: r)` | `ApproxTopK` | at most `n` targets with every row of each; the index may miss some, a boundary tie included | index probes widened by the ladder, plus the uncovered tail | `approximate`, with the declared `r` |

A returned distance is always the exact distance under the field's distance;
approximation affects only which targets are found. Today's index family,
IVF_FLAT, keeps raw vectors and meets this; a quantized family must refine
its candidates. Missing coverage never drops the uncovered rows; it changes
cost. `recall` is the one place a read declares the bound it accepts;
physical effort (`ann_nprobes`, the overfetch ladder) stays a session
setting the plan records, because the query states meaning and not effort.

The bound is a target, not a per-query guarantee: `recall: r` asks that the
expected share found of the exact window's `k` targets, the top `k` of
`distance` under the tie rule, be at least `r`, and the planner resolves it
with the session's effort settings to a probe policy the plan records. A run
reports `exhaustive` when it searched every partition, the one achieved
recall it can prove, and otherwise `approximate` with the declared `r`,
never a measured figure it does not have; `recall: 1` searches every
partition and is always exhaustive. An estimated achieved recall for a run
that is not exhaustive is stage R's.

The exact counterpart of `nearest`'s window is a target window. Over a
population with one row per target it is `distance` with `order { $distance
}` and `limit n`, the tie rule taking the boundary to the smaller id, so its
membership is the same on every run. Over a population with several rows per
target, `limit` counts rows, so the exact window takes `n` targets first, an
inline read returning `distinct { $x, $distance }` in that order with `limit
n`, and draws their rows again with a `from` over the population correlated
on the target, as after fusion. `nearest` is the canonical answer to an
unqualified request for the `k` most similar; `distance` is for an exact
answer or a radius, and it scans the population, which the skill says in
those words, since an agent given both chose the scan three times of three.

### Fusion

`rrf(arm, arm, …, k: 60, weights: [w, …])` takes 2 to 16 arms, each a
scored relation over one node column of the same name and type in every
arm. An arm produced by a ranking function is ranked by its own column in
its kind's direction, distance ascending and score descending; any other arm
must be an inline read with an `order`, which ranks each target at its first
row in that order, the tie rule breaking equal keys, so a target appearing
again further down takes no second rank. Each arm ranks the distinct targets
it selected, then by target id, from 1, so two targets tied in every arm
still get distinct fused scores *[choice]*:

```text
rrf(target) = Σ over arms that selected target of weight[arm] / (k + rank[arm, target])
```

The sum runs in written order in `F64`; `k` is in `1..=1000000` and each
weight in `(0, 1000000]`, default `1.0`, so the sum cannot overflow; a
target no arm selected is absent, and a missing arm contributes nothing
rather than zero. Two arms with the same population, field and query are a
type error, since `weights` expresses emphasis; arms over different node
columns are a type error, since the fused target would be a pair. Fan-out
rows of one target carry its score and add no vote; the result is one row
per target with the target column and the fused score, which the drawing
`from` names with `as`, and no population column, where today's fusion keeps
fan-out rows and population columns; a read that needs them draws them
again with a `from` over the population correlated on the target. An arm's
own score is unnamed inside the call (section 3): a wrapper read names it,
and
`optional { from … }` keeps the targets the other arm missed, so an arm
metric is null exactly where the arm did not select the target.

### Populations and laws

Four populations stay distinct, and every implementation keeps passing
their counterexamples: three eligible incidents and a window of two count
three before the window and two after; after fan-out three rows can hold two
incidents and `count($i)` counts rows; a global window can leave a group
empty and nothing refills it; changing eligibility leaves `bm25`'s corpus
statistics unchanged.

| Population | Meaning |
|---|---|
| Eligible | the distinct targets of the relation a ranking function takes, with their rows |
| Scoring corpus | the data behind a scorer's statistics, the field corpus for `bm25` |
| Selected | the targets that survive a window or cut |
| Aggregate input | the rows an aggregate reduces |

The laws, each one sentence because the core already holds most of them:

1. Eligibility before selection: the population relation decides who is
   eligible; a ranking selects and orders within it; projection changes
   neither.
2. Cuts are semantic: no predicate, traversal or aggregate crosses a `Cut`
   without a proof the answer is the same; policy is never a filter after
   a cut.
3. Windows are separate: `k`, physical effort and the final `limit` are
   three values, and an outer `limit` never sizes an inner window; `k` is
   required, so no default can couple them.
4. Target identity: a ranking ranks the distinct targets of one node column;
   fan-out carries the score and adds no vote.
5. Index state never changes an exact answer: `distance`, `bm25` and `match_terms`
   return the same rows under every index state in which they answer; an
   approximate `nearest` may miss targets but never drops the uncovered
   rows as a whole.
6. Every cut is total, over one total order.
7. Partitions never redefine the population: fragments, segments and shards
   are physical; a per-partition cut needs an exact merge or a declared
   approximate contract.
8. Meaning is resolved and versioned: analyzer, scorer, distance, recipe and
   fusion formula come from the accepted schema and the plan.
9. One snapshot for every arm, traversal, statistic and read (A2).
10. Separate facts: completion, representation coverage, approximation and
    relevance are reported apart; none is a probability the answer is
    right.
11. One resource protocol: rankings, fusion and exact scans charge the
    query's memory; exhaustion is a typed failure.

### Errors

Type errors: an unknown option, listing the admitted names; an option out of
range; `weights` whose length differs from the arm count; duplicate arms;
arms over different node columns; fewer than two or more than sixteen arms;
a ranking call on a `scorer = "none"` field; a token-empty query; an edit
budget outside `0..=2`; a raw vector of the wrong dimension; a ranked column
that is not a node column of the population, or whose property is not
declared for its type (`T27` *[as today]*);
`nearest` without `k` (`T17` *[as today]*). Execution errors: exhausted
memory or an exceeded work bound, typed, never an empty or truncated result.
A target missing from one arm is not an error.

## 5. Types and diagnostics

Every refusal keeps the four-field diagnostic, and a compile returns every
independent refusal of its earliest refusing stage in one pass, in source
order, each with its span. The stages are parsing, then name resolution and
typing, where `T86` belongs; lowering refuses nothing, since `P006` is a
defect. Two refusals are ***independent*** when neither follows from the
other: the parser resumes at the next element, item, statement or
declaration boundary, and the type checker gives every refused construct an
error type that passes every check, so a refusal whose only cause is an
earlier refused construct is not reported. A refusal of an unknown name (a
type, property, edge, column, option or enum value) lists up to five nearest
names of the right kind from the schema, with their types. Applying every
machine-applicable suggestion of one pass reparses, never undoes an earlier
edit, and either strictly shrinks that stage's refusals or clears them, so
the next stage reports its own; a test over the expect-error cases requires
a fixed point within three passes, and the red-team corpus, which stays
outside the repository, is run against the same rule before acceptance. Codes are allocated at
implementation under the catalogue rule in
`crates/omnigraph-compiler/src/query/codes.rs`; the names below are the ones
this RFC uses for them.

- A `let` scalar has the expression's type and nullability. A `let`
  relation has the relation's column list. A relation in scalar position is
  `T69`; a scalar in relation position (`from $v` where `$v` is a scalar) is
  the same code with the other fix.
- `from` adds the relation's columns to Γ by name; a collision is `T68`, and so is a binding, inside an inline read, a block or an `optional { }`, of a name in Γ; a name
  an inner scope reads without binding correlates (section 3). A column that
  is neither a variable nor aliased cannot be drawn from (`T74`), and the
  type checker names the column and the alias to add.
- A literal compared with a property, or listed in an `in` against one, is
  checked against the property's type wherever it is written (`where`, a
  block's or an `optional`'s `where`, a write group's `where`, a `let`): an
  enum value outside the declared set, a number against a property that is
  not numeric, an integer literal outside an integer property's range, or a
  malformed date is `T3`, with a suggestion naming the nearest allowed
  value. A float literal compared with an integer property is not one:
  section 2 compares them as `F64` through a `Cast`, as it compares an
  integer with a float anywhere. Edition 2 checked these only inside property
  braces, which edition 3 removes; without this rule a misspelled enum value
  returns no rows.
- `Call` resolves against the declarations of the same source unit *[choice]*,
  case-sensitively, exactly one; two declarations of one name in a source
  unit are `T83`, naming both spans, with the fix that renames or deletes the
  later; the registry is not searched for a declared
  read's name, and a declared read may not shadow a registry name. A budget
  overrun, a cycle that is not monotone, or a cycle with no base arm, is
  `T70` with the chain and the offending construct; a monotone cycle types to
  `Fix`, its type the fixpoint from the base arms; `let $r = rel` names a
  term under the same budget, at local scope, and may not recurse.
- `distance`, `bm25`, `nearest`, `rrf` and `union` are registry rows of kind
  `relation`; a ranking's second argument is a property access on a node
  column of its population, `Vector(n)` for `distance` and `nearest` and
  indexed full-text for `bm25` (`T27` *[as today]*), the error naming the
  column when it is not one; `nearest` requires `k` (`T17` *[as today]*) and
  takes `recall` in `(0, 1]`, the one place a read declares it: a per-query
  annotation would be a second spelling, and two windows in one read can
  want two bounds. A registry row is never named a keyword (`let`, `from`,
  `where`, `optional`, `exists`, `not`), for the reason a declared read
  never shadows a registry name.
- A block aggregate in operand position has the aggregate's type; `T40` no
  longer restricts its comparison partner.
- Arithmetic types as the core states: operands of one numeric width keep
  it, a narrower integer widens to the wider, an integer with a float is
  `F64`, a non-numeric operand is a type error naming it, and the result is
  nullable when either operand is. Overflow, a zero divisor and a non-finite
  float result are typed execution errors on the row, never a null or a
  wrapped value; the term carries `can_fail` so the planner keeps it behind
  its guards.
- `if(c, a, b)`, `coalesce(a, …)` and `concat(a, …)` are scalar registry
  rows added with the registry, `if` and `coalesce` evaluating only the
  arguments they select (section 2); `union` is a relation row whose arms must
  agree by column type in order, the mismatch naming the arm and column.
- In a write body, `delete` and `update` take a bound node or edge variable
  and `insert` a type; an endpoint assignment is a key literal of the
  endpoint's key type or a bound reference of the endpoint's type, the
  mismatch naming both; a `where` on a statement is a parse error whose fix
  prints the `match` and its `where`, the bare names of the predicate and of
  the assignments qualified and the binding's name chosen outside the scope;
  a write's elements written without `match { }` are a parse error whose fix
  adds it; `as commit` or `as unattached branch` on a read body is a parse
  error, since the kind is in the parse tree; the registry, the `@View` row,
  MCP write gating and policy scope read the kind there; a body mixing
  `delete` with `insert` or `update` is `T76`; two different values for one
  entity and property from the rows of one statement are a run-time refusal
  (`E` namespace), and across statements the later wins.
- The search refusals of [section 4](#4-search): an unknown option listing
  the admitted names, an option out of range, duplicate arms, arms over
  different node columns, an arm count outside 2 to 16, a `weights` length
  that differs from it, a ranking on a `scorer = "none"` field, a
  token-empty query, an edit budget outside `0..=2`, a raw vector of the
  wrong dimension.
- `T65` for a ranking written as a call in `order` or `return`, with the
  `from` fix; `T5`, `T22`, `T33`'s projection-under-`rrf` rule and the rest
  of today's codes keep their texts, re-anchored to registry rows. `T38`
  goes: a lexical predicate is a Boolean operand like any other, so `not
  search(…)` and `search(…) or …` are written as any Boolean is, and the
  exact lexical scan answers them where no index does (invariant 7). Infix
  `contains` is refused at type check, not parse, because the left operand's
  type decides between the `contains(…)` and the `in` fix; the same holds
  for `in` inside `match`, a triple to the parser, whose `where` fix `T7`
  prints when the right end is a list.
- Every fix is a `suggestion` of byte-range edits, the human text derived
  from it, so that an agent or the tool applies it mechanically; a test
  applies the suggestion of every refusal code and compares the reparsed
  tree with a pinned one. A refusal of a form a later stage adds names the
  stage. A parse error names the construct, never a grammar rule, and a
  short table recognizes the habits agents bring from other languages
  (single-quoted strings, `<>`, `==`, `&&`, `!`, uppercase keywords,
  `count(*)`, `-[:e]->`, `(a:T)`, `return x` without braces, `offset`,
  `group by`, `having`, `with`, `call`, `detach`) and prints the GQ form;
  the table is a lexical pass whose edits compose with the grammar
  recognizers into one suggestion; a bare identifier is not a value in a
  `match`, `where` or `return`, so a foreign word is a parse error at the
  word rather than a filter the type checker refuses later; the one
  bare-name position besides an `order` alias is the predicate of the
  statement-`where` recognizer, so that edition 2's `delete Person where
  handle = $h` still prints its fix. A parse error prints a suggestion
  wherever one exists; the refusals with none are listed in section 3 and
  name the construct. On the red-team corpus of 395 agent-written texts
  (`spike/gq3-grammar2`, the clause-list surface), 151 of 178 refusals carry
  a suggestion that reparses to the intended text and 6 texts still parse
  differently from the RFC's reading; the corpus is re-run on this surface
  before acceptance.
- A read the type checker accepts, the planner lowers. Acceptance is per
  release: a term the release's planner does not lower is refused by the
  type checker at the construct (`T86`), naming the later stage that adds
  it; its suggestion, where it has one, writes a lowered form with the same
  rows and the same result columns, and otherwise it prints none. `T86`
  never names the release's own stage: a term this RFC places in B that B's
  planner does not lower is a defect that blocks B, not a refusal. The
  closure table is the release test: every row it marks "works" lowers, and
  no text on a card or in the skill reaches `P006` or a `T86` that names B.
  On an implementation branch before the release, an unlowered B term may
  be refused with `T86` naming B so that it fails at type check rather than
  at run time; the closure-table test lists each one, and B ships when the
  list is empty.
- The codes this RFC allocates beside `T65`, `T68`, `T69` and `T70`: `T71`
  an option unknown, out of range or positional; `T72` a non-numeric or
  unsupported arithmetic operand; `T73` `union` arms that disagree; `T74` a
  name refused as a relation; `T75` an `rrf` arm fault; `T76` a write mixing
  kinds; `T77` a statement over a variable that is not a reference; `T78` an
  endpoint assignment of the wrong type; `T79` a ranked column that is not a
  node column; `T80` an annotation that is not read; `T81` a pattern whose
  components share no variable and are not key-pinned; `T82` a triple
  written against its edge's declared direction, or a selection none of
  whose members points along the written order; `T83` two declarations of
  one name in a source unit; `T84` a name an inner scope uses in a triple
  without binding it; `T85` a ranked `from` without `as`, or an `as` on a
  `from` that ranks nothing; `T86` a term the release's planner does not
  lower, naming the later stage that adds it; `P006` the planner's assertion that a term the
  type checker accepted arrived unlowered, a defect and never a refusal a
  query's author sees; and the `E` namespace for run-time refusals: integer
  overflow, a zero divisor, a non-finite float, a round budget overrun, a
  write conflict found through rows. `T27` stays the full-text code and
  `T15` the vector one. A String key literal for an integer key in an edge
  endpoint is accepted *[as today]*.
- The lint prefix `L` is added for the formatter's rewrites (`count { } > 0`
  to `exists`, a `search` or `match_text` or
  `fuzzy` call to `match_terms` once that lands) and for two rows-equal
  rewrites the formatter does not apply because they change the typed IR,
  `count { } >= 1` to `exists` and `count { } = 0` to `not exists`, and for a
  `limit` no larger than a preceding `nearest(…, k:)`.
- An unknown annotation is refused, with the exception of an allow-list of
  pure metadata the compiler never reads (`@description`, `@instruction`,
  `@example`, `@rename_from`), which is retained as `.pg` retains it today.
  Retaining every unknown name would make a later typed annotation
  non-additive: a `@budget` accepted and ignored in this release would start
  refusing reads when its stage types it. The rule for a later form is
  therefore: it starts at a token edition 3 refuses, or at a name the type
  checker refuses today with a pinned test (`@type_id` under `T6`, an open
  traversal bound under `T15`, a schema catalogue name, an unknown
  annotation); a form edition 3 accepts and ignores is not additive and is
  not admitted.

The catalogue exposes the same contracts: `@Function` rows carry kind,
parameters, options, result columns for relation functions, `can_fail` and
`volatile`; a declared read is a `@View`-shaped row with its parameters and
result columns, which is the one place the word survives.

## 6. The break

### One language

The release parses edition 3 only. There is no edition line, no edition-2
parser in the product, and no edition recorded beside a stored source. A
source written in edition 2 fails to compile like any other invalid
source, and every edition-2 form that edition 3 refuses prints its fix
(section 5). `queries validate`, `cluster plan` and `lint` report it with
that diagnostic.

### What a reader sees changed

```gq
// edition 2
query passages($matter: String, $q: String) {
  match {
    $r: SourceRevision { matter_number: $matter }
    $r hasPassage $p
    $p.text contains "tariff"
  }
  return { $r.path, $p.locator, bm25($p.text, $q) as score }
  order { bm25($p.text, $q) desc }
  limit 5
}
```

```gq
query passages($matter: String, $q: String, $k: I64 = 5) {
  match {
    let $pop = { match { $r: SourceRevision, $p: Passage, $r hasPassage $p }
                 where $r.matter_number = $matter and contains($p.text, "tariff")
                 return { $r, $p } },
    from bm25($pop, $p.text, $q) as $score,
  }
  return { $r.path, $p.locator, $score }
  order { $score desc }
  limit $k
}
```

The ranked read is longer: the population is named first as a relation, the
score is named where it is drawn, and the filters leave the pattern for
`where`. That is the cost of one shape for every retrieval, and the rewriter
pays it, not the author of stored text.

### The rewriter

The rewriter is a one-shot development tool, not part of the product. It
rewrites the repository's `.gq` and `.pg` text, the GQT corpus, user guide,
skill, examples and benchmarks included, in the break's change, and is
then discarded. No upgrade or migrate command ships: it would be a
compatibility path to maintain. It parses each source under
edition 2 and writes edition 3 as byte-range edits, proves each edit at the
strongest of three levels that holds (a typed IR equal to the original's;
else the same physical plan; else the same rows on every GQT case that runs
the text), writes no edit it cannot prove at one of them, names the
construct it could not prove, and is idempotent. The change lists every
edit proved below IR equality, before and after, for review.

| Edition 2 | Edition 3 |
|---|---|
| `$x.title contains "g"` | `contains($x.title, "g")` |
| `$x.tags contains "rust"` (a list) | `"rust" in $x.tags` |
| `$x.title starts_with "O"` | `starts_with($x.title, "O")` |
| `fuzzy($x.title, $q, 2)` | `fuzzy($x.title, $q, max_edits: 2)` |
| a filter clause in `match` | a conjunct of the `where` after the braces, in written order, joined by `and` |
| `$x: T { p: v, … }` | `$x: T` and the conjuncts `$x.p = v`, leading the `where` in written order |
| `not { P }` | `not exists { P }` in `where`; a block whose only content re-mentions an outer binding to filter it, `not { $p: Person { name: "bob" } }`, becomes the conjunct `not coalesce($p.name = "bob", false)`, or `not ($p.name = "bob")` where the predicate cannot be null, keeping the rows the block kept where the property is null; a negated lexical predicate the same way, `not coalesce(search($d.t, $q), false)` |
| a block, `optional { }` or inline read naming a fresh variable only in a triple, `count { $p worksAt $c }` | the binding inserted with the type the edge declares for that end, `count { $p: Person, $p worksAt $c }`; proved by plan |

| a block's filter clauses | the block's own `where`, inside its braces |
| clauses, `return` items and assignments separated by whitespace | commas |

| `delete T where φ` | `match { $x: T } where φ′  delete $x`, `$x` a name the declaration does not use, φ′ being φ with each bare property prefixed `$x.` and the endpoint names `from` and `to` written `$x.@src` and `$x.@dst`; `T` an edge type binds the edges |

The population the rewriter writes, named `$pop` or a fresh variant, returns
every variable the pattern binds, the ranking names its column and its
score keeps edition 2's name through `as`, so every downstream reference still
resolves; after `rrf` the tool draws the population's other columns again
with a correlated `from`. A result column an edition-2 query produced keeps
its name and type through the alias the tool adds, with the one rename the
fixed map lists. The tool takes the schema as a required input, since a
`contains` over a list and over a String are different rows, and it has a
fragment mode for a fenced block that is not a whole declaration. A human
may simplify afterwards; the rewriter never has to. On the repository's
3,231 stored declarations the spike of 2026-11-08 measured the clause-list
surface: 600 rewritten, 2,581 needing no edit, and 50 carrying a refusal,
17 fusions with duplicate arms or arms over two bindings, which edition 3
refuses by type and which are edited by hand, 2 `asc` rank keys, 3
rankings illegal in both editions, and 28 multi-statement bodies that the
group rule rewrites. The five respelling rows above edit nearly every one
of the 2,581 as well, since a read with a filter, a property brace or two
clauses changes; the refusals are the same, and the counts are re-measured
when the tool runs.

The proof compares typed IR where it can. The three structural rows, an
inserted binding, a swapped triple with both ends bound and a product
written as a `from`, change the core term by construction: an inserted
binding types to a `Scan`, an `Expand` and an identity `Filter`, a swapped
triple starts its `Expand` at the other end, and a named product adds an
inline read. Their proof is the plan, which the planner reduces to the one
the original lowered to, and their rows are checked on the engine wherever
a case runs them. Typed IR equality holds for the five respelling rows, each of
which moves a predicate within one `Filter` or spells one term without
whitespace separators (the instrument's 98 ground truths, converted to this
surface on 2026-11-11, lower to exactly their core IR), for the four
expression rows, and for the two write-statement rows, which lower to the
`Filter` over the `Scan` the edition-2 `where` lowered to, with the sink
above it; the spike proved the selection equal on the engine for 114 corpus
statements and the group rule equal on 52 multi-statement bodies. For the
ranking rows it holds after a stated ***normalisation*** of seven rules: N1,
the read's only `match` element is the `from` of a ranking; N2, the
population is the whole `match` and its `where`, returning exactly the
variables the pattern binds, with no `distinct`, `order` or `limit`; N3, a
`nearest` window has `k = limit`, and an arm under `rrf` has `k = limit` or
`k = 100` with no `limit`; N4, the score column is the leading order key, or
absent under an aggregate; N5, a bare rank key sorts descending; N6, a `let`
population is inlined; N7, `k: 60` on `rrf` is the default. Under them the
window over a population lowers to the ranked scan the edition-2 `order`
lowered to, the pattern's filters as the scan's prefilter *[as today]*, so
`search_node` finds what it finds today: 107 of 111 `nearest`, 35 of 39
`bm25` and 27 of 28 `rrf` rewrites are IR-equal, every remaining one a
refusal both editions make or the one rename the fixed map carries. That
lowering holds where the population has one row per target. Where it fans
out, the window counts targets and the `limit` counts rows; the first `n`
rows in score order belong to at most `n` targets, so with `k = limit` the
rows are equal, though the plan carries a target cut that edition 2's did
not. Rows are
checked on the engine too: 79 of 79 `nearest` and 29 of 29 `bm25` steps
equal, and `rrf` 21 of 21 in the type-population form above (18 of 21 in the
population form, which is why the tool emits the former). The 2026-11-01
numbers (1,818 declarations IR-equal, 2,968 generated reads) were measured
on the `retrieve` rows and are superseded.

### Stored sources at upgrade

A stored source that does not compile under the release refuses at boot
and in `cluster plan` with its diagnostic, as an invalid source does today.
Nothing converts it. Every refused edition-2 form prints its fix as
byte-range edits (section 5), which is enough for an agent or a person to
rewrite the source; that makes the fixes of `T7`, `T65`, `T71` and `Q008`
part of the break's contract, tested per code.

### `queries fmt`

The formatter canonicalises what the grammar cannot forbid and never changes
the typed IR. Its list is the complete set of non-canonical forms A6 admits:
`count { P } > 0` to `exists { P }`; a nested `union` to the flat one; the
ends of `<e>` and the members of an alternation to a stable order; `asc`
dropped; an alias equal to its column's name dropped; a call's options in
the registry's order with those equal to their default dropped; `bm25` over
`terms(q, mode: any)` to the String; and, once the lexical RFC lands
`match_terms`, the three older lexical calls to it. The type checker spike
pinned thirteen exact collisions in the typed IR on the clause-list surface;
five of them, `not exists { P }` beside `not { P }`, a property brace beside
its equality filter, a filter's position among the clauses, a top-level
`and` beside two filter clauses, and `return` items with and without commas,
were spellings this surface removes, and the eight that remain are re-pinned
with the parser. The formatter also prints a short `match` on one line and a
long one an element per line with a trailing comma. Two rewrites that are
rows-equal but change the IR, `count { P } >= 1` to `exists` and `count { P
} = 0` to `not exists`, are lint's and not the formatter's. A `from` over a
wrapper read whose only purpose is a rename is left alone; the formatter
does not invent a shorter form the grammar does not have.

## 7. The grammar

One grammar for schema and queries, today's `query_file` extended, as
revised on 2026-11-01. The rules below replace edition 2's in the one
grammar file and take plain names. The rule-set pin of section 11 names the
set below. In full:

```pest
query_decl    = { kw_query ~ ident ~ param_list ~ annotation* ~ (as_commit_clause | as_unattached_clause)? ~ "{" ~ (read_body | mutation_body) ~ "}" }
param_list    = { "(" ~ (param ~ ("," ~ param)*)? ~ ")" }
param         = { variable ~ ":" ~ type_ref_or_kind ~ ("=" ~ "-"? ~ literal)? }
annotation    = { "@" ~ ident ~ ("(" ~ annotation_arg ~ ("," ~ annotation_arg)* ~ ")")? }
annotation_arg = { ident ~ "=" ~ annotation_value | annotation_value }
read_body     = { match_clause ~ where_clause? ~ return_clause ~ order_clause? ~ limit_clause? }
match_clause  = { kw_match ~ "{" ~ elements ~ "}" }
elements      = { element ~ ("," ~ element)* ~ ","? }
element       = { let_clause | from_clause | optional_block | binding | traversal }
where_clause  = { kw_where ~ expr }
block_body    = { elements ~ where_clause? }
let_clause     = { kw_let ~ variable ~ "=" ~ (inline_read | expr) }
from_clause    = { kw_from ~ relation_expr ~ (kw_as ~ variable)? }            // `as` names a ranking's score (T85)
relation_expr  = { inline_read | call | variable }
inline_read    = { "{" ~ read_body ~ "}" }
optional_block = { kw_optional ~ "{" ~ block_body ~ "}" }
binding       = { variable ~ ":" ~ type_name }                                          // a node or an edge type
traversal     = { variable ~ edge_binding? ~ (undirected_edge | edge_sel) ~ traversal_bounds? ~ variable }
edge_ident    = @{ ident }                                                                // any word, keywords included; a quoted name is accepted too
block_value    = { (agg_name ~ ("(" ~ expr ~ ")")? | kw_exists) ~ "{" ~ block_body ~ "}" }
operand       = { "(" ~ expr ~ ")" | block_value | agg_distinct | literal | call | prop_access | meta_field | variable }
call           = { call_name ~ "(" ~ call_args? ~ ")" }
call_args      = { positional ~ ("," ~ positional)* ~ ("," ~ option)* | option ~ ("," ~ option)* }
positional     = { !(ident ~ ":") ~ (inline_read | expr) }
option         = { ident ~ ":" ~ (expr | expr_ident) }                                    // a bare word for an enumerated option, `mode: any`
agg_distinct   = { agg_name ~ "(" ~ kw_distinct ~ expr ~ ")" }
expr          = { or_expr }                                                              // or, and, not as today
comparison    = { sum ~ ((comp_op ~ sum) | (kw_in ~ sum) | null_test)? }
sum           = { product ~ (("+" | "-") ~ product)* }
product       = { unary ~ (("*" | "/" | "%") ~ unary)* }
unary         = { "-" ~ unary | operand }
integer       = @{ ASCII_DIGIT+ ~ !(ASCII_ALPHANUMERIC | "_" | ".") }
float_lit     = @{ ASCII_DIGIT+ ~ "." ~ ASCII_DIGIT+ ~ (("e" | "E") ~ ("+" | "-")? ~ ASCII_DIGIT+)? ~ !(ASCII_ALPHANUMERIC | "_") }
return_clause = { kw_return ~ kw_distinct? ~ "{" ~ projection ~ ("," ~ projection)* ~ ","? ~ "}" }
projection    = { expr ~ (kw_as ~ expr_ident)? }
order_clause  = { kw_order ~ "{" ~ ordering ~ ("," ~ ordering)* ~ ","? ~ "}" }
ordering      = { (expr | expr_ident) ~ order_dir? }                                    // a bare name here is a return alias
limit_clause  = { kw_limit ~ (integer | variable) }
mutation_body = { write_group+ }
write_group    = { (match_clause ~ where_clause?)? ~ mutation_stmt+ }
stmt_keyword   = @{ ("insert" | "update" | "delete") ~ !(ASCII_ALPHANUMERIC | "_") }
mutation_stmt = { where_stmt | insert_stmt | update_stmt | delete_stmt }
insert_stmt   = { "insert" ~ type_name ~ "{" ~ assignments ~ "}" }
update_stmt   = { "update" ~ variable ~ "set" ~ "{" ~ assignments ~ "}" }
delete_stmt   = { "delete" ~ variable }
assignments   = { assignment ~ ("," ~ assignment)* ~ ","? }
assignment    = { ident ~ ":" ~ (null_value | expr) }
null_value     = { kw_null ~ &("," | "}") }
where_stmt     = { ("update" ~ (variable | type_name) ~ "set" ~ "{" ~ assignments ~ "}" | "delete" ~ (variable | type_name)) ~ "where" ~ where_expr }   // edition 2's form, recognised first to print the fix; where_expr admits bare names
```

The rules that exist only to print a fix are `arrow_traversal`,
`where_stmt`, the `mutation` recognizer, the recognizers for a filter, a
`where` and property braces inside `match { }`, for `not { }`, for a missing
comma and for a write's elements without `match { }`, the infix `contains`
and `starts_with` recognizer (word-bounded, not touching `(`), the
chained-comparison recognizer, the `let … in`, `for`, `unwind`, `CASE` and
`||` recognizers, and the table of foreign words. Each prints a byte-range
suggestion.

Decisions the prototype forced, each pinned by a parser test:

- A positional argument admits an inline read, or no ranking example would
  parse; an inline read is not an operand, so an element still cannot begin
  with `{`.
- A block is an operand and nothing else. The edition-2
  `subquery_predicate` and `exists_block` rules are gone, since beside a
  block operand they gave `count { p } > 2` two trees and read `count { p }
  > 1 or $x` with the wrong precedence.
- `$a * $b` is the wildcard triple in `match` and a product in an
  expression; with predicates out of `match`, the two never meet.
- Inside `match` any word is an edge name, keywords included, and none is
  quoted: no expression is written there, and a lone variable is not an
  element, so `$d in $x` and `$a from $b` are triples. Edition 2's quoted
  `"in"` and the reserved edge names that kept a triple apart from a filter
  go with the clause list; a quoted name is still accepted.
- A bare identifier is an operand nowhere in a read but as a return alias in
  `order`, so a word from another language fails at the word.
- `date("…")` is the literal, not a call.
- A declaration's kind is decided at the token after its first `match { }`
  and `where`: `return` makes a read, a statement makes a write.
- A write group after the first opens with its `match`; consecutive
  statements are one group.
- A negative parameter default admits one sign; `signed_integer` stays
  schema-only.

`let`, `from` and `where` are contextual, word-bounded keywords, legal as
property names, aliases, assignment names and parameter names. At element
start, `from` is the element when the next token is `{`, `$` or a call, and
`let` when the next token is `$`; otherwise each is a parse error there. The
parser spike's corpus walk is the regression owner. Its 2026-11-08 counts,
of 2,753 stored texts 2,398 parsing unchanged, are of the clause-list
surface; under this one nearly every stored read changes, every change a
rewriter row with its fix printed. Every byte-range suggestion trims the
trailing whitespace pest leaves inside a span.

## 8. The syntax by example

The [before-and-after corpus](assets/2026-11-07-gq-3-before-and-after.md)
writes forty-three kinds of query in edition 2 and in edition 3 over one
schema, marking what edition 2 cannot express. The schema and three of its
examples are enough to read the rest of this document.

```pg
interface Named { name: String }

node Person implements Named { handle: String @key  name: String  age: I32?  city: String? }
node Company implements Named { slug: String @key  name: String }
node Doc { id: String @key  title: String  body: String @index(fulltext, analyzer = "english_v1")  year: I32  tags: [String]  embedding: Vector(3, distance = "cosine")? @embed("body") }
node Collection { slug: String @key  min_docs: I32 }

edge WorksAt: Person -> Company @card(0..1)
edge Knows: Person -> Person
edge Authored: Person -> Doc
edge Cites: Doc -> Doc
edge In: Doc -> Collection        // traversed as in
```

**A grouped result, filtered.** The inner read groups; the outer `where`
filters its rows like any others. This is what `having` was for. For "each
company and its headcount" the block form, `match { $c: Company, let $n =
count { $p: Person, $p worksAt $c } }`, keeps a company with no employees at
zero, which the grouped form drops; agents reach for the block form
unprompted, and the two are different terms, not two spellings.

```gq
query big_employers() {
  match {
    from { match { $p: Person, $c: Company, $p worksAt $c } return { $c, count($p) as headcount } }
  }
  where $headcount >= 100
  return { $c.name, $headcount }
  order { $headcount desc }
}
```

**A ranked window scoped by the graph, then a traversal from the hit.** The
population is named first; `k: 20` is the window; the score is named where it
is drawn; the traversal and the count
run on those twenty rows.

```gq
query cited_near($coll: String, $q: Vector(3)) {
  match {
    let $pop = { match { $d: Doc, $x: Collection, $d in $x } where $x.slug = $coll return { $d } },
    from nearest($pop, $d.embedding, $q, k: 20) as $distance,
    $d cites $other,
  }
  return { $d.title, $distance, count($other) as cites }
  order { $distance }
}
```

**A write fed by a read.** The `match` and its `where` choose the rows; each
statement names the bound entity it writes; one snapshot per group, one
commit. A write mixes no `delete` with an `update`, so retiring a person is
two declarations, or two requests.

```gq
query retire($h: String) as commit {
  match { $p: Person, $p $k:worksAt $c } where $p.handle = $h
  delete $k
}

query relocate($h: String) {
  match { $p: Person } where $p.handle = $h
  update $p set { city: null }
}
```

**Recursion.** A declared read calling itself; the `union` joins the base
case to the step, and the fixpoint is the reachable set.

```gq
query reachable($from: String) {
  match {
    from union(
      { match { $p: Person, $q: Person, $p knows $q } where $p.handle = $from return { $q } },
      { match { from reachable($from), $r: Person, $q knows $r } return { $r as q } })
  }
  return distinct { $q }
}
```

## 9. Alternatives

| Alternative | Why not |
|---|---|
| Keep non-closure and add one clause per shape (`retrieve`, `having`, `view`; this RFC's drafts to 2026-11-01) | Each clause was one spelling for one job because the language had no general way to use a result; the evaluation's claim that non-closure is what makes plan truth possible was too strong for compile-time closure, whose four costs are stated and bounded in the core |
| PR #1244's forms: `let ($a, $b) in rel`, positional tuples, `squared_l2` beside `nearest`, no reserved forms, no break | The model converges with the core (three value kinds, one binder, relation expressions); the differences are the four guardrails it leaves to acceptance gates, one ranking operator per contract instead of a scalar exact distance beside an approximate ranking, `from` instead of a Haskell-style `let … in` for a row-multiplying form, column names instead of positions, and the one-spelling rule, which it declines; without the break, `order { nearest(…) }` and `from nearest(…)` would both be legal for a release per construct |
| Relation-valued columns (nested results, GraphQL-shaped output) | Nested relational algebra: every operator needs a rule for a nested cell, row size stops being bounded, equality becomes bag equality; `List<scalar>` aggregates and node references as cells give the common shapes, and nesting flat rows by a parent column is the transport's job |
| Relation-valued parameters to a declared read at the break | Higher-order typing: a declared relation type, a subtyping rule for extra columns, and the correlation rule at the call boundary; `from` over the helper's rows then more matching covers the reuse at B; stage RP states all three ([Designs for later stages](#designs-for-later-stages)) |
| A registry scalar `distance($d.embedding, $q)` usable in any expression (pgvector's shape) | A second spelling of `Score` (A6); invisible to the ranking machinery as a predicate, so the `distance_range` pushdown and the exhaustive report would need the planner to pattern-match an expression (A5); `bm25` cannot be pointwise at all. If the corpus shows the operator form costs repair turns, the Layer 3 answer is to make a scalar `distance` the surface and `Score` its desugaring, which keeps one core term |
| Stage pipelines as the closure mechanism (TypeQL 3) | Closed by construction, but the text order is the plan order, each stage's output is its input crossed with its matches, and reads and writes mix in one transaction; `from` gives the same composition under one planner-owned shape and one commit |
| `CALL { … }` as the row-multiplying form (Cypher, GQL) | The same scoping rule; it reads as a procedure call, which it is not, and GQL also has `FOR` for the plain case |
| `for $x in rel` as the row-multiplying form | XQuery's and GQL's word; rejected narrowly because it suggests an iteration variable and GQ binds columns by name, so there is nothing for the variable to be |
| A list of clauses inside `match`, pattern and predicates separated by whitespace, with property braces (edition 2's shape; this RFC's surface until 2026-11-11, measured against `match { } where` on 2026-11-11) | Both lower to the same core IR for all 98 instrument truths. On the 45 shared items, judged by rows on #1316, it was no more correct (30 to 31 per run against 30 to 32) and had one to three more first answers accepted, the other surface's misses being `let` written before `match` and a block's `where` outside its braces, both printed fixes. With no difference in correctness the cleaner surface wins: the clause list mixes producing and removing terms in one list, needs a gap rule for `-` and a touching `(` to keep whitespace-separated items apart, and keeps the braces as a second spelling of an equality. Its one advantage, 2,581 stored declarations left unchanged, is a one-time cost the rewriter pays in a break that happens anyway |
| Positional or named destructuring on `from` | SQL's `AS t(a, b)` binds by position, but a name taken from a position breaks silently when the helper reorders its `return`; named destructuring is a second way to rename beside `as` |
| A `rank` element, `rank nearest($d.embedding, $q, k: 20) as $dist`, ranking the rows the elements before it bound | Rejected 2026-11-12. No mainstream language has a ranking step inside a pattern with one trailing predicate: ranking is `order` and `limit` at the end (SQL, SPARQL, Cypher), a function returning rows with its filter as an argument (Cypher's procedures, Kùzu, Cozo, Elasticsearch, Weaviate), a pipeline stage (ES\|QL, KQL, PRQL, GoogleSQL's pipe syntax) or a schema profile (Vespa). Inside one `where` it needs a rule placing each conjunct before or after the window, invisible in the text, or a pipeline that gives up the fixed skeleton. It would also be a second spelling of the relation form, which it cannot replace, since a fusion over two differently scoped populations needs that form. The let-first form and `as` on a ranked `from` fix its order and naming without either cost |
| A population shorthand: a node binding in relation position meaning its rows so far | Would shorten every ranked read; needs a correlation rule (uncorrelated with respect to that binding, correlated with every other) that the corpus should show agents get right before it is added; unresolved |
| A keyword `union { } { }` or an infix `rel union rel` | A form that takes relations and yields one is a relation function, as `rrf` is; a keyword would be a second shape for that |
| A list as rows: `from $list`, `unnest($list)`, GQL `FOR`, Cypher `UNWIND` | `from` binds no name and a list element has none, so the form needs the binder `from` was chosen not to have; a list parameter is matched with `in` against stored values, and constants become rows through `load`; if the corpus shows a read that needs it, it enters as a relation function with a declared column name, not as a binder; stage RP's relation-typed `query` parameter is that form ([Designs for later stages](#designs-for-later-stages)) |
| `CASE … END`, `COALESCE` and `\|\|` as grammar | Each is a pure scalar function; the registry rule makes them rows (`if`, `coalesce`, `concat`), and a keyword form would be a second spelling |
| Wrapping or null-producing integer arithmetic | SQL, Cypher, GQL and Soufflé's signed integers all raise on overflow and on a zero divisor; a null would be a silent partial result (invariant 8) and a wrapped value a wrong one |
| A `WHERE` inside a binding, `(n WHERE n.age > 30)` (GQL) | A second place for a predicate; the predicate is the `where` after the braces |
| Writes that read nothing but their own `where` (the earlier A7) | Nothing in A1 to A6 needs it; it cost one round trip and two snapshots per read-driven write and made a traversal-shaped target set unwritable; the half that matters, a read has no effects, is kept |
| Reads and writes interleaved in one body (Cypher, GQL, TypeQL pipelines) | Within a group every sink sees one snapshot; between groups a later one sees the earlier effects, as edition 2's sequential statements do, because 28 stored bodies depend on it and refusing them would be an eighth break; one publication either way |
| Explicit correlation imports, `from (q) { … }` (Cypher 25, GQL) | Correlation stays by name, but every fresh inner name has a binding site (section 3), so both silent cases are refused: an inner binding of an outer name is `T68`, and an unbound triple name is `T84`. Imports would be a second scoping syntax for the same rule |
| `l2` as the exact vector function | On a cosine field the exact form of `nearest` is cosine, so `l2` would lie or refuse; `distance` reads the field's declared distance, one spelling for one meaning on every field |
| A bare field name as a ranking's second argument | A population that returns a whole pattern has several node columns, and 68 of the 178 edition-2 ranked reads the rewriter met do; naming the column, `$d.embedding`, says which, and the other columns ride as payload |
| Lifting the constructive-or-destructive split so one write may delete and update | Invariant 4 keeps the split explicit; the RFC's first write examples mixed the two and the engine refuses that today, so the examples were split instead |
| `Fuse` carrying the population's other columns | Arms may disagree on them; the fused row has the target and its score, and a correlated `from` draws the rest, which the rewriter emits |
| Retaining every unknown annotation as metadata | A later typed `@budget` would change the meaning of text edition 3 accepts, against the additivity rule; an allow-list of pure metadata keeps `.pg`'s convenience without the trap |
| Bare identifiers as operands in a read | Edition 2 admitted them and typed them away; in edition 3 they let every foreign keyword parse as a filter and fail later with a message that names the wrong construct, so they are parse errors at the word |
| Keeping property braces beside `where` (Cypher, GQL) | A second spelling of an equality filter (A6); every pattern language has them and agents write them first, so their refusal prints the `where` conjunct as the fix |
| A `where` on `update` and `delete` beside the group's (edition 2's form) | A second predicate position for one `Filter`; the group's `match` and `where` select and the sink names its rows by reference |
| `@approximate(recall)` as an annotation beside `nearest(…, recall:)` | Two spellings of one bound; quality is the operator's property, and one read may hold two windows |
| `@satisfice` beside `@budget` | The same parameters with a different overrun behaviour; one bound with `on_exceed` |
| `@analyzed` beside `@index(p, fulltext)` | Two annotations configuring one index; the analyzer is the index's option |
| A `mutation` keyword beside `query` (GraphQL, Kusto's `.` commands; the 2026-11-01 revision) | The body's shape is the kind at parse time, so the keyword is a second source the parser must check against the first; every consumer that wants the kind at the head (the registry, MCP's write gating, policy scope, `queries list`) reads it from the parse tree, the derived view the engineering rules ask for; the languages that declare it do so because their transport needs it before parsing, which a server that compiles stored declarations at boot does not |
| A staged search syntax (`rank … yield`, named sources, `metric()`, `limit … of … per`, a `filter` stage; the 2026-09-13 draft of RFC 0048) | A second surface for the same plan nodes; `from` over relation functions is the one composition shape |
| A window equal to `limit`, or a default of `max(limit, 100)` (RFC 0048's draft) | Violates law 3, and the 2026-10-05 review's example changes the winner between `limit 100` and `limit 101`; `k` is required and no default exists |
| `candidates:` and `exact: true` as options on `nearest` | `k` is the window and `distance` the exact operator: two contracts, two operators (A8) |
| An explicit distance required on every vector | Every accepted schema would break; an omitted distance is `l2`, what they mean today |
| An `oversample` or effort option in the query | Effort is a session setting the plan records; the query states meaning, and `recall` is a bound, not an effort |
| Default `terms` to `any` and keep `search` as a synonym; or map `search` to the `all` default | Three spellings of one operation; `all` is the precise default for a predicate, and mapping to it would silently narrow every multi-word search, so the canonicalisation writes `mode: any` |
| A separate `filter` clause for predicates | `where` is the one predicate position, and a block's own `where` scopes a predicate to its pattern |
| Native fuzzy defaults or truncated expansion as the contract; rescoping statistics by every graph filter; a warning on unindexed search | Results would change with analyzer, index and segment state; rescoping can reverse the order of the same entities; a warning does not repair a matched set |
| Removing `search`, `match_text` and `fuzzy` after a deprecation release, and tightening `T27` to require the analyzer (PR 792) | A registry row is never removed and `bm25` over `@index` is text every graph writes; `fmt` canonicalises and lint names it |
| Cross-type fusion now | A node variable binds one type; an interface population answers the common case, and fusion across different node columns waits for the polymorphism stage |
| Separate RFCs for the grammar, the programme, lexical search and the search contracts (PRs 1202, 1213, 792, 793) | Four documents specifying one surface drifted from each other within a week each; one document with one decision log, and assets for the evidence |
| No programme; each stage RFC accepted on its own | The state before: ten open language, search and access RFCs, three of them permissions, three scheduling their own break, two specifying one grammar position |
| A `batch` declaration holding several reads under one snapshot (the 2026-10-31 programme) | One snapshot and one round trip are properties of a request, which already pins a snapshot and already compiles a file of declarations, so `batch { q1 q2 }` is a second spelling of a file with two declarations; `@brief` and `@phase` describe the agent's session and change no plan, so they are request fields; a stored, named group of reads is a request listing names |
| Cozo's recursion with unbounded value invention | Termination is not guaranteed and Cozo says so; GQ admits recursion over references, where the domain bounds it, and an invented value only under `min` or `max` with a round budget (A1) |
| An open upper bound on `Expand` as the only recursion (this RFC's text until 2026-11-07) | A special case of `Fix` (`reachable`); one operator covers it and the shortest path, and `Expand{m,n}` keeps the bounded-depth form |
| `min` and `max` alone as the monotonicity rule (this RFC's text until 2026-11-08) | A filter on a `max` column, an inner cut and a nested aggregate all pass it and diverge between naive and semi-naive evaluation (74 of 817 random recursions); the stated rules admit exactly the recursions on which the two agree |
| Bit-identity with Lance's unlimited scan as the WAND qualification | Lance scores in `f32`; two documents whose `F64` scores differ by less than an ulp can tie or invert, and did on a real index, so a certified margin with an `F64` rescore is needed, not a tie check |
| Cozo's fixed-rule algorithms as syntax; triggers; an imperative sublanguage | Algorithms are relation functions with declared bounds (stage R); a trigger hides what a write does from its plan (A3) and a write body with several statements says it in the open; an imperative layer has no place under A1 and A3 |
| Additive first, break last | Every construct built twice, agents reading two spellings per construct for a release; three open RFCs already schedule four majors this way |
| An arrow spelling for traversals; freezing the score column as `F64?`; removing the three lexical rows; `@distance` and `@score` meta-fields; a `file` rule; `query` for writes; a braced `where { }` clause; `graph@ns::Type`; a permanent two-edition compiler; one RFC for grammar and semantics; silent triple correction; do nothing | As recorded in the 2026-11-01 revision; none is changed by closure. Refusing the incoming triple and role-named ends were on this list until 2026-11-12: the first is now the rule (`T82`), the second an unresolved question |

## 11. Programme and rollout

The language lands in one break and a sequence of additive stages. The
order is a set of edges: a stage ships after every entry in its cell and
nothing else constrains it. After the break, a change that needs a new
grammar rule is an amendment to this RFC, enforced by a test that pins the
grammar's rule set.

### Designs for later stages

Two stages, RP and Path, lift two entries of
[Inexpressible by decision](#inexpressible-by-decision). Both keep the
algebra first-order when a read runs, so A1 holds unchanged: a relation
parameter is gone before planning, and a path is a bounded value that no
recursion grows. Each production below is an amendment under rule 1 when
its stage lands; this section fixes the design and the names.

#### Relation parameters (stage RP)

A declared read may take a relation. Its type is a row shape, written as a
`return` is:

```gq
query closure($edges: { $a: Person, $b: Person }, $from: String) {
  match {
    from union(
      { match { from $edges } where $a.handle = $from return { $b as x } },
      { match {
          from closure($edges, $from),
          from { match { from $edges } where $a = $x return { $b as y } },
        }
        return { $y as x } })
  }
  return distinct { $x }
}

query reports($from: String) {
  match { from closure({ match { $a: Person, $b: Person, $a manages $b } return { $a, $b } }, $from) }
  return { $x }
}
```

- **Inlined.** A relation argument is bound at compile time as a scalar
  argument is, under the `Call` rule: binding, never textual substitution,
  and the expanded tree counts against the plan budget. The planner never
  sees a relation parameter, and the core gains no operator.
- **Matched by name.** The argument must carry every declared column, at a
  type that fits: a non-null column fits a nullable one. Columns the type
  does not declare are dropped at the boundary. Carrying them through would
  need row polymorphism, a larger type system than this stage's need.
- **A closure.** The argument is a relation expression of the caller,
  evaluated in the caller's scope; its free variables correlate there, as a
  block's do. Inside the body, `from $edges` sees the declared columns
  only.
- **Recursion.** A recursive call passes the relation argument through
  unchanged, as it does a scalar. Passing the recursive relation itself, or
  a relation built from it, is higher-order recursion and `T70`.

A `query` may declare a relation parameter too. The client binds it as an
array of objects keyed by column name, and it lowers to a new leaf,
***Values***(rows) → `R`, whose cardinality is the number of rows, known
at bind time and capped by a bind limit (invariant 11). The bound plan
carries the rows. This is the "relation function with a declared column
name" that the list-as-rows alternative waits for, with one type for both
sources: a caller's read or the client's rows.

#### Paths (stage Path)

Paths split by cost, and the stage ships the two cases with a polynomial
bound:

| Case | Bound | Form |
|---|---|---|
| Paths of bounded length | `Expand`'s own, `\|R\| · Σ_{h=m..n} fanout^h` with `fanout` counting edges | `$a $p:knows*{1,3} $b` |
| One shortest path per pair, any depth | `≤ \|R\| · \|T′\|` rows, each path `≤ \|T′\|` nodes | `shortest $a $p:knows* $b` |
| Every simple path or trail, any depth | none: the count is exponential, counting them is #P-hard, and deciding whether a simple path or trail matching a regular pattern exists is NP-complete | refused |
| Every shortest path per pair | none: a grid has exponentially many | refused |

```gq
query within_three($from: String) {
  match { $a: Person, $a $p:knows*{1,3} $b } where $a.handle = $from
  return { $b, length($p) as hops, nodes($p) as via }
}

query route($from: String, $to: String) {
  match { $a: Person, $b: Person, shortest $a $p:knows* $b }
  where $a.handle = $from and $b.handle = $to
  return { length($p) as hops, nodes($p) as via }
}
```

- **The binder selects the semantics.** `$a knows*{1,3} $b` stays a set of
  endpoint pairs at the shortest distance, as today. Binding `$p:` on a
  multi-hop gives one row per path, the rule `$k:` already states for one
  hop (one row per edge). No keyword marks the difference.
- **`Path` is a value kind.** It alternates node and edge references,
  starts and ends at a node, and has a bounded length: at most `n` hops
  under `*{m,n}`, at most `|T′|` nodes under `shortest`. Equality is
  element-wise identity; the fixed value order compares paths element by
  element by identity, then by length, so `Order` and `distinct` need no
  new rule. A path's selector must reach one node type until Poly types a
  union of endpoints.
- **Modes.** A bound path is a `trail` by default, no edge repeated,
  Cypher's semantics and the one agents have read most. `walk` and
  `acyclic`, GQL's words, prefix the triple when a read needs them. A mode
  word on a triple that binds no path is refused, since endpoint
  reachability does not depend on it.
- **`shortest`** admits an unbounded `*`, and is the only form that does.
  It is a derived form over `Fix`: a recursion keeps each target's least
  distance with `min` and its predecessor with `min_by`, ties going to the
  least predecessor identity, so the chosen path is deterministic where
  GQL's `ANY SHORTEST` is not; a second recursion walks the predecessors
  back, reading each one's stored distance rather than computing a step,
  and an ordered list aggregate builds the `Path`. `shortest *{m,n}` bounds
  the length it accepts.
- **`min_by` and `max_by`** join `Fix`'s lattice: `min_by($v, $d)` keeps
  `$v` from the row with the least `$d`, ties to the least `$v` under the
  value order, which is the lexicographic minimum of the pair and so
  monotone. The cycle rules for `min` and `max` columns cover their columns:
  nothing on the cycle filters, groups or orders by one, and every
  expression reading one preserves its order.

Accessors are registry rows: `nodes($p)` and `edges($p)` return lists of
references, so `List` admits reference elements in this stage, and
`length($p)` counts edges. The reference interpreter checks every form
against a breadth-first oracle, `shortest` against every path of least
length, and the bound of each row of the table against the count it
reads.

#### Names

Each name follows section 3's rule: one word per core term, a form that
multiplies rows and a form that binds a value kept apart, and the most
common spelling where precedent splits.

| Concept | Name | Precedent | Not chosen |
|---|---|---|---|
| Relation type | `{ $a: Person, $b: Person }` | TypeQL 3 function streams; the shape of `return { }` | `table(…)`, `R[…]`, `relation<…>` |
| Reading one | `from $edges` | GQ's `from $r` | a new word |
| Client rows | a relation-typed `query` parameter; the leaf is `Values` | SQL `VALUES` for the leaf | `unnest`, `UNWIND`, `FOR` |
| Path binding | `$p:knows*{1,3}` | GQ's `$k:knows` | `p = (…)` of GQL and Cypher: in GQ `=` is `let`'s value binder, and this form multiplies rows |
| Path kind | `Path` | GQL `PATH`, Cypher `Path` | `List<ref>`, which needs union element types |
| Accessors | `nodes`, `edges`, `length` | Cypher and GQL, with GQ's word `edges` for Cypher's `relationships` | GQL `path_length` |
| Modes | default `trail`; `walk`, `acyclic` | GQL's mode words, Cypher's default | GQL's default `walk` |
| Shortest path | `shortest` | GQL's selector, adopted by Cypher 25 | a `shortest_paths(…)` relation function, a second form for the same term |
| Argmin | `min_by`, `max_by` | Trino, Spark, DuckDB, Snowflake and BigQuery, value first and key second | Kusto `arg_min`, ClickHouse `argMin` |

### One IR

The release has one grammar, one surface tree, one type checker and one
typed IR, the core of section 2; the planner reads only the core. Edition
2's grammar, checker and pipeline IR are deleted in the same change, with no
edition switch anywhere. Scalar expressions in the core are today's typed
expression nodes (the `Cast` nodes of invariant 9 included), extended for
arithmetic, because plans, the bound-plan mirror and the engine already
carry them. The proof that meaning did not move is the rewritten GQT
corpus: every case keeps its rows, shapes and plan lines, and a code or
column name that moves is one the fixed map of section 6 names.

The frozen v1 reference engine goes with the pipeline IR it reads. A
reference interpreter of the core, written from the operator table of
section 2 with no index, planner or optimizer, takes its place as the GQT
corpus's differential oracle. No module carries an edition number in its
name.

### Rules every later change answers

1. **No new grammar rule without an amendment.** A test pins the rule names
   of `query.pest`; a red pin is an amendment here, accepted only when the
   production starts at a token edition 3 refuses and the collision it
   designs around is named.
2. **One spelling per meaning** (A6), answered in the change's Alternatives;
   a form that falls out of a general construct is canonicalised by
   `queries fmt` and named by lint.
3. **Enabler before consumer.** An order the sequence table does not state
   does not exist; a new edge is a row change here.
4. **Measure at every stage.** The M0 instrument is re-run on the same
   corpus; the four numbers go in the release note; a stage that lowers
   first-try validity shows repair turns compensate.
5. **Cases first.** Every refusal this RFC names has an `expect error` GQT
   case written at B; a stage that lifts one flips it.
6. **Storage on its own clock.** The distributed sequence, I and Poly follow
   the storage-upgrade matrix.

## Invariants

- **7, physical acceleration is derived.** Index presence never chooses the
  analyzer, the matched set, the score or the distance; a lagging or missing
  index changes cost; an index built for another distance is never used.
- **8, integrity failures are loud.** Every refusal and resource failure is
  typed; no plausible subset, no silent default window, no truncated result.
- **9, query semantics are typed structures.** Options are typed call
  arguments carried into typed plan nodes; the lexical query is one
  `LexicalQuery`; nothing travels in strings or transport flags; a
  declaration's kind is its body's shape in the parse tree.
- **3, one coherent view.** A read holds one snapshot; a write evaluates its
  selection and effects on one; every arm, statistic and nested read of one
  query shares it.
- **4 and 5, one publication, crash convergence.** A write with a selection
  publishes once; the sinks change no staging protocol.
- **6, stable identity.** Analyzer fingerprints and representation
  identities bind to property identity; a rename keeps them, drop and re-add
  does not.
- **10, trust at the boundary.** Policy gates a write by its static target
  type whether or not the body reads.
- **11, bounded resource use.** Every `Expand` is bounded, every `Call`
  chain acyclic and budgeted, every relation function declares finite
  cardinality, and rankings, fusion and exact scans charge the query's
  memory.
- **12, one source of truth.** SchemaIR owns analyzer, scorer, distance and
  recipe; the plan owns windows and weights; descriptors and catalogue rows
  derive from them.
- **13, evidence matches the boundary.** Compiler tests own the grammar,
  GQT owns rows and errors, the oracles own scores, the instrument owns
  agent competence.

Deny-list: no synchronous index build on a content write, no logical
precondition on index coverage, no string-built predicates, no side channel
for discarded rank, no silent partial results.

## Compatibility and reversibility

- **Language.** There is no backwards compatibility. Edition 2's clause
  list inside `match`, its property braces, `not { }`, its quoted edge names
  and seven other spellings stop compiling (the rewriter table), and two shapes edition 2 accepted become type errors
  with no rewrite: an `rrf` whose arms are identical (15 stored cases, used
  to test fusion mechanics) and an `rrf` whose arms rank two bindings (2
  cases); those seventeen are edited by hand and listed in the rewriter's
  report. Three texts edition 2 accepts are refused by the RFC's own rules:
  an order key over grouped rows that is a meta-field neither returned nor a
  key (3 stored cases), since an order over groups reads keys and aggregates
  only. Nine texts edition 2 refuses are accepted, intentionally: a block
  compared with a column (`T40`), a triple with neither end bound (`T5`, 4
  cases), an order key that is not a return item (`T42`), and a Boolean or
  property item beside aggregates (`T9`, `T58`). A lexical predicate under
  `not` or `or`, which edition 2 refuses (`T38`), is accepted too. Everything else is
  additive, the schema's `@index(fulltext, …)` option included. No edition-2 text
  compiles after the break, and nothing converts stored text: it fails with
  its diagnostic, whose printed fix an agent applies. The widening of `<e>`
  over an asymmetric alternation turns a refusal into a meaning and changes
  no accepted text.
- **Schema.** Every declaration of section 4 is additive and applied in
  place: an omitted distance is `l2`; an index without `analyzer` keeps
  edition 2's analysis; a field that declares an analyzer or changes a
  distance rebuilds its index once; one that changes a recipe regenerates
  its vectors. No export and reload.
- **Results.** Rows change only where edition 2's answer depended on index
  state or letter case, and on a field that adopts a profile, where today's
  English index analysis differs from the declared one (`english_v1` is
  closest, differing by the token filter and NFC). Fusion rows change where
  an arm's window differs from today's `limit`-sized one, and a fusion
  result loses the fan-out rows and population columns today's carries,
  which the rewriter draws again with a correlated `from`. A read with
  `limit` and no `order` returns the first rows under the tie rule rather
  than the first rows a scan yields, so its rows change wherever more rows
  qualify than the limit. Scores change on adopting fields.
- **Wire.** The retrieval descriptor fields are additive; the HTTP
  contract version does not change; `openapi.json` regenerates; the explain
  and bound-plan versions advance once.
- **Reverting.** Before the break, delete this document. After it, reverting
  is reverting the change, which restores edition 2 whole; reverting a
  distance or recipe needs the rebuild or regeneration that adopting it
  needed.

## Unresolved questions

1. The population shorthand (a node binding in relation position) and its
   correlation rule; the corpus decides.
2. An edition-2 issue to file: `fuzzy($d.title, $q, 1)` through today's
    engine can miss the document holding the exact term, because the
    native expansion budget does not protect it.
3. The plan budget's default value when no `@budget(plan = n)` is declared.
4. Stage RP: whether the client-bound relation parameter ships with the
   stage or waits for a read in the corpus that needs it. The design drops
   undeclared columns at the boundary.
5. Whether `count(distinct x)` stays the one special call form.
6. The endpoint spelling: `from` and `to` in an insert against `@src` and
   `@dst` on a bound edge; unifying them is one more rewriter row.
7. Date arithmetic: a `Duration` scalar, or registry rows such as
   `days_between` and `add_days`.
8. The `.pg` spelling of the schema-level default recipe, and which
   providers can prove an immutable model revision.
9. The normalizer and Unicode data identity in the analyzer fingerprint,
   and its mapping onto RFC 0043 certificates.
10. How a declared profile's NFC reaches a native index: a derived
   normalized column the engine indexes, or normalization of stored text at
   write, which changes stored values.
11. The values of `ε` per term count and of `δ` per term in the

   1.68e-7, and a common term's native IDF rounds to zero at `N = 2^24`.
12. Whether `Fuse` should average the ranks of targets tied in an arm
    instead of assigning ordinal ranks by id.
