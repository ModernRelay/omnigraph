# RFC: GQ 3 grammar: the one break and the slots it freezes

> A term set in ***bold italics*** is defined at that spot; it is plain text
> afterwards. Code references are at `main` `f728f01e`; `query.pest`,
> `schema.pest` and `GQ_LANGUAGE_VERSION` are unchanged from `ea895066`, the
> commit the evaluation read, through `main` `ea4a16d5`. `EXPLAIN_VERSION`
> moved from `7` to `8` with #1239 (`fef28e57`, the write node kind
> `DeltaSource`, `crates/omnigraph-planner/src/explain.rs`). The bump base is
> `GQ_LANGUAGE_VERSION` `(2, 3)` and `EXPLAIN_VERSION` `8`.

## Summary

GQ makes one incompatible change to its grammar, ***edition 3***, and then
stops making incompatible changes. The release that ships edition 3 lands
every syntactic decision that would otherwise force a later break, including
the ones whose semantics arrive in later RFCs: those land as ***slots***, forms
the parser accepts and the type checker refuses with a stable code naming the
RFC that will serve them. After this release a new capability never changes
the meaning of a well-typed edition-3 query: it is a registry row, a plan node
behind existing syntax, the filling of a slot, or a new production that starts
at a token edition 3 refuses. The slots buy a committed spelling and a named
diagnostic for the forms the next RFCs already depend on; the compatibility
itself comes from the grammar's shape (ordered choice, contextual keywords,
`$`-variables, the `@` namespace), which is why a form with no slot is still
additive ([What a slot buys](#what-a-slot-buys)).

The break is defined by a ***freeze list***. It renames the write declaration
`mutation`; keeps the triple traversal exactly as edition 2 has it
(`$p worksAt $c` in either written order, `<e>` for both orientations of a
same-type edge),
rejecting an arrow spelling as decoration; gives retrieval its own clause
(`retrieve { }`) that binds typed score columns, leaving `order` to sort
values; adds `having { }` over aggregates, group keys and score columns; makes
every function a generic call resolved against a registry, so no function
remains in the grammar; closes the reserved-word set at the six logic words;
lets `limit` take a parameter; admits a generic `@name(args)` annotation on
any declaration; reserves the declaration kinds `view` and `batch`, the block
`optional { }`, the clause `returning { }`, the meta-field `@type_id`, the
catalogue type names the schema catalogue will use with their `@`-prefixed
edges, and the namespaced type reference `a::b::C`; reserves the binding form
`$x: Name($arg)` and a block aggregate in operand position, so that derived
relations, optional patterns and block aggregates as values arrive without a
grammar change; and adds an optional `gq 3;` edition line. Schema declarations
and query declarations share one grammar; a `.pg` file is a GQ file holding
only schema declarations.

A ***rewriter***, `omnigraph queries migrate`, turns every edition-2 source
into edition 3 by byte-range edits that preserve comments and layout, and
proves each rewrite by compiling both editions to the same lowered IR. The GQ
logic-test corpus, the user guide, the bundled skill and every stored query on
the graphs the maintainers operate are rewritten by that tool before the
release. The release that ships edition 3 still compiles edition 2, rewriting
a stored source at boot with a warning instead of quarantining its graph; the
release after removes the edition-2 grammar. A spike built the edition-3 front
end and the rewriter against this text and ran the proof over the repository's
2,609 sources ([Evidence](#evidence-and-tests)); its amendments are in this
revision.

What does not change: every semantic contract the language has today (static
closed typing, three-valued logic with no null literal in reads, pattern
conjunction, stratified blocks and the safety rule, reachability semantics for
bounded traversal, filter-before-rank, one total order, index required at
compile time, keyed insert as upsert, one commit per mutation, the
constructive-or-destructive rule, branch and commit statements, the `@`
namespace, the four-field diagnostic), the storage format, the `__manifest`
publication door, the HTTP contract version and the plan-acceptance contract.
Every slot's semantics stays with the RFC that owns it; this RFC owns the
grammar, the rewriter and the edition window, nothing else.

## Motivation

GQ grew one capability at a time. Each change answered the request in front
of it: a logic word reserved when a filter needed it, a ranking function placed
in `order` because `order` was where a score was first wanted, a search
function added as a keyword, an operator vocabulary amended in place, an
explain version allocated per feature, a deprecation shim per rename. Each was
right on its own terms, and none was asked to fit a shape the next five
changes would also fit. The language therefore carries decisions whose only
justification is the order they arrived in: retrieval spelled as a sort key,
functions that are grammar productions instead of registry entries, a reserved
set that grew by one word per release, and several open RFCs that each
schedule a break of their own. [A whole-language
review](assets/2026-10-28-gq-3-grammar-evaluation.md) against SQL, GQL,
Cypher, GraphQL, Datalog and the query languages of Elasticsearch, LanceDB and
Vespa found the semantics sound and the accretion the problem: every
expressiveness gap is a position the grammar never reserved, and every
scheduled break is a decision that could be made once.

This RFC opens a revision that treats the language as a whole rather than as
a queue of requests. Its aim is a foundation with six properties, each of
which a later section of this document or a named follow-up RFC is
responsible for.

- **Evolvable.** Every later capability lands without a break: the forms the
  next RFCs depend on have a reserved clause, block, declaration kind, call
  form or envelope slot ([The freeze list](#the-freeze-list)), and every
  other form starts at a token edition 3 refuses, so adding it changes no
  accepted query ([What a slot buys](#what-a-slot-buys)).
- **Maintainable.** One grammar for schema and queries, one registry for
  functions, one annotation form, one diagnostic contract, so a change has
  one place to land and one surface to document ([Design](#design)).
- **Expressive.** The forms the open gaps need, derived relations, optional
  patterns, block aggregates as values and retrieval as typed columns, have
  slots whose semantics the closure and retrieval RFCs fill without touching
  the grammar; post-group filters ship in the break; pattern-scoped writes
  are new productions the writes RFC adds, additive because they start at a
  token edition 3 refuses.
- **Extensible.** A registry row or a declaration is something an agent can
  author against a graph; a new function, view or annotation then extends the
  language without a compiler release, which is the property that matters as
  agents become the main authors of GQ.
- **One way.** One spelling per meaning, in Go's sense ("a language needs
  only one conditional control flow construct"): a respelling that adds no
  meaning is absent from the grammar and named by the diagnostics; a form
  that falls out of a general construct is canonicalised by the formatter
  ([One spelling per meaning](#one-spelling-per-meaning)). An agent that
  retrieves one example per operation, and reads one spelling in every stored
  query, is the agent the evidence below measures as reliable.
- **Self-describing at any size.** The schema is data in the same language:
  the catalogue types `@Type`, `@Property`, `@Edge`, `@Interface`, `@Index`,
  `@Function` and `@View`, joined by catalogue edges, are bound, traversed and
  counted with the same `match` and `return` as user data, and joined to it.
  A schema of a few dozen types fits in a context window; one of a few
  thousand (every source system's types, every agent's views) does not, and
  the agent then finds the type it needs the way it finds a row: by name, by
  its neighbourhood, and, once the catalogue RFC's amendment names a
  mechanism that does not open a Lance dataset, by the text of its
  `@instruction` ([Traversal](#traversal)). The evaluation's literature
  review found the full schema wins only while it fits (R1 in §9.1); past
  that, a schema the language cannot query is a schema the agent cannot use.

The rest of this section records why the project has not had these
properties, and why one early break buys them more cheaply than the breaks
already scheduled.

GQ is pre-stable, and the project has said so each time it changed the
grammar: the shared expression model's compatibility section states that "GQ is
pre-stable and a better language wins over compatibility wherever the two
conflict". It has paid for that position piecemeal. Reserving `and`, `or`,
`not`, `is` and `null` took the language from 1.0 to 2.0; reserving `in`
followed (PR #803); the operator-vocabulary amendment (PR #805) schedules
infix `contains` and `starts_with` to become calls through a deprecated rule
and two more majors (3.0, then 4.0); the analyzed lexical search RFC (PR #792)
schedules the removal of `search`, `match_text` and `fuzzy` at "the next GQ
language major"; RFC 0048 (PR #793) deprecates the positional `k` of `rrf()`
for one release. Each is a break with its own deprecation shim, lint warning,
corpus edit, skill edit and fleet sweep, and each is a release in which
agents meet two spellings of one operation. (The polymorphic types RFC, PR
#884, allocates a minor and an explain version against a stale base, explain
`4` to `5` for union scans where the base is now `8`, so that node kind takes
`9`; it is additive and is not one of these breaks.)

Three facts make one early break cheaper than many late ones.

1. **Stored text is small and mechanical to rewrite.** Stored queries are GQ
   source re-parsed at boot (`crates/omnigraph-server/src/queries.rs`); a
   parse failure quarantines the graph (`settings.rs`). The fleet the
   maintainers operate is a few graphs whose stored queries one tool can
   rewrite in one pass, and the compiler already emits byte-range
   `suggestion` edits with `machine_applicable` applicability for exactly
   this purpose ([Diagnostics](../user/queries/diagnostics.md)).
2. **The language's expressiveness gaps are the next several RFCs, and each
   needs a slot.** Optional traversal (#658), block aggregates as values
   (#1050), heterogeneous discovery (#648), one entity with its neighbourhood
   (#649), fusion with weights and thresholds (RFC 0048's deferred list), a
   derived relation other queries can bind to, and parameterised paging all
   need a clause, a block, a declaration kind or a call form the grammar does
   not have. Added one at a time, each is additive only if its position was
   already reserved; added after a freeze, each is a slot filled.
3. **The agent is the author, and the author's cost is round trips, not
   spelling.** Measured on this grammar, a general agent answered 45 of 45
   tasks correctly, with 8 of 45 first attempts refused, every one for a
   missing `()` (RFC 0047, Evidence, cited as written; the instrument reports
   no direction result). Published comparisons of query languages
   for LLM generation find a 10 to 45 point zero-shot gap between familiar
   and unfamiliar spellings that five retrieved worked examples erase
   (Sivasubramaniam et al., SM3-Text-to-Query, NeurIPS 2024), and that better
   diagnosis, not more editing, doubles repair success (Olausson et al., ICLR
   2024). A spelling therefore costs an agent one repair turn once; a second
   spelling for the same operation costs it on every query it reads.

A local change cannot do this: the grammar is a compatibility surface
([Compatibility surfaces](2026-09-14-compatibility-surfaces.md)), its
change is wire-visible through every client that sends GQ text, and the
decision to make it the last incompatible change is a lasting contract.

## User and operational behavior

### The edition line

A file may open with `gq 3;` before its settings lines. A file without the
line is read in the compiler's current edition, which this release makes 3.
`gq 2;` selects the edition-2 grammar for one release; any other edition is
refused at parse (`Q00x: unknown edition 4; this release compiles editions 2
and 3`). The stored-query registry records the edition each source was
validated under, and `queries validate`, `cluster plan` and `lint` report an
edition-2 source with the rewrite that moves it.

### What a reader sees changed

Before and after, on one query:

```gq
// edition 2
query passages($matter: String, $q: String) {
  match {
    $r: SourceRevision { matter_number: $matter }
    $r hasPassage $p
    $p.text contains "tariff"
  }
  return { $r.path, $p.locator, bm25($p.text, $q) as score }
  order { bm25($p.text, $q) desc }
  limit 5
}
```

```gq
gq 3;
query passages($matter: String, $q: String, $k: I64 = 5) {
  match {
    $r: SourceRevision { matter_number: $matter }
    $r hasPassage $p
    contains($p.text, "tariff")
  }
  retrieve { $p.lex: bm25($p.text, $q) }
  return { $r.path, $p.locator, $p.lex as score }
  order { $p.lex desc }
  limit $k
}
```

The write side:

```gq
// edition 2
query retract($slug: String) {
  update Assertion set { retracted: true } where slug = $slug
}
```

```gq
gq 3;
mutation retract($slug: String) {
  update Assertion set { retracted: true } where slug = $slug
}
```

### The freeze list

Every row ships in the edition-3 release. The third column says what the
compiler does with the form in that release; the fourth names the RFC that
owns its semantics. A form marked *slot* parses and is refused by the type
checker with one code, `T6x` (allocated at implementation under the catalogue
rule in `crates/omnigraph-compiler/src/query/codes.rs`), whose `expected`
names the construct and whose `fix` names the owning RFC; a form marked
*works* has today's semantics in the new spelling.

| Surface | Edition 3 | In this release | Owner of the semantics |
|---|---|---|---|
| Declaration kinds | `query` (reads only), `mutation` (writes), `view`, `batch`; the schema kinds `node`, `edge`, `interface` in the same grammar | `query`, `mutation` and the schema kinds work; `view` and `batch` are slots; a file mixing schema and query declarations is refused as a slot (the loader and the registry each take one kind) | derived relations RFC (`view`), the agent-first batch (`batch`), the one-file loader for the mixed file |
| Read clause order | `match` → `retrieve`? → `return` → `having`? → `order`? → `limit`? | `match`, `return`, `order`, `limit` work; `retrieve` works with today's rankings ([below](#the-retrieve-clause-in-this-release)); `having` works over aggregates, group keys and score columns under its own type rule | this RFC for `having` and the arms; RFC 0048 for everything `retrieve` gains later |
| Mutation clause order | statements → `returning`? | statements work; `returning` is a slot | writes RFC |
| Blocks in `match` | `not { }`, `exists { }`, `count|sum|min|max|avg(…) { } op expr`, `optional { }` | the four work; `optional` is a slot | derived relations RFC |

| Reserved words | `and`, `or`, `not`, `is`, `null`, `in`; every other keyword is contextual (word-bounded, legal as an identifier in operand and property position) | works; a grammar test pins the set | this RFC |
| Null | no literal in a read, a binding's property match included; `null` legal as the value of an `insert` or `set` assignment | works | this RFC |

| Annotations | `@name(args)` on any declaration, retained as metadata; arguments positional or `name = value`, the `.pg` spelling; `@description`, `@instruction` typed; `@example`, `@if_commit($p)`, `@budget`, `@approximate`, `@satisfice`, `@brief`, `@phase` reserved | the typed two work; the reserved seven are slots | the agent-first batch (`@example`, `@budget`, `@approximate`, `@satisfice`, `@brief`, `@phase`), the writes RFC (`@if_commit`, which must become the one source of the request's precondition) |
| Meta-fields | `@id`, `@src`, `@dst`, `@type`, `@type_id` | the first four work; `@type_id` is a slot | polymorphic types RFC for `@type_id` |
| Catalogue names | `@Operator`, `@Pass`, `@Setting`, `@Engine`, `@LogicalKind` exist; `@Type`, `@Property`, `@Edge`, `@Interface`, `@Index`, `@Function`, `@View` reserved; catalogue edges between them spelled with the same prefix, `$t @property $p`, `$e @from $t`, `$t @implements $i`, the ends bound as `$t: @Type` beside them; a catalogue type is a node type for binding, traversal, filters and aggregation | the five exist; the seven and the `@`-prefixed edge selector are slots; a `retrieve` arm over a catalogue type is refused with them | the engine catalogue RFC's schema extension, which declares the catalogue's edges and, if it lifts the rank-search refusal, names a mechanism that opens no Lance dataset |

| Envelope | `graph_commits` (a map keyed by graph id, one entry today) beside `graph_commit_id`; `notifications`, `why_not`, `complete`, `incomplete_reason`, `continuation`, `estimate` | present where the owning stage has shipped, absent otherwise; all additive | the envelope stage RFCs |

Two things are not on the list because they are additive by nature: a new
registry row (a function, an annotation name, a catalogue type) and a new plan
node behind existing syntax.

### What a slot buys

The spike wrote sixty later capabilities, from this RFC, its evaluation, PR
#792, #793, #805, #884, #1015 and the Lance primitives the engine does not
yet reach, as the queries they need, and parsed each under the edition-3
grammar. Sixteen parse into a slot and are refused with its owner; fourteen
are registry rows or call options; five already work; twenty-four need a new
production (pattern-scoped `update` and `delete`, `invalidate`, unions and
`is T`, qualified edge names, `use` and `namespace` blocks, arithmetic,
partial objects, `limit n per`, `at $commit`, `nulls last`, `offset`,
multivectors, new base types); one, `$p: Person at date(…)`, already parses
as a binding and two bare filters and is refused by the type checker. None
changes the meaning of a well-typed edition-3 query, because each new
production starts at a token edition 3 refuses (`Q001`). The compatibility
therefore comes from the grammar's shape, and a slot buys two things only: a
spelling the owning RFC cannot change, and a diagnostic that names that RFC
instead of reporting an unexpected token. Two later productions have a known
collision to design around, recorded here so their RFCs do: arithmetic `$x *
$y` in `match` meets the wildcard traversal `$a * $b` and needs a lookahead;
`at` on a binding meets the bare-filter clause.

### The `retrieve` clause in this release

A ***retrieve arm*** binds a score column to a binding: `$p.lex: bm25($p.text,
$q)`. The column's name lives in the binding's namespace beside its
properties; a name that collides with a declared property is a type error. In
this release the arms are exactly today's rankings and keep today's columns:

| Arm | Column | Rule carried over |
|---|---|---|
| `$d.vec: nearest($d.embedding, $q)` | `F32`, non-null: the squared L2 distance Lance ranks by, the `_distance` column the ranked scan appends; a row outside the window is absent, never null | `limit` required (today's `T17`); the window is the query's `limit`, widened by the overfetch ladder as today |
| `$d.lex: bm25($d.text, $q)` | `F32`, non-null: the BM25 score, the `_score` column; a non-match is absent | the property needs a full-text index (`T27`); eligibility placement as today |

The column keeps the type `TypedExpr::score_type` publishes today (`F32` for
these two arms, `F64` for `rrf`), so a later change of Lance's distance type
is a language break only when that owner changes. An arm is a projection alias
over the column the ranked scan appends; projected without an alias, its
result column is `<var>.<arm>`, the name the query gave it.

`order` must lead with an arm or with the fused score `rrf(arm, arm [, k:
n])`, exactly the forms `order` accepts today for `nearest(…)`, `bm25(…)` and
`rrf(…)`; `asc` on a `bm25` arm or on `rrf` is refused (`T54`), as is any
modifier on a `nearest` arm. A ***ranking call*** is a `nearest(…)` or
`bm25(…)` over a property, or an `rrf(…)` whose arguments are such calls;
written in `order` or `return` it is `T65`, whose fix is the arm, except
that an aggregate over one stays `T32` (below). `return` may project an arm
as a value (`$d.lex as score`), which is today's `T33` projection without the
repetition rule, since the arm is named once. Outside `rrf`, an arm's column
is a value of its binding for the rest of the read: `return`, `having` and
`order` may read it, and a later traversal from that binding does not drop
it. Under `rrf` an arm's own column is not a value (`T33`, as today): the
fusion carries only the fused column, and RFC 0048 owns carrying each arm's
column through `RankFuse`. A filter in `match` may not read an arm (arms are
bound after `match`).

The ***fused score*** has one spelling, `rrf(arm, arm [, k: n])`: the
registry's `rrf` row, whose positional arguments are two arms of one binding
and whose result is the `F64` `score_type` gives it today. It is not a
ranking call, since it reads two arm columns and no property, so it is not
`T65`. It may lead `order`, and `return` may project it, alone, aliased or
inside a Boolean item, only as a repeat of that leading key: today's `T33`
repetition rule, unchanged, because the fused score is written where it is
used rather than named once. Projected without an alias, its result column is
`<var>._rrf`, as today. `having` does not read it in this release (`T67`);
admitting it lifts a refusal, which is additive. This is the form the
`hybrid` example writes and the form the rewriter produces from
`rrf(nearest(…), bm25(…))`.

`having` may read an arm, and `having { $d.vec < 0.6 }` is the one new
capability this release gives retrieval. Its meaning is fixed here: the query
returns the top `limit` rows of the population that pass the predicate. That
is what the engine already does when a graph or property filter follows a
ranking: the overfetch ladder widens the window until `limit` rows pass or the
population is exhausted, and for a lone `nearest` arm the result equals what
Lance's `distance_range` computes, which a later planner change may push down.
The spike's `having_filters_groups_and_scores` pins the semantics: a lower
bound `> 0.01` on a six-row graph returns the three passing rows, not the two a
filter after the window would leave. `having` has its own type rule, `T67`
(allocated at implementation): a Boolean over aggregates, the query's group
keys and arm columns, where a group key beside an aggregate is legal, as it is
in SQL's `HAVING`, while `T58` keeps refusing that mix in `return`. Under
`rrf` neither an arm nor the fused score is an operand of `T67` in this
release.

Three refusals RFC 0048 scheduled for a later major land in this release,
because edition 3 would otherwise accept the forms and refusing them afterwards
would be a break. RFC 0048 names them as "arms on different bindings,
duplicate arms, and a leading `nearest` without `candidates` in an aggregate
query" (PR #793, Compatibility and reversibility). Edition 3 has no
`candidates` (RFC 0048 owns `k` and `candidates` on an arm, the programme's
stage R), so
every arm in an aggregate query lacks one, and the third refusal is an arm in
an aggregate query: `return { $c.name, count($d) as n } … order { $d.vec }`,
whose edition-2 form `order { nearest(…) }` the compiler accepts today
(`bind_order_key` exempts a leading ranking). Each of the three is a type
error with its own code allocated at implementation and RFC 0048's reason as
its text. `T32` is a different refusal and stays as it is: an aggregate whose
argument is a ranking call (`return { max(nearest(…)) as best }`), checked
before `T65` as `check_projection` checks the aggregate's argument today.
Admitting an aggregate-query arm that declares `candidates` is RFC 0048's
additive change. `queries migrate` reports a stored source that uses one of
the three instead of rewriting it (the corpus holds none).

Everything else RFC 0048 adds (a `k` on an arm, more than two `rrf` arms,
weights, `norm()`, `exact: true`, a reranker) is a registry row or an option on
a call, not grammar, and lands with that RFC. Plan acceptance in this release
gains the arm as a named score origin (RFC 0047's "score meaning"
requirement), `having` (predicate origin, order, row cut) and `limit $k` (the
bound value, where the validator compares the written limit today). RFC 0047's
exact fragment is a closed, versioned contract: a read with `having` or `limit
$k` is outside it in this release, and RFC 0048, which owns the fragment's
extension, either admits the two with a derivation or keeps them out.

### The syntax by example

The forms of edition 3 against one schema. "Works" forms run in the
edition-3 release with the meaning given; schema-role declarations are stored
and refused at use; "slot" forms parse and refuse with their owner; "refused"
forms are the respellings the diagnostics name, with the fix the compiler
prints. The freeze list is the inventory of forms; these examples illustrate
it, each parses under its rules, and they are among the parser-test fixtures
of the Evidence section. A form that is unchanged from edition 2 parses and
typechecks under today's compiler in its edition-2 spelling.

#### The file and the schema

```gq
gq 3;                               // optional; absent means the compiler's edition
set ann_nprobes = 40;               // settings lines come first, as today

interface Named { name: String }

node Person @instruction("One row per person, keyed by handle") implements Named {
  handle: String @key               // identity; insert upserts on it
  name: String @index               // full-text index; `bm25` and `search` need it
  age: I32?                         // nullable
  tags: [String]                    // a list of scalars
  joined: Date
  bio: String? @index
  @range(age, 0..150)               // body constraint, exact comparison
}

node Company implements Named {
  slug: String @key
  name: String
  tier: enum(standard, strategic) @index   // an enum takes no full-text index
}

node Doc @description("A document with an embedded body") {
  path: String @key
  title: String @index
  body: String @index
  embedding: Vector(1536)? @embed("body", model = "openai/text-embedding-3-large") @index
  published: DateTime
  bytes: Blob?
}

node Collection { slug: String @key }

edge WorksAt: Person -> Company @card(0..1) {   // at most one employer per person
  since: Date
  @unique(@src)
}
edge Employs: Company -> Person                 // the opposed orientation, kept for an older load
edge Knows: Person -> Person { weight: F64? }
edge Mentors: Person -> Person
edge Authored: Person -> Doc {                  // identity from the endpoints
  @key(@src, @dst)
}
edge Cites: Doc -> Doc
edge In: Doc -> Collection                       // an edge a reserved word names; quoted in a traversal
```

One grammar: this file is a `.pg` when it holds only schema declarations
and a `.gq` when it holds only query, mutation, view or batch declarations;
a file holding both is a slot. Annotation arguments are positional or
`name = value`. A declaration's annotations stand after its name and before
`implements`, and a body constraint (`@key`, `@unique`, `@index`, `@range`,
`@check` with arguments) stands inside the braces, as today. `@card`, `@key`,
`@unique`, `@index`, `@range` and `@check` keep their meanings and spellings;
nothing a `.pg` file accepted is refused.

#### Schema roles: stored, refused at use

```gq
node Event @valid(asserted_at, retracted_at) {    // stored in SchemaIR; the writes RFC gives it meaning
  id: String @key
  asserted_at: DateTime
  retracted_at: DateTime?
  text: String @analyzed(analyzer = "english")    // stored in SchemaIR; the lexical RFC gives it meaning
}
```

`@valid` and `@analyzed` are schema roles, not slots: the declaration is
accepted and kept in SchemaIR, and a query or write that would depend on the
role is refused until its owner ships (the schema-roles row of the freeze
list).

#### A read: bindings, filters, operators

```gq
query adults($min: I32 = 30, $handles: [String], $cutoff: Date?)
  @description("People over a given age among the given handles")
  @instruction("Pass `$cutoff` to keep only people who joined before it") {
  match {
    $p: Person { name: "Alice" }          // binding with a property match (equality)
    $p.age >= $min                        // comparison: = != < <= > >=
    $p.age is not null                    // null test; a null comparison is null, and a filter keeps true rows
    "rust" in $p.tags                     // membership in a list property
    $p.handle in $handles                 // membership in a list parameter
    $p.handle in ["alice", "bob"]         // membership in a list literal
    $p.joined < $cutoff                   // a nullable parameter: a null value makes the comparison null, so no row passes
    contains($p.name, "Al")               // exact substring (a call, not an operator)
    starts_with($p.name, "A")             // exact prefix
    $p.joined >= date("2025-01-01")       // a call folded to a literal at compile time; `date()` is a `Date`
    ($p.age > 60 or $p.age < 20) and not $p.name = "Bob"   // `or` loosest, then `and`, then `not`
  }
  return { $p.handle, $p.name, $p.age as years }
  order { years desc, $p.handle }         // any projected value or alias; ties by the next key
  limit 20
}
```

A parameter is `$name: Type`, nullable with `?`, with an optional literal
default. The six reserved words are `and`, `or`, `not`, `is`, `null`, `in`;
every other keyword is contextual, so `$p.order`, `$p.limit` and an edge
named `match` are legal. There is no `null` literal in a read: `$p.age =
null` is a parse error, `is null` is the test.

#### Traversals

```gq
query graph_shapes($h: String) {
  match {
    $p: Person { handle: $h }
    $p worksAt $c                         // directed, source on the left; `$c` is bound by the edge's endpoint type
    $c: Company                           // the same variable bound again adds a constraint, not a second row
    $c worksAt $boss                      // legal: written against the schema, resolved as the incoming orientation;
                                          // `queries fmt` rewrites it to `$boss worksAt $c`
    $p <knows> $f                         // undirected, either orientation, deduplicated
    $p $k:knows $g                        // the edge row bound as `$k`; one row per matching edge
    $k.weight > 0.5                       // an edge property
    $p (knows | mentors) $x               // alternation, each member in its declared orientation
    $p (worksAt | employs) $firm          // opposed members: each resolves in the orientation the endpoint types admit
    $near: Person
    $p *{1,2} $near                       // every edge between the two declared types (Knows, Mentors), one or two hops
    $p knows{2,2} $fof                    // exactly two hops
    $d: Doc  $d "in" $coll                // a quoted edge name for an edge a reserved word names
  }
  return { $f.handle, $k.@src, $k.@dst, $k.@type, $near.@id, $firm.slug, $p }   // meta-fields; a bare node is one object column
}
```

A wildcard needs a declared type at both ends (`T5`), and bounds are finite
and need a same-type edge above one hop. `<e>` over an asymmetric edge, alone
(`$p <worksAt> $c`) or in an alternation (`$p <worksAt | employs> $c`), and
`<*>` between two different types are `T22`, as today, whose fix is the
directed form above. A bound edge
cannot be projected bare (`T23`), a hop-bounded edge cannot be bound, and an
anonymous `$_` is a fresh node each time. `$e.@src` and `$e.@dst` report the
stored orientation whatever order the triple was written in, which is why
both stay.

#### Blocks

```gq
query by_blocks($h: String, $least: I64) {
  match {
    $p: Person { handle: $h }
    not { $p worksAt $_ }                         // no matching row
    exists { $p authored $d  $d.published > datetime("2026-01-01T00:00:00Z")  $d.published <= now() }   // at least one; `now()` is the request's clock, a `DateTime`
    count { $p knows $f } >= $least               // the aggregate of the block's matches, compared with a scalar
    sum($k.weight) { $p $k:knows $_ } > 1.5       // sum, avg, min, max over a block property
  }
  return { $p.handle }
}
```

A block runs once per outer row and must read an outer variable. The right
side is a literal, `now()` or a parameter. `count { P } > 0` and `count { P }
= 0` are legal and `queries fmt` writes them as `exists { P }` and `not { P }`.

#### Return, aggregates, distinct, paging

```gq
query colleagues($k: I64 = 10) {
  match { $p: Person  $p worksAt $c  $p knows $f }
  return {
    $c.name,                                      // a group key: every non-aggregate projection groups
    count($f) as friends,
    count(distinct $f.age) as ages,               // distinct under `count` only; `sum(distinct …)` is `T57`
    avg($f.age) as mean_age,
    min($p.joined) as first_joined,
    count($f) > 3 as busy                          // a comparison in `return` needs an alias
  }
  having { friends >= 2 and $c.name != "Acme" }   // over aggregates and group keys; `T58` keeps refusing this mix in `return`
  order { friends desc, $c.name }
  limit $k                                        // a non-null `I64` parameter; null or negative refuses at bind
}

query names() {
  match { $p: Person }
  return distinct { $p.name }                     // one row per distinct projected tuple, before `order` and `limit`
}
```

`sum` over integers accumulates exactly and rounds once to `F64`; an
all-aggregate query over zero rows returns one row. Each result column needs
a distinct name (`T25`).

#### Retrieval

```gq
query hybrid($vq: Vector(1536), $tq: String, $slug: String, $k: I64 = 10) {
  match {
    $d: Doc                                       // the ranked binding
    $a: Person  $a authored $d                    // scope first: only this author's documents are candidates
    $a worksAt $c  $c: Company { slug: $slug }
    $d.published > datetime("2025-01-01T00:00:00Z")   // a filter in `match` is applied before any arm scores
  }
  retrieve {
    $d.vec: nearest($d.embedding, $vq)            // F32 squared L2 distance; `$vq` may be a String the provider embeds
    $d.lex: bm25($d.body, $tq)                    // F32 BM25 score; the property needs a full-text index (`T27`)
  }
  return { $d.path, $d.title, rrf($d.vec, $d.lex, k: 60) as score }   // the fused score, F64; repeats the leading key (`T33`)
  order { rrf($d.vec, $d.lex, k: 60) }            // the fused score's one spelling: `rrf` over two arms
  limit $k
}

query nearby($vq: Vector(1536), $k: I64 = 10) {
  match { $d: Doc }
  retrieve { $d.vec: nearest($d.embedding, $vq) }
  return { $d.path, $d.vec as distance }          // an arm is a value
  having { $d.vec < 0.6 }                         // the top `limit` rows of the population passing the threshold
  order { $d.vec }                                // a `nearest` arm takes no direction
  limit $k
}

query one_arm($q: String) {
  match { $d: Doc }
  retrieve { $d.lex: bm25($d.title, $q) }
  return { $d.title, $d.lex }                     // unaliased: the result column is `d.lex`
  order { $d.lex desc }                           // `desc` is accepted on a score; `asc` is `T54`
  limit 5
}

query text_predicates($q: String) {
  match {
    $d: Doc
    search($d.title, $q)                          // full-text filter, no ranking, no `limit` needed
    fuzzy($d.title, $q, max_edits: 2)             // the third argument is a named option
    match_text($d.body, $q)
  }
  return { $d.path }
}
```

A `nearest` arm requires a `limit` (`T17`) and its window is widened by the
overfetch ladder as today; a `bm25` arm is the whole matching population; an
`rrf` is the union of its arms. A filter in `match` cannot read an arm; under
`rrf` an arm's own column is not a value in `return` or `having` (`T33`, which
is why `hybrid` projects the fused score and `nearby` filters on its lone
arm); the fused score is projected only as a repeat of the leading `order`
key (`T33`) and is not read by `having` (`T67`); a ranking call under an
aggregate is `T32`, as today; two arms with the same call over one property,
arms over two bindings, an arm in an aggregate query, and more than two `rrf`
arms are refused in this release (RFC 0048's rules). `search`, `fuzzy` and `match_text` stand alone or
`= true`, joined by `and`; negate one with `not { search(…) }`.

#### Writes

```gq
mutation hire($h: String, $slug: String, $since: Date)
  @description("Employ a person; upserts on the person's handle") {
  insert Person { handle: $h, name: $h, tags: [], joined: $since }   // keyed insert is an upsert
  insert WorksAt { from: $h, to: $slug, since: $since }               // endpoints by key value; `from` and `to` are the endpoint names
  update Person set { bio: null } where handle = $h                   // `null` is legal as an assignment value
}

mutation retire($h: String) {
  delete WorksAt where @src = $h                                      // meta-fields in a mutation predicate
  delete Person where handle = $h
}

mutation propose($h: String) as commit {                              // a publishable proposal, not a branch write
  update Person set { name: "Proposed" } where handle = $h
}

mutation sketch($h: String, $base: String) as unattached branch on $base {   // a nonpublishable snapshot
  insert Person { handle: $h, name: $h, tags: [], joined: date("2026-01-01") }
}
```

A mutation is constructive (inserts and updates) or destructive (deletes),
never both; an edge cannot be updated (`T16`); a `@key` property cannot be
assigned. These are today's rules under the new keyword. `null` is legal only
as the whole value of an assignment (`mutation_assignment`, in
[Parameters, limit, null](#parameters-limit-null)); `where bio = null` stays
the parse error it is in a read.

#### The catalogue

```gq
query operators() {
  match { $o: @Operator }                         // the five engine catalogue types exist and work
  return { $o.name, $o.inputs }
}

query schema_types() {                            // slot: `@Type` and the `@property` edge
  match { $t: @Type  $p: @Property  $t @property $p }
  return { $t.name, $p.name }
}
```

A catalogue type is bound, traversed, filtered and counted like a node type;
it is never written, loaded or rank-searched (the catalogue RFC's rule), so
`retrieve { $t.lex: bm25($t.instruction, $q) }` over `@Type` is refused with
the slot until the catalogue amendment names its mechanism.

#### Slots: forms that parse and refuse with their owner

```gq
view Contested($since: DateTime) {                // `T6x`: derived relations RFC
  match { $a: Doc  $r: Doc  $r cites $a  $r.published >= $since }
  return { $a as doc, count($r) as attacks }
}

query uses_slots($h: String, $c: Commit, $b: Branch) {   // `Commit` and `Branch` kinds: branch-statements RFC
  match {
    $p: Person { handle: $h }
    optional { $p worksAt $co }                   // outer join: derived relations RFC
    $x: Contested(datetime("2026-01-01T00:00:00Z")) { doc: $d }   // a view binding, `(` touching the name: derived relations RFC
  }
  return {
    $p.handle,
    count { $p knows $_ } as knows,               // a block as a value: derived relations RFC
    $p.@type_id                                   // polymorphic types RFC
  }
}

mutation with_returning($h: String, $c: String) @if_commit($c) {   // `@if_commit`: writes RFC
  delete Person where handle = $h
  returning { @id }                               // writes RFC
}

batch explore @brief("which types mention pricing") @phase(explore) {   // `batch` and its annotations: agent-first batch
  query a() @budget(rows = 1000) { match { $p: Person } return { $p.handle } }
  query b() @approximate(recall = 0.9) @satisfice(ms = 300) { match { $p: Person } return { $p.name } }
}

query namespaced() {
  match { $o: crm::Operator }                     // a namespace segment: schema namespaces RFC
  return { $o.name }
}
```

Each refusal's `expected` names the construct and its `fix` names the owning
RFC ("not yet served in this release"). An `expect error` GQT case per slot
is written at the break; the owning RFC flips it.

#### Formatter rewrites (`queries fmt`), named by lint

| Written | Canonical |
|---|---|
| `count { $p knows $_ } > 0` | `exists { $p knows $_ }` |
| `count { $p knows $_ } = 0` | `not { $p knows $_ }` |
| `$c worksAt $p` under `edge WorksAt: Person -> Company` | `$p worksAt $c` |
| `$x.@type = "Person"` (once `is` lands) | `$x is Person` |
| `search($d.title, $q)` (once `match_terms` lands) | the `match_terms` call it equals |

Neither tool changes meaning, and both prove it the same way: the text before
and after the edit is compiled and lowered, and the edit is written only when
the two lowered IRs compare equal under the comparison
[the rewriter](#the-rewriter) names. The line between them is the input: the
rewriter takes edition-2 text that edition 3 refuses, the formatter takes
edition-3 text and writes its canonical instance. The first three rows above
compare equal on today's compiler: `count { P } > 0` and `exists { P }` lower
to one IR, as do `count { P } = 0` and `not { P }`, and lowering emits a
triple's `Expand` from the bound end, reversing the edge selection when only
the destination is bound (`ir/lower.rs:591-603`, `EdgeSelection::reversed`),
so both written orders of a directed triple lower to one IR, inside `not`,
`exists` and `count` included. The `is` and `match_terms` rows are proved by
the RFCs that add those forms.

### The rewriter

`omnigraph queries migrate` takes `.gq` and `.pg` files or a `--target`, parses
each source under edition 2, and writes edition 3:

- as byte-range edits (the `suggestion` shape), so comments and layout
  survive;
- adding `gq 3;` as the first line;
- refusing to write when the edited text does not lower to the same IR as
  the original, and naming the construct it could not prove. The comparison
  is the one the spike ran (`gq3/migrate.rs`, `compile_ir` and `prove_decl`):
  the text of the `Debug` rendering of the lowered read's parameters,
  pipeline, projections, `distinct`, order and limit (a mutation's whole
  `MutationIR`), the declaration name aside, compared as strings. It is not a
  derived equality: `QueryIR`, `IROp`, `MutationIR` and `MutationOpIR` derive
  only `Debug` and `Clone` (`crates/omnigraph-compiler/src/ir/mod.rs`), and
  the derived `Eq` and `Hash` of `IRExpr`, `IRProjection` and `IROrdering`
  cover expressions, not the pipeline;
- idempotent: a second run changes nothing.

| Edition 2 | Edition 3 |
|---|---|
| `query name(…) { insert … }` | `mutation name(…) { insert … }` |
| `$x.title contains "g"` | `contains($x.title, "g")` |
| `$x.tags contains "rust"` (a list property) | `"rust" in $x.tags` |
| `$x.title starts_with "O"` | `starts_with($x.title, "O")` |
| `fuzzy($x.title, $q, 2)` | `fuzzy($x.title, $q, max_edits: 2)` |
| `order { nearest($d.e, $q) }` | `retrieve { $d._distance: nearest($d.e, $q) } … order { $d._distance }` |
| `order { bm25($d.t, $q) desc }` | `retrieve { $d._score: bm25($d.t, $q) } … order { $d._score desc }` |
| `order { rrf(nearest(…), bm25(…), 60) }` | two arms, `order { rrf($d._distance, $d._score, k: 60) }` |
| `return { …, nearest($d.e, $q) as score }` | `return { …, $d._distance as score }` |
| `return { …, nearest($d.e, $q) }` | `return { …, $d._distance }`, the result column `d._distance` as today |
| `return { …, bm25($d.t, $q) as score }`, `return { …, bm25($d.t, $q) }` | `$d._score as score`, `$d._score` (the result column `d._score`, `F32`, as today) |
| `return { …, rrf(nearest(…), bm25(…)) as fused }` | `return { …, rrf($d._distance, $d._score) as fused }`, `F64` as today |
| `return { …, rrf(nearest(…), bm25(…)) }` | `return { …, rrf($d._distance, $d._score) }`, the result column `d._rrf` as today |
| `bm25(…) > 0.0 as hit`, `nearest(…) < 1.0 as close`, `rrf(…) > 0.0325 as high`, and `not`, `is null`, `in` or `and` over a ranking call, in `return` or `order` | the same item with each call replaced: `$d._score > 0.0 as hit`, `$d._distance < 1.0 as close`, `rrf($d._distance, $d._score) > 0.0325 as high` |
| `order { nearest(…), nearest(…) }`, `order { rrf(…), (rrf(…) > 0.0325) asc }` | one arm for the repeated call: `order { $d._distance, $d._distance }`, `order { rrf($d._distance, $d._score), (rrf($d._distance, $d._score) > 0.0325) asc }` |

The ranking rows are one rule, and the table lists the shapes the corpus
runs (`issue_640_search_score_projection.gqt`,
`rank_call_nested_in_a_boolean_projection.gqt`): every ranking call in
`order` or `return`, at any depth, is replaced by a reference to its arm;
identical calls share one arm, so the rewriter never writes two arms with
the same call over one property; an `rrf` keeps its call, with arms as its
arguments and `k` as an option, since `rrf` over arms is the fused score's
one spelling. A source edition 2 refuses has no IR to compare and is not
rewritten. Everything not in the table is unchanged text; a triple in either written
order, `search`, `match_text` and `fuzzy` with named options, and `<e>` stay
as they are. The generated arm names are `_distance` and `_score`, the names
of the columns the ranked scan appends, and `_distance2` for a second arm of
the same kind, so that every result column an edition-2 query produces keeps
its name and its type and no client reads a renamed column. A human may
rename an arm afterwards; the rewriter never has to.

The proof compares lowered IR, and it passes for rankings because an arm
reference is resolved to its call before IR is built: `$d._distance` in `order`
lowers to the same `IRExpr::Nearest` the edition-2 call lowered to, so
`search_node` finds what it finds today and the comparison holds. The spike
ran this proof over the repository's 2,609 sources (every GQT `query` and `mutate`
section, the user and developer guides' code blocks, the skill, the `.gq`
fixtures): 1,818 declarations compile to identical lowered IR, none differ, 611
statements are unchanged, 43 documentation blocks with no schema are checked
for parse only, and 2,968 generated reads migrate IR-equal and idempotent. Of
132 `expect error` steps, the spike's code map moved three to `T65`, the
edition-3 code for a ranking call: two from `T33`
(`nearest_projected_without_retrieval` and `nearest_projected_other_query`,
a ranking call in `return`) and one from `T32`
(`nearest_projected_under_aggregate`, `max(nearest(…))`). This revision keeps
`T32` for an aggregate over a ranking call, so that step keeps its code: 130
keep their code, two move, and the map has one entry, `T33` to `T65` for a
ranking call in `return`. The corpus gate counts query-text edits only, and
the tool rewrites those two expectation lines from that map.

### The edition window at boot

The edition-3 release boots an edition-2 stored source by rewriting it in
memory and logging the edits, once per source per boot (a warning with the
query's name and each edit, repeated on every boot until an operator runs
`queries migrate` on the cluster bundle, since the boot rewrite never writes
the bundle), so no graph is quarantined for a source the proof accepts. A
source the proof refuses is a parse failure for the purposes of boot and
quarantines its graph as one does today, with the construct the proof could
not carry in the diagnostic; the loud outcome is the point (invariant 8).
`cluster plan` prints the same edits as a pre-upgrade finding. The release
after this one compiles edition 3 only; an edition-2 source then fails
validation with a diagnostic whose fix is the `queries migrate` command. The
bundled skill, the user guide and the GQT corpus are edition 3 in the release
that ships it; the skill's command index and condensed reference are
regenerated, not edited.

### Refusals

Every refusal keeps the four-field diagnostic. New codes, allocated at
implementation:

- `Q00x` unknown edition; `Q00x` an edition line after another statement;
- an arrow traversal (`-e->`, `<-e-`, `-e-`, with or without a binding and
  bounds), the infix string operators, a positional `k` or `max_edits`, a
  ranking call in `order` or `return` (`T65`; the fused score `rrf(arm, arm)`
  is not one, and an aggregate over a ranking call stays `T32`) and `query`
  with a mutation body are parse or type errors whose `fix` is the rewritten
  text (a `machine_applicable` suggestion computed without the schema);
- `T5`, `T22` and `T32` keep today's meaning in full: `T22` still refuses
  `<e>` over an asymmetric edge, alone or in an alternation, and `<*>`
  between two different types, with the directed form as its fix;
- a lint for `count { } > 0` and `count { } = 0`, whose `fix` is the `exists`
  or `not` block, and one for a directed triple written against schema order,
  whose `fix` is the clause in schema order; both are `queries fmt` rewrites.
  The query diagnostic catalogue (`crates/omnigraph-compiler/src/query/codes.rs`)
  admits `Q`, `T` and `P` today and gains the prefix `L` for lints, whose
  rule is that a lint's rewrite is written only when the lowered IR compares
  equal (the rewriter's comparison);
- `T67` for a `having` expression outside its rule; the three RFC 0048
  refusals named above (duplicate arms, arms over two bindings, an arm in an
  aggregate query), each with its own new code;
- `T6x` reserved construct: `view`, `batch`, `optional { }`, a
  binding with arguments, a block aggregate as a value, `returning`,
  `@type_id`, the reserved annotations and catalogue names, a `retrieve` arm
  over a catalogue type, a namespaced type reference, a `Branch` or `Commit`
  parameter, a file mixing schema and query declarations; `expected`
  names the construct, `fix` names the owning RFC and says "not yet served in
  this release";
- a `retrieve` arm name colliding with a property; an arm read in `match`; an
  `order` that does not lead with an arm or an `rrf` over arms when a
  `retrieve` clause is present.

## Design

### One grammar for schema and queries

`query.pest` and `schema.pest` become one grammar whose start rule is today's
`query_file`, extended by the edition line and the declaration kinds and
otherwise kept, so that every statement the file accepts today (`show`,
`branch`, `commit`, `load`, `explain`, the settings, `statement_trailer`) and
the missing-`()` diagnostic the competence instrument measures stay where
they are:

```pest
query_file  = { SOI ~ edition? ~ setting_stmt* ~ (show_stmt ~ statement_trailer? | branch_stmt ~ ";"? ~ statement_trailer? | commit_stmt ~ ";"? ~ statement_trailer? | load_stmt ~ ";"? ~ statement_trailer? | explain_stmt ~ statement_trailer? | declaration* ~ missing_param_list?) ~ EOI }
edition     = { kw_gq ~ integer ~ ";" }
declaration = { schema_decl | query_decl | mutation_decl | view_decl | batch_decl }
missing_query_keyword = @{ ("query" | "mutation" | "view") ~ !(ASCII_ALPHANUMERIC | "_") }
```

The schema rules move unchanged except for `type_name` where a type is
referenced, which becomes a `type_path` admitting namespace segments (below),
`vector_type`, which admits `distance=`, and `annotation`, which becomes the
generic form below. `cardinality` (`@card(0..1)`) and `body_constraint`
(`@key(@src, @dst)`, `@range(age, 0..150)` inside the braces) stay as they
are, with their range bounds; the generic annotation does not absorb them. A
`.pg` file is a `query_file` holding only `schema_decl`s; the loader keeps the
extension and `cluster.yaml` keeps its `schema:` key, both of which now parse
with the one grammar. Nothing a `.pg` file accepted today is refused (the
spike parsed the 432 GQT schemas and the repository's five `.pg` files under
the one rule). A file holding both schema and query declarations parses and is
refused as a slot in this release; the loader and the stored-query registry
each take one kind, and the RFC that lets one file carry both says what the
mixed file means.

### One spelling per meaning

The freeze list is checked against one rule, in Go's sense: the grammar has
one form for one meaning, and the formatter canonicalises what the grammar
cannot forbid. Concretely:

- A respelling that adds no meaning is not in the grammar. The arrow
  traversal (`-e->`, `<-e-`, `-e-`), the infix `contains` and `starts_with`,
  the positional `k` of `rrf` and `max_edits` of `fuzzy`, a ranking written as
  a call in `order`, and `query` around a write are each a parse or type error
  whose `fix` prints the one form. The diagnostics know every respelling an
  agent trained on Cypher, SQL or GraphQL is likely to write. The rule also
  cuts the other way: a decoration on the one spelling that carries no
  information is not added, which is why the traversal keeps its triple and
  gains no arrowhead ([Traversal](#traversal)).
- A form that falls out of a general construct and has a canonical instance
  is rewritten to that instance by `omnigraph queries fmt`, the rewriter's
  second job (`gofmt -s` is the precedent), and named by lint: `count { P } >
  0` becomes `exists { P }` and `count { P } = 0` becomes `not { P }`; a
  directed triple written against the schema's order (`$c worksAt $p` under
  `edge WorksAt: Person -> Company`), which edition 2 accepts and the type
  checker resolves to the incoming orientation, becomes the triple in schema
  order; once the polymorphic types RFC adds `is`, `$x.@type = "Person"`
  becomes `$x is Person`; once the lexical RFC lands `match_terms`, a `search`,
  `match_text` or `fuzzy` call becomes the `match_terms` call it equals, the
  three rows staying in the registry for good. The grammar keeps `exists`
  because ISO GQL has only `EXISTS` and the planner's semi-join is the honest
  plan for it. A formatter rewrite is written only when the text before and
  after it lowers to one IR under the rewriter's comparison; what separates
  it from the rewriter's break is its input, text edition 3 already accepts.
- Forms that look alike but differ in meaning stay: `return { $a.slug }`
  (a column) and `return { $a }` (one object; the partial object
  `$a { slug }` is a later production); `$e.@src` (stored
  orientation) and the pattern's left end (written orientation); `limit 10`
  and `limit $k`; `count(distinct $x)` and `return distinct`; `having` and a
  `match` filter.
- One argument has one form: a registry function declares each argument
  positional (required) or named (an option), and a caller cannot choose.
- A later RFC's Alternatives section answers this rule for every form it
  adds; `@if_commit($p)` and the request's `--if-commit` precondition field
  are the first case, which is why `@if_commit` is a slot here and not a
  typed annotation: the writes RFC must say the field is derived from the
  annotation, never a second source.

### Declarations

```pest
query_decl    = { kw_query    ~ ident ~ param_list ~ annotation* ~ "{" ~ read_body ~ "}" }
mutation_decl = { kw_mutation ~ ident ~ param_list ~ annotation* ~ (as_commit_clause | as_unattached_clause)? ~ "{" ~ mutation_body ~ "}" }
view_decl     = { kw_view     ~ type_path ~ param_list ~ annotation* ~ "{" ~ read_body ~ "}" }
batch_decl    = { kw_batch    ~ ident ~ annotation* ~ "{" ~ declaration* ~ "}" }
param_list    = { "(" ~ (param ~ ("," ~ param)*)? ~ ")" }
param         = { variable ~ ":" ~ type_ref_or_kind ~ ("=" ~ literal)? }
type_ref_or_kind = { param_type | kw_branch | kw_commit }
```

`query` with a mutation body, or `mutation` with a read body, is a type error
with the rewrite as its fix; the parser accepts both so the message can name
the construct. A `view` has a type name because it is bound as one. `batch`
holds declarations; it is refused as a whole.

No declaration kind is reserved for permissions. The permissions model is
not accepted (two drafts, PR #951 and PR #1197, propose different units of
authority), and nothing is lost by waiting: a file-level declaration keyword
is additive whenever it arrives, because a file can never begin with a bare
identifier, so a later `contract`, `policy` or any other kind joins
`declaration` as one more ordered-choice alternative without a break. The
freeze list reserves only forms whose later addition *would* break stored
text or whose shape the next RFCs already depend on.

### Read body and the retrieve clause

```pest
read_body       = { match_clause ~ retrieve_clause? ~ return_clause ~ having_clause? ~ order_clause? ~ limit_clause? }
retrieve_clause = { kw_retrieve ~ "{" ~ retrieve_arm+ ~ "}" }
retrieve_arm    = { variable ~ "." ~ ident ~ ":" ~ call ~ ","? }
having_clause   = { kw_having ~ "{" ~ expr ~ "}" }
limit_clause    = { kw_limit ~ (integer | variable) }
clause          = { negation | optional_block | subquery_predicate | exists_block | binding | arrow_traversal | traversal | filter }
optional_block  = { kw_optional ~ "{" ~ clause+ ~ "}" }
binding         = { variable ~ ":" ~ bound_type ~ ("{" ~ prop_match_list ~ "}")? }
bound_type      = ${ type_path ~ view_args? }         // the `(` touches the name
view_args       = !{ "(" ~ (expr ~ ("," ~ expr)*)? ~ ")" }
block_value     = { (agg_name ~ ("(" ~ expr ~ ")")? | kw_exists) ~ subquery_block }
```

A `binding` with an argument list names a `view`; the type checker refuses it
in this release. The argument list must touch the type name (`Contested(`):
with whitespace admitted, `$p: Person` followed by a parenthesised filter on
the next line, legal edition-2 text, would be read as view arguments, a silent
change of meaning the spike's `rfc_binding_rule_swallows_a_parenthesised_filter`
caught. `block_value` joins `operand` (below) so a block aggregate can stand
where a value stands; the type checker refuses it in this release and the
derived relations RFC gives it the `SubqueryAggregate` the engine already runs
for the predicate form. Both are listed so that compositional closure, the
capability the next RFC adds, needs no grammar change: a view declaration, a
view binding, an optional block, a block as a value and `having` all parse
today.

An arm's column is a `PropAccess` whose property is the arm name; the type
checker records it in the binding's scope with the arm's result type and
refuses a read of it inside `match`. Before IR is built, every reference to an
arm is resolved to the arm's call, so `order { $d._distance }` lowers to the
`IRExpr::Nearest` the edition-2 `order { nearest(…) }` lowers to, the
planner's search node selection (`optimizer.rs` `search_node`) reads the
leading `order` key exactly as it does today, and the rewriter's IR-equality
proof holds without a second comparison. Lowering maps the call to today's
logical nodes (`Nearest`, `TextSearch`, `RankFuse` in
`crates/omnigraph-planner/src/logical.rs`) and the arm's column to the score
column the ranked scan already appends (`_distance`, `_score`, `_rrf`), the
arm name being the projection alias. `having` lowers to a `Filter` above
`Aggregate`, or above the ranked scan's `Sort` and below `Limit` when the
query has no aggregate (the spike's `explain_retrieve_having.json`: the
`match` filter in the Lance scan filter, `Nearest k: 2` bound from `$k`, the
scan and search fused physically, `having` a typed `Filter` with its threshold
cast to `F32`); both are nodes the planner has. The explain document and
bound-plan versions advance once because score columns are named by the query
and `having` and `limit $k` are new plan inputs.

### Traversal

```pest
traversal       = { variable ~ edge_binding? ~ (undirected_edge | edge_sel) ~ traversal_bounds? ~ variable }
undirected_edge = { "<" ~ (edge_wildcard | edge_alternatives | catalogue_edge | edge_ident | string_lit) ~ ">" }   // `<knows | likes>` as today
edge_sel        = { edge_alternation | edge_wildcard | catalogue_edge | edge_ident | string_lit }
catalogue_edge  = @{ "@" ~ ident }   // an edge of the catalogue's own schema; a slot
arrow_traversal = { variable ~ ("<-" | "-") ~ edge_binding? ~ edge_sel ~ traversal_bounds? ~ ("->" | "-") ~ variable }   // tried before `traversal` in `clause`; recognised only to print the fix
```

The traversal keeps edition 2's spelling and edition 2's rules: a triple,
`<e>` for either orientation, today's `T5` and `T22`. This RFC's first draft
replaced it with an arrow (`$p -worksAt-> $c`, `$p -worksAt- $c`) for the
reader and for the model's Cypher prior, and the direction evidence removed
both reasons. The arrowhead carries no information: when the two endpoint
types differ the schema fixes the orientation, and when they are the same
(`Person knows Person`, `Company subsidiaryOf Company`) the position does,
in a triple exactly as in an arrow form. It is a decoration on the one
spelling, and the one-spelling rule, applied from the other side, asks what
a decoration buys. A reader reads `$p worksAt $c` in source-to-target order,
as a sentence; the one in-context measurement GQ has is on the triple (RFC
0047, Evidence: 45 of 45 tasks correct, 8 of 45 first attempts refused, all
for a missing `()`; it reports no direction result), while CypherBench marks a
reversed relation in 9 of 55 gpt-4o error marks on the arrow form; and
keeping the triple removes the single largest rewrite from the break, since
every stored query has a traversal, and the arithmetic-minus rule with it.
`arrow_traversal` is in the grammar only as a recognizer, placed before
`traversal` in the `clause` choice so the parser reaches it, and never
reaching `<knows>`, which stays the undirected form. An agent writing
`$p -worksAt-> $c`, `$c <-worksAt- $p` or `$a -knows- $b` from a Cypher
habit gets a parse error whose fix prints the triple in the arrow's
direction, source on the left, computed without the schema: `$c <-worksAt-
$p` becomes `$p worksAt $c`, not `$c worksAt $p`, because on a same-type edge
the direction is the only meaning (the spike: `Q008`,
`the_triple_is_unchanged_and_arrows_print_the_triple`, which fixes `$f
<-knows- $p` to `$p knows $f`, with a binding and bounds carried through).

Edition 2 accepts a directed triple in either written order and resolves it
against the schema: `$c: Company worksAt $p` under `edge WorksAt: Person ->
Company` is the incoming orientation (`Direction::In` on the member), and
the corpus writes it (`issue_659_compiler_scopes.gqt`, inside `not`, `exists`
and `count` blocks). Edition 3 keeps that. The two orders are one meaning, the
type checker already records which orientation each member takes, and
refusing one order would be a break the first draft's `T5` hid from the
compatibility list; the swap keeps the lowered IR equal (lowering emits the
`Expand` from the bound end, `ir/lower.rs:591-603`; the spike's comparison,
four of four corpus cases and a same-type negative control) and the rows
equal on Lance, so either rule is implementable, and the one that breaks
nothing wins.
`queries fmt` writes the schema's order, so a stored query reads
source-to-target, and lint names the rewrite. `T5` keeps today's meaning, an
edge whose declared endpoints admit neither order of the written types, with
its fix unchanged. The deterministic correction the Cypher ecosystem bolts
on after generation (LangChain's `CypherQueryCorrector`, built because models
"can sometimes mess up the direction of the relationship") is therefore not
needed on the triple: the compiler resolves the orientation itself, and the
formatter makes the text say it. For a same-type edge the position is the
only carrier of meaning and nothing can check it against the schema; the
edge's `@description` and the skill's schema card say in words which end is
which.

A catalogue edge carries the `@` prefix for the reason catalogue types do:
a user schema may declare an edge named `property` or `from`, and one
spelling per meaning forbids resolving a bare name against two namespaces by
endpoint type. Its ends are bound as any traversal's are, by separate
bindings: `$t: @Type  $p: @Property  $t @property $p`. The engine catalogue
RFC says the five catalogue types are derived at query time, never stored,
that writes, loads and text or rank search over them are refused, and that
catalogue access never calls Lance; this RFC reserves the seven names and the
edge selector as slots and changes none of that. A `retrieve` arm over a
catalogue type (`match { $t: @Type } retrieve { $t.lex: bm25($t.instruction,
$q) }`) therefore parses and is refused with the slot. The amendment that
lifts the refusal names its mechanism, and that mechanism opens no Lance
dataset for rows the catalogue keeps derived (a searchable catalogue table
would be a second schema store, invariant 12); `bm25` stays on user tables,
where the index exists, until then.

`<e>` means both orientations of a same-type edge, deduplicated, as today.
`T22` keeps today's meaning in full, one rule in every section of this RFC:
`<e>` over an asymmetric edge is refused whether it stands alone (`$p
<worksAt> $c`, `test_undirected_traversal_rejected_on_asymmetric_edge`) or in
an alternation (`$p: Person  $c: Company  $p <worksAt | employs> $c`), and
so is `<*>` between two different types (`issue_659_compiler_scopes.gqt`,
`undirected_cross_type_wildcard`). The fix is the directed form, which
already says what an undirected reading would: `$p (worksAt | employs) $c`
resolves each member in the orientation its endpoint types admit today
(`resolve_member`), and `$c * $p` takes every edge between the two types in
either orientation. Resolving `<e>` per member instead, as the 2026-11-01
revision wrote, would have made `<worksAt | employs>` a second spelling of
`(worksAt | employs)` and left `<*>` over the same two types refused, two
widths of one rule. The `<` and `>` of the undirected form are already the comparison operators of
`comp_op`; the ordered choice tries `traversal` before `filter` inside
`match`, as today, so `$a <knows> $b` is never read as a comparison, and the
function-registry work adds no operator that changes this.

### Calls and the reserved set

```pest
call         = { call_name ~ "(" ~ call_args? ~ ")" }
call_name    = @{ !reserved ~ ident }
call_args    = { positional ~ ("," ~ positional)* ~ ("," ~ option)* | option ~ ("," ~ option)* }
positional   = { !(ident ~ ":") ~ expr }              // so `rrf($a, $b, k: 60)` reaches `option`
option       = { ident ~ ":" ~ expr }
agg_distinct = { agg_name ~ "(" ~ kw_distinct ~ expr ~ ")" }
operand      = { "(" ~ expr ~ ")" | block_value | agg_distinct | call | prop_access | meta_field | variable | literal | reserved_property | expr_ident }
list_lit     = { "[" ~ (list_item ~ ("," ~ list_item)*)? ~ "]" }
list_item    = { literal | call }                     // `[date("…"), …]` stays legal; the call must fold
reserved     = { kw_and | kw_or | kw_not | kw_is | kw_null | kw_in }
```

The rules `now_call`, `search_call`, `fuzzy_call`, `match_text_call`,
`bm25_call`, `rrf_call`, `rank_expr`, `agg_call`, `agg_func`,
`nearest_ordering`, `date_lit` and `datetime_lit` are deleted; `date("…")` and
`datetime("…")` are calls the compiler folds to literals as `ir/fold.rs` folds
constants today, inside a list literal included (`issue_801_in_predicate_over_a_list.gqt`
writes `[date("…"), …]`). `positional` looks ahead for `ident ~ ":"` because
PEG does not backtrack: without it `k` in `rrf($a, $b, k: 60)` is taken as a
bare-name positional and the option never parses. A call resolves in the type
checker against a ***function registry***: name, positional parameter types,
named options with their types and ranges, result type rule, kind (`scalar`,
`aggregate`, `predicate`, `ranking`), and the two planner facts `can_fail` and
`volatile`. In this release the registry holds exactly the functions the
grammar held, with their current type rules (`T8`, `T19`, `T20`, `T21`,
`T27`, `T33`, `T38` keep their texts, re-anchored to registry rows); `rrf`
admits `k:` as its one option and `fuzzy` admits `max_edits:` where its third
positional stood. A registry row is never removed: `search`, `match_text` and
`fuzzy` stay, and when the lexical RFC lands `match_terms`, `queries fmt`
canonicalises the three to it and lint names the rewrite; that RFC's
scheduled removal of the three names and its `T27` tightening (refusing
`bm25` over `@index` without `@analyzed`, a refusal of text every graph
writes today) are withdrawn by this rule, since either would be a second
break ([Decision log](#decision-log)). The registry is a Rust table in
`omnigraph-compiler`; the catalogue type `@Function` that exposes it is a
reserved name here and lands with the schema catalogue. Block aggregates
(`count { } > n`) keep their keyword form: they are logic over a pattern, not
calls, as the operator-vocabulary amendment classifies them. `agg(distinct
x)` keeps its special form for every aggregate name, because `distinct` is
contextual and the form is the one every comparator spells the same way;
`sum(distinct $x)` stays the type error it is today (`T57`) rather than
becoming a parse error (`issue_954_count_distinct.gqt`).

A grammar test pins the reserved set: every keyword outside the six is used
as a property name after a dot, as an edge name in a traversal, as a return
alias and as a bare property in a mutation `where`, and parses.

### Annotations, meta-fields, catalogue names, type references

```pest
annotation       = { "@" ~ ident ~ ("(" ~ annotation_args ~ ")")? }
annotation_args  = { annotation_arg ~ ("," ~ annotation_arg)* }
annotation_arg   = { ident ~ "=" ~ annotation_value | annotation_value }
annotation_value = { literal | variable | meta_field | ident }
meta_field       = @{ "@" ~ ident }
type_name        = @{ ASCII_ALPHA_UPPER ~ (ASCII_ALPHANUMERIC | "_")* }
type_path        = @{ (ident ~ "::")+ ~ type_name | "@" ~ type_name | type_name }   // a catalogue name takes no segment
type_ref         = { core_type ~ "?"? }                                  // today's `schema.pest` property type, enums included
param_type       = { (list_type | base_type | vector_type) ~ "?"? }      // today's `query.pest` `type_ref`, renamed
```

Annotation arguments are positional values or `name = value`, in any order
and number (`@valid(a, b)`, `@analyzed(analyzer = "…")`, `@embed("text",
model = "…")`, `@if_commit($c)`, `@instruction("…")`), the spelling stored
`.pg` text already uses (`annotation_kwarg` in `schema.pest`); a call's
options use `:` and an annotation's use `=`, because the two are different
things (a call is an expression, an annotation a declaration's metadata) and
the one-spelling rule applies per meaning, not per punctuation mark. The
evaluation's `@budget(rows: 10)` is therefore spelled `@budget(rows = 10)`.
Annotations are generic on every declaration and resolve against an
***annotation registry*** of the same shape as the function registry (typed
arguments; `scalar` or `declaration` scope); an unknown name is retained as
metadata as `.pg` does today. Meta-fields resolve against a closed list in the
type checker (`@id`, `@src`, `@dst`, `@type`, `@type_id`); `@type_id` is in
the list and refused. The first draft also reserved `@distance` and `@score`
as fields of an arm's column; they are dropped, because the arm's column is
the one spelling of the score and `prop_access` is one level deep, so the two
names had no position to stand in. Catalogue type names resolve against the
catalogue registry; the seven reserved names are in it and refused. A
`type_path` with a namespace segment resolves to a refusal until the schema
namespaces RFC lands; the grammar admits it so that RFC adds no rule, and the
federation reservation is the sentence that an outermost segment may later
name a graph. A catalogue name takes no segment (`crm::@Operator` is a parse
error), which is the rule the schema namespaces RFC states. `type_path` names
a type; `type_ref` (a property's type) and `param_type` (a parameter's type,
with `type_ref_or_kind` adding the kinds `Branch` and `Commit`) keep today's
rules, so `String?`, `[String]` and `Vector(1536)` parse where they parse
today and a namespace segment never stands in them.

### Parameters, limit, null

`param` gains a default literal and the kinds `Branch` and `Commit` in
`type_ref_or_kind`; the binder refuses the two kinds in this release. `limit`
takes an `integer` or a `variable` declared `I64` non-null; a null or negative
value is a bind-time refusal (the spike's `limit_binds_a_parameter`: `k` of
1, 2 and 4 on Lance, a negative value refused at bind, explain showing
`Nearest k: 2` bound from `$k`). `null` is admitted by the grammar only as the
whole value of a mutation assignment, and `expr` has no `null` alternative:

```pest
mutation_assignment = { ident ~ ":" ~ (kw_null | expr) ~ ","? }   // `bio: null`; `bio: null or …` is a parse error
```

There it is
`Literal::Null` of the property's type, which the write path already handles
for a null constant result; a binding's property match (`$p: Person { age:
null }`) is a read and keeps today's parse error, as does a read filter
containing `null`.

### Envelope

`ReadOutput` gains `graph_commits: BTreeMap<String, String>` keyed by graph id
(the request's graph when served, the store's graph identity when embedded),
with one entry today, beside the existing `graph_commit_id`; the other names
in the freeze list are reserved as optional fields and omitted while their
stage has not shipped. All are additive under the HTTP conventions
([HTTP API conventions](2026-10-19-http-api-conventions.md)); the HTTP contract
version does not change, because the edition travels inside the query text.
`openapi.json` regenerates.

### The rewriter

`queries migrate` is a compiler-owned pass over the edition-2 AST, which the
compiler keeps for one release behind the `edition` token. Each rewrite is a
list of `(start, end, replacement)` edits in UTF-8 byte offsets of the original
source, the `suggestion` shape; the tool applies them highest offset first,
prepends the edition line, parses the result under edition 3, lowers both to
IR and compares. Comments survive because the pass never re-prints. The server
runs the same pass at boot for an edition-2 stored source, keeps the rewritten
text in memory for the registry, and logs the edits; the on-disk source in
the cluster bundle is the operator's to rewrite with the tool.

### What is inherited and what is added

Nothing here reads or writes Lance; no storage surface changes. Added by
Omnigraph: the grammar, the edition token, the two registries as compiler
tables, the arm-as-column lowering onto existing plan nodes, the `having`
filter placement, the rewriter and its IR-equality proof, and the boot-time
rewrite.

## Invariants

- **9, query semantics are typed structures.** Strengthened: functions,
  annotations and catalogue names leave the grammar for typed registries; a
  score is a typed column with a named producer; nothing new travels in
  strings.
- **8, integrity failures are loud.** Every slot refuses with a stable code
  and a fix; the rewriter refuses to write a rewrite it cannot prove, and a
  stored source it cannot prove at boot quarantines its graph as a parse
  failure does today; an edition it does not know is a refusal, never a
  guess.
- **12, one source of truth.** The frozen score column is the type
  `score_type` publishes and the column the ranked scan appends; the arm is
  an alias over it, not a second column. The catalogue stays derived: a
  `retrieve` over it is refused until an amendment names a mechanism that
  opens no Lance dataset.
- **13, evidence matches the boundary.** The grammar's evidence is the corpus
  rewritten mechanically and green, plus IR equality; the spelling's evidence
  is the competence instrument on the new spelling before the break; the
  spike is the evidence that the grammar as written parses its own examples
  and today's text.
- **3 and 4, one coherent view, one publication.** Untouched; no read or write
  path changes.
- **11, bounded resources.** Untouched; `limit $k` binds to the same `Limit`.

Deny-list items touched: none. The rewriter is a compiler pass, not a side
channel; `having` is a `Filter` node, not a string.

## Compatibility and reversibility

- **This RFC is the break.** The spellings it removes are `query` for a
  write, the infix string operators, the positional `k` of `rrf` and
  `max_edits` of `fuzzy`, and a ranking written as a call in `order` or
  `return`; the refusals it adds to accepted text are RFC 0048's three
  ("arms on different bindings, duplicate arms, and a leading `nearest`
  without `candidates` in an aggregate query", which in edition 3, with no
  `candidates`, is any arm in an aggregate query).
  Every other edition-2 text parses and typechecks unchanged under edition 3:
  the triple in either written order, `<e>`, the edge binding, alternation,
  wildcard and quoted edge, `search`, `match_text` and `fuzzy`, every `.pg`
  construct (the reserved set does not grow, every new keyword is
  contextual). `T5`, `T22` and `T32` keep today's meaning, so no traversal
  edition 2 refuses gains a meaning.
- **One release of overlap.** The edition-3 release compiles edition 2 and
  rewrites it at boot with a warning; the next release removes the edition-2
  grammar and refuses it with the `queries migrate` fix. `GQ_LANGUAGE_VERSION`
  becomes the edition and moves from `(2, 3)` to `(3, 0)`; PR #805's `(3, 0)`
  and `(4, 0)` are withdrawn so this is the one major ([Decision
  log](#decision-log)); the compatibility-surfaces hash file, when it lands,
  pins the edition-3 rules.
- **Wire.** Additive envelope fields; no HTTP contract bump (the spike booted
  and served an edition-3 stored read with `retrieve`, `having` and `limit
  $k` under today's envelope, `ranking.score_columns` included); explain
  moves from `8` and the bound-plan version advances once (named score
  columns, `having`, `limit $k`). Result column names and types are
  unchanged for every migrated query.
- **Storage.** None.
- **Stored queries.** Every stored query in the fleet is rewritten by the tool
  before the release ships (Evidence); a stored source the sweep missed is
  rewritten at boot in the overlap release.
- **Skill, docs, corpus.** Rewritten by the tool in the same release;
  `skills/omnigraph` byte identity is checked by the existing owner.
- **Reverting.** Before the overlap release ends, revert restores the
  edition-2 grammar and the old spellings' rules; the rewriter has no inverse
  and none is built, since a stored edition-3 source would have to be
  rewritten by hand. After the edition-2 grammar is removed, reverting is a new
  edition.

## Alternatives

| Alternative | Why not |
|---|---|
| Additive first, break last: ship every new form beside the old one with a deprecation, remove the old ones in a final major | Every construct built twice, every corpus and skill edit made twice, agents reading two spellings for a release per construct; three open RFCs already schedule four majors this way |
| Keep rankings in `order` (RFC 0048's "adds no clause and no stage") | One token selects the population and sorts the rows; a score cannot be a filter; `candidates`, `weight`, `exact` and `k` become grammar on the call; the aggregate and `distinct` cases need a special rule. A named arm makes every one of those an expression or an option |
| An arrow spelling for traversals (`$p -worksAt-> $c`, `-e-`), as in Cypher, GQL and SQL/PGQ | This RFC's first draft, for readability and the model's prior; rejected on 2026-10-30: the arrowhead carries nothing the position and the schema do not, the one measurement on the triple shows no direction errors while CypherBench shows arrows do not prevent them, and it was the break's largest rewrite |
| Refuse an incoming triple (`$c worksAt $p` under `Person -> Company`) as `T5` with a swap fix, so every stored query reads source-to-target | The first two drafts; rejected on 2026-11-01: the two orders are one meaning the type checker already resolves, refusing one is a break the compatibility list had hidden, and the formatter gives the reader schema order without one |
| Freeze the score column as `F64?`, null outside the window, named after the arm | The first drafts; rejected: the engine publishes a non-null `F32` (`F64` for `rrf`) and absent rows, and renaming the column changes two result shapes for nothing; the arm is an alias over the column the scan appends |
| Remove `search`, `match_text` and `fuzzy` in edition 3, as the lexical RFC schedules | Their replacement, `match_terms`, is the lexical RFC's and ships after the break, so the removal would make the break wait on that RFC or leave edition 3 without a lexical predicate; the rows stay for good and `queries fmt` canonicalises once `match_terms` exists |
| `@distance` and `@score` as meta-fields of an arm's column | Dropped: the arm's column is the one spelling of the score, and `prop_access` is one level deep, so the two names had no position |
| A `file` rule of `statement \| declaration*` | Dropped the statements the grammar accepts today and the missing-`()` diagnostic the competence instrument measures; today's `query_file` is extended instead |
| Keep `query` for writes | Agents trained on GraphQL write `mutation { }` and the skill documents the trap; a keyword lets lint classify before the body |
| A separate `where { }` clause for filters | Rejected by the shared expression model for reasons that hold: conditions belong beside the pattern; retrieval is different because an arm is not a condition on one row |
| `graph@ns::Type` for the federation segment | A second delimiter where the namespace RFC's `::` already nests; an outermost segment is enough and needs no grammar now |
| Permanent two-edition compiler | Not needed for one break; the registry records the edition, and a second break, if one comes, builds the N-1 arm then |
| One RFC for grammar and semantics (the PR #606 shape) | Closed on 2026-09-28 because it could not be accepted or evidenced piecemeal; this RFC owns the grammar and the window and names the owner of every slot |
| Correct a wrong triple silently against the schema (LangChain's `CypherQueryCorrector`) | Not needed: an incoming triple is not wrong, the type checker resolves its orientation from the schema (a same-type edge takes the written position, so nothing is guessed), and `queries fmt` writes the schema order so the text says what the compiler did; a post-generation corrector would be a second resolver |
| Resolve `<e>` per member over asymmetric members (the 2026-11-01 revision's `T22` narrowing) | Withdrawn on 2026-11-08: the directed alternation `(worksAt \| employs)` already resolves each member, so `<worksAt \| employs>` would be a second spelling of it, and `<*>` between the same two types (`T22` in the corpus) would stay refused, two widths of one rule |
| Name the fused score as a third arm (`retrieve { … $d.fused: rrf($d.vec, $d.lex) }`, then `order { $d.fused }`) | An arm is a scan over one property that appends a column; an `rrf` over arms would be an arm over arms, a second kind of arm the RFC 0048 refusals (duplicate arms, more than two `rrf` arms) would have to tell apart. `rrf(arm, arm)` is today's shape with arms for calls, keeps today's `T33` repetition rule, and needs no rule beyond it |
| Role-named relation ends instead of direction (TypeQL `links (employee: $p, employer: $c)`) | Right for n-ary relations, which GQ does not have; for a binary edge the role names document `src` and `dst`, which `@description` does; a role name on an edge declaration stays additive if a later RFC wants it |
| Stage pipelines as the closure mechanism (TypeQL 3: `match`, `reduce`, `match`, `insert` in any order) | Closed by construction, but the text order is the plan order, each stage's output is its input crossed with its matches, and reads and writes mix in one transaction; the reserved `view`, `optional`, block values and `having` give the measured closure cases under one planner-owned shape and one commit |
| Do nothing | The next five RFCs each break the language once |

## Rollout

1. **Parser-only build and measurement.** The edition-3 grammar behind the
   `edition` token with every slot refusing; the competence instrument run on
   it; the freeze list amended if the measurement says so. `implementation`
   stays `not-started`.
2. **Compiler, registries, lowering, rewriter.** One PR series: grammar, the
   function and annotation registries holding today's functions and
   annotations, arm lowering and `having`, the edition token, the rewriter with
   IR-equality proof. `implementation` to `in-progress`.
3. **Corpus, docs, skill, fleet.** The corpus rewritten by the tool; the user
   guide and skill rewritten; `cluster plan` on the maintainers' graphs clean.
4. **Release N.** Edition 3 the default; edition 2 rewritten at boot with a
   warning. `implementation` to `partial`.
5. **Release N+1.** Edition-2 grammar removed; `GQ_LANGUAGE_VERSION` `(3, 0)`
   is the edition. `implementation` to `complete`.

Each stop is independently safe: step 1 changes nothing a user sees; step 2
is inert until a file says `gq 3;` or the default moves; steps 3 and 4 are
the release; step 5 is the removal every deprecation ends in.

## Unresolved questions

1. The arm spelling: `$d.lex: bm25($d.text, $q)` (column first, as this draft
   writes it) or `bm25($d.text, $q) as $d.lex` (call first, mirroring `return`).
   The parser-only measurement decides.
2. Whether `count(distinct x)` stays the one special call form or becomes a
   registry function `count_distinct(x)`; the former is kept here for
   familiarity.
3. The `graph_commits` key for an embedded target with no graph id.
