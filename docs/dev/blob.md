# Blob internals

**Audience:** contributors changing Blob reads, writes, transport or maintenance
**Authority:** how Blob cells cross the engine, cluster, server and CLI;
user-visible behavior and limits are in [Blob values](../user/blobs.md), test
owners in [test ownership](test-ownership.md#blob-behavior), and the reasons in
[RFC 0033](../decisions/0033-blob-management.md)

Omnigraph treats a Blob as one property cell on an existing node or edge. Lance owns the Blob-v2 physical placement; Omnigraph owns logical identity, snapshot selection, authorization, external-source admission, bounded delivery, and graph-level publication.

## Logical states

A Blob cell is null, managed or external ([Blob values](../user/blobs.md)); null detection is the `crates/omnigraph/src/blob.rs` doc comment. Managed placement—inline, packed, or dedicated—is derived Lance state and is not exposed as a product contract.

Blob properties cannot be keys, unique values, query projections, filters, ordering keys, or aggregate inputs. `.gq` rejects projection rather than substituting a plausible null.

## Engine read facade

The public engine entry point is `Omnigraph::read_blob_at(ReadTarget, BlobCell)` in `crates/omnigraph/src/blob.rs`; its doc comment holds the snapshot pinning, the bounded `BlobReader` and the historical identity fences.

### Historical identity fences

These are compatibility limits, not lookup fallbacks: a Blob reader never silently selects a different lifetime. The rules are on `read_blob_at`.

## Write-path admission

Input values and the default denial of new external references are in [Blob values](../user/blobs.md#writing-blob-values). A configured policy permits only normalized URIs beneath declared bases. Cluster serving projects only server-safe bases; `file://` may be useful to a deliberate embedded process but is never admitted by the HTTP server. The same policy authorizes the source of a `load csv` statement (`crates/omnigraph/src/loader/csv.rs`): `probe_csv_source` runs the ingress preflight through `TableStore::external_source` (`authorize`, the size probe against `load_source_max_bytes`) and keeps the probe's size, etag and version. An overwrite then reads the object by byte range from its parse partitions (`ExternalSource::read_range`, each range a conditional GET with `If-Match` on the probe's etag, refused when the object's size or tag changed); an append or merge reads it whole once (`ExternalSource::read_whole`, the complete response checked while it streams, so a replacement after the probe cannot publish an old-length prefix). The bytes are parsed and staged, and no reference to the object is stored.

A base may not overlap Omnigraph storage. Ingress reads with the process's storage principal, so a base over a graph or cluster root would let a writer copy manifest, table, or ledger bytes into a managed cell that Cedar then serves as graph data. Three checks hold the rule, each against the roots it knows: configuration capture compares every base with the storage root it knows (`external_blob_base_overlaps_storage_root`): a declared `storage:` at `cluster validate` and the selected root at plan and apply, while source-only validation with no declared root has none to compare; serve boot quarantines a graph whose applied server-safe base overlaps that root, and `Omnigraph::with_external_blob_policy` refuses a base overlapping the handle's own graph root. The comparison is by URI component in either direction, using the lexical and canonical forms of both sides (`ExternalBlobBase::ensure_disjoint_from_storage_root`). The root is classified by the storage layer's rule (`omnigraph_storage::storage_kind_for_uri`), so an absolute local path containing `://` is a local root, and a local root is made absolute by the storage adapter's own lexical fold (`omnigraph_storage::absolutize_lexically`), so `<dir>/link/../cluster` is compared at `<dir>/cluster`, where storage writes. A base whose scheme cannot name the root's storage kind (any base against an `az://` or in-memory root, an `s3://` base against a local root, a `file://` base against an S3 root) is disjoint without the root being rendered. A same-kind root that has no base-shaped form (an empty or percent-sign path component, an ancestor that fails to resolve for a reason other than absence) and a root in an unrecognized scheme fail closed as `StorageRootConflict::UncomparableRoot`, published as `external_blob_storage_root_uncomparable`; `StorageRootConflict::Overlap` is `external_blob_base_overlaps_storage_root`, and a base or policy that fails its own validation is `StorageRootConflict::InvalidPolicy`, never either code. Serve boot applies the quarantine only to a graph entry whose composite digest binds its policy; any other entry fails boot with `external_blob_policy_digest_mismatch`.

Admission is done after last-write-wins coalescing, so superseded external references cannot trigger target I/O. Equivalent normalized references are probed and read once per bounded operation where materialization is required, while every reference counts its payload length. An immutable `WriteBudget` carries the effective `write_max_bytes` for independent row-data and payload admission. URI metadata, selected reference count and per-URI length retain their fixed pre-effect limits; the user-facing values and reported resources are listed once in [Blob limits](../user/blobs.md#limits).

Storage mode determines ownership:

- full-table overwrite may retain an allowed external descriptor;
- keyed insert/upsert and row-writing merge materialize selected external bytes into managed values because the keyed Lance writer has no safe external-reference option;
- a pointer-only branch adoption keeps the existing dataset version and performs no source-object I/O.

An existing stored external reference remains classifiable even if current ingress policy would reject creating it, and exportable when it names its whole object (below). Omnigraph never deletes the referenced object.

Schema apply never materializes a Blob. Adding, renaming or dropping a property, Blob or not, is a metadata-only commit that keeps every data file (see [writes.md](writes.md#mutation-and-load)): managed payloads, null and valid-empty cells and external descriptors, ranged ones included, stay exactly as stored, and an added Blob property reads as null in every existing row. A dropped Blob property's managed bytes stay with their data files until the next `optimize`, which rewrites every fragment still holding a dropped column without reading it; `cleanup` then deletes the old data files and their sidecars once no retained version names them.

A null assigned to a nullable Blob clears the cell; `resolve_assignments` refuses a null on a non-nullable one before the update opens its table. An update omits the Blob columns it assigns from its materializing scan (`scan_with_pending_materialized_blobs`'s `omit_blob_columns`): their old cells are never taken, authorized, probed, read, or charged to the byte budget. An update that assigns no Blob and is its mutation's only write to the type may stage a column patch instead (`TableStore::scan_update_matches`, `KeyedWriteSemantics::KnownPresentColumnPatch`; see [writes.md](writes.md#column-patch-updates)): its scan reads no Blob payload, a stored external reference stays as stored, and nothing is charged for the Blob columns. It is chosen whenever a matched row's omitted Blob holds an external reference. A whole-row rewrite cannot carry the reference as stored, so the same update beside another statement on the type reads it or is refused. Otherwise, in a whole-row update, every other Blob cell of a matched row is carried, which means reading it and rewriting it as managed bytes, because the keyed writer has no external-reference option. Carrying a stored external reference therefore passes the graph's policy; a refusal on that path is `OmniError::StoredExternalBlobDenied`, naming the type, id and property, distinct from `ExternalBlobPolicy`, which refuses caller input. Merge and new-input admission keep `ExternalBlobPolicy`.

A materializing rewrite (a carried update or merge cell, the bounded rewrite stream) reads the managed cells of one batch through `TableStore::managed_blob_payloads`, one `Dataset::read_blobs` call, never one `BlobFile::read` per row. It passes managed row ids only, because given an external row Lance resolves and reads the referenced object itself; external cells go through the preflight (keyed writes). The read is streamed (`try_into_stream`, never `execute`) with an explicit `BLOB_READ_IO_BUFFER_BYTES` buffer, since Lance's default is 32 MiB times the store's I/O parallelism, and each value is checked against its descriptor length as it is consumed. Export and the change-feed baseline read the same way through `BlobRowReader` (`crates/omnigraph/src/db/omnigraph/export.rs`). Change-feed images, the change comparator's payload tie-break and entity reads use a one-row reader: the change feed admits one change at a time against its page budget, and its continuation sentinel reads no payload. Only the single-cell read facade keeps `take_blobs`, for bounded ranges of one stable row id.

A whole-object surface cannot carry a ranged external descriptor: `ExternalBlobRef::whole_object_uri` refuses it, and the HTTP redirect, CLI delivery and export all refuse it rather than widen it. Surfaces that are not reloaded describe it as `{"uri", "offset", "length"}`; which surfaces those are is the doc comment of `RangedExternalBlobs` in `crates/omnigraph/src/db/omnigraph/export.rs`, and the descriptor decoder's refusal of an offset with size 0 is in `crates/omnigraph/src/blob.rs`.

## Engine cell writes

`Session::put_blob_at_as` and `Session::clear_blob_at_as` replace one cell of an existing row as Mutation-protocol writes, not a writer kind of their own: an attempt captures a `WriteTxn`, stages one `PendingMode::Upsert` row through `MutationStaging`, and runs the Mutation tail, `commit_staged_mutation` then `publish_committed_mutation`. `forbidden_apis.rs` registers the file under `MUTATION_V9`. The row rebuild, the precondition base and the receipt's ETag are the module doc of `crates/omnigraph/src/exec/blob_write.rs`.

## HTTP and CLI delivery

`GET` and `HEAD /graphs/{graph_id}/blob` delivery, the `302` for an external value and the CLI's `blob get` and `blob stat` are specified in [Blob values](../user/blobs.md#http-reads). A missing or non-Blob property, an unknown entity or null cell (one 404), an unsatisfiable range, a failed precondition and an integrity failure are distinct typed outcomes. MCP reaches Blob cells through `blobs_stat` and `blobs_clear`; it has no put.

`PUT` and `DELETE /graphs/{graph_id}/blob` call the engine cell writes; the PUT ingress and status mapping are on `server_blob_put` in `crates/omnigraph-server/src/handlers.rs`. `omnigraph_api_types::parse_blob_if_match` and `blob_write_output` are shared by the server and the CLI. The CLI's `blob put` and `blob clear` bounds, delivery and exit statuses are the module doc of `crates/omnigraph-cli/src/blob_cli.rs`.

## Maintenance and export

Export emits managed values as base64; how it writes external values is under [Write-path admission](#write-path-admission).

`optimize` compacts Blob-bearing tables. The pinned Lance release must pass the substrate guard proving null, empty, non-empty, neighboring payloads, stable row IDs, and range reads survive fragment compaction. Lance materializes every managed payload of a compaction scanner batch, so `stage_compaction` executes the plan's tasks itself and derives each task's batch size from a descriptor-only scan of that task's fragments: the largest row's managed Blob bytes, summed over its Blob columns (external descriptors are carried unread and count nothing), so one batch materializes at most `COMPACTION_BLOB_BATCH_BYTES` of managed payload. A row over 16 MiB puts its whole task on one-row batches, and a row over the budget is materialized whole. Every task of a Blob table gets the derived size explicitly (1 to 8192 rows, or a caller's smaller one), so it takes precedence over `LANCE_DEFAULT_BATCH_SIZE`, including when the variable is smaller. All tasks are sized before any executes, so when a fragment being compacted holds a descriptor the decoder refuses, sizing can refuse the compaction with a Blob integrity error before that table is rewritten, and nothing is committed; a table with nothing to compact is not scanned. This bounds payload per batch, not heap: Lance's writer copies inline payloads into its prepared arrays while the batch is held; see the compaction fence in [lance-fences.md](lance-fences.md#compaction-of-blob-tables). `cleanup` can reclaim old managed bytes with their dataset versions; callers must quiesce long-lived readers before destructive GC.

`omnigraph upgrade` reads no Blob descriptor and contacts no Blob store. Its supported legacy conversion validates the source's commit history without rewriting table rows; the stamp-only route for already served formats changes metadata only. The [storage upgrade support matrix](versioning.md#storage-upgrade-support-matrix) owns the supported sources and target. When a graph requires an [export/load rebuild](versioning.md#rebuild), the export rule above governs its external descriptors.
