# CI / Release Workflows

`.github/workflows/`:

- **ci.yml**: text-only changes skip the expensive jobs; otherwise `Test Workspace` runs `cargo test --workspace --locked --features omnigraph-engine/failpoints,omnigraph-cluster/failpoints` on ubuntu-latest with protobuf compiler. The feature superset compiles the current source tree once and executes every workspace test target with failpoint hooks present but inert unless a test configures one, including the engine/cluster failpoint suites, the full RFC-026 private `memwal_stream` target, Gate R0's local retention/closure cells, and B2a's small 1/8 retained-history regression. Its captured full-suite log must contain every load-bearing Gate-R0 classifier/authority/source/retry/sweep/widest cell with the expected polarity, the measured local evidence line, the full-fold RSS remeasurement cell and 384-MiB tripwire, B2a's passing small-depth cell and evidence prefix, and both explicitly ignored decision-scale cells. A rename, inverted test, unexpected unignore, or missing evidence therefore fails. The one-sided peak-RSS-lift tripwire detects implementation-shape drift even when common initialization censors the paired lifetime high-water lift to zero or a negative value; the child separately asserts the exact work, and the threshold is not a runtime allocator limit. B2a LIST/timing/RSS output is advisory rather than an SLO or quota. Default-feature production libraries are also compiled by the AWS, v10-fence, and default-RustFS jobs. The workflow also runs the AGENTS.md cross-link integrity check (`scripts/check-agents-md.sh`).
  - **`Test Workspace` does not run on pull requests.** The job requires both a non-PR event and `run_full_ci == true`, so the feature-superset suite runs only on non-text pushes to `main` (post-merge), on `v*` tags, and on manual `workflow_dispatch`. The independent `V10 ↔ V11 Format Fence` job has the same gates and builds the immutable final-v10 CLI in parallel instead of serializing that cold compile ahead of the current workspace. `RustFS S3 Integration` is also push-/tag-/dispatch-only, but starts after classification in parallel with both jobs. The fast PR gates remain `Classify Changes`, `Check AGENTS.md Links`, `Container Entrypoint`, and `Test omnigraph-server --features aws`. `Test Workspace` is correspondingly **not** in the required-check list (`.github/branch-protection.json`); see [branch-protection.md](branch-protection.md).
  - **Why the jobs are split this way:** a 2026-07-28 cold diagnostic measured 25m40s for the then-current genuine-predecessor CLI, 25m29s for the featureless current workspace, and 23m21s for a second current-tree failpoint compile before the run was canceled at 1h14m. The feature-superset command removes that second current-tree graph, while the genuine-v10 and RustFS graphs run concurrently because neither depends on the workspace result. The exact 8,192-row / near-32-MiB Gate-R0 boundary and its 384-MiB RSS remeasurement are unchanged; the scaling removes duplicated compilation rather than reducing correctness evidence. Each heavy job retains an independent timeout.
  - **Consequences to internalize:** (1) a regression that the suite would catch now lands on `main` and turns the post-merge run red, rather than being blocked pre-merge — `main` can briefly break, so run the feature-superset command above locally before merging anything non-trivial, or trigger this workflow on your branch via the Actions "Run workflow" button. (2) CI does not auto-regenerate `openapi.json`; for server/API changes, regenerate it locally with `OMNIGRAPH_UPDATE_OPENAPI=1 cargo test -p omnigraph-server --test openapi` and commit it, or the strict drift check fails.
  - **Applying this policy:** removing `Test Workspace` from the JSON is inert until an admin runs `./scripts/apply-branch-protection.sh`. **Run it immediately after this change merges** — until then GitHub still requires a `Test Workspace` context that no longer reports on PRs, which leaves every open PR permanently pending (the job-never-reports trap).
- **Firehose PR tier (shadow until measured):** `Firehose PR smoke` and `Firehose dependency rebuild` are stable, always-created job names with no workflow-level path filter. Their classifier fails closed to source work for empty or indeterminate diffs and treats only known top-level documentation files and documentation-format files under `docs/` as docs-only. In particular, a Markdown or text fixture under `crates/` is source.
  - **Current shadow suspension:** `Firehose dependency rebuild` still starts and reports, but its changed/missing-key cold branch explicitly returns `shadow-disabled` without checkout, setup, or compilation while the harness is reduced. The first exact changed-key run (`30419113338`) spent 29m25s on the workspace-wide no-run build, then 20m59s recompiling the focused engine graph, and reached the 3,300-second command cap while beginning a third graph. Its selected engine and leaf tests passed before timeout; this was a compile-shape failure, not a correctness-test failure. Do not treat the no-op reporter as evidence or activate either context. Re-enable the versioned cold-policy gate only after an isolated single-graph harness passes the cold bound; focused validation remains local in the interim.
  - `scripts/ci/firehose-key.sh` keys the reusable dependency environment by the exact Rust identity and target, every workspace Cargo manifest plus Cargo configuration and `Cargo.lock`, feature/profile/flags, build scripts and protobuf inputs, runner-image and installed-package identities, the workflow and its full-SHA action pins, branch-protection declaration, and the CI helper scripts. Ordinary Rust source is deliberately absent. The protected-main packer dynamically removes every workspace package output before archiving `target` and Cargo dependency sources, so source-built OmniGraph objects cannot cross PRs.
  - A protected `push` to `refs/heads/main` is the only publisher. It reuses the already-tested `Test Workspace` target and is a terminal job: AGENTS links, entrypoint, workspace, firehose reporters, immediate-predecessor fence, AWS, and both RustFS matrix entries must all succeed first. Main runs are non-canceling; superseded PR runs remain cancelable. The publisher attests the exact archive through the pinned workflow and then uploads the immutable key-named Actions artifact as its final mutation. PR jobs have only read permissions against that namespace. Lookup trusts only a completed-success terminal publisher job from the protected push, rather than the race-prone overall workflow status; more than one live trusted protected-main binding for one key fails closed. Verification binds the repository, workflow, workflow/source digest, main ref, checksum, and embedded key. No PR-produced archive is ever promoted.
  - The shadow implementation's write-once binding is currently **retention-scoped**, not durable: GitHub Actions artifacts expire after at most 90 days, deletion removes the surviving binding, and a later protected-main run could bind the same key to a newly packed digest. Expiry/deletion is safely treated as a missing key for PR correctness, but this does not yet meet RFC-026's durable key→digest activation contract. Before the checks become required, add a non-expiring immutable binding (or amend the RFC with an equally strong construction) and prove same-key rebinding remains impossible after the payload expires.
  - On an unchanged, available key, `Firehose PR smoke` performs the only package/toolchain setup, verifies and restores the protected-main artifact into an empty runner, and runs `scripts/ci/firehose-smoke.sh` under a 780-second aggregate command cap inside a 15-minute job. It publishes a tiny artifact scoped to that workflow-run ID. `Firehose dependency rebuild` validates that current-run evidence and reports without repeating package/toolchain setup or compilation.
  - On a changed key, `Firehose PR smoke` performs no setup and explicitly delegates. On a missing trusted artifact, it delegates after lookup. `Firehose dependency rebuild` is then the sole cold compile and smoke owner, with a 3,300-second command cap inside one hard 60-minute job. It publishes nothing durable. Both contexts still report for docs-only changes.
  - These two jobs are intentionally **not yet in** `.github/branch-protection.json`. The pre-existing evidence does not exercise this exact artifact path: cold main run `30381949221` needed about 39 minutes for `Test Workspace`; warm run `30388677816` restored about 807 MiB in 17 seconds, compiled in 3m49s, and completed the workspace job in 9m54s, but that was the opportunistic Rust cache rather than the immutable attested archive. Before activation, close the durable-binding gap above, record at least 20 successful unchanged-key artifact-hit PR samples, and require p95 end-to-end critical path through both `Firehose PR smoke` and its dependent evidence reporter at or below 15 minutes, with every embedded smoke duration at or below 780 seconds. Also record changed/missing-key cold runs below the 60-minute job ceiling and validate the publish → lookup → attestation → empty-runner restore path. If those bounds do not hold, isolate a smaller protocol harness; do not raise the timeouts.
  - The local owner is `bash scripts/ci/test-firehose-ci.sh`; also run `shellcheck scripts/ci/*.sh` and `actionlint .github/workflows/ci.yml`.
- **AWS feature build job**: `cargo build/test -p omnigraph-server --features aws` on ubuntu-latest.
- **Windows binary build job**: `cargo build --release --locked -p omnigraph-cli -p omnigraph-server` on windows-latest with smoke checks for `omnigraph.exe version`, `omnigraph-server.exe --help`, and PowerShell installer syntax.
- **RustFS S3 integration**: spins up RustFS in Docker and runs the bucket-gated S3 suites against it. Its two parallel matrix entries correspond to the two real Cargo feature graphs: `default` compiles and executes the six selected engine/server/cluster/CLI integration-test binaries in one Cargo invocation, then verifies all twelve required S3 cells and rejects every explicit unconfigured skip from the captured log. `failpoints` runs `failpoints s3_`, RFC-026 B2a's exact provider shard-manifest-failure/orphan-retention cell, and Gate R0's exact configured-RustFS widest-generation closure cell on one failpoint build. `fail-fast: false` and one `rust-cache` key per feature graph preserve independent reporting without the previous five copies of the shared Lance/DataFusion target tree. The physical-ref, enrollment, B2a, and Gate-R0 evidence checks prevent a renamed test or explicit skip from passing vacuously; Gate R0 additionally requires the measured `rustfs` evidence line. This job carries **correctness and load-bearing decision** suites only; RFC-013's `write_cost_s3`, RFC-024's `durable_head_lookup_cost`, and B2a's ignored configured-RustFS 1/8/32/128 cost sweep remain on-demand **cost** instruments. Gate R0 preserves closure/monotonic-retention evidence, while B2a pins typed provider failure plus non-authoritative retained orphan behavior; neither creates a finite storage claim. A measured cold run of the old five-shard layout spent about 26–29 minutes per shard, almost entirely duplicating the same compile. An engine-first combined trial instead discovered the default graph serially—22m04s for the engine owner, then 15m51s for the server owner; cluster compilation was still running when the 50-minute job timeout canceled it and skipped CLI. The single compile-and-run graph keeps the two target caches and reduced runner-minutes without that waterfall; a 45-minute timeout bounds either feature graph. It depends only on classification and begins in parallel with `Test Workspace`; explicit event gating keeps it off pull requests, and non-code documentation-only pushes do not schedule it. Not a required check.
- **release-edge.yml**: on every push to main, retags `edge`, builds Linux x86_64 / Linux arm64 / macOS arm64 archives and Windows x86_64 zip + sha256, publishes a rolling prerelease, then smoke-tests the Windows PowerShell installer against `edge`.
- **release.yml**: on `v*` tags, builds the Linux x86_64 / Linux arm64 / macOS arm64 archives and Windows x86_64 zip release matrix, updates the Homebrew tap (`scripts/update-homebrew-formula.sh`) by pushing the regenerated formula to `ModernRelay/homebrew-tap`, and smoke-tests the Windows PowerShell installer against the tag.
- **package.yml**: manual ECR image build; emits two image tags per commit (`<sha>`, `<sha>-aws`) via CodeBuild.
- **publish-image.yml**: builds and pushes the public `omnigraph-server` container image to GHCR (`ghcr.io/modernrelay/omnigraph-server:<tag>`) and to Docker Hub (`docker.io/modernrelay/omnigraph-server:<tag>`, the primary anonymous-pull channel; skipped when the `DOCKERHUB_*` secrets are unset) on `v*` tag pushes, plus manual `workflow_dispatch` with an explicit existing `v*` tag to backfill an image for a past release. Compiles the binaries inside a `rust:1-bookworm` builder container to match the Dockerfile's bookworm-slim runtime glibc (host-built ubuntu binaries do not run there), builds with `--features omnigraph-server/aws`, and moves `latest` only on real tag pushes — never on backfill dispatches. Separate from release.yml so an image-publish failure cannot block the binary release / Homebrew chain.
