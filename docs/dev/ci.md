# CI / Release Workflows

`.github/workflows/`:

- **ci.yml**: text-only changes skip the expensive jobs; otherwise `Test Workspace` runs `cargo test --workspace --locked --features omnigraph-engine/failpoints,omnigraph-cluster/failpoints` on ubuntu-latest with protobuf compiler. The feature superset compiles the current source tree once and executes every workspace test target with failpoint hooks present but inert unless a test configures one, including the engine/cluster failpoint suites, the full RFC-026 private `memwal_stream` target, Gate R0's local retention/closure cells, and B2a's small 1/8 retained-history regression. Its captured full-suite log must contain every load-bearing Gate-R0 classifier/authority/source/retry/sweep/widest cell with the expected polarity, the measured local evidence line, the full-fold RSS remeasurement cell and 384-MiB tripwire, B2a's passing small-depth cell and evidence prefix, and both explicitly ignored decision-scale cells. A rename, inverted test, unexpected unignore, or missing evidence therefore fails. The tripwire detects implementation-shape drift; it is not a runtime allocator limit; B2a LIST/timing/RSS output is advisory rather than an SLO or quota. Default-feature production libraries are also compiled by the AWS, v9-fence, and default-RustFS jobs. The workflow also runs the AGENTS.md cross-link integrity check (`scripts/check-agents-md.sh`).
  - **`Test Workspace` does not run on pull requests.** The job requires both a non-PR event and `run_full_ci == true`, so the feature-superset suite runs only on non-text pushes to `main` (post-merge), on `v*` tags, and on manual `workflow_dispatch`. The independent `V9 ↔ V10 Format Fence` job has the same gates and builds the immutable final-v9 CLI in parallel instead of serializing that cold compile ahead of the current workspace. `RustFS S3 Integration` is also push-/tag-/dispatch-only, but starts after classification in parallel with both jobs. The fast PR gates remain `Classify Changes`, `Check AGENTS.md Links`, `Container Entrypoint`, and `Test omnigraph-server --features aws`. `Test Workspace` is correspondingly **not** in the required-check list (`.github/branch-protection.json`); see [branch-protection.md](branch-protection.md).
  - **Why the jobs are split this way:** a 2026-07-28 cold diagnostic measured 25m40s for the genuine-v9 CLI, 25m29s for the featureless current workspace, and 23m21s for a second current-tree failpoint compile before the run was canceled at 1h14m. The feature-superset command removes that second current-tree graph, while the genuine-v9 and RustFS graphs run concurrently because neither depends on the workspace result. The exact 8,192-row / near-32-MiB Gate-R0 boundary and its 384-MiB RSS remeasurement are unchanged; the scaling removes duplicated compilation rather than reducing correctness evidence. Each heavy job retains an independent timeout.
  - **Consequences to internalize:** (1) a regression that the suite would catch now lands on `main` and turns the post-merge run red, rather than being blocked pre-merge — `main` can briefly break, so run the feature-superset command above locally before merging anything non-trivial, or trigger this workflow on your branch via the Actions "Run workflow" button. (2) CI does not auto-regenerate `openapi.json`; for server/API changes, regenerate it locally with `OMNIGRAPH_UPDATE_OPENAPI=1 cargo test -p omnigraph-server --test openapi` and commit it, or the strict drift check fails.
  - **Applying this policy:** removing `Test Workspace` from the JSON is inert until an admin runs `./scripts/apply-branch-protection.sh`. **Run it immediately after this change merges** — until then GitHub still requires a `Test Workspace` context that no longer reports on PRs, which leaves every open PR permanently pending (the job-never-reports trap).
- **AWS feature build job**: `cargo build/test -p omnigraph-server --features aws` on ubuntu-latest.
- **Windows binary build job**: `cargo build --release --locked -p omnigraph-cli -p omnigraph-server` on windows-latest with smoke checks for `omnigraph.exe version`, `omnigraph-server.exe --help`, and PowerShell installer syntax.
- **RustFS S3 integration**: spins up RustFS in Docker and runs the bucket-gated S3 suites against it. Its two parallel matrix entries correspond to the two real Cargo feature graphs: `default` runs `s3_storage`, the exact physical-ref ABA and MemWAL enrollment guards, server `s3`, cluster `s3_cluster`, and the CLI S3 flow on one shared default-feature build; `failpoints` runs `failpoints s3_`, RFC-026 B2a's exact provider shard-manifest-failure/orphan-retention cell, and Gate R0's exact configured-RustFS widest-generation closure cell on one failpoint build. `fail-fast: false` and one `rust-cache` key per feature graph preserve independent reporting without the previous five copies of the shared Lance/DataFusion target tree. The physical-ref, B2a, and Gate-R0 steps check that their exact filters matched so a renamed test cannot pass vacuously; the B2a and Gate-R0 commands reject their explicit unconfigured skips, and Gate R0 additionally requires the measured `rustfs` evidence line. This job carries **correctness and load-bearing decision** suites only; RFC-013's `write_cost_s3`, RFC-024's `durable_head_lookup_cost`, and B2a's ignored configured-RustFS 1/8/32/128 cost sweep remain on-demand **cost** instruments. Gate R0 preserves closure/monotonic-retention evidence, while B2a pins typed provider failure plus non-authoritative retained orphan behavior; neither creates a finite storage claim. A measured cold run of the old five-shard layout spent about 26–29 minutes per shard, almost entirely duplicating the same compile; the two-graph layout retains parallel wall-clock while reducing runner-minutes and cache pressure. It depends only on classification and begins in parallel with `Test Workspace`; explicit event gating keeps it off pull requests, and non-code documentation-only pushes do not schedule it. Not a required check.
- **release-edge.yml**: on every push to main, retags `edge`, builds Linux x86_64 / Linux arm64 / macOS arm64 archives and Windows x86_64 zip + sha256, publishes a rolling prerelease, then smoke-tests the Windows PowerShell installer against `edge`.
- **release.yml**: on `v*` tags, builds the Linux x86_64 / Linux arm64 / macOS arm64 archives and Windows x86_64 zip release matrix, updates the Homebrew tap (`scripts/update-homebrew-formula.sh`) by pushing the regenerated formula to `ModernRelay/homebrew-tap`, and smoke-tests the Windows PowerShell installer against the tag.
- **package.yml**: manual ECR image build; emits two image tags per commit (`<sha>`, `<sha>-aws`) via CodeBuild.
- **publish-image.yml**: builds and pushes the public `omnigraph-server` container image to GHCR (`ghcr.io/modernrelay/omnigraph-server:<tag>`) and to Docker Hub (`docker.io/modernrelay/omnigraph-server:<tag>`, the primary anonymous-pull channel; skipped when the `DOCKERHUB_*` secrets are unset) on `v*` tag pushes, plus manual `workflow_dispatch` with an explicit existing `v*` tag to backfill an image for a past release. Compiles the binaries inside a `rust:1-bookworm` builder container to match the Dockerfile's bookworm-slim runtime glibc (host-built ubuntu binaries do not run there), builds with `--features omnigraph-server/aws`, and moves `latest` only on real tag pushes — never on backfill dispatches. Separate from release.yml so an image-publish failure cannot block the binary release / Homebrew chain.
