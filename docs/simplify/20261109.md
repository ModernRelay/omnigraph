# Simplification candidates, 2026-11-09

**Audience:** maintainers reviewing code-removal work
**Base:** `main` at `f0df46736c3598b6f70d30a6cb01abfa6320d788`

This report lists the candidates found in one search for code that can be
deleted to lower maintenance cost. One candidate became a pull request. The
others are ranked below with what was checked and why they were not taken.

"Liability" means code that a maintainer must read, keep correct and change
together. Fewer lines are evidence of less liability, not proof.

## Taken

### 1. One list of Lance's virtual columns, not three

**Kind:** a special case that should be general (also a hand-written copy of
a Lance function).

Lance's scanner adds five columns to a scan when asked: `_rowid`, `_rowaddr`,
`_rowoffset`, `_row_created_at_version` and `_row_last_updated_at_version`.
Lance names them in one function, `lance_core::is_system_column`
(`lance-core-13.0.0/src/lib.rs:93-98`). Before this change the workspace had
three more hand-written copies of the same five names:

| Copy | Used for |
|---|---|
| `omnigraph-compiler` `schema::is_reserved_storage_system_column` | refusing a property with one of these names |
| engine `changes::model::is_reserved_storage_system_column`, with its own test | dropping these columns from change images, the schema fingerprint, export and push comparison |
| engine `loader::is_reserved_physical_input_field` (the five names plus `_tombstone`) | refusing load input fields with these names |

The engine copy existed only because the compiler's copy is private to its
crate (its comment says so). Its test said that a new Lance column must be
added to the compiler list and to this copy "in one audited change".

The engine uses the columns that Lance adds, so Lance's own function is the
right owner there. The change:

- deletes the engine copy and its test, and calls `lance_core::is_system_column`
  at its five call sites;
- reduces the loader predicate to `field == "_tombstone" ||
  lance_core::is_system_column(field)`;
- moves the deleted test's negative cases (`_rowdy`, `_row_custom` and others
  are not system columns) into the existing guard
  `lance_surface_guards.rs::compiler_rejects_five_surveyed_lance_virtual_system_columns`,
  which already checks that Lance reserves the five names and that the
  compiler refuses them.

The compiler keeps its copy: it does not depend on Lance, and that guard
already ties its list to Lance's.

- **Liability removed:** two copies of a list that had to change together by
  hand, and one test that only tested a copy.
- **Liability added:** five call sites now name a `lance_core` function
  directly. The engine already depends on `lance-core` and uses its column
  constants elsewhere. If a Lance upgrade adds a sixth column, the engine now
  drops it automatically, which is what it needs; the compiler copy still has
  to be updated, as before.
- **Behavior:** unchanged. At the pinned Lance 13.0.0 the function matches
  exactly the same five names, with no prefix rule.
- **Lines:** the three engine-side definitions and the test went from 52 lines
  to 3; the guard gained 13. The whole change is 23 lines added and 59 removed.

## Not taken

Ranked by liability removed against risk.

### 2. Unused direct dependencies

**Kind:** dead code (dependencies). **Outcome:** not taken this run; good
next candidate.

No Rust source in the declaring crate names these dependencies:
`dashmap`, `tower-http` and the `lance-index` dev-dependency in
`omnigraph-server`; the `lance-index` dev-dependency in `omnigraph-cli`;
`ahash`, `arrow-ord` and `arrow-cast` in `omnigraph-compiler`; the
`lance-namespace-impls` dev-dependency in `omnigraph-engine`; `lance-core` in
`omnigraph-dst`; the `serial_test` dev-dependency in `omnigraph-core`.
`cargo tree -i` shows that every one of them stays in the build through
another crate, so removing them shortens the manifests but not the dependency
tree, and it can change feature unification. It was ranked below the taken
candidate for that reason. `arrow-ipc` in `omnigraph-catalog` was left out
because open pull requests change that crate.

### 3. A cost counter that nothing increments

**Kind:** dead code. **Outcome:** not taken; needs a reviewer to confirm what
the remaining limits cover.

`omnigraph-core` `instrumentation::record_projection_identity_rows` has no
caller since its only call was removed in #863. The counter it feeds stays at
zero, so the assertions on it in `tests/integration/merge_projection_cache.rs`
always pass. Removing it removes test assertions, so the change needs a
reviewer to agree that they test nothing.

### 4. Small unused items

**Kind:** dead code. **Outcome:** not taken; reported by the search, not yet
checked by a build.

`engine::push::hydrate::hydrated_columns`, `MutationStaging::pending_row_count`
(`#[allow(dead_code)]`), the test-only `loader::preflight_strict_row_arrow_bytes`
shim, and the `PreparedClone` alias in `omnigraph-bench`. About 50 lines.

### 5. Hand-written hex helpers

**Kind:** bloat. **Outcome:** not taken.

Two hex-digit parsers (`blob.rs`, `omnigraph-storage`) can use
`char::to_digit(16)`, and two SHA-256 hex encoders (`omnigraph-storage`,
`omnigraph-cli` `skill.rs`) can use `format!("{:x}", Sha256::digest(..))`,
as the server already does. About 25 lines.

### 6. Copies in the CLI of functions that exist elsewhere

**Kind:** special cases. **Outcome:** not taken.

The test-only `normalize_bearer_token` in `omnigraph-cli` copies the server's
function and tests only itself. `graph_type_subject` in the CLI copies the one
in `omnigraph-core`. The CLI and server each spell `EntityKind::as_str` and the
API-to-engine `EntityKind` mapping inline in several places. About 50 lines
in all.

### 7. The `JavaScript` mode of `JsonParamMode`

**Kind:** dead code. **Outcome:** not taken; it needs a design decision.

No production caller passes `JsonParamMode::JavaScript`; only one in-source
test does. Removing it deletes about 150 lines in
`omnigraph-compiler/src/query_input.rs`, but it is a public enum of a crate
meant for publication, so removing it is an API decision.

### 8. The retired benchmark pipeline

**Kind:** dead code. **Outcome:** not taken; it needs a maintainer decision.

`omnigraph-bench` keeps `worker.rs`, `supervisor.rs`, `fixture_worker.rs` and
`real_graph_run.rs` (about 5,400 lines) behind `#[cfg(test)]`. The subcommands
they start were removed in #894. The [testing guide](../dev/testing.md#cost-tests-and-benchmarks)
still names the retired runner as a test oracle, so retiring it is a decision
for the maintainers.

### 9. A hand-written list-literal builder

**Kind:** bloat. **Outcome:** not taken; medium risk.

`exec/mutation.rs` `typed_list_literal_to_array` repeats one builder loop for
ten element types (about 120 lines). DataFusion's
`ScalarValue::new_list(..).to_array_of_size(..)` could replace it, but the
error text, the zero-row case and the order of errors must be kept exactly.

### Checked and rejected

- The single-batch shortcuts before `concat_batches` are not redundant: with
  one batch, `concat_batches` can panic where `RecordBatch::try_new` returns an
  error.
- `make_list_value_builder` in the loader is not Arrow's `make_builder`: the
  buffer sizes and the error for an unsupported element type differ.
- The `SnapshotScanner` pass-through methods are a sealing boundary, not a
  layer that only forwards calls.
- Candidates in files that open pull requests change were skipped, including
  `schema_for_table_key` in `exec/merge.rs` and `normalize_branch_name`.
